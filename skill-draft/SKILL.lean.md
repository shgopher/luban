# 鲁班写作法（Luban Writing Method）

> **一句话**：把「知识 / 概念 / 主题」写成**可扫读、可自测、信息零丢失**的技术讲解。
> 单篇按此法写；多篇按「铁律 6」拼——**先读目录，主场讲透，客场只引用**。
> 命名寓意：像鲁班做木工一样，每一处都有章法，宁可慢，不出废料。

---

## 参考范文与工具（写作前先读，内化结构）

- `references/example-testing.md` —— 演示：多概念对比表、Go 代码、反模式表、自检题（测试金字塔 / 单元测试 / 集成测试）
- `references/example-release-strategy.md` —— 演示：四方案对比、决策表、铁律、自检题（滚动 / 蓝绿 / 金丝雀）
- `references/cross-refs.md` —— 跨篇协作详解：判主场、切边界、层间分工、接缝、反模式、自检题（摘要不够时读）
- `scripts/make-index.py` —— 抽每节「一句话」+ 引用图：辅助读目录后的筛选与下游查询
- `scripts/linkify-refs.py` —— 把「编号 + 标题」批量转成相对路径链接（跑完再校验）
- `scripts/check-refs.py` —— 全书引用校验器：死链 / 裸编号 / 方向代词 / 悬空 / 编号错配，交付前必跑

## 一、六条铁律（按优先级，不可违反）

1. **知识零丢失。** 原文中每个知识点都必须出现：定义、原理、步骤、数字、优缺点、适用场景、结论、坑。**删的是水，不是肉。**
2. **先结论，后论证。** 读者扫读只靠加粗和表格，也能拿走 80% 信息。
3. **讲得比原文更清楚，而不是更短。** 原文啰嗦就合并；原文没讲透就补一句"本质上就是……"——但**不得编造原文没有的事实、数据、结论**。
4. **数字说话。** 禁用"更好 / 更快 / 更优 / 非常重要"这类无信息量的词。要么给比例、给时长、给阈值，要么删掉。
5. **原汁原味的类比要保留。** 类比是记忆钩子（"掐指一算""大禹治水""国不可一日无君"），但要转述得更利落，不硬凑谐音梗。
6. **全书一体化：先读目录，再动笔；主场讲透，客场只给结论 + 编号。** 同一知识点全书只设一个主场。目录必读（10k，占全书 4.7%），正文只精读相关的那几篇——**读什么由目录定，读多深由一句话定**。铁律 1 管「不掉肉」（相对原文），本条管「不重复」（相对全书）——**零丢失 ≠ 到处重复**。

## 二、全书视角：定位与跨篇协作

> **一句话**：先读全目录、只精读相关的几篇；主场讲透，客场只给结论 + 编号。完整规则见 `references/cross-refs.md`。

**铁律 6：先读目录，再动笔；一篇只讲一层，全书只讲一遍。** 同一知识点全书只设一个主场，客场只给一句自足的结论 + 编号。铁律 1 管「不掉肉」（相对原文），本条管「不重复」（相对全书）——**零丢失 ≠ 到处重复**。

### 动笔前四步

| 步 | 做什么 | 成本 |
|---|---|---|
| ① **读全文目录** | 篇 → 章 → 节 全看一遍（**必做**，一次会话只需一次） | 10.3k |
| ② **圈相关** | 标出 3–8 个可能相关的节（兄弟 / 上下游 / 可能重复的） | 0 |
| ③ **筛选** | `make-index.py . -q 核心词 同义词`，看候选的一句话 | ~0.4k |
| ④ **精读** | 只对真正相关的 1–3 篇读全文 | 5.7k/篇 |

> 🔑 **目录必读，正文精读。「读什么」由目录决定，「读多深」由一句话决定。** 正文 22 万 token 绝不能通读；目录 10.3k 必须读完——grep 只找得到你想到的词，目录让你看到你没想到的节。

```bash
python3 scripts/make-index.py .                    # 建索引：抽出每节「一句话」，供 ③④
python3 scripts/make-index.py . -d 本节编号          # 谁引用了我（入度 0 = 结论没被接住）
python3 scripts/check-refs.py . --quiet            # 收尾校验
```

> ⚠️ 禁止 `cat` 索引（524 节 ≈ 5 万 token）；但**不许用 `-q` 代替读目录**。

### 三条硬规则

| 规则 | 判据 |
|---|---|
| **主场 : 客场 ≥ 3 : 1**（同术语出现处数） | 低于 2 : 1 = 已经长出第二个主场 |
| **引用一律「编号 + 标题 + 相对路径链接」** | 站点里点得动；禁「前文 / 下文 / 后面会讲」：不可定位、导出即失效 |
| **可引用未写的节，不可替它下结论** | 写 `见 44.8 索引原理（待补）`，不许写它的方案 |

### 三种合法形态 / 五种禁止（都带链接）

| ✅ | 行内 `见 [24.6 本地消息表](…/24.6-本地消息表.md)`（12 字短标题）· 括号 `（[34.4 优化手段](34.4-优化手段.md)）`· 前文已说标题时只留编号 `本地消息表（[24.6](…)）` |
|---|---|
| ⚠️ | 指向**还没写**的节：`见 44.8 索引原理（待补）`——没文件就不写链接（死链比没链接更糟）。那一节写完后：行内「待补」由 `linkify-refs.py` **自动删**；关联块里的 `- 待补：44.8 …` 要**手工整行删掉**并入前置/下游，漏删报硬错误 |
| ❌ | 方向代词 · 裸编号 · **有标题没链接**（站点里点不动，读者只能手工翻目录）· 标题与目录不符 · 一页 8 个长链接 |

### 文末「关联」块（≤ 4 行，带链接，与正文行内引用一一对应）

```markdown
### 关联
- 前置：[24.4 TCC](24.4-TCC.md)、[24.6 本地消息表](24.6-本地消息表.md)
- 并列：[24.5 Saga](24.5-Saga.md)（补偿型，无冻结）
- 下游：[24.9 事务模型选型](24.9-事务模型选型.md)
- 待补：44.8 索引原理（未写，无链接）
```

**交付前**跑 `python3 scripts/check-refs.py .`：死链 0、裸编号 0、方向代词 0、**待补过期 0**（该节已写却还标待补，是硬错误）。
待补清单用 `check-refs.py . --todo` 看；每写完一节跑一次 `linkify-refs.py .` 回填链接。

> 💡 需要判断「两个主场怎么切」「层间怎么分工」「案例怎么复用」，或要改这套规范时，读 `references/cross-refs.md`（含四类引用关系、接缝、反模式、9 道自检题）。

## 三、每节的标准结构

```
### <标题>

### 一句话
> 用一句话说清：这节解决什么问题、给出什么答案。

### 正文（按需组合下面第四节的元素）
- 先给结论，再给论证
- 凡多方案/多概念，必须配表格
- 代码必须真实可运行，注释讲清"每步在做什么"

### 反模式 / 坑
- 明确写"别这么做" + "后果"

### 关联（跨篇协作，见第二节）
- 前置：[24.4 TCC](24.4-TCC.md)、[24.6 本地消息表](24.6-本地消息表.md)
- 并列：[24.5 Saga](24.5-Saga.md)（补偿型，无冻结）
- 下游：[24.9 事务模型选型](24.9-事务模型选型.md)
- 待补：44.8 索引原理（未写，无链接）

### 自检
Q1 ...（能检验真懂假懂的题）
▸ 答案：...（含要点，不是复述正文）

Q2 ...
▸ 答案：...

Q ...
▸ 答案：...
```

**硬性要求**：
- 每个小节必须有 `### 一句话`，且只有一行（用于自动生成速览）。
- 文末必须有**自检题**，格式是 `Q` + `▸ 答案`。
- 自检题的答案要能**暴露"背过但没懂"**，不要出"复述正文"的题。
- 文末「关联」块 ≤ 4 行，且与正文行内引用一一对应（正文没引的，不许写进块里）。

## 四、八种写作元素（工具箱，按需选用）

| # | 元素 | 何时用 | 格式要点 |
|---|---|---|---|
| 1 | **一句话点题** | 每节必用 | `> 一句话：……` |
| 2 | **破除误区表** | 主题有流行误解时 | 两列：`误区 \| 现实` |
| 3 | **对比表** | 有 2 个以上方案/概念时 | 维度做列，方案做行；≤7 列 |
| 4 | **代码示例** | 涉及工程实践时 | 可运行 + 行内注释解释"为什么" |
| 5 | **反模式表** | 有常见错误时 | 两列：`反模式 \| 后果` |
| 6 | **铁律 / 关键结论** | 最重要的判断 | `> 🔑` 引用块，一句话 |
| 7 | **自检题** | 每节文末 | `Q` + `▸ 答案` |
| 8 | **决策表 / 清单** | 需要"怎么选"时 | `你的情况 \| 选什么` |

**符号约定**（全文统一）：
- 🔑 = 关键结论 / 铁律
- ⚠️ = 坑 / 易错点
- 💡 = 补充说明（可选的、扩展的）
- **加粗** = 必记内容

## 五、语言风格

- **中文技术白话**，句子短。能用一句说清，不用三句。
- **先结论后论证**，不铺垫、不卖关子。
- **不写空话**："非常重要""极其关键""众所周知"——删。
- **不写自指**："本文""这一讲""接下来我们看看"——删。
- **术语照抄原文**：Raft、Paxos、CAP、2PC 等保持原拼写，不翻译。
- **表格优于长段落**，列表优于长句。

---

## 六、压缩与深度标准

- 输出字数 ≈ 原文清洗后字数的 **55%–70%**。
- **判断标准（唯一）**：一个没读过原文的工程师，读完能**通过相关岗位面试**、能**在选型时说出所以然**。
- 宁可偏全，不可偏短——知识零丢失（铁律 1）优先于压缩比。

## 七、写完后的 QA 自检清单

交付前逐条过：

- [ ] 每个小节有 `### 一句话`（且只有一行）
- [ ] 有多方案/多概念的地方有**对比表**
- [ ] 数字具体（比例 / 时长 / 阈值 / 成本量级）
- [ ] 代码**能跑**（Go/Python 等，不是伪代码）
- [ ] 有反模式 / 坑
- [ ] 文末有**自检题 + ▸ 答案**
- [ ] 无寒暄 / 广告 / 感谢 / 留言 / 课程推广
- [ ] 无"更好/更快/非常重要"这类空词
- [ ] 表格列数一致，代码围栏成对
- [ ] 动笔前读完全文目录，圈出相关节，并精读过其中相关的 1–3 篇
- [ ] 别节主场的内容没有第二次展开（客场 ≤ 1 段）
- [ ] 引用一律「编号 + 短标题 + 相对路径链接」，无「前文 / 下文 / 后面会讲」
- [ ] 已写节的引用全部带链接且可达；未写节标「待补」不写死链
- [ ] `check-refs.py . --todo` 里的待补都是真的还没写；已写的待补全部删干净（行内由 linkify 删，关联块手工删）
- [ ] 悬空引用（该节未写）都带「（待补）」
- [ ] 文末「关联」块与行内引用一一对应
- [ ] 每节跨篇引用 3–8 处（现状均值 1.47，差 2–5 倍）
- [ ] `python3 scripts/check-refs.py .` 零硬错误
- [ ] `python3 scripts/make-index.py . -q <核心术语>` 反查过一遍，没有漏掉的既有节

## 八、一个完整示例（速览）

```markdown
### 一句话
> 发布策略决定"新版本怎么替换旧版本"，核心权衡是风险 ↔ 成本 ↔ 速度。

### 四种策略一张图看全
| 策略 | 做法 | 停机 | 回滚速度 | 资源成本 |
| ...  | ...  | ...  | ...      | ...      |

### 逐个拆解
#### ① 滚动发布
- 优点：不停机、无需额外资源
- 命门：新旧版本共存窗口（见铁律 2）

> 🔑 滚动发布的命门是"新旧共存窗口"：发布期间新旧同时在线，
> 不兼容就随机报错——最难查的一类线上问题。

### 反模式
| 反模式 | 后果 |
| ...    | ...  |

### 自检
Q1 滚动期间错误率"时好时坏"，最可能的原因？
▸ 答案：新旧版本不兼容，发布窗口里两版同时在线导致随机报错。
```

## 九、交付

- 先写 Markdown 源文件（UTF-8）。
- 交付前跑 `python3 scripts/make-index.py <书稿目录>` 更新索引，再跑 `check-refs.py`，硬错误清零再交付。
- 本轮新增了编号，同步更新目录（README / TOC）——**目录永远先于正文**。
- 若用户要 Word/PDF，用 office-docx 技能转 DOCX，并跑结构校验。
- 写完用 `present` 交付成品文件，正文里**只给核心结论 + 表格**，不重复全文。
