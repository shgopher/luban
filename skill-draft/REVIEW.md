## 一、先回答你这次的问题：不通读，怎么保证不漏

「通读目录」是**过程规定**，代价随书稿变大；而且它规定的是「你怎么知道」，不是「你知不知道」。规范应该钉住不变量：

| 原来（v1） | 现在（v2） |
|---|---|
| 动笔前通读目录 | 动笔前**说得清四个编号**（前置 / 并列 / 下游 / 兄弟边界） |
| 怎么读的，不追究 | 靠读还是靠查，不规定；小书直接读，大书查索引 |
| 成本随书稿线性增长 | 成本 **O(命中)**，与全书规模无关 |

### 成本账（实测，0.7 token/字粗估）

| 读什么 | 体量 | ≈ token | 每篇都读？ |
|---|---|---|---|
| 全书正文 | 31.0 万字 | **217k** | ✗ 绝对不能 |
| 全目录 README-v2 | 14,754 字 | 10.3k | ✗ 只在建索引时看一次 |
| **章骨架**（83 章各一行） | 1,298 字 | **0.9k** | ✓ 必读，防漏 |
| 索引查询（命中 5 节） | ~600 字 | **~0.4k** | ✓ 3–5 次 |
| 命中节的「一句话」 | ~100 字/节 | ~0.07k | ✓ 只读命中的 |

### 最终账本（实测，详见 `token-cost.md`）

| 方案 | 每篇 token | 增量 | 比例 | 100 篇 |
|---|---|---|---|---|
| 基线：完全不考虑跨篇 | 13.50k | — | — | 1.35M |
| **B 摘要装法（推荐）** | 16.59k | **+3.09k** | **+23%** | 1.66M |
| A 全塞装法 | 22.31k | +8.81k | +65% | 2.23M |
| 对照：每篇通读全目录 | 23.82k | +10.32k | +76% | 2.38M |
| 对照：每篇通读全书正文 | 230.5k | +217k | +1607% | 23M |

B 的构成：`skill +1.63k · 骨架 0.35k · 查询 0.63k · 校验 0.42k · references 摊销 0.07k = +3.09k`。

> 🔑 **A 装法的增量几乎等于每篇多读一遍全目录**——把整章塞进 SKILL.md，等于每写一节就把目录重读一次。所以推荐 B：**铁律与命令进 SKILL.md（+1.63k），完整规则进 `references/cross-refs.md`（按需读）**。两套装法的判定标准完全一样，只差在规范放哪。

绝对值固定、比例随素材变：素材 0 → A +113% / B +40%；素材 11.4k → A +46% / B +16%。素材越厚，协作开销占比越低。

### 关键设计：把「读」换成「查」

索引由脚本一次生成（**0 token**，不进上下文）：

```bash
python3 scripts/make-index.py .                      # 建索引（写完一节重跑，1 秒）
python3 scripts/make-index.py . -c                   # 章骨架：83 行，0.9k，唯一必读
python3 scripts/make-index.py . -q 幂等 去重 幂等键    # 查重 + 查前置
python3 scripts/make-index.py . -d 24.6              # 查下游：谁引用了我
ls v2/L1-分布式原理/24-分布式事务/                     # 查兄弟：3–8 行
```

真实输出（你的书，跑出来的）：

```
命中 2 节：

  24.4  TCC (空回滚 / 幂等 / 悬挂)  〔11320 字 · 出度 2 · 被引 1〕
        TCC 让每个参与方用 Try/Confirm/Cancel 三个本地操作参与分布式事务…
  25.4  幂等设计与去重  〔7488 字 · 出度 2 · 被引 0〕
        幂等让「同一请求执行 N 次」与「执行 1 次」等价…
```

两条命令之后你就知道「幂等有两个候选主场：24.4 与 25.4」——**没读任何正文**。

> ⚠️ 索引文件自身也不便宜（524 节 ≈ 7.6 万字 ≈ 5 万 token），所以永远 `-q`，不要 `cat`。

### 两条防漏（grep 只找得到你想到的词）

1. **骨架必读**：83 章 0.9k token，保证不漏掉整个领域。全书唯一「必须读」的东西。
2. **收尾反查**：写完把本文 5–8 个核心术语再 `-q` 一遍。同义词漏检（查「缓存」不命中「L1/L2」）靠这一步兜。

## 二、这套方案的边界（不吹）

| 局限 | 影响 | 兜底 |
|---|---|---|
| grep 只找得到你想到的词 | 同义词、旧译名漏检 | 骨架防领域级遗漏 + 术语表登记别名 + 收尾反查 |
| `terms.tsv` 只给候选，不判主场 | 「本地消息表」在 24.9 出现 22 次、24.6 只有 7 次，但主场显然是 24.6——**频率 ≠ 主场** | 只当警报用，主场由「谁负责讲透」判 |
| 新节要先写进索引 | 不重跑就查不到 | 写完一节重跑一次，1 秒 |
| 索引是生成物 | 可能过期 | 加进 `.gitignore`，随时可重建 |

## 三、顺手体检（这次用完整引用图算，比 v1 准）

v1 只数了 `见 N.N` 形态，漏了本书最常见的括号式 `(24.6)`，所以低估了引用密度。重算：

| 指标 | 实测 | 说明 |
|---|---|---|
| 节 / 字 / 平均 | 38 节 / 31.0 万字 / 8,166 字 | |
| 引用边 / 密度 | **56 条 / 1.47 处每节** | 目标 3–8，差 2–5 倍 |
| 悬空（指向未写节） | **23/56 = 41%**，涉及 20 个目标 | 悬空是主态，不标「待补」就是假账 |
| 括号式 `(24.6)` 占比 | **46/67 = 69%** | 只给编号不给标题，读者要翻目录 |
| 孤岛（出入皆 0） | **5 节**：1.2、4.1、26.2、53.2、53.3 | 53.1 讲了金字塔三层，却没链到 53.2/53.3 |
| 双向引用 | 56 条边里只有 **3 对**（11%） | 被引方不知道谁依赖它 |
| 主场重叠 | 「幂等」25.4 : 24.4 = **1.6 : 1**（分工线 3:1） | 两篇各讲一版 |
| 编号错配 | 40.1 写「见 26.3 依赖倒置」，依赖倒置是 26.2 | 工具发现的真实错误 |

`check-refs.py` 报告：**6 条悬空未标待补 + 1 条编号错配 + 16 处裸编号**。建议规范落地后按 SOP 统一改一轮。
