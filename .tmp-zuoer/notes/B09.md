## 69｜程序员练级攻略：开篇词
> 源文件 `.tmp-zuoer/txt/69丨程序员练级攻略：开篇词.txt`，汉字 4,433 字

### 一句话结论
写这篇不是「再列一遍书单」，而是先把**态度问题**解决掉：学习没有速成，三条看似合理的借口（理论无用 / 能力到瓶颈 / 技术太多学不完）全部是为懒惰找的理由；先把标准立高（取法其上），再按「入门 → 修养 → 专业基础 → 软件设计 → 高手成长」五段走。

### 知识点全清单（A1 零丢失）
1. **由来**：2011 年在 CoolShell 发表《程序员技术练级攻略》，读者反馈「跟着这篇文章找到了不错的工作」并要求更新；作者自评旧文「写得也不算特别系统，同时标准也有点低」——当时是给一个想入门的朋友写的，所以要从头更新。
2. **五大篇章**：入门篇、修养篇、专业基础篇、高手成长篇、软件设计篇（原文列举顺序为入门/修养/专业基础/软件设计/高手成长）。
3. **三段进阶链条**（原文并列的三组坐标）：从陌生 → 熟悉 → 理解掌握；从编码 → 设计 → 架构；从码农 → 程序员 → 工程师 → 架构师；最终「从普通到精通到卓越」。
4. **入门篇的语言选择**：先推 Python 和 JavaScript。Python「语法比较简单，有大量的库和语法糖，是零基础的人学习编程的不二之选」；JavaScript 是前端语言，「更容易让你获得编程的成就感」。
5. **入门篇的工具与环境**：操作系统 Linux、编程工具 Visual Studio Code。
6. **为什么必须学 Web**：Web 互联网是**第三次工业革命信息化浪潮中最大的发明**，「也是每个程序员都不能错过的」。
7. **入门篇的收尾**：给出 Web 编程入门的学习要点 + 一个实践项目，帮助理解和巩固。
8. **关键心态提醒**：「你千万不要以为自己已经入门了。我只是用这些内容给你一些成就感，并激发你持续学习的兴趣。」——入门篇的目标是**动机**，不是能力。
9. **正式入门切 Java**：理由是「它是所有语言里综合实力最强的」。
10. **正式入门的工具**：编程 IDE、版本管理工具 Git、调试前端程序的工具、数据库设计工具。
11. **正式入门的项目**：同时设置**业务和技术两方面**的需求，跟着做一遍「对学习编程会有更多的理解和感悟」。
12. **修养篇的定位**：进入专业编程世界之前要树立正确的三观和心态，「这对于程序员来说至关重要」。两个比喻：**民工建筑队 vs 专业工程队**、**小作坊 vs 工厂**——「他们并不仅仅是差别在技能和技术上，更是差别在做事的心态和三观上」。
13. **修养包含六项**：英文能力、提问的能力、写代码的修养、安全防范意识、软件工程和上线规范、编程规范。
14. **修养是分水岭**：「有修养的程序员才可能成长为真正的工程师和架构师，而没有修养的程序员只能沦为码农，这是码农和工程师的关键区分点」；修养「决定了这条路你到底能走多远，是精髓所在」。
15. **专业基础篇三块**：①编程语言——C、C++、Java 三门工业级语言；②理论学科——算法、数据结构、网络模型、计算机原理；③系统知识——Unix/Linux、TCP/IP、C10K 挑战。
16. **从业方向**（原文给了 5 类）：底层（操作系统、文件系统、数据库、网络）／架构（分布式系统架构、微服务、DevOps、Cloud Native）／数据（大数据、机器学习、人工智能）／前端（用户体验、交互）／其它（安全开发、运维开发、嵌入式开发）。
17. **方向选择的两条判断**：①「各种技术方向不是鱼和熊掌，是可以兼得的」；②「很多技术是相通的，关键是你是学在表面还是深入本质」。选哪个「完全遵从于你的本心」。
18. **软件设计篇内容**：结合各主流语言讲泛型编程、函数式编程、面向对象编程等**编程范式**；讲 DRY（避免重复）、KISS（简单）、迪米特法则（最少知识原则）、面向对象的 S.O.L.I.D 等经典设计原则。定位：「这是从工程师通往架构师的必备技能」。
19. **高手成长篇内容与定位**：涵盖系统、数据库、分布式架构、微服务、容器化和自动化运维、机器学习、前端方向、技术论文；「深度一下子拔高了好几个数量级」。
20. **三个待回答的问题（= 三个普遍借口）**：①理论和现实的差距——「从学校毕业的时候只做过小玩具一样的程序」；②技术能力的瓶颈——「工作中需要的技术只不过是不断地堆业务功能，完全没有技术含量」；③技术太多学不过来——「有没有什么速成的方法？」
21. **对借口的反驳①（理论无用）**：「并不是理论和现实的差距大，而是你还没有找到相关的场景，来感受到那些学院派知识的强大威力。」算法与数据结构、操作系统原理、编译原理、数据库原理、计算机原理是「想要成为一个专家必须要学的东西」。判据句：「如果你觉得这些理论上的东西无用，那么只能说明，你只不过在从事工人的工作，而不是工程师的工作。」两个类比：**工人 vs 工程师**、**建筑工人 vs 建筑架构师**。
22. **对借口的反驳②（能力瓶颈）**：「技术能力的瓶颈，以及技术太多学不过来，只不过是你为自己的能力不足或是懒惰找的借口罢了。」技术是死的，努力就能学会；聪明人花时间少、笨点的人花时间多；**差距主要来自「学习方法的不同」与「基础知识储备的不同」**。方法得当 + 多花时间在基础上 → 「会让你未来学习应用知识的时间大大缩短」。
23. **对借口的反驳③（速成）**：「这里没有学习技术的速成的方法，真正的牛人不是能够培训出来的，一切都是要靠你自己去努力和持续地付出。」
24. **一条安慰式判据**：「以绝大多数人努力的程度，和为自己不努力找借口的程度为参考，只要你坚持正常的学习就可以超过大多数人了。」
25. **两篇前置阅读**：《Teach Yourself Programming in Ten Years》（中英对照版）、《程序员的荒谬之言还是至理名言？》。作者的意思是：读完觉得能坚持再看这个系列，否则「只要大致浏览一下目录及其中的某个章节，就会选择放弃」——**这个系列故意设了劝退门槛**。
26. **五条学习建议**（原文逐条）：①一定要坚持，保持长时间学习，甚至终生学习的态度；②一定要动手，不管例子多么简单，至少自己动手敲一遍，看看是否理解了里头的细枝末节；③一定要学会思考，思考为什么要这样而不是那样，还要举一反三；④**不要乱买书，不要乱追新技术新名词**，基础的东西经过很长时间积累，会在未来至少 10 年通用；⑤回顾历史，看看历史时间线上技术的发展，才能明白明天会是什么样。
27. **高标准原则**：引《易经》「取法其上，得乎其中，取法其中，得乎其下，取法其下，法不得也」——「我这里会给你立个比较高标准，你要努力达到。相信我，就算是达不到，也会比你一开始期望的要高很多」。

## 70｜程序员练级攻略：零基础启蒙
> 源文件 `.tmp-zuoer/txt/70丨程序员练级攻略：零基础启蒙.txt`，汉字 4,129 字

### 一句话结论
零基础阶段唯一要优化的目标是「**让人愿意继续学下去**」，所以语言要选有成就感的（Python、JavaScript）而不是工业级的（Java），项目要能端到端做出一个东西（Blog/BBS），而不是把语法学完。

### 知识点全清单（A1 零丢失）
1. **入门的第一性目标**：「对从零基础开始的人来说，最重要的是能够对编程有兴趣，而要对编程有兴趣，就要有成就感。而成就感又来自于用程序打造东西。」这是全篇的判据源头。
2. **两份入门教程，两个方向**：第一份偏后端，「主要是让你体会到编程是什么」；第二份偏前端，「主要是让你做点实际有用的东西。嗯，做个网页吧」。两份都「从环境准备开始，一点一点地从一些简单又有意思的东西入手」。
3. **在线练习**：CodeAbbey 上做一些在线编程的小练习。
4. **Python 入门书（两本，作者给了取舍）**：第一本《与孩子一起学编程》——「以 Python 语言教你如何写程序，是一本老少咸宜的编程书」，教编小游戏 + 基本编程知识；系统学习另有《Python 编程快速上手》与《Python 编程：从入门到实践》两本，**第一本偏文本处理（Word、Excel、PDF），第二本有 Web 项目和代码部署**；「如果可能的话，可以把两本书中的示例都跑一遍。如果你时间有限的话，我推荐你看第二本」。
5. **在线 Python 课**：Codecademy: Learn Python、People Can Program（英文）。
6. **入门语言为什么是 Python 和 JavaScript**：Python「语法比较简单，有大量的库和语法糖，是零基础的人学习编程的不二之选」；JavaScript「是前端的语言，为了让你更有编程的成就感」。
7. **一条重要的反向判据**：「注意：对于计算机专业的学生来说，一般会使用 Pascal 做为入门的编程语言，但我觉得编程入门还是要以培养兴趣为主，所以，还是选一些能让人有成就感的语言会更好」——**专业惯例 ≠ 入门最优**。
8. **JavaScript 入门**：MDN 的 Web 开发入门（MDN = Mozilla Developer Network，「你可以认为是 Web 方面的官方技术网站」），教程带你建一个网站，然后把网页**发布在 GitHub 上**。
9. **操作系统入门**：Linux。理由——「虽然 Windows 占据着更多的桌面市场，但是你还是要了解 Linux」。资源：W3CSchool 的 Linux 教程。
10. **编程工具**：Visual Studio Code，「时下最流行也是最好用」，「潜力十足」，用它开发 Python、JavaScript、Java、Go、C/C++「都能得心应手」。
11. **为什么学 Web**：「因为你正身处于第三次工业革命的信息化浪潮中，在这个浪潮中，Web 互联网是其中最大的发明，所以，这是任何一个程序员都不能错过的。」
12. **Web 编程的四个学习方向**：①MDN JavaScript 教程（「最权威的 JavaScript 官方教程」，初级→中级→高级）；②W3School JavaScript 教程（偏 Web 编程）；③廖雪峰 JavaScript 全栈教程（偏应用，含 Node.js 后端）；④前端基础。
13. **前端基础的正确学法（重要判据）**：CSS、HTML、JavaScript 三件；「文档很大，你要学习的并不是所有的东西，而是**了解 CSS 和 HTML 是怎么相互作用来展示数据的**，然后，不用记忆文档中的内容，这两个文档是用来查找知识的」。另外简单学「用 JavaScript 操纵 HTML」，理解 DOM 和动态网页。
14. **后端基础**：想省事可直接用 Python 或 Node.js（廖雪峰教程里有）；想试另一种主流脚本语言可以搞 PHP，「也是很快就可以上手的语言」。
15. **三门后端语言的排序与理由（Python > PHP > Node.js）**：
    - Python：「应用面还是很广的」，性能可能有问题，「但是用于一些性能不敏感的和运维或是一些小工具相关的，还是非常好用的」；机器学习、AI 也有 Python；做爬虫、简单中间件、应用或业务服务也不错。
    - PHP：「比较主流的简单的语言」，但「其发展潜力有限，虽然可以让你找得到工作，但是一般玩玩就行了」。
    - Node.js：「号称 JavaScript 的后端版，但从目前发展来说，在后端的世界里，并不能承担大任，而且问题很多」。前端用它做后端粘合层，「我个人觉得这样做法只是掩盖前后端配合有问题，或是接口设计思维上的懒惰，我还是希望前端程序员应该认真学习一门真正的后端语言」。

## 71｜程序员练级攻略：正式入门
> 源文件 `.tmp-zuoer/txt/71丨程序员练级攻略：正式入门.txt`，汉字 3,885 字

### 一句话结论
「正式入门」的标志不是学完了更多语法，而是**切到工业级静态语言（Java）并做出一个前后端分离的完整项目**；做完这一层你会像「全栈工程师」，但深度不够——此时是「一般程序员和高级程序员的分水岭」，必须选一个方向扎下去。

### 知识点全清单（A1 零丢失）
1. **学完零基础篇后的两种反应**：一种是有兴趣甚至小骄傲（「请保持这种感觉，但是你也要清醒一下，上面的那些东西，还不算真正的入门，你只是**入门了一条腿**」）；另一种是被吓着、觉得太难。
2. **对「太难」的回应**：「无论你做什么事，你都会面对各式各样的困难，这对每个人来说都是一样的，而只有兴趣、热情和成就感才能让你不畏惧这些困难。」判据：问自己是否从中收获了成就感——没有，可能这条路不适合你；**有一丁点儿，也应该继续坚持**。
3. **本篇的定位**：「让你成为更为专业的入门程序员」；「此时，你可能需要读一些比较枯燥的书，但我想说，这些是非常非常重要的。你一定要坚持住。」
4. **先读一篇方法论**："The Key To Accelerating Your Coding Skills"——「会告诉你如何有效地快速提高自己的编程能力」。
5. **编程技巧**：《代码大全》。评价（含判据）：「这本书好多年没有更新了，其中有一些内容可能有点过时，但还是一本非常好的书」；有点厚，**不需要马上看完**，「在你的编程路上，这本书可以陪你走很久」；「好的书和不好的书最大的区别就是，好的书在你不同的阶段来读，你会有不同的收获，而且还会产生更多的深层次的思考」。
6. **编程语言**：开始了解 Java，「我个人觉得 Java 是世界上目前为止综合排名最好的语言。你一定要学好这门语言」。
7. **Java 入门书**：《Java 核心技术（卷 1）》——除语法外「还会让你了解面向对象编程是个什么概念」；觉得深可降到《Head First Java》。
8. **Spring 必学**：《Spring in Action》或直接从最新 Spring Boot（《Spring Boot 实战》）；「里面可能会有很多你从来没有听说过的东西，比如 IoC 和 AOP 之类的东西，能看懂多少就看懂多少，没事儿」。
9. **操作系统**：《鸟哥的 Linux 私房菜》——「会让你对计算机和操作系统，以及 Linux 有一个非常全面的了解，并能够管理或是操作好一个 Linux 系统」；「这本书的确并不适合初学者，你能看多少就看多少吧」，专业部分看不懂「没关系，就暂时略过」。
10. **网络协议**：到 MDN 读官方 HTTP 文档；**必须知道的三个关键点**：①HTTP 头；②HTTP 的请求方法；③HTTP 的返回码。另需了解 Cookie、缓存、会话、链接管理。「对于 HTTP 协议，你不需要知道所有的东西，你只需要了解这个协议的最关键的那些东西就好了」。
11. **数据库设计**：慕课网在线课「数据库设计的那些事」——每个小课 5–6 分钟，全部不到 2 小时；目标是「搞清楚数据的那几个范式，还有 SQL 语句的一些用法」；数据库用开源 **MySQL**（官方文档或《MySQL 必知必会》）。
12. **前端**：jQuery（和 JavaScript 相关）、Bootstrap（和 CSS 相关），「直接上其官网看文档就好了」。**最重要的一条**：学会用 JavaScript Ajax 请求后端的 API 接口，「而不是再像前面那样用后端来向前端返回 HTML 页面的形式了」；配套要学 JavaScript 的 **Promise 模式**（阮一峰翻译的 ES6 教程有相关内容）。
13. **字符编码**：处理中文时会出现乱码，需要了解 **ASCII 和 Unicode**；资源：文章「关于字符编码，你所需要知道的（ASCII, Unicode, Utf-8, GB2312…）」、Wikipedia - Character encoding、GitHub 上的 Awesome Unicode / Awesome Code Points。
14. **为什么从 Python/JavaScript 切到 Java（四条理由，这是全篇最可迁移的部分）**：
    1. 「Java 是所有语言里面综合实力最强的」——几乎所有大型的互联网或是分布式架构基本上都是 Java 技术栈，所以它是**工业级的编程语言**，而「Python 和 JavaScript 还达不到这样的水准」。
    2. 没用 Java 入门，是因为「编程是一件比较费脑子的事，一开始学习时，兴趣的培养很重要」；Python 简单容易上手，Java 则可能比较难。
    3. 「像 Python 和 JavaScript 这样的动态语言用着是很爽，但是，**只有像 C、C++ 和 Java 这样的静态语言才可以让你真正地进阶**。」
    4. 「对于一个合格的程序员，掌握几门语言是非常正常的事情」——一方面让你对不同的语言进行比较、有更多思考，另一方面「这也是一种学习能力的培养」。反面： 「很多时候，一些程序员只在**自己熟悉的技术**而不是**合适的技术**上工作，这其实并不好，这会让你的视野受限，而**视野会决定你的高度**」。
15. **编程工具四类**：①IDE——传统可用 Eclipse，推荐 IntelliJ IDEA，想时髦用 Visual Studio Code；②版本管理——「传统的有 P4、SVN、CVS 等，但都会被 Git 取代，所以，你就只用学习 Git 就好了」，教程用 Pro Git 第二版（枯燥的备选《猴子都能懂的 Git 入门》），并学会用 GitHub；③调试前端——学会用 Chrome 调试；④数据库设计工具——MySQL WorkBench。
16. **实践项目：投票系统。业务需求 5 条**：①用户只有在登录后才可以生成投票表单；②投票项可以单选、可以多选；③其它用户投票后显示当前投票结果（**但是不能刷票**）；④投票有相应的时间，页面上需要出现**倒计时**；⑤投票结果需要用**不同颜色不同长度的横条**，并显示**百分比和人数**。
17. **技术需求 4 条**：①用 Java Spring Boot 实现，**后端不返回任何 HTML，只返回 JSON 数据**给前端；②由前端的 jQuery 来处理并操作相关 HTML，动态生成前端展示的页面；③前端页面要**响应式**（手机端和电脑端有不同呈现），用 Bootstrap 完成；④在微信中通过**微信授权后记录用户信息，以防止刷票**。
18. **可选挑战 2 条**：①不用刷新页面就能动态看到投票结果变化；②Google 一些画图表的 JavaScript 库，把图表画得漂亮一些。
19. **时间预期（重要数字）**：「上面那些书和知识你要看完，还要能理解并掌握，我估计你最少也要花 **1–2 年**左右的时间」。验收：「不用精通，能独立地做出上面的那些实践项目，那么，你就算是真正的入门了」。
20. **这一层的自我定位**：「你已经是一个『全栈工程师』的样子了」；如果此时对编程还有很大热情，「你可能会是一个非常不错的程序员」。
21. **薪资与能力画像**：「我相信你可以找到至少**年薪 20 万以上**的工作了，而且你的知识面算是有不错的广度了。但是深度还不够，这个时候，是一个比较关键点了。」
22. **分水岭的两条路**：①「你可以就此止步，加入一些公司，在那里按部就班地完成一些功能性的开发，成为一个**搬砖的码农**」；②「你也可以开始选择一个方向开始深入」。作者建议选第二条：「因为你并不知道你未来会有多大的可能性……所以为什么不再更努力一把呢？」原文定性：「这也是一般程序员和高级程序员的分水岭了，能不能过去就看你的了」。

### 一句话结论

学语言不是学语法，是**学「它在解决哪门语言的问题」**：C 解决「贴近机器」，C++ 解决「C 没有抽象」，Java 解决「工程化与生态」，Go 解决「C 太原始、C++ 太复杂、Java 太高级」的夹缝；而「工业级」有硬判据——**ISO 标准化 + 厂商标准化委员会 + 生产环境在用**。

### 知识点全清单（A1 零丢失）
1. **专业编程要学的三方面**：编程语言、理论学科、系统知识。
2. **「工业级语言」的判据（这是全篇最可迁移的一条）**：「主要是，C 和 C++ 语言规范都由 **ISO 标准化**过，而且都有**工业界厂商组成的标准化委员会**来制定工业标准。次要原因是，它们已经在业界**应用于许多重要的生产环境**中。」
3. **C 的定位**：「现今这个世界上几乎所有重要的软件都跟 C 有直接和间接的关系，操作系统、网络、硬件驱动等等。说得霸气一点儿，**这个世界就是在 C 语言之上运行的**。」
4. **C++ 的定位**：「现在主流的浏览器、数据库、Microsoft Office、主流的图形界面、著名的游戏引擎等都是用 C++ 编写的」；「很多公司都用 C++ 开发核心架构，如 Google、腾讯、百度、阿里云等」。
5. **Java 的定位与优势**：「代码稳定性超过 C 和 C++，生产力远超 C 和 C++」；有 JVM 可以轻松跨平台、做代码优化、做 AOP 和 IoC 这样的高级技术；「以 Spring 为首的由庞大的社区开发的高质量的各种轮子让你只需关注业务，是能够快速搭建企业级应用的不二之选」；「金融电商公司则广泛地使用 Java 语言」。
6. **Go 的推荐理由（全部是原话可引的判据）**：①「C 语言太原始了，C++ 太复杂了，Java 太高级了，所以 Go 语言就在这个夹缝中出现了」；②「这门语言已经 **10 多年**了，其已成为**云计算领域事实上的标准语言**，尤其是在 Docker/Kubernetes 等项目中」；③「Go 语言社区正在不断地从 Java 社区移植各种 Java 的轮子过来」；④「如果你要写一些 **PaaS 层**的应用，Go 语言会比 C 和 C++ 更好，目前和 Java 有一拼」；⑤「Go 语言语法特别简单，你有了 C 和 C++ 的基础，学习 Go 的学习成本**基本为零**」。
7. **为什么必须学理论学科（三条理由）**：①「这些理论知识可以说是计算机科学这门学科最精华的知识了。说得大一点，这些是人类智慧的精华」——想成为高手必学；②「当你在解决一些很复杂或是很难的问题时，这些基础理论知识可以帮到你很多。我过去这 **20 年**从这些基础理论知识中受益匪浅」；③「这些理论知识的思维方式可以让你有触类旁通，一通百通的感觉。虽然知识比较难啃，但啃过以后，你将获益终生」。
8. **一条反「等用到再学」的判据**：「你千万不要觉得在你的日常工作或是生活当中根本用不上，学了也白学，这样的思维方式千万不要有，因为这是**平庸的思维方式**。如果你想等我用到了再学也不晚，那么你有必要看一下这篇文章《程序员的荒谬之言还是至理名言？》」。
9. **什么是系统知识**：「系统知识是**理论知识的工程实践**，这里面有很多很多的细节」——Unix/Linux、TCP/IP、C10K 挑战。「这些知识是你能不能把理论应用到实际项目当中，能不能搞定实际问题的重要知识」。
10. **系统知识什么时候用得上（四个场景）**：「当你在编程的时候，如何和系统进行交互或是获取操作系统的资源，如何进行通讯，当系统出了性能问题，当系统出了故障等」。
11. **系统知识的世界观比喻**：「这些东西，你可以认为是**计算机世界的物理世界**，上层无论怎么玩，无论是 Java NIO，还是 Nginx，还是 Node.js，它们都逃脱不掉最下层的限制。」
12. **Java 的入门书单与理由**：《Java 核心技术：卷 1 基础知识》——Sun 公司官方用书，适合时常翻阅的参考手册；「书中有较多地方进行 Java 与 C++ 的比较，因为当时 Java 面世的时候，又被叫作『C++ Killer』」；作者由此「C -> C++ -> Java」整条线融会贯通。
13. **Java 进阶线**：Spring 两本——《Spring 实战》（传统 Spring）与《Spring Boot 实战》（新式微服务的 Spring），「如果你只想看一本的话，那么就看后者」；《Effective Java》（第三版，2017 年末出版）——「模仿 Scott Meyers 的经典图书《Effective C++》」，是**经验之谈**，「你一定要读」；配套推荐 **Google Guava 库**（JDK 的升级库：集合、缓存、原生类型支持、并发库、通用注解、字符串处理、I/O），「其还是 Effective Java 这本书中的那些经验的实践代表」。
14. **设计模式**：《设计模式》（GoF）为经典；觉得难可看《Head First 设计模式》。**关键提醒**：「学习面向对象的设计模式时，你不要迷失在那 **23 个**设计模式中，你一定要明白这两个原则」。
15. **两条面向对象原则及其理由（原文给了完整论证，这部分最值得落地）**：
    - **Program to an 'interface', not an 'implementation'**（面向接口编程，而非面向实现）。三条理由：①「使用者不需要知道数据类型、结构、算法的细节」；②「使用者不需要知道实现细节，只需要知道提供的接口」；③「利于抽象、封装，动态绑定，多态。符合面向对象的特质和理念」。
    - **Favor 'object composition' over 'class inheritance'**（优先对象组合，而非类继承）。四条理由：①「继承需要给子类暴露一些父类的设计和实现细节」；②「父类实现的改变会造成子类也需要改变」；③「我们以为继承主要是为了代码重用，但实际上在子类中需要重新实现很多父类的方法」；④「继承更多的应该是**为了多态**」。
16. **Java 并发与性能**：《Java 并发编程实战》——「一本完美的 Java 并发参考手册」，内容覆盖：并发性与线程安全的基本概念、类库提供的并发构建块、避免并发危险、构造线程安全的类及验证规则、把小线程安全类组合成更大的、利用线程提高吞吐量、识别可并行执行的任务、提高单线程子系统响应性、确保并发程序执行预期任务、提高并发代码性能和可伸缩性；高级主题含显式锁、原子变量、非阻塞算法、自定义同步工具类。《Java 性能权威指南》——用 JDK 自带工具收集性能数据、理解 JIT 编译器优缺点、调优 JVM 垃圾收集器、管理堆内存与 JVM 原生内存、优化线程与同步性能；有余力再读《深入理解 Java 虚拟机》补底层细节。
17. **《Java 编程思想》的定位**：「上面的书让你从**微观**角度了解 Java，而这本书则可以让你从一个**宏观**角度了解 Java」；信息密度大，「读起来是非常耗大脑的，因为它会让你不断地思考」。
18. **《精通 Spring 4.x》**：「一共 **800 多页**，都是干货」；最不错的是**分析原理**，IoC 和 AOP 分析得很棒，「其对任何一个技术都分析得很细致和全面，不足之处就是内容太多了」。
19. **学完 Java 这条线的能力判断**：「如果你把上面的这些知识都融汇贯通的话，那么，你已是一个高级的 Java 程序员了，我保证你已经超过了绝大多数程序员了。基本上来说，你在技术方面是可以进入到一线公司的，而且还不是一般的岗位，至少是高级程序员或是初级架构师的级别了。」
20. **C 语言必须学的理由（判据）**：「这个世界上绝大多数编程语言都是 **C-like** 的语言，也是在不同的方面来解决 C 语言的各种问题。这里，我想放个比较武断话——**如果你不学 C 语言，你根本没有资格说你是一个合格的程序员！**」他也承认现实：「现在，可能不会有多少人学习 C 语言了」，因为有 Java/Python 屏蔽底层细节，也有 Go 这类新兴语言更容易写高性能软件。
21. **明确的书目警告（反例）**：「**千万不要看谭浩强的 C 语言的书。各种误导**，我大学时就是用这本书学的 C，后来工作时被坑得不行。」
22. **学 C 的心理曲线**：「C 语言这么底层，而且代码经常性地崩溃，经过一段时间的挣扎，你才开始觉得你从这个烂泥坑里快要爬出来了」，但之后「你还需要看看《C 陷阱与缺陷》这本书，你会发现，这里面的坑不是一般大」。
23. **C 的两本核心书**：①《C 程序设计语言》（K&R）——「已故的 C 语言之父 Dennis M. Ritchie 和著名科学家 Brian W. Kernighan 合作的圣经级的教科书」；**注意**「其 C 语言的标准不是我们平时常说的 ANSI 标准，而是原作者的标准，又被叫作 **K&R C**」；「很轻薄，也简洁，不枯燥，是一本你可以拿着躺在床上看还不会看着看着睡着的书」。②《C 语言程序设计现代方法》——「这本书更实用，也够厚，完整覆盖了 **C99** 标准，习题的质量和水准也比较高」，还「探讨了现代编译器的实现，以及和 C++ 的兼容，还揭穿了各种古老的 C 语言的神话和信条」。
24. **为什么要学 C++（两条）**：①「C++ 是目前世界上**范式最多**的语言了，其做得最好的范式就是『**泛型编程**』，这在静态语言中，是绝对地**划时代**的一个事」；②「看看 C++ 是如何解决 C 语言中的各种问题的」。坦承：「这是世界目前来说最复杂也是最难的编程语言了」。
25. **C++ 书单与读法**：《C++ Primer 中文版》——「前面 **1/3** 讲 C 语言，后面讲 C++」；知识点多且晦涩，但「你主要就看几个点，一个是**面向对象的多态**，一个是**模板和重载操作符**，以及一些 **STL** 的东西。看看 C++ 是怎么玩**泛型和函数式编程**的」。②《Effective C++》《More Effective C++》——「不厚，但是我读了 **10 多年**，每过一段时间再读一下，就会发现更多的收获」；「这两本书的内容会随着你经历的丰富而变得丰富」；「其中影响最大的不是书中的那些 C++ 的东西，而是**作者的思维方式和不断求真的精神**」。③《深度探索 C++ 对象模型》——「非常非常难啃」，「看完后，C++ 对你来说就再也没有什么秘密可言」。④ C++ 作者 Bjarne Stroustrup 写的 C++ FAQ。
26. **学 C/C++ 必须懂编译器**：「学习 C/C++ 都是需要好好了解一下编译器到底干了什么事的。就像 Java 需要了解 JVM 一样。」
27. **Go 的学习路径**：入门首选 **Go by Example**；在线电子书 **Go 101**；纸书 **The Go Programming Language**（豆瓣 **9.2** 分，原文发布时国内没有卖）；官方 **Effective Go** 必读（「告诉你如何更好地使用 Go 语言，以及 Go 语言中的一些原理」）。
28. **Go 的并发学习材料**：Rob Pike（Unix 老牌黑客罗勃·派克）在 Google I/O 的两个分享——Go Concurrency Patterns、Advanced Go Concurrency Patterns（含幻灯片和演讲视频）；GitHub wiki 上的 Go 精华文章列表、Go 相关博客列表、Go Talks；Awesome Go。
29. **小结的主张**：推荐 C、C++、Java、Go **四门**；「一个合格的程序员应该掌握几门语言」——理由两条：①「这会让你对不同的语言进行比较，让你有更多的思考」；②「这也是一种学习能力的培养，会让你对于未来的新技术学习得更快」。
30. **作者自己的学习顺序**：「其实我是先学了 Java，然后又去学了 C++，之后去学了 C 语言的。C -> C++ -> Java 整条线融汇贯通，这对我未来的技术成长有非常大的帮助。」
31. **留言区补充（作者回复，属可迁移的优先级判据）**：「1）我把 Java 放在第一位，就是说 Java 很重要。C 语言要学。C++ 可以跳过，学了 C 语言，Go 语言很自然就学会了。编程语言不复杂的，多花点时间没坏处。2）**不要取舍，排优先级**。这些基础知识都是计算机科学专业大学本科的知识，4 年你能拿得出来吗？3）Java 语言让你不用关注底层，而关注业务和架构，C 语言让你关注底层原理，Go 语言介于 C 和 Java 之间，掌握多门语言会让你对他们有比较。」

### 一句话结论

## 75｜程序员练级攻略：系统知识
> 源文件 `.tmp-zuoer/txt/75丨程序员练级攻略：系统知识.txt`，汉字 4,130 字

### 一句话结论
系统知识是**理论到工程的落地层**，而它只有三大件：**操作系统（计算）、网络系统（通信）、数据库系统（存储）**；衡量是否学会的标准不是「读过 CSAPP 和 TCP/IP 详解」，而是**能不能写出 telnet 聊天服务器、HTTP 服务器、Ring-buffer 消息队列**。

### 知识点全清单（A1 零丢失）
1. **第一本书与它的定位**：《深入理解计算机系统》（原书 *Computer Systems: A Programmer's Perspective*）。作者的一个判断：「这本书叫做《**程序员所需要了解的计算机知识**》更为合适。」
2. **CSAPP 的最大价值（原文给了完整的层次链，这句可逐字引）**：「本书的最大优点是为程序员描述计算机系统的实现细节，帮助其在大脑中构造一个**层次型的计算机系统**。从最底层的数据在内存中的表示到流水线指令的构成，到虚拟存储器，到编译系统，到动态加载库，到最后的用户态应用。」
3. **学 CSAPP 的收益（判据）**：「通过掌握程序是如何映射到系统上，以及程序是如何执行的，你能够更好地理解**程序的行为为什么是这样的**，以及**效率低下是如何造成的**。」「再强调一下，这本书是程序员必读的一本书！」
4. **理查德·史蒂文斯（Richard Stevens）的三本经典**：《Unix 高级环境编程》、《Unix 网络编程》（第 1 卷 套接口 API、第 2 卷 进程间通信）、《TCP/IP 详解 卷 I 协议》。原文附了生平：「理查德·史蒂文斯于 **1999 年 9 月 1 日**离世，终年 **48 岁**。死因不详，有人说是滑雪意外，有人说是攀岩意外，有人说是滑翔机意外。」
5. **三本书的阅读体验（如实）**：「这三本书可能都不容易读，一方面是比较厚，另一方面是知识的密度太大了，所以，读起来有点枯燥和乏味。但是，这没办法，你得忍住。」
6. **《TCP/IP 详解》的特殊地位**：「这本书迄今至少被**近五百篇学术论文**引用过。这本写给工程师看的书居然被各种学院派的论文来引用，也是很神奇的一件事了。」「虽然理查德·史蒂文斯不是 TCP 的发明人，但是这本书中把这个协议深入浅出地讲出来，还画了**几百张时序图**，也是令人叹为观止了。」
7. **通俗替代（原文给了取舍条件）**：「如果你觉得上面这几本经典书比较难啃，你可以试试下面这些通俗易懂的（当然，如果读得懂上面那三本的，下面的这些也就不需要读了）」——《Linux C 编程一站式学习》《TCP/IP 网络编程》《图解 TCP/IP》（「其实并不是只讲了 TCP/IP，应该是叫《计算机网络》才对，主要是给想快速入门的人看的」）《The TCP/IP Guide》（豆瓣 **9.2**，HTML 英文免费版，「里面的图画得很精彩」）。
8. **抓包是学协议的必要动作（判据）**：「学习网络协议不单只是看书，你最好用个**抓包工具**看看这些网络包是什么样的。」书：《Wireshark 数据包分析实战》——「结合一些简单易懂的实际网络案例，图文并茂地演示使用 Wireshark 进行数据包分析的技术方法」，「也拥有了一定的**黑客的技能**」。
9. **Unix 编程的进阶**：看完《Unix 高级环境编程》后「趁热打铁」看《Linux/Unix 系统编程手册》或罗伯特·拉姆（Robert Love）的 *Linux System Programming*；中文版《Linux 系统编程》「虽然和《Unix 高级环境编程》很像，不过其主要突出的是 **Linux 的一些关键技术和相关的系统调用**」。
10. **协议细节的补充材料（五篇）**："Let's code a TCP/IP stack" 系列 1–5：①Ethernet & ARP；②IPv4 & ICMPv4；③TCP Basics & Handshake；④TCP Data Flow & Socket API；⑤TCP Retransmission。
11. **六个动手要点（系统知识的学习要点，全部是「写代码」而非「读书」）**：①「用这些系统知识操作一下**文件系统**，实现一个可以**拷贝目录树**的小程序」；②「用 **fork / wait / waitpid** 写一个多进程的程序，用 **pthread** 写一个多线程带同步或互斥的程序。比如，多进程购票的程序」；③「用 **signal / kill / raise / alarm / pause / sigprocmask** 实现一个多进程间的信号量通信的程序」；④「学会使用 **gcc** 和 **gdb** 来编程和调试程序」；⑤「学会使用 **makefile** 来编译程序」；⑥「**Socket** 的进程间通信。用 C 语言写一个 1 对 1 的聊天小程序，或是一个简单的 HTTP 服务器」。
12. **C10K 问题与提出者**：「当你读完《Unix 网络编程》后，千万要去读一下『C10K Problem』」。提出者**丹·凯格尔（Dan Kegel）**，「目前在 Google 任职」；原文列了他的履历：「**1978 年**起开始接触计算机编程，是 **Winetricks** 的作者，也是 **Wine 1.0** 的管理员，同时也是 **Crosstool**（一个让 gcc/glibc 编译器更易用的工具套件）的作者。还是 **Java JSR 51** 规范的提交者并参与编写了 Java 平台的 **NIO 和文件锁**，同时参与了 **RFC 5128** 标准中有关 **NAT 穿越（P2P 打洞）**技术的描述和定义。」
13. **C10K 的本质（全篇最重要的一段定义，逐句保留）**：「C10K 问题本质上是**操作系统处理大并发请求的问题**。对于 Web 时代的操作系统而言，对于客户端过来的大量的并发请求，需要创建相应的**服务进程或线程**。这些进程或线程多了，导致**数据拷贝频繁**（缓存 I/O、内核将数据拷贝到用户进程空间、阻塞），**进程/线程上下文切换消耗大**，从而导致**资源被耗尽而崩溃**。这就是 C10K 问题的本质。」
14. **为什么值得学 C10K（判据）**：「了解这个问题，并了解操作系统是如何通过**多路复用**的技术来解决这个问题的，有助于你了解各种 I/O 和异步模型，这对于你未来的编程和架构能力是相当重要的。」
15. **C10M**：「现在，整个世界都在解决 **C10M** 问题」，推荐文章 *The Secret To 10 Million Concurrent Connections - The Kernel Is The Problem, Not The Solution*。
16. **三个实践项目（原文给了完整需求，可直接当验收题）**：
    - **telnet 聊天服务器**（6 条需求）：①每个客户端可以用 `telnet ip:port` 的方式连接到服务器；②新连接需要用用户名和密码登录，没有则注册；③可以选择一个聊天室加入聊天；④管理员有权创建或删除聊天室，普通人员只有加入、退出、查询聊天室的权力；⑤聊天室需要有人数限制；⑥每个人发出来的话，其它所有人都要能看到。
    - **简单 HTTP 服务器**（4 条需求）：①解释浏览器传来的 HTTP 协议，只需要处理 URL path；②把所代理的目录列出来；③在浏览器上可以浏览目录里的文件和下级目录；④点击文件则把文件打开传给浏览器（浏览器能自动显示图片、PDF、HTML、CSS、JavaScript 及文本文件）；点击子目录则进入子目录并列出文件。
    - **生产者/消费者消息队列**（5 条需求）：①采用 **Ring-buffer** 的数据结构；②可以有多个 **topic** 供生产者写入、消费者取出；③支持多个生产者**并发写**；④支持多个消费者消费（只要有一个消费者成功处理消息就可以删除消息）；⑤**不丢数据**（要把消息**持久化**下来）；⑥**性能很高**。
17. **小结的三条重点（原文明确排序）**：
    - **编程语言**：「以工业级的 C、C++、Java 这三门语言为主」，「因为有工业级的标准化组织在控制着这几门语言，而且也有工业级的企业应用。尤其是 Java，还衍生出了大量的企业级架构上的开源生态。你**至少需要掌握 C 语言和 Java 语言**」。另推荐 Go（云计算事实标准，Docker/Kubernetes）。
    - **算法和数据结构**：「这个太重要了，尤其是最基础的算法和数据结构，这是任何一个称职的程序员都需要学习和掌握的。**你必需要掌握**。」
    - **计算机的相关系统（三大件）**：「你至少要掌握三个系统的基础知识，一个是**操作系统**，一个是**网络系统**，还有一个是**数据库系统**。它们分别代表着计算机基础构架的三大件——**计算、存储、网络**。」
18. **时间与薪资（本批第二个硬数字）**：「如果想看完我推荐的那些书和知识，并能理解和掌握，我估计怎么也得需要 **4–5 年**的时间。嗯，是的，就是一个计算机科学系科班出身的程序员需要学习的一些东西。」（留言作者补充口径：「无 996 的在职」。）
19. **走到这里的能力判断**：「你已经是一个**合格的程序员**了，而且你的潜力和可能性是非常非常高的」；「你已经超过了绝大多数人，而且还是排在上游的比较抢手的程序员了。我相信你至少可以找到**年薪 50 万以上**的工作了」。
20. **还缺什么（原文诚实）**：「但是，你还需要很多的经验或是一些实践，以及一些大系统大项目的实际动手的经验。」
21. **五个方向与转方向的成本（判据）**：「往后面走，你需要开始需要**术业有专攻**了」——
