## 判据与红线
- **A 模式精写标准**：原文的每个知识点都要能在笔记里指出来；删的是水，不是肉。
- **不许编造**：原文没有的数字、结论、人名、产品，一律不许补；原文模糊处标注「原文未展开」。
- **保留原汁原味的类比与比喻**（如「按下葫芦浮起瓢」「将军赶路不追小兔」），它们是记忆钩子。
- **落点建议要可执行**：说清「补进哪一节、补哪几条」，不要写「可以补充到相关章节」。
- 时间/项目管理类、职业成长类内容也是有价值的：落到 `v2/组织/`、`v2/附录/` 也可；但区块链、具体厂商产品版本这类时效性内容，若建议不取，要写明理由。
- 书中已有大量重复主题（分布式、弹力、缓存、网关、服务网格、发布策略等），**不要建议重复造主场**：已覆盖就只写「客场引用即可」。
