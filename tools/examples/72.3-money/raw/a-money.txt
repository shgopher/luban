## A1 float64 的表示误差与累加误差

0.1+0.2 的 0.30000000000000004441（运行时 ==0.3: false；字面常量比较会得 true，因为常量按任意精度算）
0.1 的 0.10000000000000000555
19.99*3 的 59.96999999999999886313（int64 分口径：5997 分）
1.005 的原值 1.00499999999999989342：乘 100 = 100.49999999999998578915，roundHalfUp=1.00
2.675 的原值 2.67499999999999982236：乘 100 = 267.50000000000000000000，roundHalfUp=2.68
（1.005 与 2.675 看似同一类「半值」，前者舍成 1.00、后者舍成 2.68——差别只来自二进制表示）

100 万笔 0.01：float64 累加 = 10000.0000001719 元（误差 +0.0000001719 元）
100 万笔 0.01：int64 分累加 = 1000000 分 = 10000.00 元（误差 0）
100 万笔 19.99：float64 累加 = 19989999.999900 元（应为 19990000.00，误差 -0.000100 元）
100 万笔 19.99：int64 分累加 = 1999000000 分 = 19990000.00 元

## A3 舍入顺序：逐行舍入累加 vs 合计一次舍入（整数分口径，精确）
每行 33.33 元、税率 9.50%：逐行税 317 分 × 2 = 634 分；合计计税 633 分；差 1 分/单
整单金额：逐行 = 7300 分（73.00 元），合计 = 7299 分（72.99 元）

## A4 残差分摊：100.00 元给 3 人（最小单位 = 分）
每份独立四舍五入：分 [3333 3333 3333]，合计 9999 分（应收 10000 分，差 -1 分）
最大余数法：      分 [3334 3333 3333]，合计 10000 分（应收 10000 分，差 +0 分）
换算成元：33.34 / 33.33 / 33.33

## A4b JSON 传输：数字型金额在 2^53 之后会静默改值
int64 9007199254740993 编码为 JSON 数字：{"amount_minor":9007199254740993} → 按 float64 解析 = 9007199254740992（是否等于原值: false）
编码为 JSON 字符串：{"amount_minor":"9007199254740993"} → 按 int64 解析 = 9007199254740993（是否等于原值: true）
安全整数边界：2^53-1 = 9007199254740991；超过它的整数在 JS/float64 里不再一一对应
