# 实测 D：索引维护写放大（Redis @127.0.0.1:16394，redis_version:8.10.2）
环境: macOS arm64 / Go go1.27.1 / Redis 8.x @16394 / 2026-11-21
点集 n=1000000，p=6 层级；一次全量更新中 1000000 个点（100.0%）换格

[0] 建全量 per-cell 索引 1M ZADD: 3.57s（280134 ops/s，3.570 s/百万次）
    keys=56435, DBSIZE=56435
[A] 原地更新（ZREM旧格 + ZADD新格）1M 点 = 2000000 条命令: 5.107s
    → 391637 ops/s；5.107 s/百万次更新；单点代价 2 ops
    → 10 万点 @5s 更新 = 2 万更新/s = 4 万 ops/s；100 万点 @5s = 20 万更新/s = 40 万 ops/s
[B] 单 key 分数覆盖（ZADD 覆盖 score）1M 点 = 1000000 条命令: 3.584s
    → 278981 ops/s；3.584 s/百万次更新；单点代价 1 op
    → MEMORY USAGE geo:live = 74.12 MB（77.7 B/member）
[C] 影子索引全量重建 1M ZADD: 3.532s（283125 ops/s，3.532 s/百万次）
    原子切换 RENAME geo:shadow → geo:live2: 213.041µs（O(1)）
    → 若 10 分钟窗口内 20 万更新/s：双写 = 2×120M = 240M ops；重建一次 3.532 s
