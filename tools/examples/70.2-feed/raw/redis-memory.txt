结论：
  1) 生产形态每 member = 84 B，单个用户 1000 条收件箱 = 82.1 KB；100 万活跃用户 ≈ 78.27 GB（只存 ID 与 score，不含正文）
  2) 旧口径（3000 个「只有 1 条」的 key）= 95 B/条：key 的固定开销摊到 1 条上，高估约 13%；这也是不能拿小 key 的读数外推大 key 的原因
  3) member 补零的内存代价：补零 84 B/条 vs 不补零 68 B/条，每百万用户多 14.66 GB（用内存换「字符串序=数值序」）
  4) 100 万 member 的实测总增量 = 80.15 MB，可反推「活跃用户数 × 每箱长度」的内存预算

  5) MEMORY USAGE inbox:u0（1000 条，含 key 与分配器开销）= 93795 字节
