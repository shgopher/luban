# 22.6 拜占庭将军：口头消息 OM(1) 与 3f+1 的界 (可运行复现)

对应正文：[22.6 拜占庭将军问题](../../../v2/L1-分布式原理/22-故障模型与理论边界/22.6-拜占庭将军问题.md)

## 这段代码证明什么

用一段只依赖标准库的 Go 程序实现 OM(1)（一个指挥官 + n-1 个下属，最多 1 个叛徒），把三个结论跑成可比对的输出：

| 场景 | 配置 | 预期 |
|---|---|---|
| ① | n=4，指挥官忠诚，3 号叛徒 | 忠诚下属一致，且跟随指挥官 |
| ② | n=3，指挥官忠诚，2 号叛徒 | 忠诚下属的决策被叛徒带偏（忠诚命令丢失） |
| ③ | n=3，指挥官叛徒 | 忠诚下属一致，但一致到错的值上 |

② 与 ③ 合起来就是 `n ≥ 3m+1` 的直观证明：节点在两种场景里看到的消息完全一样，却要求不同的正确动作。

## 跑法

```bash
cd tools/examples/22.6-byzantine
go run .
```

无外部依赖、无网络、无随机数，输出可逐字比对。

  忠诚下属 1 的决策 = 0
  忠诚下属 2 的决策 = 0
  忠诚下属是否一致：true；是否等于指挥官命令 (1)：false；消息数：4

=== 消息数：OM(1) = (n-1) + (n-1)(n-2) ===

## 假设与边界

- 只实现 `OM(1)`，不是通用的 `OM(m)` 递归；通用版的递归深度是 m，消息数随 m 指数增长。
- 叛徒策略固定（指挥官对奇数编号报反值、下属统一报反值），不是最坏策略；但足以构造不可区分场景。
- 平票按 `RETREAT(0)` 处理，对应 Lamport 原文的默认动作。
- 消息数只统计「发出去的条数」，不含签名、确认与重传开销。
