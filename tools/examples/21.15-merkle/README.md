# 21.15-merkle：Merkle Root 与篡改检测

[21.15 可验证数据结构：哈希链与 Merkle 树](../../../v2/L1-分布式原理/21-共识与选主/21.15-可验证数据结构：哈希链与Merkle树.md) 的配套代码：把「相邻两个摘要拼起来再哈希、逐层向上」这个构造跑一遍，验证两个结论——**改一笔交易，根就变**；**要证明某笔交易在树里，只需 `log2(n)` 个兄弟哈希，不需重传全部交易**。

|---|---|
| `main.go` | `hashLeaf`（交易摘要）、`hashPair`（定序拼接）、`buildLevels`（自底向上建树，奇数复制末节点）、`merkleRoot`、`proof`（兄弟路径）、`changedPerLevel`（逐层统计变化节点）、`main` |

## 期望输出（go1.27.1 darwin/arm64，Apple M1，2026-11 实测）

```text
交易数 8，树高 4 层（含根）
merkle root = 00c44ac866986502024c56baf8a3fd1f010819c810c62746b0e85601039a478c
第 3 笔交易的证明路径长度 = 3 个哈希
篡改后 root = 4eb4b144c1d221df87422648a4bcc6160b4c2550fe7ec5c914acfa323a01bd25
检测到篡改 = true
每层变化的节点数 = [1 1 1 1]（对照：叶子总数 8）
```

读法：

- 8 笔交易 → 8 个叶子、4 层（8 → 4 → 2 → 1），**证明路径 3 个哈希**，即 `log2(8)`；
- 改第 4 笔交易，每层只有 **1 个**节点变化，共 4 个哈希要重算——对照 8 个叶子，这就是 `O(log n)` 与 `O(n)` 的区别；
- 根本身也变了（`00c44a…` → `4eb4b1…`），所以「拿根对一下」就能发现任何一笔交易被改。

## 假设与浮动

- 交易是硬编码字符串，**没有随机数、没有时间**，所以 root 每次运行完全相同（十六进制逐字节可比）。
- 树高与证明路径长度是**结构决定的**，不随机器变；只有哈希实现变（比如换 SHA-256 的变体）才会让 root 值变。
- 奇数个叶子时最后一个复制一份与自己配对（`r = i`），这是比特币的做法；本例 8 个叶子是满二叉树，走不到这条分支。
- 本程序不验签、不排序交易：**Merkle 只保证「内容变了根就变」，不保证「谁有权写」**——权限要靠签名，见 [21.14 PoW 与中本聪共识](../../../v2/L1-分布式原理/21-共识与选主/21.14-PoW与中本聪共识.md)。
