输出：

```text
fib(32) 朴素递归              = 2178309  耗时 25.38875ms
fib(32) memoize(fibNaive) 套壳 = 2178309  耗时 22.069708ms  ← 白套，递归绕过了 cache
fib(32) 自引用 memoize         = 2178309  耗时 101µs  ← 线性

```

2026-11-28 在有并发任务时补测，三个数整体上浮（1357 / 1374 / 1849 ns），但**比值不变**：泛型 ≈ 具体类型，`[]any` 贵 1.36–1.8 倍。看比值，不看绝对值。

泛型 `[]T` 与具体类型 `[]int64` 同速，`[]any` 多一次装箱、慢 1.4–1.8 倍。基准随机器波动：多次运行大致是 330–360 ns（具体/泛型）与 490–600 ns（`[]any`）。

## 装饰器部分（`paradigm.go`）

`runParadigm()` 演示三件事：

| 写法 | 耗时（三次运行区间） | 为什么 |
|---|---|---|
| `fibNaive(32)` | 25.4–31.1 ms | 朴素递归，调用次数按黄金比例指数增长 |
| `memoize(fibNaive)(32)` | 22.1–30.0 ms | **白套**：`fibNaive` 内部调用的是它自己，不是装饰后的函数，cache 永不命中 |
| 自引用 `fib = memoize(...)` | 61.9–106.0 µs | 递归也走装饰后的函数值，线性 |

结论：装饰器改的是**函数值**，不是函数体；递归场景必须先确认"递归调用的是哪个函数值"。另外 `LoggingCounter` 演示 Go 的嵌入是**编译期委托**（无虚函数表），`UndoStack` 演示撤销栈用 `nil` 占位而不是删除——删元素会让后续下标全部错位，且离开作用域前要释放闭包。

**绝对值会漂**：同一台 M1 在并发任务多的时候测到过 79.8 ms / 34.6 ms / 106 µs，空闲时是 25 ms 量级。看比值（朴素 : 自引用 ≈ 250–500 倍），不看单次绝对值。
