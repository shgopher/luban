== 输入 ==
  读 500 QPS / 写 20 TPS / 缓存吸收 20% / 陈旧预算 5000ms
  单表 100 万行 / 单库 5 GB / 3 AZ / RPO 3600s / RTO 3600s

== 决策链 ==
  1. 写侧：20 TPS 在安全线 2800 内（水位 1%）→ 写仍可单主
  2. 容量：单表 100 万行、单库 5 GB 未超阈值 → 不因容量分片
  3. 读侧：500 QPS ×(1-缓存 20%)=400，再乘 AZ 冗余 1.50 → 需 600 QPS，单副本 12000 → 0 个副本
  4. 扇出：0 个副本 × 2.0 MB/s = 0 MB/s 主库上行
  5. RPO≤3600s：异步复制 + 定时备份即可
  6. RTO>5min：可接受人工切换，但要把「谁来点」写进值班表
  7. 成本：1 个盒子（1 主 + 0 从）× 2000 元 = 2000 元/月；每万读 QPS 1675 元/月

== 结论 ==
  拓扑：单机
  理由：读写都在单机安全线内
  读能力：11940 QPS（水位 3%）
  可用性：MTTR 1800s × 每月 1 次故障 → 年停机 6.00h，可用性 99.9315%（3.16 个 9）
  费用：2000 元/月，24000 元/年

== 陈旧预算 ==
  无副本：陈旧预算不适用，可用性只能由备份恢复时长（RTO）兜底

== 决策记录（ADR 片段）==
  决定：数据库采用「单机」。
  依据：读写都在单机安全线内；读 500 QPS 需 0 个副本（含 AZ 冗余 1/(1-1/3)=1.5）；RPO=3600s 由异步复制兜住，不额外付半同步的 RTT；RTO=3600s 决定切换方式。
  代价：每月 2000 元；主库扇出 0 MB/s；故障时年停机预算 6.00 小时。
