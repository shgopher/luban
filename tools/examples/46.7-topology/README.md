# 46.7-topology：数据库部署拓扑选型计算器

[46.7 数据库的架构定位与部署拓扑选型](../../../v2/L4-组件与技术/46-数据架构/46.7-数据库架构定位与部署拓扑选型.md) 的配套代码：把「架构决策链」算成一组可核对的数——几个盒子、几个副本、每月多少钱、卡在哪一步、可用性折算几个 9。

它不回答「用 MySQL 还是 TiDB」，只回答「给定读写量、数据量、RPO/RTO 与单价，这台数据库在架构里该摆成什么形状」。

```bash
cd tools/examples/46.7-topology
go run .                                  # 默认：大促型（读 6 万 QPS、RPO=0、RTO=60s）
go run . -read 30000 -write 600 -rows 5e6 -data 120 -rpo 5 -rto 300
go run . -read 500 -write 20 -rows 1e6 -data 5 -rpo 3600 -rto 3600 -stale 5000
go test ./...                             # 副本数 / 分片触发 / 单机判定 / 成本 5 个用例
```

## 输出节选（大促型，默认参数）

```text
== 决策链 ==
  1. 写侧：800 TPS 在安全线 2800 内（水位 29%）→ 写仍可单主
  2. 容量：单表 5000 万行、单库 800 GB 超阈值（2000 万行 / 500 GB）→ 归档或分片
  3. 读侧：60000 QPS ×(1-缓存 30%)=42000，再乘 AZ 冗余 1.50 → 需 63000 QPS，单副本 12000 → 6 个副本
  4. 扇出：6 个副本 × 2.0 MB/s = 12 MB/s 主库上行
  5. RPO=0：异步复制不达标，需半同步（AFTER_SYNC）或组复制/共识复制，写延迟 +1 次 RTT
  6. RTO≤60s：必须自动切换（选主+VIP/代理改指向），人工不可能达标
  7. 成本：7 个盒子（1 主 + 6 从）× 2000 元 = 14000 元/月；每万读 QPS 1716 元/月

== 结论 ==
  拓扑：分片 + 只读副本
  理由：单表容量到顶：按该维度分片，每个分片再按读维度挂副本
  读能力：81600 QPS（水位 51%）
  可用性：MTTR 60s × 每月 1 次故障 → 年停机 0.20h，可用性 99.9977%（4.64 个 9）
  费用：14000 元/月，168000 元/年

== 风险（触发但未违反硬约束）==
  - 6 个副本超舒适区 5：先做缓存与归档，再考虑级联复制
```

## 输出节选（典型业务系统：读 3 万 QPS、写 600 TPS、缓存吸收 50%）

```text
  拓扑：一主 2 从（异步）
  理由：读需扩展、可容忍秒级丢失：异步复制最便宜
  读能力：34200 QPS（水位 44%）
  可用性：MTTR 300s × 每月 1 次故障 → 年停机 1.00h，可用性 99.9886%（3.94 个 9）
  费用：4500 元/月，54000 元/年
```

## 输出节选（小内部系统：读 500 QPS、能接受小时级停机）

```text
  拓扑：单机
  读能力：11940 QPS（水位 3%）
  可用性：MTTR 1800s × 每月 1 次故障 → 年停机 6.00h，可用性 99.9315%（3.16 个 9）
  费用：2000 元/月，24000 元/年

== 陈旧预算 ==
  无副本：陈旧预算不适用，可用性只能由备份恢复时长（RTO）兜底
```

## 假设与浮动（哪些数能抄，哪些不能）

| 参数 | 默认值 | 性质 | 怎么换成你的 |
|---|---|---|---|
| `-read-per-node` | 12000 QPS | **合成值**，代表单副本安全读能力 | 压测你自己的查询，取 70% 水位 |
| 写安全线 | 4000×70%=2800 TPS | **合成值**，随单条事务大小差一个数量级 | 用 `sysbench oltp_write_only` 压出本机拐点 |
| 单表/单库阈值 | 2000 万行 / 500 GB | 来自 44.14 的 B+ 树三层估算 | 阈值只决定「该不该看分片」，不决定「必须分」 |
| `-price` | 2000 元/月 | 示例单价 | 换成你云的实例报价（含存储与备份） |
| `-cache` | 30% | 需要你填的实测命中率 | 从缓存监控取读命中率，不要拍脑袋 |
| 可用性 | 每月 1 次故障 × MTTR | **显式假设** | 换成你的 MTBF 实测值；只报 MTTR 会把可用性报成 6 个 9 |

## 配套实测

同一目录下的 [mysql-repl/](mysql-repl/README.md) 是在 Docker 里跑 MySQL 8.0 一主一从的验证脚本：20 次写后读、停回放造滞后、20 万行大事务、`DROP TABLE` 传播、提升演练。正文那四段“真实输出”就来自它，`./verify.sh` 可复现。

- 本程序只做**容量与成本的一阶估算**，不含网络、备份存储、跨 AZ 流量费与人力成本。
- 数字会随查询模式漂：同一台机器，点查与范围扫描的单副本能力能差 10 倍。看**比值与量级**，不要对齐小数点。
