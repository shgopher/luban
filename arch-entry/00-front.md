# 前言

## 这本手册解决什么问题

你可能是第一次以「架构师」的身份参加需求评审、写技术方案、拍板上线。你缺的不是又一本讲 CAP 和 Raft 的书，而是：

- 需求会上该问什么，才能不返工；
- 方案文档怎么写，才能一次通过；
- 数据库、缓存、消息、部署、发布，具体怎么配；
- 出事时先看什么、先动哪里。

这本手册只写这些。**原理能删的都删了，命令和清单能给的都给了。**

## 和完整教程的关系

完整教程覆盖 84 章、594 节，从内核到组织、从共识算法到 MLOps，是给资深架构师查漏补缺用的。这本手册是从里面抽出的「上岗第一年真正会用到的 20%」，并且重写成了更浅、更短、更可抄的形式。

想深入某一块，附录 D 给了对应的章节索引。**先用这本上手，再按需回完整教程补原理。**

## 怎么读

| 你的情况 | 建议路线 |
|---|---|
| 下周要接第一个方案 | 第 1–3 章 → 第 11–12 章 → 附录 A |
| 系统天天出故障 | 第 10 章 → 第 13 章 → 第 20 章 |
| 要拆服务/做演进 | 第 5 章 → 第 19 章 |
| 要带团队落地 | 第 18 章 → 第 19 章 → 附录 B |
| 完全新手 | 按附录 D 的 30 天计划走 |

每一章的结构固定：一句结论 → 对比表 → 可抄的配置/命令 → 坑 → 三道自检题。**先看表格和加粗结论，需要时再看正文。**

## 约定

- 命令默认在 Linux / macOS 下执行，K8s 示例基于 1.29+，MySQL 基于 8.0，Redis 基于 7.x，Go 基于 1.22+。
- 代码块标注了语言，Go 示例可直接放进项目改两个值。
- 「经验值」表示来自实践的估算，不是厂商承诺；上线前用自己的压测校准。
- 🔑 是关键结论，⚠️ 是坑，💡 是补充。

## 一句提醒

架构师的价值不在「知道最多」，在「在信息不全时做出可回退的决策」。这本手册给的是脚手架，真正的能力要在项目里长出来。
