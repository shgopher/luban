## 二、每处的边界与新增内容清单

### 1. 43.7 延迟消息与定时消息（新增子节）

**新增 `## 延迟消息之上：任务调度还差哪四件事`**（或拆成 3 个 `###`）：
- 边界表：消息级「到点可见」vs 任务级「谁跑 / 跑几次 / 失败怎么办」；
- 四件事：分片（广播/分片键/倾斜）、失败重试与死信、调度中心高可用（选主/CAS/fencing）、幂等执行与错过触发补跑；
- 一张「单机 cron / 调度中心+执行器 / 时间轮 / 延迟队列」决策表（延迟量级、规模、运维成本）；
- 一段「什么时候别上调度系统」（任务少、单机 cron 够用、无分片需求）。
- 可运行代码：一个 **Go/Python 时间轮或分片调度最小模拟**，本机跑出输出；若用模拟器，正文写「本机仿真」，原始输出放 `.cache/` 并在正文给路径。
- 与 12.1 的边界：12.1 只加一句「集群调度（Borg/Mesos/Omega）与任务调度不是一层，任务调度见 43.7」，不展开。

**不写**：xxl-job/ElasticJob 的具体部署命令（无本机环境）；改用「产品名 + 版本无关判据 + 以官方文档为准」，且必须给判据表。

### 2. 66.2 消息可靠投递与离线（新增子节）

**新增 `## 从「叫醒」到通知服务：通道、模板、频控、降级`**：
- 通道选型表（APNs / FCM / 厂商通道 / 短信 / 邮件 / 站内信）：延迟量级、成本量级、到达率口径、失败模式；
- 模板与变量：缺变量时渲染占位而非整条失败；
- 频控与免打扰：营销/系统/事务三类分开，频控阈值是「打扰预算」不是「异常拦截」；
- 到达率口径：发送/送达/展示/点击/转化，分子分母写清；
- 失败重试与降级通道：每通道独立预算，重试窗口不能超过 SLO；
- 合规：退订、敏感词、号码脱敏、保留期。
- 与 66.2 原「推送通道/回执」的分工：原文只讲「只做叫醒」「送达≠已读」，新子节讲「怎么把通知送到、送不到怎么办」。
- 可运行代码：**本机 Go/Python 投递漏斗模拟**（去重→频控→通道选择→降级），真实输出；标「本机仿真」并给原始路径。

**不写**：厂商 SDK 配置、真实 APNs/FCM 证书流程（无环境）；只写版本无关的判据与参数。

### 3. 63.5 推荐效果评估与 A/B（新增子节）

**新增 `## 从一次 A/B 到实验平台`**：
- 分流：hash 分桶 / 分层 / 互斥 / 流量比例；随机化单元（用户/设备/会话）；
- SRM 检查：分流坏了后面全白算；
- 多重比较与偷看：主指标唯一、Bonferroni/FDR、固定样本量；
- 实验生命周期与平台架构：配置 → 分流 SDK → 指标管道 → 看板；
- 与 63.5 原内容的边界：原文讲「怎么算样本量/NDCG/推荐 A/B 的坑」，新子节讲「多实验并行时不互相污染」。
- 可运行代码：**Python 两比例样本量 + SRM 卡方 + 偷看 A/A 仿真**；真实输出；标「本机计算/仿真」。
- 33.4 的「实验平台 vs 灰度」区分只写一句：灰度是发布，A/B 是判断。

**不写**：SaaS 产品采购建议（上次样板里的 LaunchDarkly/Optimizely 内容撤掉）；只留「自建 vs 买」的判据。
