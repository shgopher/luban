# 第 36 章 灾备 · 概论

## 一句话

> 机房没了、数据丢了怎么办？丢多少数据（RPO）与停多久（RTO），由复制方式和切换流程决定，不由“有没有备份”决定。

## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **RPO** | 最多能丢多少数据 | 云同步后拍的照片，掉水里就没了 |
| **RTO** | 最多能停多久 | 跳闸后从一片黑到能做饭 |
| **全量 / 增量 / 差异** | 三种备份的成本结构 | 抄笔记：整本重抄 / 补新增 / 补改页 |
| **冷备 / 温备 / 热备** | 恢复时还有多少活要人干 | 灭火器：锁仓库 / 挂墙拔销 / 喷淋自开 |
| **两地三中心** | 同城两个中心加异地一个 | 同城两间办公室，外地一个仓库 |
| **多活** | 多机房同时接活，一个没了照跑 | 两家分店同开，一家关门客人拐另一家 |
| **单元化（Set 化）** | 用户的请求和数据锁进自闭环单元 | 小区自带配电房，停一片不影响别片 |
| **脑裂 / fencing** | 两个主都以为自己是主，用围栏挡旧的 | 两人各拿一份遗嘱，只认那枚印章 |

> 主线一条：**先定丢多少、停多久，再决定钱花在哪**。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “有备份就有灾备了” | 备份只解决数据还在；没有预置环境和恢复流程，RTO 照样被拖长 |
| “多活就是多建几个机房” | 门槛不是机房数量，是冲突方案、流量调度和演练能力 |
| “切换前多同步几次就不丢数据” | 要堵的是脑裂和位点，多同步只是把窗口推小 |

## 读完自检（入门级 3 题）

**Q1** 同事说“备份买了，灾备就没问题了”，漏了什么？

▸ 答案：漏了“停多久”那一半。备份只保证数据还在，RTO 由预置环境与切换流程决定。

**Q2** 冷备和热备的差别，是硬盘快慢吗？

▸ 答案：不是，是**恢复时还有多少活要人干**：冷备要人装机导数据，热备自动切。杠杆是自动化。

**Q3** 什么时候只做两地三中心、不上多活就够？

▸ 答案：能接受“机房没了先停一段再恢复”时就够。成本随层数翻倍，门槛在冲突与演练。
