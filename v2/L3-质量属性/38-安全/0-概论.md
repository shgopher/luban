## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **威胁建模** | 画数据流与信任边界，逐格认领威胁再排序 | 绕房子看哪扇窗能推开 |
| **信任边界** | 低信任区进入高信任区的那条线 | 小区门、单元门、家门 |
| **认证** | 只回答“你是谁”：凭证放哪、谁验、谁能偷 | 刷脸证明你是住户 |
| **授权** | 只回答“你能做什么” | 门禁卡开不了机房 |
| **AEAD** | 加密的同时校验数据有没有被改过 | 信封封口贴防拆条 |
| **去标识化** | 去掉姓名，组合起来仍能定位到人 | 涂掉号码也只剩一个人 |
| **零信任** | 删掉“在内网”这个隐含凭证，每次重验 | 每道门都刷卡 |

> 记住 **“每次请求都重新判断一次”**，其余内容都是它的外壳。

## 本章要解决的 8 个真问题

| 问题 | 在哪一节 | 一句话答案 |
|---|---|---|
| 我该防谁、防到什么程度？ | [38.1](38.1-威胁建模.md) | 按“可利用性 × 影响”排序，产出是“改哪里、谁改、多久改完” |
| 登录用 Session 还是 JWT？ | [38.2](38.2-认证.md) | 差别在凭证放哪、由谁验，选错只是把攻击面搬家 |
| 权限选 RBAC 还是 ABAC？ | [38.3](38.3-授权.md) | 看表达力、判定成本、治理成本；多数系统 RBAC 就够 |
| 用了 AES 就算加密做对？ | [38.4](38.4-加密.md) | 事故多在模式、随机数与密钥管理，不在算法本身 |
| 打星号就匿名了吗？ | [38.5](38.5-数据分级与脱敏.md) | 去标识化不等于匿名化，能组合定位到人仍是个人信息 |
| 参数化了为什么还被注入？ | [38.6](38.6-常见攻击.md) | 根因只有两个：把输入当代码、把带凭证的请求当本人意图 |
| 内网调用还要验证吗？ | [38.8](38.8-零信任.md) | 要：把“攻陷一台 = 攻陷一片”改成“每跳都要重新攻陷” |
| 被入侵第一步做什么？ | [38.11](38.11-安全应急响应.md) | 先止血并保住证据，别先重启或删日志 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “上了 HTTPS 就安全了” | 事故几乎都不是算法被破解，而是模式、随机数、密钥管理用错 |
| “内网里的人是自己人” | 零信任把网络位置换成每次请求的身份与设备校验 |
| “安全就是上线前扫一遍” | 修复成本按阶段摊开：需求期建模、编码期扫描、上线后只剩应急 |

## 读完自检（入门级 3 题）

**Q1** 威胁建模的交付物是什么？

▸ 答案：不是一张吓人的清单，而是**排好序的“改哪里、谁改、多久改完”**：画数据流与信任边界，用 STRIDE 认领威胁，再按可利用性 × 影响排序。

**Q2** 认证和授权各回答什么？

▸ 答案：**认证问“你是谁”**，看凭证放哪、谁验、能被谁偷；**授权问“你能做什么”**，在表达力与成本间取舍。

**Q3** 发现被入侵，第一件事？

▸ 答案：**先止血，同时保住证据**。先重启、先删日志，就把可追查性连同损失一起交出去。
