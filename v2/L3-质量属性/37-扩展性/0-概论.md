# 第 37 章 扩展性 · 概论

## 一句话

> 流量涨了，该加机器还是拆单点？答案是：先垂直扩到甜点，再复制无状态层，最后才拆那个所有人都必经的单点——拆不动的那处就是上限。

## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **垂直 / 水平扩展** | 机器变强，还是变多 | 面馆换大锅，还是再开两家分店 |
| **无状态化** | 状态搬出实例内存，放到哪里都能访问 | 行李寄存前台，谁值班都能取 |
| **分片** | 按 key 切成互不重叠的片 | 电话簿按姓氏首字母拆成 26 本 |
| **读写分离** | 读分给副本，写只有一个主库 | 一个窗口收钱，几个台子只答问 |
| **单点** | 几乎全部流量都必经的那处 | 全城一座桥，不拓宽就只堵桥头 |
| **阿姆达尔定律** | 加速比上限 1/(1−p)，p 是可并行比例 | 十人搬砖，砌墙只有一人能上 |
| **弹性伸缩** | 容量追上负载变化的速度 | 雨天临时多开一个收银台 |
| **微内核** | 内核只管插件管理、连接、通信 | 插座面板不动，换哪个电器都能插 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “扩展性就是加机器” | 只加速可并行那部分；串行不降，钱花在排队上 |
| “无状态化就是没有状态” | 状态没少，只是搬到了哪个实例都能访问的地方 |
| “拆成微服务就能扩展” | 卡住容量的是必经的那处；只拆进程不动它，副本只是更快挤到门口 |

## 读完自检（入门级 3 题）

**Q1** 应用从十台加到二十台，吞吐纹丝不动，第一步做什么？

▸ 答案：先定瓶颈——分层压测加利用率对照（[37.7](37.7-扩展瓶颈识别.md)）；若卡在单点写或单表维护上，加副本只是让请求更快挤到同一门口。

**Q2** 判断一个服务是否无状态化，只用哪条标准？

▸ 答案：**随机杀掉一台实例，用户有没有感觉**。有感觉，状态还在实例内存里。

**Q3** 加机器只能加速可并行的那部分，那还能加出多少收益？

▸ 答案：先测可并行占比 p，天花板是 1/(1−p)，加机器只决定离天花板多远；p 不测就扩容，钱多半花在排队上（[37.5](37.5-加速比与阿姆达尔定律.md)）。
