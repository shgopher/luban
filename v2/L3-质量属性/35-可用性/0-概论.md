## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **可用性（几个 9）** | 一年里能正常用的时间占比 | 店一年 365 天有几天真开门 |
| **MTBF** | 两次故障平均隔多久 | 灯泡亮多久烧掉 |
| **MTTR** | 从坏到好平均多久，含发现与决策 | 水管爆了到修好、水压回来 |
| **SLO 与错误预算** | 内部目标，加一份允许失败的额度 | 流量套餐还剩多少可以造 |
| **冗余** | 多备一份，坏了一个顶上 | 备用钥匙挂在同一扣上就白备 |
| **熔断 / 降级** | 下游坏了先别打；打不过去返回凑合结果 | 电梯坏了走楼梯，别按按钮干等 |
| **爆炸半径** | 一次故障最多连累多大范围 | 水密门：一舱进水，船还能开 |

## 弹力设计：四层框架与选择顺序

“弹力”（resilience）不是“不出故障”，而是**故障了还能扛**。陈皓把手段归成四层，层次比单个手段更重要：

| 层 | 手段 | 关键前提 | 主场 |
|---|---|---|---|
| **① 冗余** | 多实例、多机房、多活 | 服务发现、负载均衡、动态路由、健康检查**四件套** | [35.3 冗余](35.3-冗余.md)、[36.4 两地三中心与多活](../36-灾备/36.4-两地三中心与多活.md) |
| **② 解耦** | 水平分片（业务/用户）、垂直异步（事件/MQ/工作流）、舱壁 | 分片键、消息不丢 | [19 数据分区](../../L1-分布式原理/19-数据分区/19.1-分区键设计.md)、[43 消息队列](../../L4-组件与技术/43-消息队列/43.1-消息模型.md) |
| **③ 容错** | 重试、熔断、幂等、限流、降级、补偿 | **幂等**是重试与补偿的前提 | [35.5](35.5-超时重试与退避.md)–[35.8](35.8-故障隔离.md)、[25.4 幂等设计与去重](../../L1-分布式原理/25-并发、冲突与幂等/25.4-幂等设计与去重.md)、[24.5 Saga](../../L1-分布式原理/24-分布式事务/24.5-Saga.md) |
| **④ 自动化运维** | 流量调度 + 服务监控（APM + 调度两套） | 监控能触发动作，而不是只报警 | [50 可观测性](../../L4-组件与技术/50-可观测性/0-概论.md)、[47 网关与入口](../../L4-组件与技术/47-网关与入口/47.1-反向代理.md) |

**选择顺序**是从根上到兜底，不是从“最酷的手段”开始：

1. **先消单点**（冗余）：单点是所有故障的地基，不消单点，其他手段都是补丁。
2. **再切爆炸半径**（分片 / 舱壁 / 隔离）：隔离的代价是容量碎片，所以先算“一次故障最多连累多少”。
3. **再上容错**（超时 / 重试 / 熔断 / 限流 / 降级 / 补偿）：它们只处理“已经坏掉”的部分。
4. **最后自动化**（监控 → 自动限流/降级）：人肉运维会让前三层全部落空。

四个具体判据（都有原文出处）：

| 判据 | 内容 |
|---|---|
| 隔离的三档 | 完全独立 / 独立数据分区共享服务 / 全共享；折衷是“共享服务 + 分区隔离”，重租户独立（42） |
| 状态的取舍 | 无状态是最佳实践（状态外置），代价是多一层依赖与网络开销；有状态靠分片（45） |
| 动态限流 | 不设固定阈值，看过去 10 秒的 P90/P99；超阈值则 QPS 减半 → 慢启动 → 再减 1/4 → 1/8（49） |
| 补偿 | 设计正向流程时同时设计反向补偿；前提是各服务幂等 + 上游重试（46） |

> 🔑 **不要尝试去避免故障，而是要把处理故障的代码当成正常的功能，做在架构里、写在代码里。**
>
> ⚠️ 最容易被跳过的是第 ④ 层：**人肉运维时，故障发生那一刻根本来不及做运维决定，前三层就都白做了。**

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「多部署一套就等于高可用」 | 冗余买 MTBF 不买 MTTR；副本共享同一集群或发布流水线时会一起挂，等于没备 |
| 「失败了就重试，成功率自然会上去」 | 超时乘上重试就是故障放大器，一次下游抖动会变成全站雪崩；重试要幂等、有上限、带抖动 |
| 「写了 99.9% 就算达标」 | 不写口径、不写年故障次数，目标就不可换算；全站平均还藏得住「部分用户永久坏」 |

## 读完自检（入门级 3 题）

**Q1** 承诺 99.99%，按时间口径，一个月最多能停多久？

▸ 答案：4 分 23 秒（一年 52 分 34 秒）。每月坏一次，扣掉检测 1 分钟、判决 1 分钟，留给恢复不到 2 分钟，人力来不及。

**Q2** 两个 99% 的副本并联，账面 99.99%，线上只有 99.9%，为什么？

▸ 答案：故障不独立。两副本共享同一机房或发布流水线会一起挂，并联收益没了。修法是消除共享故障源，而非加副本。

**Q3** 熔断和降级只做一个会怎样？

▸ 答案：只熔断得到快速报错的系统；只降级得到一直等超时的系统。两个成对：先快速失败，再决定返回什么。
