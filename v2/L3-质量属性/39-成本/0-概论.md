## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **单位成本** | 总花销 ÷ 业务量（每单/每用户/每 GB·月） | 不看这月油钱，看每公里几毛 |
| **单位收入** | 同一分母下的收入 | 每公里向乘客收几块 |
| **规模效应** | 量变大时单位成本怎么变 | 包月卡：去 20 次单次才便宜 |
| **热层** | 常被读的数据，单价最高 | 当季衣服挂在衣柜门口 |
| **冷层** | 很少被读的数据，单价低 10–20 倍 | 过季衣服压进床底收纳袋 |
| **取回费** | 从冷层读数据要另付的钱 | 快递柜超时取件按次收钱 |
| **最短存储期** | 存不满规定时间就删，要补差价 | 年卡中途退，折扣按原价补回 |
| **请求费** | 每次读写列举都计费，文件越小越亏 | 停车按进出闸机次数收 |

```
        这个月账单又涨了
              │
              ▼
   ┌──────────────────────────┐
   │ 换分母：每单/每用户/每 GB·月 │  ← 39.1
   └─────────────┬────────────┘
                 ▼
         单位成本 vs 单位收入
                 │
      ┌──────────┴──────────┐
      ▼                     ▼
 成本 < 收入            成本 ≥ 收入
 增长 = 摊薄            增长 = 放大亏损
      │
      ▼
 降本顺序
 删需求 → 压线性项 → 摊薄固定项 → 最后动架构
      │
      ▼
 存储（39.3）：按访问频率定价
 热 → 温 → 冷 → 归档
      │
      ├── 先删数据、再压缩
      ├── 再换层（单价低 10–20 倍）
      └── 代价：取回费/最短存储期/请求费/RTO
```

- 上半张判「要不要降」，下半张定「从哪降」。
- 换层在链路末端：前两步不动，它只是挪钱。
- 每下一步多一个代价：比收入、比取回费、比 RTO。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「成本就是云账单」 | 账单只是总成本的一部分，只盯它会把降本做成「买更便宜的机器」 |
| 「量做大了就一定便宜」 | 单位成本随规模怎么变由成本结构决定，它有下限 |
| 「换到更冷的层就等于省钱」 | 只有访问频率真的低才省，取回费、最短存储期会把单价差吃回去 |

## 读完自检（入门级 3 题）

**Q1** 老板问「这个月花了多少」，为什么先反问「这个月多少单」？

▸ 答案：总额不能判断好坏——**同一个总额，配大单量与小单量是两种生意**。要换成单位成本，再和同分母的单位收入比。

**Q2** 冷层单价低 10–20 倍，为什么把数据全搬过去可能更贵？

▸ 答案：单价只是成本的一项：**取回一次要付取回费，存不满最短存储期就删要补差价，读写列举还付请求费**——访问模式一变，成本结构就反过来。

**Q3** 存储成本要降，第一步做什么？

▸ 答案：**先删数据和压缩，再谈换层**。删除直接归零，压缩对所有层同时生效；换层只是挪到单价更低的层，还要拿 RTO 与代码复杂度去换。
