# 第 39 章 成本 · 概论

## 一句话

> 这一章回答「降本从哪下手」：先把总额换成每单、每用户、每 GB·月的单位成本，确认它低于单位收入，再按「先删、再压缩、再摊薄、最后动架构」的顺序动手。

## 5 分钟入门：先记住这 12 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **单位成本** | 总花销 ÷ 业务量（每单/每用户/每 GB·月） | 不看这月油钱，看每公里几毛 |
| **单位收入** | 同一分母下的收入 | 每公里向乘客收几块 |
| **规模效应** | 量变大时单位成本怎么变 | 包月卡：去 20 次单次才便宜 |
| **边际成本** | 再多一单要多花多少 | 第 21 次进健身房不额外收钱，但第 21 单要多买一份料 |
| **热层 / 冷层** | 常读的数据单价高，少读的单价低 10–20 倍 | 当季衣服挂门口，过季压床底 |
| **取回费** | 从冷层读数据要另付的钱 | 快递柜超时取件按次收钱 |
| **峰均比** | 峰值 ÷ 均值，决定「买容量还是买弹性」 | 高峰期打车加价，平时车闲着 |
| **水位（余量）** | 容量用到几成，余量就是为抖动多买的 | 高速留出的车距 |
| **盈亏平衡使用率** | 承诺折扣的「用不满就亏」界线 | 年卡要一年去满多少次才回本 |
| **覆盖率** | 承诺量占基线的比例 | 包月套餐买几份才不浪费 |
| **归因覆盖率** | 有主的成本占总成本的比例 | 家庭账单里有多少记在谁名下 |
| **TCO** | 全生命周期成本：资源 + 人力 + 迁移 + 风险 | 买车不只看车价，还要看保险、油、保养 |

## 一张图：这章的骨架

```
        这个月账单又涨了
              │
              ▼
   ┌──────────────────────────┐
   │ 换分母：每单/每用户/每 GB·月 │  ← 39.1
   └─────────────┬────────────┘
                 ▼
         单位成本 vs 单位收入
                 │
      ┌──────────┴──────────┐
      ▼                     ▼
 成本 < 收入            成本 ≥ 收入
 增长 = 摊薄            增长 = 放大亏损
      │
      ▼
 降本顺序
 删需求 → 压线性项 → 摊薄固定项 → 最后动架构
      │
      ├── 容量：买峰值还是买弹性？水位多高？（39.2）
      ├── 存储：按访问频率分层（39.3）
      ├── 采购：基线买承诺、波动买按需、可中断买 Spot（39.4）
      ├── 治理：账单拆成量/价/新增，归到人头上（39.5）
      └── 架构：改不改、改哪一层，用 TCO 与回本周期判（39.6）
```

- 上半张判「要不要降」，下半张定「从哪降」。
- 五个手段不是并列的：**越靠后的手段代价越大、周期越长**，先做完前面的再动后面的。
- 每一步都要留下代价：换层拿 RTO 换，买承诺拿确定性换，改架构拿复杂度换。

## 4 个最常见误解

| 误区 | 现实 |
|---|---|
| 「成本就是云账单」 | 账单只是总成本的一部分，只盯它会把降本做成「买更便宜的机器」 |
| 「量做大了就一定便宜」 | 单位成本随规模怎么变由成本结构决定，它有下限（边际成本） |
| 「换到更冷的层就等于省钱」 | 只有访问频率真的低才省，取回费、最短存储期会把单价差吃回去 |
| 「优化就是省钱」 | 优化首先要有归因；没有归因的降本，砍掉的往往是核心链路——机制见 [39.5](39.5-FinOps与账单治理.md) |

## 读完自检（入门级 4 题）

**Q1** 老板问「这个月花了多少」，为什么先反问「这个月多少单」？

▸ 答案：总额不能判断好坏——**同一个总额，配大单量与小单量是两种生意**。要换成单位成本，再和同分母的单位收入比。

**Q2** 冷层单价低 10–20 倍，为什么把数据全搬过去可能更贵？

▸ 答案：单价只是成本的一项：**取回一次要付取回费，存不满最短存储期就删要补差价，读写列举还付请求费**——访问模式一变，成本结构就反过来。

**Q3** 同一个容量需求，「按峰值买」和「基线 + 弹性」差在哪？

▸ 答案：差价买的是「不确定性」。按峰值买任何时刻都不排队，但峰均比 2.2 时平均利用率只有 45.5%，一半容量在空转；基线 + 弹性用溢价单价覆盖只出现几小时的峰值，示例里省 37%。**判据是峰均比与「每天用几小时」——超过 15.2 小时/天的那部分，买固定更便宜**（[39.2](39.2-容量规划.md)）。

**Q4** 预留打折 35%，为什么不能「有多少买多少」？

▸ 答案：承诺是**单边义务**：折扣的前提是使用率超过 `折后价 ÷ 按需价`（示例 65%），用不满就比按需还贵；而且承诺期越长越难退（业务下坡、架构换代都会让承诺空转）。**正确做法是只承诺基线（覆盖 80%–90%），峰值按需、可中断买 Spot**（[39.4](39.4-弹性与预留实例.md)）。
