# 83.4 学习路径索引

## 一句话

> 学习路径不是「从第 1 章读到第 83 章」，而是**以你手上那个决策为起点，向前后各取三步**；读完不产出，等于没读。

## 先选一种读法（三种别混着用）

| 读法 | 什么时候用 | 怎么走 | 产出 | 时间 |
|---|---|---|---|---|
| **查证式** | 手上正压着一个决策 | 用 [83.1 术语表](83.1-术语表.md) 统一词 → 目录的「一句话」选 3 篇 → 只精读这 3 篇 | 一页结论 + 两个备选 + 淘汰条件 | 2–4 小时 |
| **系统式** | 知道自己哪层虚，要补 | L0 → L5 逐层走，每层 1 篇「主场」+ 2 篇「客场」 | 每层一张「我原来以为 / 实际是」对照表 | 4 周 |
| **面试式** | 有明确时间点 | 按岗位题单反查章节，每题准备「结论 + 数字 + 反例」 | 20 道题的答题卡 | 1–2 周 |

> 🔑 判据：**你这次读，是为了做决定，还是为了知道？** 为了知道，就只在系统式里读；其余两种读法都以「产出一个可被评审的东西」结束。

## 怎么查这本书

| 想找什么 | 用什么 | 说明 |
|---|---|---|
| 某个概念的**主场** | 目录里的节标题 + 「一句话」 | 每节第一句就是结论，扫 20 条能定位 90% |
| 某个词到底指什么 | 见 [83.1 术语表](83.1-术语表.md) | 按「架构 / L0 / L1 / L2 / L3 / L4 / L5 / AI」分组 |
| 某个结论的**出处** | 见 [83.2 参考文献与经典论文](83.2-参考文献与经典论文.md) | 按「你手上的问题」组织，不按年份 |
| 某个能力该选什么 | 见 [83.3 工具与产品清单](83.3-工具与产品清单.md) | 重点看「什么时候别用」那一列 |
| 某个架构该画成什么样 | 见 [80.1 C4 模型](../../附录/80-架构文档与表达/80.1-C4模型.md)、[80.2 架构图规范](../../附录/80-架构文档与表达/80.2-架构图规范.md) | 先定层级，再定元素 |

## 一、四阶段成长路径

每个阶段只回答一个问题：**你现在能对什么负责？** 读的章节服务于这个「负责范围」，不是服务于「知识完整」。

## 五、验收：五级能力自评

「读完了」不是验收标准。用下面这张表给自己定级，**升不上去的那一级，就是下一步该读的章节**。

| 级别 | 判据 | 自测题（答不上就退回上一级） |
|---|---|---|
| **L1 名词级** | 能说出这个词是什么 | 「幂等是什么？」 |
| **L2 解释级** | 能解释它解决什么问题、代价是什么 | 「为什么幂等这么难？代价是什么？」 |
| **L3 权衡级** | 能说出它和邻居的取舍，并给数字 | 「TCC 和 Saga 你怎么选？分界线的数字是什么？」 |
| **L4 决策级** | 能在约束下做决定，并写清退出条件 | 「预算只有 3 个人月，你选哪个？什么信号出现就停？」 |
| **L5 反例级** | 能举出它**失效**的真实案例，并说明为什么当时没发现 | 「你见过的 TCC 空回滚是怎么发生的？监控为什么没抓到？」 |

> 🔑 面试与评审的分水岭在 **L3 → L4**：L3 是「知道有取舍」，L4 是「敢在信息不全时下注，并为下注设止损」。L5 是「踩过并复盘过」。

## 六、三个实战作业（带验收标准）

### 作业 1：一页 ADR

| 项 | 要求 |
|---|---|
| 交付物 | 背景 / 3 个备选 / 评估维度与权重 / 决定 / 后果与退出成本，各不超过 5 行 |
| 评分点 | ① 权重写在打分之前；② 每个备选都有「什么时候它更好」；③ 退出成本有数字（人月或迁移窗口） |
| 常见不合格 | 只写一个方案；打分没有权重；没有「反面后果」 |

### 作业 2：容量估算

| 项 | 要求 |
|---|---|
| 交付物 | 峰值 QPS → 单实例能力（压测或推算）→ 副本数 → 冗余系数 → 机器数 → 月成本 |
| 评分点 | ① 每一步都有来源（压测数据 / 官方基准 / 推导）；② 明确写出「哪些假设最可能错」；③ 给出成本区间而非一个数 |
| 常见不合格 | 直接套「一台扛 1000 QPS」；忽略长尾与冗余；把平均值当峰值 |

### 作业 3：AI 功能验收

| 项 | 要求 |
|---|---|
| 交付物 | 20 条 eval（含 5 条「应该拒答」）+ 通过率门槛 + 失败归因分类 + 上线后的在线监控指标 |
| 评分点 | ① 覆盖正常 / 边界 / 对抗 / 拒答四类；② 门槛是数字，且有依据；③ 失败能归因到「检索 / 生成 / 工具 / 解析」四层之一 |
| 常见不合格 | 只有 happy path；用「感觉不错」当验收；没有拒答题（模型必然硬答） |

## 反模式

| 反模式 | 后果 |
|---|---|
| 收藏式学习（存 200 篇，读 3 篇） | 产生「我知道」的错觉，决策时说不出依据 |
| 只读不写 | 没有产出物，就无法暴露「以为懂了」的地方 |
| 跳过 L1 直接学 K8s / 微服务 | 学到的是操作，不是判断；一遇故障就回到「重启试试」 |
| 只学 AI 不学分布式 | Agent 的失败模式全是分布式问题：超时、重试、幂等、状态 |
| 追新不补基础 | 每年换一套名词，判断力不增长 |
| 用「读完」当验收 | 读书量与决策质量无关 |
| 按目录顺序通读 | 前 20 章读完就放弃；应带着问题跳读 |
| 学完不回到真实系统 | 知识停留在纸面，遇到真实约束就崩 |

## 自检

**Q1** 你只有 2 小时，要判断「我们该不该把单体拆成微服务」。请给出你的检索路径（不超过 4 步），并说明为什么不需要读完第 30 章。

▸ 答案：① 先用 [83.1 术语表](83.1-术语表.md) 校准「微服务 / 分布式单体 / 模块化单体」三个词，避免把「拆分」等同于「微服务」；② 读 [26.6 模块化与包设计](../../L2-架构风格/26-分层与依赖/26.6-模块化与包设计.md) 拿到「边界怎么定」的判据；③ 读 [24.9 事务模型选型](../../L1-分布式原理/24-分布式事务/24.9-事务模型选型.md) 判断「拆完事务能否收敛」；④ 读 [74.1 康威定律及其逆定律](../../组织/74-康威定律与团队拓扑/74.1-康威定律及其逆定律.md) 判断团队能否跟上。不需要读完第 30 章，是因为**当前决策的瓶颈不是「微服务怎么做」，而是「该不该拆」**——前者是实施知识，后者是判断知识；顺序错了，读得越多越容易直接开拆。

**Q2** 有人说「我按 12 周计划读完了，但感觉什么也没学到」。请指出这个计划最可能被误用的地方，并给出修正。

▸ 答案：误用在**把「读完」当成「完成」**。计划里每周都要求「产出可评审物」，如果只是翻完章节没做产出，就等于只完成了 1/3。修正：① 每周只留一个产出，其余时间用来改这个产出；② 产出必须被一个真实的人（同事/评审）挑过毛病；③ 每两周做一次「回讲」——不看笔记讲 10 分钟，讲不顺的地方就是没懂。**判据：能不能不用原文，把这一周的内容讲给一个外行听明白。**

**Q3** 请用五级自评表判断：「我知道 CAP 是分区时在 C 和 A 之间取舍」属于哪一级？要到 L4 还缺什么？

▸ 答案：属于 **L2（解释级）**——能说清它解决什么问题。要到 L3，需要说出它和 PACELC 的差别、以及「平时在 L 与 C 之间取舍」的具体例子；要到 L4，需要在一个真实系统上做出决定并写清退出条件，例如「订单履约链路在分区时选 CP（拒绝写入），因为超卖资损大于短时不可用；停机超过 5 分钟转人工」——**有选择、有数字、有止损**才是 L4。

**Q4** 为什么「按角色路径」和「按场景路径」要分开？各自适合什么情况下用？

▸ 答案：角色路径是**长期能力结构**，回答「我这个岗位三年该长成什么样」，适合做季度/年度学习规划；场景路径是**短期决策支持**，回答「下周三的评审我怎么准备」，适合临时查证。混用的典型错误是：用角色路径的「完整」去应付一个具体决策（读了三周还没开会），或用场景路径的「够用」去替代长期积累（每次都临时抱佛脚，永远停在 L2）。

**Q5** 如果你只能记住这一节的一句话，应该记哪句？为什么？

▸ 答案：记「**以你手上那个决策为起点，向前后各取三步**」。因为它同时约束了三件事：起点是**真实决策**（不是目录第一页）、范围是**三步**（不是整本书）、方向是**前后都要**（向前补原理、向后看落地）。它把「学习」从「消费内容」改成了「解决约束下的问题」，而这正是架构能力的定义。
