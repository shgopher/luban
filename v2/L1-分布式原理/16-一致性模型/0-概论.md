## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **一致性模型** | 对「能读到什么值」的承诺 | 快递时效：次晨达 / 不保证 |
| **严格一致** | 读必须返回最近的那次写 | 全国钟表分秒不差 |
| **线性一致** | 读写原子生效，像只有一份数据 | 一个窗口卖票，不卖重座 |
| **顺序一致** | 顺序统一，但可落后于真实时间 | 按名单唱票，唱得晚 |
| **因果一致** | 有因果的操作不许颠倒 | 回复不会早于原话 |
| **最终一致** | 停写后副本最终变成一样 | 分店价格牌迟早一致 |
| **会话保证** | 会话内四条：读己之写、单调读、单调写、写跟随读 | 自己改的简历，自己刷新看得见 |

> 只要记住 **「约束越多 → 越像单机 → 越贵」**，五个模型就是它的不同档位。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「从弱到强的排行榜，选最右边」 | 模型是几组正交约束（实时序、全序、事务原子性、客户端会话）的组合，每加一条都付 RTT 与可用性 |
| 「最终一致就是不用管」 | 只承诺停写后收敛，无时间上界；缺冲突解决规则就不收敛 |
| 「线性一致靠对准时钟」 | 它靠逻辑全序与共识；靠物理时钟的严格一致不可实现 |

## 读完自检（入门级 3 题）

**Q1** 严格一致为什么做不到？还值得讲吗？

▸ 答案：它假设全局时钟、写生效瞬间全局可见，多机不成立；它只当**参照系与下界**。

**Q2** 线性一致与顺序一致只差哪一条？

▸ 答案：差**实时先后**。前者要求不重叠的操作按真实先后生效，读到必是最新值，代价是 RTT + 共识；后者只要全序符合程序顺序，可落后于现实，故允许旧值。

**Q3** 用户刚存的资料刷新就看不见，会话保证能修吗？

▸ 答案：能修「自己看不到自己写的」，靠读己之写、单调读。但它不改全局模型：其他客户端仍可能读到旧值。
