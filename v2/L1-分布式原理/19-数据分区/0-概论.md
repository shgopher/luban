## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **分片** | 全量切几份，各放一台机器 | 租几间仓库分着放 |
| **分区键** | 决定数据去哪片的字段 | 分拣只看收件城市 |
| **哈希分区** | 取哈希再取模，落点固定 | 取号机按尾数分窗口 |
| **范围分区** | 按顺序切区间 | 图书馆按索书号排架 |
| **一致性哈希** | 节点与 key 同环，顺时针找 | 圆桌转盘顺时针 |
| **虚拟节点** | 一个节点占多个 token | 一个厨师挂多个窗口 |
| **再平衡** | 搬到新均衡态，搬时可读写 | 一边营业一边换店 |
| **热点** | 单 key 请求量远超平均 | 全城爆款只在一家店 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「分片就是副本」 | 副本是同一份数据的多份拷贝，管可用性；分片是不同数据的划分，管容量。两者正交，先分片再复制 |
| 「加机器就能解决慢」 | 扩容只摊薄总量；热点 key、最新时间、大 V 挤在一片，机器越多那片越慢 |
| 「一致性哈希自动均衡」 | 它只保证增删时迁移少，不保证负载均；节点少时可能有节点拿到 2 倍平均，靠[虚拟节点](19.5-虚拟节点.md)与[有界负载](19.6-有界负载一致性哈希.md)补救 |

## 读完自检（入门级 3 题）

**Q1** 查一个用户，两种分区各要打几片？

▸ 答案：哈希**只打一片**，同一 key 落点唯一；范围**可能跨多片**，区间越大跨越多。反过来查某段时间，范围只扫相邻几片，哈希要扫全部。

**Q2** 加一台机器，为什么不用搬走大部分数据？

▸ 答案：新节点只占环上一段弧，只有弧上的 key 换主人，其余顺时针找到的节点没变；等权时平均只迁 `1/(N+1)`。

**Q3** 上了分片，为什么扩容不等于热点消失？

▸ 答案：分片解决**总量**，扩容只是摊到更多片；热点是**请求集中**，扩容后仍在同一片。
