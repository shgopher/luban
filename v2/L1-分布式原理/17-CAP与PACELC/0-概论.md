## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **分区（P）** | 节点活着，但彼此收不到消息 | 对讲机坏了，人都在 |
| **C（一致性）** | 读到最近一次写入的值 | 账本只一份，刚存就查得到 |
| **A（可用性）** | 每个请求都要有回答，超时不算 | 电话必须有人接，信箱不算 |
| **CP** | 分区时让少数派闭嘴（拒写） | 对不上账就先停办 |
| **AP** | 分区时两侧照写，事后合并 | 两个收银台各记各的，打烊对账 |
| **PACELC** | 平时要一致，就付一次跨副本往返 | 总部盖章 vs 门店开票 |
| **BASE** | 不求每步都对，只求最终收敛 | 先发货后补发票，月底平账 |

> 记住 **“P 是事实，C/A 与 L/C 才是选项”**。

- **左支管故障时刻，右支管日常运行**：前者才是 CAP，后者才是每天的账；
- **越往下，责任越往业务移**：一致性从“数据库保证”到“业务兜底”。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “三选二，从 C、A、P 里丢一个” | P 是网络的事实不是选项，C 与 A 也不是按钮；取舍不是一次性全局决定，而是按操作、按时间下注 |
| “BASE 就是放弃一致性” | 它把标准从“每一步都对”降级为“最终收敛”，代价是正确性责任从数据库转到业务 |
| “CAP 就是这套理论的全部” | 它只说分区时的 C/A；之后补的是可用性连续、延迟记账、哪些操作无需协调 |

## 读完自检（入门级 3 题）

**Q1** 分区时让少数派拒写，是 CP 还是 AP？改成“照写、事后合并”呢？

▸ 答案：前者 CP，后者 AP。判据不是宣传语，而是**分区时对少数派做什么**：拒写拿可用性换一致，照写拿一致性换可用。

**Q2** 为什么“丢掉 P、只保 C 和 A”走不通？

▸ 答案：分区不是机器坏掉，而是节点之间收不到消息；只要有跨节点复制，P 就在。按“分区不会发生”设计只会得到脑裂。

**Q3** 两个系统都自称“AP、最终一致”，为什么不足以支撑选型？

▸ 答案：AP 只回答了分区那一瞬，没回答平时的账：要不要多付一次往返、冲突谁收拾。
