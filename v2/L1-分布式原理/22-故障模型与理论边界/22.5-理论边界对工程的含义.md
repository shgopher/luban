# 22.5 理论边界对工程的含义

## 一句话

> 理论边界不是 “劝你别做”，而是 “告诉你必须买什么保险”：CAP 让你选一致性还是可用性，FLP 让你买超时与随机化，拜占庭让你买 3f+1 与签名——**每一条边界都对应一笔工程成本，逃不掉，只能选**。

## 四条边界 → 四笔成本

| 边界 | 说了什么 | 工程对策 | 代价 |
|---|---|---|---|
| **CAP** | 分区时只能在 C 与 A 之间选 | 按业务分级：资金强一致、feed 可用性优先 | 强一致 → 延迟与可用性下降 |
| **FLP** | 异步 + 崩溃下无确定共识 | 超时 + 随机化 + 部分同步假设 | GST 前不可用；超时误判 |
| **拜占庭（3f+1）** | 需 ≥3f+1 才能容忍 f 个作恶 | 多副本 + 签名 + 审计 | 资源 ×3，性能下降 |
| **两将军/不可靠信道** | 无法在不可靠信道上 “确认对方确认” | 幂等 + 重试 + 对账 | 业务复杂、需去重 |

## 代码：把边界变成配置

```yaml
# Raft 类系统的常见“边界配置”——每个数字都对应一笔成本
election_timeout: 150ms-300ms     # 太短：误切主；太长：RTO 上升
heartbeat_interval: 50ms          # 心跳开销 vs 检测速度
quorum: 2/3                       # 3 副本容忍 1 故障；5 副本容忍 2，写延迟 +1 RTT
read_index: true                  # 强一致读要等 leader 确认，牺牲读延迟
```

```text
选型口诀：
  要“绝不丢”     → 多数派写 + 强一致读，接受延迟
  要“一直可用”   → 异步复制 + 冲突合并，接受短暂不一致
  要“防作恶”     → 3f+1 + 签名，接受 3 倍资源
  要“防重复”     → 幂等键 + 对账，接受业务复杂度
```

## 反模式

| 反模式 | 后果 |
|---|---|
| 宣称 “我们既强一致又高可用” | 分区时必然打脸，只是没遇到 |
| 用 CAP 当 “三选二” 口号 | 忽略 P 是常态，C/A 是分区时的取舍 |
| 把 FLP 当 “算法不够好” | 反复换组件，问题依旧 |
| 无脑上拜占庭容错 | 3 倍资源换来用不上的保证 |
| 认为 “重试就能解决不可靠信道” | 重复与乱序没处理，问题变成资损 |
| 不写 “边界假设” | 换机房/换网络后行为突变，无人能解释 |

## 三条铁律

> 🔑 **P 是常态，C/A 是分区时的取舍**；别把 CAP 当 “平时三选二”。

> 🔑 **每条理论边界都要落成配置或流程**，否则等于不知道。

> 🔑 **假设要写进文档**（“本系统假设同机房 RTT < 1ms”），换环境前先复核。

## 自检

**Q1** 为什么说 “CAP 不是三选二”？

▸ 答案：因为 **P（分区）不是可选项**：网络分区迟早发生，系统无法 “不要 P”。CAP 真正说的是 “**分区发生时**，只能在 C 与 A 之间选一个”。平时（无分区）可以同时有 C 和 A——把 CAP 当 “三选二” 会导致 “平时也牺牲性能” 的错误设计。

**Q2** FLP 对工程最直接的影响是什么？

▸ 答案：**必须引入超时**，而超时必然带来 “误判” 与 “GST 前不可用”。所以任何共识系统都要接受 “网络抖动时短暂不可用/切主”，并把 “检测参数” 纳入 SLO 管理，而不是追求 “永不误判”。

**Q3** 什么时候值得上拜占庭容错？

▸ 答案：当参与者**可能主动作恶**且无法用法律/合同约束时：公链、多方计算、跨组织联盟链。企业内部（可信运维）用崩溃容错（2f+1）就够；上 BFT 是 3 倍资源换 “用不上的保证”。

**Q4** “两将军问题” 在工程上对应什么？

▸ 答案：对应 “**无法确认对方收到**”：发送方永远不能确定 “确认消息是否送达”。工程解法不是 “更可靠的信道”，而是**幂等 + 重试 + 对账**：允许重复，用去重消除副作用，用对账发现遗漏（见 [31.5 事件的可靠投递](../../L2-架构风格/31-事件驱动/31.5-事件的可靠投递.md)）。

**Q5** 为什么 “理论边界” 常被当成 “架构借口”？

▸ 答案：因为边界容易被用来**回避具体设计**：一句 “CAP 嘛，没办法” 就跳过了 “到底哪个业务要 C、哪个要 A”。正确的用法是 “边界 → 分级 → 配置”：把每个业务域的一致性/可用性需求写清楚，再选实现，而不是用定理当挡箭牌。

**Q6** 一个新系统上线前，至少要写清哪几条假设？

▸ 答案：四条：**故障模型**（崩溃/拜占庭/网络分区）、**时序假设**（同机房 RTT、跨区延迟上界）、**一致性目标**（强一致/最终一致/读己之写）、**恢复目标**（RTO/RPO）。这四条决定了 “超时、副本数、重试、对账” 的所有参数。

**Q7** 理论边界与成本是什么关系？

▸ 答案：**每条边界都对应一笔可量化的成本**：强一致 = 多一个 RTT + 可用性下降；BFT = 3 倍资源；对账 = 人力与复杂度。架构决策的本质是 “用多少钱买哪种保证”，而不是 “能不能绕过定理”。
