# 21.14 PoW 与中本聪共识：用算力给投票权定价

## 一句话

> PoW 不是 “更快的共识”，而是把 “一票” 换成 “一份可验证的算力消耗”：它解决的是**开放网络里 “一人多号” 的 Sybil 问题**，代价是概率最终性、低 TPS 与能源开销。

## 先分清它解决的是哪个问题

Raft、PBFT 都默认 “成员是已知的，一个节点就是一票”。这个默认在公网不成立：注册一个节点几乎零成本，攻击者可以开一万个号，把 “多数派” 直接买下来。这叫 **Sybil 攻击**，它不是拜占庭故障的一种，而是**成员身份**层面的问题。

| 成员模型 | 身份成本 | “一票” 有意义吗 | 适用共识 |
|---|---|---|---|
| 封闭、已知（公司内网） | 运维一台机器 | 有 | Raft / ZAB，`2f+1` |
| 半开放、需准入（联盟链） | 组织资质 + 证书 | 有 | PBFT / Tendermint，`3f+1` |
| 全开放、匿名（公链） | 接近 0 | **没有** | 先解决 Sybil：PoW / PoS |

> 🔑 所以 PoW 和 PBFT 不在同一层：**PBFT 假设 “叛徒数 < n/3”，PoW 先让 “买票” 变得昂贵，再谈多数派**。把两者放进同一张 “共识算法对比表” 比较 TPS，等于拿保险条款比保费。

## 机制：哈希难题 + 最长链 + 难度调整

### ① 哈希难题：把 “出块权” 变成抽奖

区块头只有 80 字节，矿工反复改 `nonce`（以及可变的 coinbase 字段），直到整个头的 SHA-256 双哈希小于目标值 `target`：

| 字段 | 作用 | 与挖矿的关系 |
|---|---|---|
| `version` | 协议版本 / 投票位 | 可改，扩大搜索空间 |
| `prev_block` | 父区块哈希 | 决定 “接在哪条链后面” |
| `merkle_root` | 交易集合的承诺 | 改交易就要重算 |
| `timestamp` | 时间戳 | 有允许偏差，不能当精确时钟 |
| `bits` | 目标值的紧凑编码 | 难度调整改的就是它 |
| `nonce` | 32 位计数器 | 主要搜索变量 |

“小于 target” 等价于 “哈希有 `k` 个前导零比特”，单次尝试成功率 `2^-k`，期望尝试 `2^k` 次。下面这段程序实测了不同难度下的尝试次数：

```go
// 找到 k 个前导零比特需要多少次哈希？期望 2^k，但方差极大。
func mineOnce(bits int, seed uint64) uint64 {
	var buf [8]byte
	for nonce := uint64(0); ; nonce++ {
		binary.LittleEndian.PutUint64(buf[:], seed^nonce)
		h := sha256.Sum256(buf[:])
		if leadingZeroBits(h) >= bits {
			return nonce + 1
		}
	}
}
```

完整代码在仓库 [tools/examples/21.14-pow/](../../../tools/examples/21.14-pow/README.md)，`go run .` 可复现。

本机实测（macOS，Apple M1，Go 1.27.1，每档 300 次）：

```text
=== 哈希难题：找到 k 个前导零比特要试多少次（每档 300 次试验）===
位数     期望 2^k       实测均值         最大
8      256          239          1018
12     4096         4449         39170
16     65536        59120        249349
20     1048576      1311467      3653408
```

两件事值得注意：

- 均值贴着 `2^k`，说明 “算力占比 = 出块概率” 在期望意义上成立；
- **最大值可以到均值的 3 倍以上**，这不是 bug，是几何分布的重尾——所以 “谁先挖到” 是抽奖，不是按算力排队。

### ② 最长链：用累计工作量定义 “真相”

分叉是常态：两个矿工几乎同时出块，网络会短暂分成两条链。规则不是 “谁先到”，而是 **累计工作量最大的那条链获胜**（比特币里近似为 “最长链”，因为难度一致）。被抛弃的块叫孤块，矿工拿不到奖励。

| 概念 | 含义 | 工程后果 |
|---|---|---|
| 分叉 | 同一高度出现多个块 | 正常现象，靠后续块收敛 |
| 孤块 | 不在最长链上的块 | 矿工收益波动，交易可能 “消失” |
| 确认数 | 块之后又叠了多少块 | 每多 1 个确认，回滚成本指数上升 |
| 6 个确认 | 行业惯例（约 60 分钟） | 大额交易仍建议 12+ |

### ③ 难度调整：把出块时间拉回 10 分钟

算力上涨，出块变快；协议每 **2016 个块**（约 2 周）按 “实际耗时 / 期望耗时（20160 分钟）” 调整 `target`，单次调整幅度限制在 4 倍以内。算力翻倍，难度就翻倍：

| 相对算力 | 同样 target 下的期望出块 | 难度倍数 |
|---|---|---|
| 0.5× | 20 分钟 | 0.5 |
| 1× | 10 分钟 | 1 |
| 2× | 5 分钟 | 2 |
| 4× | 2.5 分钟 | 4 |

> ⚠️ 难度调整有滞后：算力突然暴跌时，出块会先变慢，最多要等一个调整周期才恢复。这是 “10 分钟” 只是**目标值**、不是 SLA 的原因。

## 概率最终性：为什么必须等确认

PoW 没有 “提交即终局”。攻击者算力占比 `q`，诚实链领先 `z` 个块，双花成功率由白皮书模型给出：攻击者在诚实网络挖出这 `z` 个块的同一时间窗内挖到 `K ~ Poisson(z·q/p)` 个块，再从落后 `z-K` 的位置追。

| 攻击者算力 `q` | `z=1` | `z=3` | `z=6` | `z=12` |
|---|---|---|---|---|
| 10% | 20.5% | 1.3% | **0.024%** | ≈ 0 |
| 20% | 41.7% | 10.3% | 1.4% | 0.03% |
| 30% | 62.8% | 32.5% | **13.2%** | 2.4% |
| 40% | 82.9% | 66.7% | 50.5% | 30.7% |

（模拟值与公式在 10 万次试验下误差 < 2%，见示例输出。）

读法：

- **10% 算力、6 个确认**，双花概率约万分之二——这就是 “6 确认” 成为行业惯例的算术依据；
- **30% 算力、6 个确认**，仍有 13% 风险，大额必须加到 12 个确认以上，或者干脆等更久；
- 确认数的本质是**用时间换确定性**，交易所对充值的确认数要求，就是这条曲线的工程取值。

> 🔑 51% 攻击能做什么、不能做什么：能双花自己的交易、能审查交易、能让链短暂分叉；**不能伪造别人的签名、不能把别人地址里的币转走**。它攻击的是 “定序”，不是 “所有权”。

与 BFT 的最终性对比：

| 维度 | PoW | PBFT / Tendermint |
|---|---|---|
| 最终性 | **概率的**：`z` 越大越接近 1，但永不为 1 | **确定的**：commit 即终局（在 `f` 假设内） |
| 达成条件 | 算力多数（经济假设） | `2f+1` 投票（身份假设） |
| 回滚 | 可能，深度越大越难 | 不会（除非超过 `f` 个节点作恶） |
| 延迟 | 10 分钟/块，6 确认约 1 小时 | 秒级到几秒 |

## 为什么企业里几乎不用

| 维度 | PoW 的代价 | 企业诉求 |
|---|---|---|
| TPS | 基础层约 7 TPS（1 MB 块 / 10 分钟 / 约 250 B 一笔） | 数千到数十万 |
| 延迟 | 6 确认约 60 分钟 | 毫秒到秒 |
| 最终性 | 概率的，理论上可回滚 | 确定性，可审计 |
| 能耗 | 百 TWh 量级（随币价与算力波动） | 成本与碳排有硬约束 |
| 成员 | 开放匿名 | 已知、可追责 |
| 运维 | 矿池、算力、孤块 | 标准 SRE 体系 |

企业里真正需要 “跨组织互不信任” 的场景，用的是 **PBFT / Tendermint**（见 [21.13 PBFT](21.13-PBFT.md)），因为参与方是已知机构，身份本身就有成本，不需要用算力再买一次 “投票权”。

**PoS（权益证明）** 是同一条思路的另一种定价方式：用 “质押的币” 替代 “烧掉的算力”，作恶会被罚没（slashing）。它把能耗降了几个数量级，代价是引入 **弱主观性**——新加入的节点需要一个可信的近期检查点，不能只靠创世块自己推。以太坊的最终性检查点大约 13 分钟，仍然不是 “提交即终局”。

| 维度 | PoW | PoS |
|---|---|---|
| 投票权来源 | 算力（外部资源） | 质押（系统内资产） |
| 作恶成本 | 电费 + 矿机折旧 | 质押被罚没 |
| 能耗 | 高 | 低几个数量级 |
| 新节点同步 | 无需信任任何检查点 | 需要弱主观性检查点 |
| 常见误区 | “去中心化 = 无成本” | “质押 = 无风险” |

## 什么时候 PoW 是对的

| 场景 | 是否适合 | 理由 |
|---|---|---|
| 公网匿名、无准入的支付/价值转移 | ✅ | 需要 Sybil 抵抗 + 抗审查 |
| 跨组织、但有资质的联盟 | ❌ | 用 PBFT，身份已足够 |
| 公司内部配置中心、选主 | ❌ | Raft，`2f+1` 就够 |
| 需要秒级确定性最终性 | ❌ | PoW 的概率最终性天生不满足 |
| 需要 “随时加入、随时退出” | ✅ | 无需准入，算力即门票 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 把 PoW 和 Raft 放同一张表比 TPS | 结论必然是 “PoW 很慢”，但没回答它为什么存在 |
| 用 1 个确认就发货 | 10% 算力下双花成功率 20%，等于没确认 |
| 以为 51% 能偷任意地址的币 | 只能双花/审查，所有权由签名保护 |
| 把 “最长链” 理解成 “块数最多” | 难度不一致时要比**累计工作量**，不是高度 |
| 用 PoW 解决内部选主 | 白付能源与延迟，还得不到确定性最终性 |
| 忽略难度调整滞后 | 算力骤降时出块变慢，误判为 “网络故障” |
| 把 PoS 当成 “无成本共识” | 弱主观性、罚没条件、质押流动性都是成本 |

## 自检

**Q1** PoW 到底解决了什么、没解决什么？

▸ 答案：解决开放网络里的 Sybil（让 “多开号” 变得昂贵），从而让 “多数派” 有意义；不解决低延迟、确定性最终性、高 TPS，也不防 51% 算力攻击。

**Q2** 为什么 10% 算力、6 个确认时风险约万分之二，而 1 个确认时高达 20%？

▸ 答案：双花概率随确认数指数衰减。1 个确认时攻击者只需在短窗口内追平；6 个确认时要在诚实链继续延伸的情况下追 6 个块，概率按 `(q/p)^z` 量级下降。

**Q3** “最长链” 为什么严格说是 “累计工作量最大链”？

▸ 答案：难度会调整，块高度相同不代表工作量相同。分叉选择必须比较累计难度，否则攻击者可以用低难度块堆高度。

**Q4** 51% 攻击者能做什么、不能做什么？

▸ 答案：能双花自己的交易、审查交易、制造短期分叉；不能伪造签名、不能转走别人地址的币。它破坏的是定序与可用性，不是签名与所有权。

**Q5** 企业跨组织对账，为什么选 PBFT 而不是 PoW？

▸ 答案：参与方已知且有资质，身份本身有成本，不需要算力再买投票权；PBFT 提供确定性最终性和秒级延迟，代价只是 `3f+1` 副本，远低于 PoW 的延迟与能耗。

**Q6** PoS 的 “弱主观性” 指什么？

▸ 答案：新节点不能只凭创世块和当前链自己判断哪条是正链，需要一个近期可信检查点；PoW 的新节点可以只靠累计工作量独立判断，这是两者信任起点的差别。
