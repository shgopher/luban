# 第 24 章 分布式事务 · 概论

## 一句话

> 一个操作横跨两个库、两个服务时，怎么保证**要么全成、要么全不成**？答案不是最强的协议，而是按约束挑模型，让不一致窗口有人兜底。

## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **本地事务** | 一个库内全做或全不做 | 写错就撕页重写 |
| **2PC** | 问所有人能否提交，全票才提交 | 逐个问，全好才开幕 |
| **协调者** | 做最终决定，挂了大家只能等 | 导游一人喊集合、发车 |
| **TCC** | Try 预留、Confirm 扣减、Cancel 释放 | 订房冻结押金，入住转消费 |
| **Saga** | 拆成本地事务，失败逆序补偿 | 掉棒后沿原路收回 |
| **本地消息表** | 待发消息与业务同一本地事务写入 | 信和账本锁进同一抽屉 |
| **事务消息** | 半消息先藏，本地成功才转正，丢则回查 | 先贴单不揽收，有货才上门 |
| **最大努力通知** | 尽力发 + 对端幂等 + 主动查询 | 反复打电话，最后翻记录核对 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 分布式事务就是 2PC，越强越好 | 2PC 投票到提交一直阻塞，协调者挂了只能等；选型看总成本 |
| 最终一致等于不可靠 | TCC、Saga、消息表、事务消息都最终一致；靠重试、幂等、对账 |
| 上了 MQ 就自动一致 | MQ 只管投递，业务与消息的原子性仍要消息表或事务消息 |

## 读完自检（入门级 3 题）

**Q1** 同库与跨库转账，差在哪？

▸ 答案：撤销由谁保证。同库时 A/I/D 靠日志、锁、回滚段，失败能原地回滚；跨库没人能锁住两边，只能靠协议或补偿，中间态被看见。

**Q2** 参与者都投了“能提交”，协调者却挂了，为何不能自己提交？

▸ 答案：投票只说“我能做”，不代表别人赞成。自己提交可能撞上别人的回滚。等恢复，是拿可用性换一致性。

**Q3** 本地消息表和事务消息，都保证业务与消息原子性，差在哪？

▸ 答案：前者把消息写进**同一个库**，跟业务一个本地事务提交，再搬去 MQ；后者先存 Broker 当半消息，本地成功才转正，丢了回查。
