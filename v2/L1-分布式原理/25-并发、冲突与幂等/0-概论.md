## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **并发冲突** | 两个写同时改一份数据，后提交的盖掉先提交的 | 同改表格一格，后存的赢 |
| **悲观并发** | 先锁再改，别人排队 | 进厕所先锁门 |
| **乐观并发** | 先改，提交时验版本，不一致就重试 | 查版本，不对就重写 |
| **MVCC** | 写留新版本，读按自己的快照挑 | 每版书留一本，按借书那刻的看 |
| **冲突率** | 同一份数据被并发写的比例，选型的唯一依据 | 路口同一秒几辆车要过 |
| **幂等** | 同一请求执行 N 次与执行 1 次结果一样 | 电梯按钮按十次也只来一趟 |
| **幂等键** | 一次业务操作固定不变的身份证 | 快递单号：重发还是那一单 |
| **CRDT** | 可合并结构，乱序、重复合并结果都一样 | 各往清单添菜，合起来不重不漏 |

- **事前**：锁换“等待”，版本换“重试”，按冲突率选；
- **事中与事后**：撞上后先问业务含义再定谁赢；重发消除不了，只能让重复无害；快照与 CRDT 靠合并。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “乐观锁不阻塞，所以更快” | 不排队但会重试；冲突高时重试比排队更费 CPU。要看成本是重试还是等待 |
| “MVCC 读写不互斥，所以没代价” | 旧版本要清理，清理追不上长事务，表就膨胀 |
| “幂等就是让上游别重发” | 做不到不重发，只能让重发无害：幂等键、唯一约束、结果一起存 |

## 读完自检（入门级 3 题）

**Q1** 冲突率高时，为什么不该用乐观并发？

▸ 答案：乐观的成本是**重试**：冲突越高重试越多，做过的活反复作废；悲观只让人排队，冲突高时更划算。

**Q2** MVCC 的账单记在哪？

▸ 答案：记在**旧版本**上：写产生新版本、读按快照挑，旧版本必须清理；长事务让它清不掉，表就膨胀。

**Q3** 超时重发了同一个“扣款”，怎么只扣一次？

▸ 答案：**稳定幂等键**（重发时不变）+ **唯一约束兜底**（重复插入被挡）+ **结果一起存**（同一次写入）。
