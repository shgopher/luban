## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **发布策略** | 逐台换、整套换、一小部分先换 | 换灯泡：一间间换、整层换 |
| **特性开关** | 代码已上线、功能不生效，出事秒关 | 灯装好了，开关先不按 |
| **回滚** | 回到已知可用状态，不是反向执行部署 | 撤到上一个营地，不是倒着走 |
| **Expand-Contract** | 改表拆成先加、再迁、最后删 | 先修新楼梯，再拆旧的 |
| **向后兼容** | 旧消费者不改一行代码也能继续工作 | 新插座留了旧插头的孔 |
| **灰度** | 小部分流量先给新版，观察后再放量 | 新菜先端给一桌客人试吃 |
| **流量染色** | 请求带上版本标记，走完整链路 | 公告栏贴纸，中转站不许撕 |

> 一条链：**策略管怎么换，开关管何时放，染色管谁先碰，回滚管能不能退。**

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “回滚就是把发布反着执行一遍” | 代码能退，数据、消息、缓存、外部副作用不一定能退 |
| “网关切了 10% 就是灰度” | 只决定入口；内部 RPC、消息、定时任务、缓存回源仍可能走旧版 |
| “加了开关就能随时关” | 开关解耦的是部署与发布，代价是多一条没人管的分支 |

## 读完自检（入门级 3 题）

**Q1** 滚动发布期间错误率“时好时坏”，最可能的原因？

▸ 答案：新旧版本在窗口里同时在线，请求随机落到两版；接口或数据格式不兼容就随机报错。

**Q2** 上周那个功能出问题了，为什么不能直接“回滚一下”？

▸ 答案：先确认“已知可用状态”在哪。动过库表、发过消息、写过缓存或调过接口，反向执行退不回去。

**Q3** 网关切了 10% 流量到新版本，为什么可能还不算灰度？

▸ 答案：入口只决定第一跳。染色没随请求走完 RPC、消息、定时任务，下游仍跑旧版，就是混部。
