## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **主干** | 所有人最后都要合进去的线 | 小区唯一的主干道 |
| **分支寿命** | 改动从提交到合入等了多久 | 借梯子一个月，邻居只好再买一把 |
| **合并冲突** | 两人改同一处，机器停下等人裁 | 两人改同一份菜单，末页两版 |
| **特性开关** | 没做完的功能进主干，配置里关着 | 装修一半的房间上锁，整楼照常营业 |
| **代码评审** | 进主干前让别人看一眼 | 出厂前的质检工位 |
| **评审尺寸** | 一次送审多大：200–400 行、60 分钟内 | 两碗刚好，二十碗尝不出味 |
| **语义化版本** | 三个数字：会不会坏 / 多了什么 / 只修 bug | 快递单备注：换地址、加赠品、补包装 |
| **单仓 / 多仓** | 一个仓库还是几个 | 一栋楼办公 vs 各自租楼 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「分支开得多 = 管理规范」 | **分支寿命**决定成本；长寿分支逼所有人替它付冲突与重跑 |
| 「评审就是多找几个资深的人看」 | **单次尺寸与时长**决定拦截率：200–400 行、60 分钟内 |
| 「单仓落后，多仓先进」 | 两笔成本交换：单仓内部化协调，多仓外部化独立性 |

## 读完自检（入门级 3 题）

**Q1** 为什么「分支挂得越久越贵」不是感觉，而是能算的？

▸ 答案：贵在**分叉宽度**：挂得越久，主干与分支碰过的文件重叠越多，冲突与重跑一起涨，两个量都能从 git 里数出来。

**Q2** 主干开发把等待压到小时级，代价是什么？

▸ 答案：半成品必须被**特性开关和自动化测试**接住；没有这两样，短分支就是往主干扔半成品。

**Q3** 你删掉一个公开函数，版本号只当 minor 发了，问题在哪？

▸ 答案：major 说「会不会坏」，删公开函数就是会坏；发成 minor 等于承诺「可以无脑升级」。变更日志这份账本，也得由机器从提交规范算。
