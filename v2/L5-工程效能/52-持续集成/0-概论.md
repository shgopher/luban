# 第 52 章 持续集成 · 概论

## 一句话

> 从提交到拿到可信的“能不能上”，怎么用最少墙钟时间证明它——答案：按关键路径与成本顺序排缓存、检查、扫描、排队，不给每步加速。

## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **流水线** | 提交后自动跑的步骤串，最后给通过或不过 | 洗车线：冲水、打沫、吹干依次来 |
| **关键路径** | 最长的那条链，决定总共等多久 | 三人接力搬箱，最慢那个定何时完 |
| **构建缓存** | 上次算过的结果存下来，这次直接用 | 昨天切好的菜放冰箱，今天直接用 |
| **门禁** | 不满足条件不许往下走的检查 | 机场安检口，过不了不让登机 |
| **ratchet（棘轮）** | 只许变好不许变差的门槛，旧账先记着 | 只能往紧调的扳手 |
| **可达漏洞** | 代码真会执行到的依赖漏洞 | 东门锁坏了，但你从不走东门 |
| **利用率 ρ** | 机器有多满，越接近 1 排队越长 | 单窗口食堂，人多就排到门外 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “持续集成就是提交后自动跑测试” | 测试只是末端一段；体验由构建能否复用、检查贵不贵、排队多长决定 |
| “门禁越严越安全” | 只加规则不分层，最后一定被人绕过；flaky 又让人重跑成习惯，红绿灯失真 |
| “漏洞清零才算安全” | 产出该是可达路径上、有修复版本的清单；17 条压成 0 条可达才算完 |

## 读完自检（入门级 3 题）

**Q1** 两个 PR 步骤一样多，为什么一个 4 分钟、一个 12 分钟？

▸ 答案：耗时看**最长路径**，不是步骤总和。差别在关键路径那一步、缓存命中、排队时长。

**Q2** 团队把 lint 规则从 50 条加到 200 条，平均修复时间反而变长？

▸ 答案：规则没分层。秒级的在提交前挡机械问题，十秒到分钟级的放合并后，中间用 ratchet 挡新增。

**Q3** 扫描器报了 17 条漏洞，先修哪条？

▸ 答案：先问**可不可达**——代码真会走到且有修复版本的那条先修；模块级告警多不可达。
