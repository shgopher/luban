# 52.6 代码生成：把规范交给生成器

## 一句话

> 代码生成不是"少写几行"，而是把只活在注释和评审意见里的规范编译成**派生物**：源码是唯一真相，产物是它的函数，CI 用一次"重新生成 + diff 为空"证明 `f(源) ≡ 产物`；iam/onex/fastgo 的差别不在工具，而在四道关——谁声明、谁编排、谁入库、谁锁版本。

## 先破除四个误区

| 误区 | 现实 |
|---|---|
| "生成器是框架附赠的功能" | iam 的生成器是仓库里的 `tools/codegen/codegen.go`（440 行）；onex 有 5 个自研 `cmd/gen-*`。生成器是**仓库资产**，要和业务代码一起评审、一起回滚 |
| "生成物提交了就万事大吉" | 生成物的价值是"可重建"而不是"已提交"。入库的生成物必须配"再生成一次、diff 为空"的门禁，否则手改会静默生效 |
| "生成得越多越省事" | 生成器覆盖**结构**，不覆盖**判断**：fastgo 用 gorm.io/gen 生成 2 个模型共 56 行，没有一行业务规则 |
| "生成器版本无所谓" | onex 的 mockgen 版本从 go.mod 读，iam 的 `install.mockgen` 用 `@latest`；后者无法保证"今天和明天生成的文件一致" |

## 五类生成物：先分类，再决定怎么管

| 类别 | 产物是什么 | 源头 | 实例（本机实测） | 进仓库 |
|---|---|---|---|---|
| 类型 | 表结构 → struct、枚举 | schema / 常量 | fastgo `internal/apiserver/model/*.gen.go` 2 个共 56 行；onex 8 个 `*.gen.go` | 是 |
| 注册表 | 常量 → `init()` 注册调用 | 常量 + 注释 | iam `code_generated.go`，27 条 `register(...)` | 否（构建时生成） |
| mock | interface → 测试替身 | 接口声明 | iam 4 个 `mock_*.go` 共 1170 行；onex 18 个；fastgo 4 条 `go:generate` | 是 |
| 文档 | 结构化注释 → markdown 表 | 同注册表 | iam `error_code_generated.md` 27 行；onex swagger/CLI 文档 | 是 |
| 构建元数据 | git 状态 → 二进制版本变量 | git + 时间 | fastgo `build.sh` 注入 4 个变量 | 不适用 |

> 🔑 分类的唯一用处是决定产物去处：**人读的进仓库、编译器读的不进、构建期才知道的只进二进制**。mock 的消费方是单元测试（见 [53.2 单元测试](../53-测试与质量保障/53.2-单元测试.md)），接口一改 mock 必须跟着改，这正是它适合"生成 + 入库 + diff 门禁"的原因。

## 判据一：源码是唯一真相，产物是派生物

iam 用一条链把 27 个错误码从"注释"变成"运行时注册表 + 对外码表"，中间不需要人再抄一遍。输入长这样（`internal/pkg/code/base.go` 真实片段）：

```go
//go:generate codegen -type=int
//go:generate codegen -type=int -doc -output ../../../docs/guide/zh-CN/api/error_code_generated.md

// Common: basic errors.
const (
	// ErrSuccess - 200: OK.
	ErrSuccess int = iota + 100001

	// ErrUnknown - 500: Internal server error.
	ErrUnknown
)
```

生成器（440 行）在中间做四件事：

1. **类型检查**：`packages.Load`（`LoadSyntax`）加载整个包，常量值来自 `go/types`——`iota + 100001` 是类型检查器算的，不是生成器自己解析表达式。
2. **只认 const**：`ast.Inspect` 筛 `*ast.GenDecl` 且 `decl.Tok == token.CONST`，再按 `-type=int` 过滤。
3. **注释即协议**：`ParseComment` 用正则 `\w\s*-\s*(\d{3})\s*:\s*([A-Z].*)\s*\.\n*` 抽 HTTP 码和文案；匹配不上**回落 500 + 打日志**，不中断生成。
4. **两条出口**：默认写 `code_generated.go`（`init()` 里一串 `register(...)`），`-doc` 写 markdown 表；Go 产物过 `go/format.Source`，格式坏在生成期就报。

实测：3 个源文件 → **27 条 `register` + 27 行 markdown**；`make gen.errcode` 一次产出两份。iam 仓库里已提交的表头长这样：

```markdown
| Identifier | Code | HTTP Code | Description |
| ---------- | ---- | --------- | ----------- |
| ErrUserNotFound | 110001 | 404 | User not found |
| ErrReachMaxCount | 110101 | 400 | Secret reach the max count |
```

第二行值得看两眼：常量名叫 `ErrReachMaxCount`，注释却写着 `// ErrEncrypt - 400: ...`——注释里的标识符是错的，但生成器只取"HTTP 码 + 文案"，产物照样正确。**生成器用结构（常量名）兜底，用注释补充元数据**，比全塞进注释稳。

> 🔑 单一真相源的判据：**删掉产物，能不能从源码无歧义重建？** 能，就可以生成；不能（要靠人的判断），就别生成。

## 判据二：就近声明 + 统一编排

| 仓库 | `go:generate` | 构成 | 编排入口 | 一次生成的范围 |
|---|---|---|---|---|
| iam | 9 条 | codegen 4、mockgen 4、swagger 1 | `make gen` = `gen.clean` → `gen.errcode` → `gen.docgo.doc` | 先删旧产物，再生成注册表、码表、doc.go |
| onex | 29 条 | mockgen 18、wire 11（10 条 `go run`、1 条 `wire .`） | `make gen.run` = docgo + protoc + `go generate ./...` | protobuf、mock、wire、K8s 代码 |
| fastgo | 4 条 | mockgen 4 | 手工 `go generate ./...`（只有 `build.sh`） | 只有 mock |

三条分工规则，三份仓库都遵守：

1. **`go:generate` 只声明"我在哪个文件边界上"**，不写顺序、清理、工具安装。onex 那 11 条 wire 里，10 条写的是 `go run github.com/google/wire/cmd/wire`——连二进制都不要求，版本由 go.mod 定；剩下 1 条是裸 `wire .`，反而成了版本不留痕的那一条。
2. **Makefile 负责顺序与前置**：`tools.verify.<tool>` 保证工具存在（onex 的 `go.generate: tools.verify.mockgen tools.verify.wire`），`gen.clean` 保证先删再生成；iam 的 `all: tidy gen ... build` 把 `gen` 排在 `build` 前。
3. **两边都不手写输出路径**：iam 只有 `-doc` 那条显式给了 `-output`，其余靠默认命名（目录名 + `_generated.go`），产物与源码同目录，diff 好定位。

`go:generate` 多不等于"更爱生成"，而是**接口多**：onex 有 883 个 `.go` 文件、18 个 mock 接口，所以 29 条；fastgo 只有 4 个接口要 mock。生成放在流水线哪一段（构建前串行，还是独立并行 job）直接影响墙钟时间，见 [52.4 流水线设计与耗时优化](52.4-流水线设计与耗时优化.md)。

> ⚠️ 声明就近的代价：`go generate ./...` 会跑遍全仓，任何一个包失败都中断整条命令。onex 用 `tools.verify.*` 防"生成到一半发现没装 mockgen"。

## 判据三：生成物入库与否，看两条硬判据

| 判据 | 问什么 | 结论 |
|---|---|---|
| 消费门槛 | 新人 clone 后不装工具、不跑生成，`go build ./...` + `go test ./...` 能不能过？ | 不能 → 必须入库，或把生成塞进构建入口 |
| 可读性 | 有人需要在 PR diff 里读它、在仓库里搜它吗？ | 要 → 必须入库 |

| 仓库 | 入库的生成物 | 不入库的生成物 | 依据 |
|---|---|---|---|
| iam | 4 个 `mock_*.go`（1170 行）+ `error_code_generated.md`，共 5 个 | `code_generated.go` | 文档给人看、mock 给测试用；注册表由 `make gen` 构建前生成，`gen.clean` 删所有 `*_generated.go` |
| onex | **全部入库**：6 类口径去重 131 个 | 无 | K8s 生成物依赖 controller-gen/protoc 版本，入库才能 clone 即编译 |
| fastgo | 2 个 `*.gen.go` | 4 条 mockgen 的产物一个都没入库 | 模型是编译必需品；mock 暂未入库 |

onex 那 131 个的构成：`zz_generated.*` 28、`*_generated.go` 7、`*.gen.go` 8、`mock_*.go` 18、`wire_gen.go` 5、`pkg/generated/` 下 70。注意**直接相加是 136，去重才是 131**——有 5 个文件同时落在两类口径里（4 个 `pkg/generated/` 下的 `*_generated.go`、`pkg/generated/openapi/zz_generated.openapi.go`）。统计生成物时口径必须写清，不然"入库数"会凭空多出 5。

> ⚠️ 不入库有个真坑，iam 身上最清楚：`register()` 在 `internal/pkg/code/code.go:58` 定义，但**全仓库没有任何一处调用**——它只被生成物调用，而 `code_generated.go` 不在 `git ls-files` 里。只跑 `go build ./...` 时包能编译（未使用的函数合法），但 `errors.MustRegister` 一次都没执行，错误码注册表是空的：这是"编译通过、功能缺失"，不是编译错误。

## 判据四：生成器版本要锁（onex 的三种锁法）

| 锁法 | 做法 | 实例 | 防住什么 | 代价 |
|---|---|---|---|---|
| 源码入仓 | 生成器和业务同仓、同 commit | iam `tools/codegen/codegen.go`（`go install` 仓库内路径）；onex 5 个 `cmd/gen-*` | "换台机器产物就变" | 生成器要自己维护 |
| go.mod 锁版本 | `go run <module>/cmd/x`，版本由 go.mod 定 | onex 10 条 `go run github.com/google/wire/cmd/wire`；`WIRE_VERSION`/`MOCKGEN_VERSION` 用 `get_go_version` 读 go.mod | 工具版本漂移 | 需要模块缓存或网络 |
| 显式版本变量 | Makefile 里写死 | onex `GEN_TOOL_VERSION ?= v0.3.25` | 不防 | 与 go.mod 双写，必漂 |
| `@latest`（反例） | 装最新 | iam `install.mockgen`、`install.swagger` | — | 今天和明天的产物不保证一致 |

第二种是 onex 的主锁法，也是最值得抄的一组定义：

```make
# scripts/make-rules/common.mk
get_go_version = $(shell go list -m $1 | awk '{print $$2}')
# scripts/make-rules/common-versions.mk
WIRE_VERSION    ?= $(call get_go_version,github.com/google/wire)
MOCKGEN_VERSION ?= $(call get_go_version,github.com/golang/mock)
```

`WIRE_VERSION` 在 go.mod 里是 `v0.5.0`，`MOCKGEN_VERSION` 取项目依赖的 `github.com/golang/mock` 版本——**生成器版本 = 库版本**，升级库时生成器自动跟着升。第三种已经漂了：`GEN_TOOL_VERSION` 写 `v0.3.25`，而 go.mod 里是 `gorm.io/gen v0.3.23`；两者作用于不同路径所以目前没炸，但只要有人用 gentool 重生成，产物就和库版本对不上。生成器版本变了，构建缓存 key 也该变——缓存 key 含什么，见 [52.1 构建与缓存](52.1-构建与缓存.md)。

> 🔑 生成器就是编译器：升级它会改产物。判据不是 `which mockgen`，而是"**这个 commit 用哪个版本生成**"。

## 判据五：生成的是结构，不是业务

fastgo 的 `internal/apiserver/model/user.gen.go` 是 gorm.io/gen 从 `user` 表直接投影出来的：9 个字段、列名、类型、默认值全部来自 schema，连注释都抄数据库的 `comment`。生成器把"数据库长什么样"翻译成"Go struct 长什么样"，翻译过程没有判断。

它生成不了的是判断：为什么用户表这样拆（[83.3 架构设计文档模板](../../附录/83-架构文档与表达/83.3-架构设计文档模板.md) 的"选型"章节）、错误码该不该复用（[40.7 错误码体系](../../L3-质量属性/40-可维护性/40.7-错误码体系.md) 的主场）、业务规则该放哪层（[26.3 整洁架构](../../L2-架构风格/26-分层与依赖/26.3-整洁架构.md) 的同心圆：生成器只服务外圈的 ORM、协议、mock、文档，内圈不生成）。

什么时候**别**上生成器，判据是 `生成频率 × 每次手工维护成本 > 生成器维护成本`：

| 场景 | 别上的理由 |
|---|---|
| 一次性脚本、30 行的迁移工具 | 生成器的模板/测试/报错路径比脚本本身长 |
| 只有 3 个值的枚举 | `stringer` 的间接层比手写 `String()` 更贵 |
| 模型还在天天改 | 每次 schema 变更都重跑，PR 里全是生成物 diff |
| 输出需要人的判断 | 生成的只是"错误决策的快照"，还带着自动生成的权威感 |

## 最小生成器：179 行标准库，复刻 iam 的两份产物

iam 用 `go/packages` 换来通用性（任意整数表达式、build tags），代价是 440 行。多数仓库的错误码只有 `iota + N` 一种写法——这时一个标准库小程序就够。三个取舍：只认 `iota + N` 和裸字面量、不处理 build tags、注释协议与 iam 同款。

输入是 3 个 const 块 10 个常量（`input.go` 全文，含一条格式不合规的注释用于验证回落）：

```go
// 输入样本：与 iam internal/pkg/code/base.go 同一种写法（注释 + iota），
// 只保留 10 个常量，方便把生成结果整段贴进书里。
package code

// Common: basic errors.
const (
	// ErrSuccess - 200: OK.
	ErrSuccess int = iota + 100001

	// ErrUnknown - 500: Internal server error.
	ErrUnknown

	// ErrBind - 400: Error occurred while binding the request body to the struct.
	ErrBind

	// ErrTokenInvalid - 401: Token invalid.
	ErrTokenInvalid

	// ErrPageNotFound - 404: Page not found.
	ErrPageNotFound
)

// common: database errors.
const (
	// ErrDatabase - 500: Database error.
	ErrDatabase int = iota + 100101
)

// common: authorization errors.
const (
	// ErrEncrypt - 401: Error occurred while encrypting the user password.
	ErrEncrypt int = iota + 100201

	// ErrExpired - 401: Token expired.
	ErrExpired

	// ErrPasswordIncorrect 密码错误（注释格式不合规，用来验证 500 回落）
	ErrPasswordIncorrect

	// ErrPermissionDenied - 403: Permission denied.
	ErrPermissionDenied
)
```

程序共 179 行，核心两个动作：**AST 里算值**、**两个渲染器出两份产物**。完整源码如下，与 `input.go` 放进同一目录即可 `go run`：

```go
// 最小错误码生成器：只用 Go 标准库，把「const 块 + 注释」编译成
// （a）Go 注册代码 （b）Markdown 错误码表。
// 用法：go run gen.go -out out input.go
package main

import (
	"flag"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"os"
	"path/filepath"
	"regexp"
	"strconv"
	"strings"
)

// 注释协议：`// ErrXxx - 404: User not found.` 与 iam 的 codegen 一致。
var docRE = regexp.MustCompile(`-\s*(\d{3})\s*:\s*(.+?)\s*\.?\s*$`)

type entry struct {
	Name string // 常量名
	Code int    // 常量值
	HTTP int    // 注释里的 HTTP 状态码
	Desc string // 注释里的描述
}

func main() {
	out := flag.String("out", "out", "output directory")
	check := flag.Bool("check", false, "verify files are up to date, exit 1 on drift")
	flag.Parse()
	if flag.NArg() == 0 {
		fmt.Fprintln(os.Stderr, "usage: gen [-out dir] [-check] <input.go> [more.go ...]")
		os.Exit(2)
	}
	entries, pkg, err := parse(flag.Args())
	if err != nil {
		fmt.Fprintln(os.Stderr, "gen:", err)
		os.Exit(1)
	}
	files := map[string][]byte{
		"code_generated.go":       genGo(pkg, entries),
		"error_code_generated.md": genMarkdown(entries),
	}
	if *check {
		os.Exit(doCheck(*out, files))
	}
	if err := os.MkdirAll(*out, 0o755); err != nil {
		fmt.Fprintln(os.Stderr, "gen:", err)
		os.Exit(1)
	}
	for name, data := range files {
		if err := os.WriteFile(filepath.Join(*out, name), data, 0o644); err != nil {
			fmt.Fprintln(os.Stderr, "gen:", err)
			os.Exit(1)
		}
	}
	fmt.Printf("generated %d entries -> %s/{code_generated.go,error_code_generated.md}\n", len(entries), *out)
}

// parse 解析所有输入文件的 const 块。iota 的值在这里算，不依赖 go/types：
// 同一 const 块内第 i 项的 iota 就是 i，所以 `iota + N` 的值 = i + N。
func parse(paths []string) ([]entry, string, error) {
	fset := token.NewFileSet()
	var out []entry
	pkg := ""
	for _, path := range paths {
		f, err := parser.ParseFile(fset, path, nil, parser.ParseComments)
		if err != nil {
			return nil, "", err
		}
		pkg = f.Name.Name // 所有输入必须同包，取第一个即可
		ast.Inspect(f, func(n ast.Node) bool {
			decl, ok := n.(*ast.GenDecl)
			if !ok || decl.Tok != token.CONST {
				return true
			}
			offset, useIota := 0, false
			for i, spec := range decl.Specs {
				vs, ok := spec.(*ast.ValueSpec)
				if !ok || len(vs.Names) != 1 || vs.Names[0].Name == "_" {
					continue // 生成器只认单名常量，其余显式跳过
				}
				if len(vs.Values) > 0 { // 空值项沿用上一项的表达式
					offset, useIota = exprOffset(vs.Values[0])
				}
				code := offset
				if useIota {
					code = i + offset
				}
				doc := ""
				if vs.Doc != nil {
					doc = strings.TrimSpace(vs.Doc.Text())
				}
				httpCode, desc := parseDoc(doc)
				out = append(out, entry{vs.Names[0].Name, code, httpCode, desc})
			}
			return true
		})
	}
	if len(out) == 0 {
		return nil, "", fmt.Errorf("no const found in %v", paths)
	}
	return out, pkg, nil
}

// exprOffset 识别两种写法：`iota + N` 与裸字面量 N。
func exprOffset(e ast.Expr) (int, bool) {
	if be, ok := e.(*ast.BinaryExpr); ok && be.Op == token.ADD {
		if id, ok := be.X.(*ast.Ident); ok && id.Name == "iota" {
			if lit, ok := be.Y.(*ast.BasicLit); ok {
				n, _ := strconv.Atoi(lit.Value)
				return n, true
			}
		}
	}
	if lit, ok := e.(*ast.BasicLit); ok {
		n, _ := strconv.Atoi(lit.Value)
		return n, false
	}
	return 0, false // 复杂表达式不猜：本生成器只覆盖 iam 用到的两种写法
}

// parseDoc 解析 `- 404: User not found.`；格式不对时回落 500，与 iam 一致。
func parseDoc(doc string) (int, string) {
	m := docRE.FindStringSubmatch(doc)
	if m == nil {
		return 500, "Internal server error"
	}
	httpCode, _ := strconv.Atoi(m[1])
	return httpCode, m[2]
}

// genGo 生成 init 注册代码，最后过一遍 go/format —— 格式错误在生成期就暴露。
func genGo(pkg string, entries []entry) []byte {
	var b strings.Builder
	b.WriteString("// Code generated by minicg; DO NOT EDIT.\n\n")
	b.WriteString("package " + pkg + "\n\nfunc init() {\n")
	for _, e := range entries {
		fmt.Fprintf(&b, "\tregister(%s, %d, %q)\n", e.Name, e.HTTP, e.Desc)
	}
	b.WriteString("}\n")
	src, err := format.Source([]byte(b.String()))
	if err != nil {
		panic(fmt.Sprintf("generated code does not parse: %v", err))
	}
	return src
}

// genMarkdown 生成人读的错误码表，行顺序与源码声明顺序一致。
func genMarkdown(entries []entry) []byte {
	var b strings.Builder
	b.WriteString("# 错误码\n\n！！本文件由 `minicg` 生成，不要对此文件做任何更改。\n\n")
	b.WriteString("| Identifier | Code | HTTP Code | Description |\n| --- | --- | --- | --- |\n")
	for _, e := range entries {
		fmt.Fprintf(&b, "| %s | %d | %d | %s |\n", e.Name, e.Code, e.HTTP, e.Desc)
	}
	return []byte(b.String())
}

// doCheck 把生成结果与磁盘文件逐字节比较，是 CI 里挡住「手改生成物」的那道门。
func doCheck(dir string, files map[string][]byte) int {
	drift := 0
	for name, want := range files {
		got, err := os.ReadFile(filepath.Join(dir, name))
		if err != nil || string(got) != string(want) {
			fmt.Printf("drift: %s is out of date\n", name)
			drift++
		}
	}
	if drift > 0 {
		fmt.Printf("%d file(s) out of date, run: go run gen.go -out %s <input.go>\n", drift, dir)
		return 1
	}
	fmt.Printf("OK: %d file(s) up to date\n", len(files))
	return 0
}
```

## 生产落地：指名 → 可抄 → 可验 → 可退

**指名**：Go 自带 `go/ast` + `go/format`（零依赖，本节 179 行路线）；要"任意表达式都算对"用 `golang.org/x/tools/go/packages` + `go/types`（iam 440 行路线）；schema 驱动选 `gorm.io/gen`（fastgo/onex 生成模型）、`sqlc` 或 `ent`；接口替身用 `mockgen`，枚举字符串用 `stringer`，K8s 对象用 `controller-gen`。

**可抄**（生成、校验分开；`ALLOW_GEN_DRIFT=1` 是紧急放行开关）：

```make
.PHONY: gen verify-gen
gen: ## 生成全部派生物
	go generate ./...
	go run ./tools/minicg -out internal/pkg/code internal/pkg/code/base.go

verify-gen: gen ## CI 门禁：再生成一次，产物必须没变化
	@if [ "${ALLOW_GEN_DRIFT:-0}" = "1" ]; then echo "⚠️ 生成物漂移放行（需开 ticket）"; exit 0; fi
	@if [ -n "$$(git status --porcelain -- '*_generated.go' '*.gen.go' '*_generated.md')" ]; then \
		echo "生成物与源码不一致：请跑 make gen 并提交"; git status --short; exit 1; fi
	@echo "生成物一致"
```

**可验**（本机真实输出，一成功一失败）：

```console
$ GO111MODULE=off go run gen.go -out out -check input.go
OK: 2 file(s) up to date
$ echo $?
0

$ sed -i '' 's/| Token invalid |/| Token expired |/' out/error_code_generated.md
$ GO111MODULE=off go run gen.go -out out -check input.go
drift: error_code_generated.md is out of date
1 file(s) out of date, run: go run gen.go -out out <input.go>
$ echo $?
1
```

`-check` 的价值不是"再生成一遍"，而是拿内存里的新结果与磁盘逐字节比对：有人手改产物（哪怕一个词），下一条命令就红。这类门禁必须做 canary（上面那条 `sed` 就是手工版）：门禁一直绿，可能只是它从没检查到东西。

**可退**：

- 门禁误伤发布：`ALLOW_GEN_DRIFT=1` 放行一轮，同时开 ticket 写进发布检查单（与 [52.2 静态检查](52.2-静态检查.md) 里 `LINT_BLOCKING=false` 同一套规矩）。
- 生成器改坏了：生成器和产物在同一个 commit，`git revert` 一次回滚两者，别只回滚产物。
- 某类产物不再生成：删 `go:generate` 行 + 从仓库删产物，两步同 PR，否则出现"无源产物"。
- 紧急手工修补产物：允许，但必须在同一 PR 里改源码再重跑生成，否则下次 `make gen` 把补丁冲掉。

## 参数怎么给

| 你的情况 | 优先做 |
|---|---|
| 常量/枚举 → 文案、码表 | 自研 100–200 行标准库生成器（本节路线） |
| 表结构 → struct | `gorm.io/gen` 或 `sqlc`；产物入库，CI 校验 diff |
| 接口 → mock | `mockgen`；`go:generate` 写在接口所在文件，产物入库 |
| 要处理复杂表达式/多包 | 上 `go/packages` + `go/types`（iam 路线） |
| 团队 < 5 人 | 只做"注释 → 文档/注册表"这一种 |
| 已有历史手写产物 | 先跑一次生成、把 diff 作为基线提交，再开门禁（ratchet 思路） |
| 生成器依赖外部二进制 | 版本进 go.mod（onex 的 `get_go_version`），不要 `@latest` |

## 反模式

| 反模式 | 后果 |
|---|---|
| 手改生成物 | 下次生成被覆盖，评审时又看不见这处改动，线上行为和代码不一致 |
| 生成器用 `@latest` 安装 | 今天和明天的产物不保证一致，无法复现、无法回滚 |
| 生成物入库但不跑 diff 门禁 | 漂移静默生效，半年后没人敢重新生成 |
| 生成物不入库、构建前也不生成 | iam 的坑：编译通过、`register` 一次没调、注册表为空 |
| 注释格式不校验就回落默认值 | 注释写错不报错，只是生成一张错的码表 |
| 用字符串拼接解析 `iota` | 表达式一改（`iota*100`）就错，且错得很隐蔽 |
| 为一次性脚本、3 个值的枚举上生成器 | 生成器维护成本超过手写，团队多一个要懂的东西 |
| 生成业务规则、架构判断 | 产出的是"错误决策的快照"，还带着自动生成的权威感 |
| 生成器与产物版本不一起升 | 生成器回滚了产物没回滚，下次生成炸出无关 diff |
| 把生成物当手写代码评审 | 评审预算被几百行样板吃掉，真正改生成器输入的 3 行没人看（见 [51.2 代码评审](../51-版本与协作/51.2-代码评审.md)） |

## 自检

**Q1** iam 的 `code_generated.go` 不在 `git ls-files` 里，`go build ./...` 却能过。这说明"不入库"安全吗？

▸ 答案：不安全，能编译 ≠ 功能完整。`register()` 只被生成物调用，生成物缺席时函数没人用、编译器不管，但 `errors.MustRegister` 一次都没执行，注册表是空的——问题是"运行时没有码"，不是编译失败。安全组合只有两种：入库 + diff 门禁，或 不入库 + 构建前必生成（iam 的 `all: tidy gen ... build`）；两者都不做，就是"看起来能跑"。

**Q2** iam 用 440 行 `go/packages` + `go/types`，本节只用 179 行标准库。哪个会算错？

▸ 答案：标准库版会在"输入写法超出假设"时出错。iam 用类型检查器求值，`iota*100`、`1<<3`、跨文件引用别的常量都能算对；本节版本只认 `iota + N` 和裸字面量，遇到别的表达式返回 0，码值就错。反过来 iam 也有风险：`ParseComment` 匹配不上时回落 500，注释写错同样不报错。结论：生成器不必通用，但必须**在输入上 fail loud**，而不是回落到"看起来合理"的默认值。

**Q3** onex 的 `WIRE_VERSION ?= $(call get_go_version,...)` 和 `GEN_TOOL_VERSION ?= v0.3.25` 有什么区别，哪个更危险？

▸ 答案：前者是**单源**版本（`go list -m` 从 go.mod 读，库升它就升），后者是**双写**（go.mod 里 `gorm.io/gen v0.3.23`，Makefile 里写 `v0.3.25`）。双写的危险不在"现在不炸"，而在于**未来某次重生成**：谁用 gentool 重跑模型，产物就和库版本对不上，而且因为产物是"生成"的，没人会怀疑它。锁版本的正解是让版本只有一个来源；做不到时才写死，并注释说明原因。

**Q4** 生成物入库和即用即生成，两个相反的做法都对：怎么判断？

▸ 答案：看两条判据。① 消费门槛：新人 clone 后不装工具、不跑生成，build + test 能不能过？不能就必须入库或把生成塞进构建入口。② 可读性：有人要在 PR 里读它吗？要读就入库。iam 的 mock 和码表满足②，入库；`code_generated.go` 只满足"编译期需要"，选了不入库 + `make gen` 前置。onex 的 131 个生成物满足①（依赖 controller-gen/protoc 版本），全部入库 + diff 门禁。标准不是"生成物脏不脏"，而是"谁消费它、在哪一步消费"。

**Q5** 注释写成 `// ErrTimeout - 418: I'm a teapot.`，iam 那条流水线到哪一步才出问题？

▸ 答案：生成期不报错（正则匹配任意 3 位数字），生成物也正常；问题出在**运行时**——`register()` 里有白名单 `gubrak.Includes([]int{200,400,401,403,404,500}, httpStatus)`，不在名单直接 `panic`，程序**启动就崩**，只跑 `go build` 不一定发现。正解是把校验前移：生成器里对 HTTP 码和注释格式做严格校验，在生成期 fail loud。

**Q6** 什么情况下不该上生成器？给一个可执行的判据。

▸ 答案：判据是 `生成频率 × 每次手工维护成本 > 生成器维护成本`。维护成本包括模板/解析逻辑、错误路径、测试、版本锁定、CI 门禁、新人学习。反例：30 行的一次性迁移脚本、3 个值的枚举（`stringer` 间接层比手写 `String()` 贵）、模型天天改（PR 里全是生成物 diff）、输出需要人的判断。反过来，**结构稳定 + 手工维护次数多 + 有明确单一真相源**的东西，才值得生成。
