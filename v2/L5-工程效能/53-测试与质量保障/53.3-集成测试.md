# 53.3 集成测试

## 一句话

> 集成测试解决 “**单元都对了，拼起来却不对**”——用真实依赖验证模块之间真的合得上。

## 为什么单元测试全绿，集成还是会挂

因为单元测试把依赖 **mock** 掉了。真实对接时，mock 的假设会撞上现实的契约：

| 单元测试里 mock 的假设 | 现实的契约 |
|---|---|
| "Save 返回 nil" | 数据库字段类型不匹配，报错 |
| "这个查询返回一行" | SQL 写错了，返回零行 |
| "Redis 肯定连着" | key 前缀对不上，读不到 |

> 🔑 **mock 验证的是 “你的假设”，集成测试验证的是 “真实的契约”。**假设对了，不代表契约对。

## 核心：集成测试必须用 “真实依赖”

如果用 mock，那就是单元测试，不是集成测试。集成测试的价值恰恰在 “真实”：

- 真实数据库 (Postgres / MySQL)
- 真实缓存 (Redis)
- 真实消息队列 (Kafka / RabbitMQ)
- 真实的外部 API (或其替身服务器)

## Go 怎么起真实依赖：testcontainers

`testcontainers-go` 用 Docker 在测试里拉起真实依赖，测完自动销毁：

```go
import (
    "context"
    "database/sql"
    "fmt"
    "testing"

    _ "github.com/jackc/pgx/v5/stdlib" // pgx 驱动
    "github.com/testcontainers/testcontainers-go"
    "github.com/testcontainers/testcontainers-go/wait"
)

func TestUserRepo_Insert(t *testing.T) {
    ctx := context.Background()

    // 1. 起一个真实的 Postgres 容器
    pg, err := testcontainers.GenericContainer(ctx,
        testcontainers.GenericContainerRequest{
            ContainerRequest: testcontainers.ContainerRequest{
                Image:        "postgres:16-alpine",
                ExposedPorts: []string{"5432/tcp"},
                Env: map[string]string{
                    "POSTGRES_PASSWORD": "test",
                    "POSTGRES_DB":       "app",
                },
                WaitingFor: wait.ForLog("database system is ready to accept connections"),
            },
            Started: true,
        })
    if err != nil {
        t.Fatal(err)
    }
    defer pg.Terminate(ctx) // 测完销毁，不留垃圾

    // 2. 拿到真实连接串
    host, _ := pg.Host(ctx)
    port, _ := pg.MappedPort(ctx, "5432")
    dsn := fmt.Sprintf("postgres://postgres:test@%s:%s/app?sslmode=disable", host, port.Port())

    db, err := sql.Open("pgx", dsn)
    if err != nil {
        t.Fatal(err)
    }
    defer db.Close()

    // 3. 建表（生产上换成 migrate 迁移脚本）
    if _, err := db.Exec(`CREATE TABLE users (id BIGSERIAL PRIMARY KEY, name TEXT)`); err != nil {
        t.Fatal(err)
    }

    // 4. 走真实的 repository，再从数据库读回来验证
    repo := NewUserRepo(db)
    if err := repo.Insert(ctx, User{Name: "张三"}); err != nil {
        t.Fatalf("Insert: %v", err)
    }

    var name string
    if err := db.QueryRow(`SELECT name FROM users WHERE id = 1`).Scan(&name); err != nil {
        t.Fatal(err)
    }
    if name != "张三" {
        t.Fatalf("got %q, want 张三", name)
    }
}
```

这测试真正验证了：**连接串对、驱动对、建表 SQL 对、Insert 的 SQL 对、字段映射对**——这五件事，单元测试的 mock 一件都验证不了。

## 测试数据管理：每个测试要干净

| 方案 | 做法 | 取舍 |
|---|---|---|
| **事务回滚** | 整个测试包在一个事务里，测完 rollback | 简单，但不适用于代码里有 `COMMIT` 的场景 |
| **独立 schema** | 每个测试用独立 schema，测完 drop | 干净，实现略复杂 |
| **容器隔离** | 每个测试起一个新容器 | 最干净，但最慢 |

## 何时写、何时不写

| ✅ 该写集成测试 | ❌ 不该写（交给单元测试） |
|---|---|
| 数据访问层（SQL、ORM 映射、迁移脚本） | 纯业务逻辑（计算、校验） |
| 缓存层（序列化、TTL、key 设计） | 分支判断、状态机 |
| 消息层（生产/消费、序列化格式） | 工具函数 |

## 自检

**Q1** 单元测试全绿，但一上环境就报 “字段类型不匹配”。这说明什么？哪个测试层该背锅？

▸ 答案：**单元测试的 mock 没验证真实契约**。这类 “SQL 对不上、类型对不上” 的问题，只有集成测试 (连真实数据库) 才能提前暴露。

**Q2** 有人在集成测试里用内存数据库 (如 SQLite) 替代 Postgres。这会有什么盲区？

▸ 答案：SQL 方言不同 (upsert、锁语义、内置函数)，“SQLite 能跑” 不代表 “Postgres 能跑”。**内存数据库是另一种 mock，不是集成测试**——它把你要验证的 “真实契约” 又替换掉了。
