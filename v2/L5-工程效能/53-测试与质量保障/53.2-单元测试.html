                53.2 单元测试

                一句话

                单元测试只测一个函数 / 方法的行为，不碰任何外部依赖，追求快、独立、可重复。

                测什么、不测什么

                ✅ 该测 ❌ 不该测
                纯逻辑（计算、校验、转换、排序） 外部依赖（数据库、HTTP、文件、时钟）
                分支与边界条件（空值、零值、极值） 框架 / 库的自身行为（别人测过了）
                错误处理路径（参数非法、状态异常） 私有实现细节（内部变量、私有函数名）

                Go 怎么写：表驱动测试

                表驱动是 Go 社区的标配——一个测试函数覆盖多组用例：

                func Add(a, b int) int { return a + b }

func TestAdd(t *testing.T) {
    tests := []struct {
        name string
        a, b int
        want int
    }{
        {"正数相加", 1, 2, 3},
        {"负数相加", -1, -2, -3},
        {"零参与", 0, 5, 5},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := Add(tt.a, tt.b); got != tt.want {
                t.Errorf("Add(%d,%d) = %d, want %d", tt.a, tt.b, got, tt.want)
            }
        })
    }
}

                两个要点：

                • t.Run 把每组用例变成子测试，跑挂了可以单独 go test -run 'TestAdd/正数相加' 复现。
                • 失败信息带上输入和期望——只写 "not equal" 的测试，等于没写。

                FIRST 五原则

                原则 含义 违反的后果
                Fast 毫秒级，一个包测完 < 1 秒 慢 → 人不跑
                Independent 测试间不共享状态、不依赖顺序 互相污染，时好时坏
                Repeatable 任何时候跑结果一样 依赖时间/随机 → flaky
                Self-validating 自己断言，不靠人肉看输出 "看打印日志"不算测试
                Timely 和功能代码一起写 事后补 = 没人补

                好测试 vs 坏测试

                好测试 坏测试
                测行为（给输入，看输出） 测实现（断言调了哪个函数）
                一个测试一个断言意图 一个测试里塞十件事
                失败信息一眼看出错在哪 失败只有一句 "not equal"

                最普遍的反模式：测了实现细节

                // ❌ 测实现：验证内部调用了 save()，断言 saveCalled == true
// 后果：你一重构（改函数名、改内部结构），测试就挂一大片，
//       即使对外行为完全没变。测试成了重构的"人质"。

                🔑 记住：改实现不该让测试挂，改行为才该。 如果每次重构都要连带改测试，说明测试和实现耦合了——这是单元测试里最普遍的坏味道。

                自检

                Q1 你重构了一个函数——行为完全不变，只改了内部实现。单元测试应该怎样？

                ▸ 答案：**全部照常通过。**如果挂了一片，说明测试耦合了实现细节 (断言了内部函数调用/内部状态)，需要重写成 “测行为”。

                Q2 一个单元测试失败信息只有 got != want，够吗？缺什么？

                ▸ 答案：不够。缺输入是什么、期望多少、实际多少。没有这三样，你每次都要先复现、再加打印才能知道错哪——测试白写了。
