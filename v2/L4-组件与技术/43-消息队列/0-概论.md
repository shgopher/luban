## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **Topic** | 一类消息的名字 | 一个微信群 |
| **分区** | 切成几条独立的队 | 银行四个窗口，各排各的 |
| **分区键** | 决定进哪条队 | 按尾号分窗口，同号总回一窗 |
| **位点** | 读到第几条 | 书签，合上书也知道读哪 |
| **ACK** | 「这条处理完了」 | 取件后点「已取件」 |
| **消费组** | 一组消费者分着读完 | 班组包干，各管一片 |
| **再均衡** | 成员一变就重分，期间停消费 | 换班时全体停手重分工 |
| **积压** | 还没被消费的条数 | 快递柜塞满，新件放不进 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「用了 MQ 就不会丢消息」 | 语义不是开关，默认可能丢也可能重；恰好一次要生产幂等、存储去重、消费端原子三段全成立（[43.2](43.2-投递语义.md)、[43.6](43.6-可靠投递与幂等消费.md)） |
| 「消费不过来就加消费者」 | 并行度上限是分区数，加分区还会打散 key（[43.3](43.3-顺序与分区.md)）；先看 C 是否高于 P（[43.5](43.5-积压与背压.md)） |
| 「消息取走就没了」 | 它是只追加日志加索引，按保留期可回放；回放多久、丢不丢由存储与复制决定（[43.9](43.9-存储与索引.md)、[43.10](43.10-复制与高可用.md)） |

## 读完自检（入门级 3 题）

**Q1** 一条消息给 5 个下游各一份，成本比只给一个差几倍？

▸ 答案：投递与存储都按订阅者数放大，量级 5 倍；只关心一部分该拆 Topic 或按 tag 过滤。

**Q2** 生产 8000 条/秒、3 个消费者各 2000 条/秒，积压会自己消掉吗？

▸ 答案：不会。消费 6000 低于生产 8000，积压线性上涨；要么把消费抬上去，要么生产端背压。

**Q3** 「处理成功但提交位点前宕机」和「先提交位点再处理」，各出什么问题？

▸ 答案：前者重投、可能重复执行；后者丢消息。所以先处理后提交，再去重。
