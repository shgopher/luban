## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **倒排索引** | “词 → 含这个词的文档清单” | 书末索引页：查到词就给页码 |
| **分词** | 把一句话切成可查的最小单位 | 把整句拆成积木，拆错就拼不回 |
| **TF-IDF** | 本篇常见、别篇少见的词才重要 | 简历写“精通 COBOL”稀有才加分 |
| **BM25** | 给 TF-IDF 加长度归一与饱和 | 作文按密度评分，不按字数 |
| **分片** | 大索引切几份放几台机器 | 电话簿太厚，拆成三册 |
| **副本** | 每个分片多存几份 | 同一册多印几本，丢一本不怕 |
| **刷新间隔** | 新文档多久能被搜到 | 新书到馆编目上架才可借 |
| **GeoHash** | 经纬度压成带前缀的字符串 | 地图打格编号，比报坐标好找 |

> 记住 **“先建表 → 再查表 → 再排队”**，架构、选型、地理检索都是它的变形。

## 一张图：这章的骨架

```
                     几百万篇文档
                          │
                          ▼
             ① 分词（45.1）把每篇切成词
                          │
                          ▼
        ② 建倒排表（45.1）：词 ──▶ [docID, 词频, 位置]
                          │
            ┌─────────────┼──────────────┐
            ▼             ▼              ▼
   ③ 分布式（45.3）  ④ 排序（45.2）  ⑤ 地理（45.5）
   分片 │ 副本 │       TF-IDF/BM25    二维 → GeoHash
   刷新间隔            │               前缀
            └─────────────┼──────────────┘
                          ▼
        用户输入“手机 维修” ── 用同一套分词切开
                          │
                          ▼
              ⑥ 查倒排表，取候选 docID 集合
                          │
                          ▼
                 ⑦ 打分排序，返回前 N 条
```

- **上半段是写**：先分词建表，代价一次付掉，查询不用扫全库；
- **下半段是读**：查询词语文档必须同一套分词，否则“明明有却搜不到”；
- **三条支路是同一张表的不同用法**：切开、排队、降维。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “全文检索就是给数据库加索引、把 LIKE 换种写法” | 倒排存的是**词 → 文档清单**，天然秒定位；排序用的词频与逆文档频率，B+ 树不提供 |
| “一个词出现越多越相关” | 逆文档频率给到处都有的词降权，BM25 再做长度归一与饱和，防长文与堆词刷分 |
| “写进去马上能搜到” | 中间隔着**刷新间隔**；越实时吞吐越低，是交换不是 bug |

## 读完自检（入门级 3 题）

**Q1** 为什么“词 → 文档清单”比“文档 → 词”更适合搜索？

▸ 答案：搜索输入是词、要的是文档。倒排直接定位候选清单；正排得逐篇翻，随全库线性变慢。

**Q2** 一个词长文出现 10 次、短文出现 5 次，谁更该靠前？

▸ 答案：不一定。次数要配逆文档频率看稀有度，长度归一会扣掉篇幅长的水分，堆词还会被饱和压住。

**Q3** “新加的商品搜不到”，先查什么？

▸ 答案：先查刷新间隔，写入到可搜之间有可见性延迟；再查分词是否把商品名切碎。
