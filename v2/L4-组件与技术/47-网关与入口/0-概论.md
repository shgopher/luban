## 5 分钟入门：先记住这 6 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **反向代理** | 代表后端接收请求的那一层 | 门卫代收快递，业主不用守门 |
| **API 网关** | 每个 API 都要的治理集中做 | 写字楼前台：登记、发卡、放行 |
| **南北向 / 东西向** | 用户进系统的流量 / 服务互调的流量 | 进小区大门 / 楼里串门 |
| **分流键** | 切流量用的字段，同键不换堆 | 按姓氏分批体检，一家人同批 |
| **信任边界** | 身份从不可信变可信的那条线 | 安检门：过了门才进隔离区 |
| **破坏性变更** | 让老调用方不改代码就坏的改动 | 偷偷换掉别人家门牌号 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "API 网关就是反向代理换个名" | 代理解决"怎么送到"；网关多担一套与业务无关、每个 API 都有的治理。判据是职责 |
| "鉴权统一在网关做掉就行" | 网关只做认证与 scope 级粗授权；"能不能退这个订单"要知道归属，服务才知道 |
| "灰度就是随机抽一批流量" | 随机不认键，同一用户会来回跳。本质是按键切两堆并保证键不跳 |

## 读完自检（入门级 3 题）

**Q1** 反向代理替后端做了什么？代价是什么？

▸ 答案：终结 TLS、路由、负载均衡、缓冲、限流；代价是**多一跳，多一个超时、缓冲与连接池的失效点**。

**Q2** 什么情况下要在反向代理之外再加一层 API 网关？

▸ 答案：当需要一套每个 API 都必有的治理：认证、配额、版本、协议转换。分界是职责。

**Q3** 用户说"版本一会儿新一会儿旧"，先查哪一节？

▸ 答案：[47.3](47.3-路由与灰度.md)。看分流键是否稳定、是否随机放量，再看粘性。
