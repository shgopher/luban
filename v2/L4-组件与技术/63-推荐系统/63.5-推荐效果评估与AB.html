                63.5 推荐效果评估与 A/B

                一句话

                离线指标（NDCG/Recall）只能筛掉明显差的模型，最终判决必须靠线上 A/B；而 A/B 的第一道门槛不是显著性，是样本量——效果提升 5% 通常需要几十万到上百万用户才能测出来。

                三层评估

                层 指标 作用 陷阱
                离线 Recall@K、NDCG@K、AUC 快速迭代、筛模型 与线上不一致（特征泄漏、分布不同）
                在线（小流量） CTR、CVR、停留、点击深度 真实效果 样本不足、多重比较
                长期 留存、复购、生态健康 是否可持续 观察周期长，短期指标可能相反

                🔑 离线上限决定“能不能试”，线上决定“要不要上”。离线涨 10%、线上不涨是常态——离线指标衡量的是“拟合历史”，线上衡量的是“改变未来”。

                代码：NDCG 与 A/B 样本量

                package main

import (
	"fmt"
	"math"
)

// NDCG@k：相关性 rel，折损 1/log2(i+1)
func ndcg(rel []float64, k int) float64 {
	dcg := 0.0
	for i := 0; i < k && i < len(rel); i++ {
		dcg += rel[i] / math.Log2(float64(i+2))
	}
	// 理想排序：降序
	ideal := append([]float64{}, rel...)
	for i := 0; i < len(ideal); i++ {
		for j := i + 1; j < len(ideal); j++ {
			if ideal[j] > ideal[i] {
				ideal[i], ideal[j] = ideal[j], ideal[i]
			}
		}
	}
	idcg := 0.0
	for i := 0; i < k && i < len(ideal); i++ {
		idcg += ideal[i] / math.Log2(float64(i+2))
	}
	if idcg == 0 {
		return 0
	}
	return dcg / idcg
}

func main() {
	fmt.Println("=== NDCG@5：两种排序的质量 ===")
	rel := []float64{3, 2, 3, 0, 1, 2}
	good := []float64{3, 3, 2, 2, 1, 0}
	bad := []float64{0, 1, 3, 2, 3, 2}
	fmt.Printf("理想排序 NDCG = %.3f（基准 1.000）\n", ndcg(good, 5))
	fmt.Printf("次优排序 NDCG = %.3f\n", ndcg(rel, 5))
	fmt.Printf("糟糕排序 NDCG = %.3f\n", ndcg(bad, 5))

	fmt.Println("\n=== A/B 样本量：CTR 从 2% 提升 5%（相对）需要多少人 ===")
	const p = 0.02
	const zAlpha = 1.96 // 95% 置信
	const zBeta = 0.84  // 80% 功效
	for _, mde := range []float64{0.01, 0.05, 0.10, 0.20} { // 相对提升
		delta := p * mde
		n := 2 * (zAlpha + zBeta) * (zAlpha + zBeta) * p * (1 - p) / (delta * delta)
		fmt.Printf("相对提升 %4.0f%%（绝对 %.4f）→ 每组约 %.0f 人\n", mde*100, delta, n)
	}

	fmt.Println("\n=== 按流量算要跑多久 ===")
	const dau = 1_000_000
	for _, mde := range []float64{0.05, 0.10} {
		delta := p * mde
		n := 2 * (zAlpha + zBeta) * (zAlpha + zBeta) * p * (1 - p) / (delta * delta)
		days := 2 * n / dau // 两组各 n 人，按全量流量
		fmt.Printf("提升 %2.0f%%：每组 %.0f 人 → 全量流量约 %.1f 天（只分 10%% 流量则 %.0f 天）\n",
			mde*100, n, days, days*10)
	}
}

                读数：

                相对提升 每组样本量 全量流量下的天数
                20% 约 1.9 万 0.04 天

                🔑 这张表解释了两件事：① “提升 1%”的实验要跑半个月，所以小公司很难测出微小改进；② 实验流量越少、指标方差越大（如 GMV、留存），需要的样本量成倍增加。先算样本量，再决定实验周期，否则会得到“不显著”的假阴性。

                A/B 的四个坑

                坑 后果 解法
                样本量不足就看结果 假阳性/假阴性 先算 power，跑够样本
                多重比较（同时看 10 个指标） 至少一个“显著” Bonferroni/ FDR 校正
                分流不均匀（用户 ID 取模偏斜） 组间基线不同 哈希分流 + AA 测试
                只看短期指标 伤害长期留存 长期指标 + 护栏指标

                从一次 A/B 到实验平台：分流、SRM、偷看

                前面的样本量公式与四个坑解决“一次实验怎么算”；但推荐团队一个月跑几十个实验时，真正的事故不在统计公式，而在实验之间互相污染、分流悄悄坏掉、每天看一次 p 值。这一小节只讲平台化，样本量公式不重复。

                五个部件

                部件 回答的问题 典型实现
                实验配置 谁、多大规模、跑多久、主指标是什么 配置中心/实验库，实验 ID + 版本
                分流 SDK 同一用户每次请求落到哪一组 hash(uid + salt) % 10000 分桶，桶号映射实验组
                分层与互斥 多个实验能不能同时跑 层（layer）正交；同层实验互斥
                指标管道 指标怎么算、口径是否一致 埋点 → 数仓 → 指标定义卡 → 看板
                判决与归档 谁有权宣布结论、结论存哪 实验报告 + 主指标 + 护栏 + 复算链接

                分流：三件事比 hash 函数更重要

                1. 分桶要稳定：hash(uid + salt) 而不是 hash(uid)；salt 一改等于把用户重新洗牌，在途实验全废。
                2. 随机化单元要与业务一致：推荐/增长的效应通常按用户随机；按请求随机会让同一用户同时看到两个版本，效应被稀释。设备/会话只在“登录态不稳定”时退而求其次。
                3. 分层与互斥：不同层（召回层、排序层、UI 层）可以正交叠加；同一层内的实验必须互斥，否则两个实验同时改排序，结论无法归因。
                随机化单元 适合 代价
                用户 推荐、增长、权益 需要稳定 uid；未登录用户要兜底
                设备 客户端/广告 换设备即换组；模拟器/多设备作弊
                会话 搜索、冷启动 同一用户体验不一致，效应被稀释

                SRM：分流坏了，后面的统计全白算

                SRM（Sample Ratio Mismatch）：实际进入各组的人数比例，与设计比例显著不符。它不告诉你效果，只告诉你实验已经不可信。检测用卡方：

                χ² = Σ (O − E)² / E，两组时 df=1；p < 0.001 就告警（阈值故意设严，避免频繁误报）。

                常见原因：分流 SDK 版本不一致、埋点只丢了某一组、机器人/爬虫进组、上线时改了 salt、实验开关没真正生效。

                # srm_peek.py —— 只用标准库：SRM 卡方 + 偷看对假阳性的影响（A/A，真实效应 0）
import math, random
from statistics import NormalDist

def chi2_sf_df1(x):
    return math.erfc(math.sqrt(x / 2.0))

def srm(a, b):
    n = a + b; e = n / 2
    chi = (a - e) ** 2 / e + (b - e) ** 2 / e
    return chi, chi2_sf_df1(chi)

for a, b in [(500000, 500000), (505000, 495000), (510000, 490000)]:
    chi, p = srm(a, b)
    print(f"{a}:{b}  chi2={chi:8.2f}  p={p:.3e}  {'告警' if p < 0.001 else 'OK'}")

def two_prop_p(x1, n1, x2, n2):
    p1, p2 = x1 / n1, x2 / n2
    p = (x1 + x2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    return 1.0 if se == 0 else 2 * (1 - NormalDist().cdf(abs((p1 - p2) / se)))

def draw(n):
    return sum(1 for _ in range(n) if random.random() < 0.10), n

random.seed(7); trials, N = 2000, 20000
fixed = sum(1 for _ in range(trials) if two_prop_p(*draw(N), *draw(N)) < 0.05)
random.seed(7); peek = 0
for _ in range(trials):
    x1 = x2 = n1 = n2 = 0
    for _ in range(10):
        a, _n = draw(N // 10); b, _n2 = draw(N // 10)
        x1 += a; x2 += b; n1 += N // 10; n2 += N // 10
        if two_prop_p(x1, n1, x2, n2) < 0.05:
            peek += 1; break
    else:
        if two_prop_p(x1, n1, x2, n2) < 0.05: peek += 1
print(f"固定样本假阳性 {fixed/trials*100:.1f}%；偷看停 {peek/trials*100:.1f}%")

A/A 实验（真实效应 0）：固定样本只看一次 假阳性 4.7%；
每 10% 偷看一次、显著就停 假阳性 19.9%（4.3 倍）

                🔑 平台的三个硬数字必须在开实验前写死：分流比例（SRM 阈值 0.001）、主指标与护栏、固定样本量。任何“先跑跑看，显著就停”的流程，都会把 5% 的假阳性抬到 20% 左右。

                实验平台与灰度发布不是一回事

                维度 A/B 实验 灰度/发布
                目的 判断“哪个更好”（可能要回滚策略） 降低发布风险，默认新版本要全量
                分流 随机、按用户/设备、可长期 按流量比例/白名单，短窗口
                结论 统计显著 + 护栏 + 业务判断 错误率/延迟达标即放量
                失败动作 关实验、回滚策略 回滚版本

                两者共用“分流 + 看板”，但判决逻辑不同：实验要“证明差异”，发布要“证明没变坏”。把实验当发布（直接全量）会丢掉对照；把发布当实验（长期只放 1%）会拖死交付。

                什么时候别自建实验平台

                实验 <20 个/季度、指标口径简单、团队没有数仓：用 SaaS 或现有数仓 + 分流 SDK 拼一个最小闭环即可。自建平台的门槛不是统计，而是指标管道与口径治理——没有指标定义卡，平台只会生产更多“没人信的显著”。

                反模式

                反模式 后果
                离线涨点就全量 线上不涨甚至跌
                实验中途偷看结果就停 假阳性率暴涨
                只报“CTR 涨了”不报护栏指标 用时长换点击，体验变差
                用同一批用户反复做实验 学习效应污染
                不分层（新老用户混在一起） 效应被稀释
                用高方差指标（GMV / 留存）做小流量实验 样本量成倍不够，结论多半是假阴性，实验白做

                自检

                Q1 为什么离线指标涨了，线上 CTR 却不涨？

                ▸ 答案：三个常见原因：① 分布不一致（离线用历史日志训练，线上是新策略产生的数据）；② 特征泄漏/线上线下特征不一致（63.3）；③ 指标错位——离线 NDCG 衡量“排序质量”，线上 CTR 还受展示样式、位置、多样性影响。离线只能证明“模型能拟合历史”，不能证明“能改变用户行为”。

                Q2 为什么“实验跑了一天就显著”通常不可信？

                ▸ 答案：因为样本量不足时，随机波动很容易产生“显著”差异（假阳性）；而且早期用户与后期用户的行为分布不同（新奇效应、时段效应）。正确做法是先算所需样本量，跑满周期（通常至少一个完整周，覆盖工作日与周末），并看护栏指标有没有恶化。

                Q3 同时看 10 个指标，为什么至少有一个“显著”是正常的？

                ▸ 答案：在 95% 置信水平下，单个指标有 5% 概率“假显著”；看 10 个独立指标，至少一个假显著的概率是 1-(0.95)^10 ≈ 40%。所以要么事先指定唯一主指标（其余为护栏/探索），要么做多重比较校正（Bonferroni 把阈值降到 0.005，或 FDR 控制）。

                Q4 同样是把 CTR 从 2% 往上提，测 5% 的相对提升和测 1% 的相对提升，实验周期差多少？小流量团队该怎么决策？

                ▸ 答案：提升 5% 每组约 30 万人，全量流量约 0.6 天，只分 10% 流量则要 6 天；提升 1% 每组约 750 万人，全量流量也要约 15 天。样本量由效果大小和指标方差决定，所以小团队很难测出微小改进；正确顺序是先算样本量、再定实验周期，否则多半得到“不显著”的假阴性。

                Q5 一次实验同时看 10 个指标：CTR 显著上涨、停留时长显著上涨、GMV 不显著。能直接宣布成功吗？还缺什么？

                ▸ 答案：不能。95% 置信下单个指标就有 5% 概率假显著，看 10 个指标至少一个假显著的概率约 40%，要先区分唯一主指标与护栏/探索指标，并对多重比较做校正（Bonferroni / FDR）。另外不能只看涨了的指标，护栏指标（如用时长换点击）和长期留存、生态健康都要一并报。
