# 63.8 推荐模型：结构谱系与上线方式

## 一句话

> 深度推荐模型的演进只有三条主线——**加宽（记忆）、加深（泛化）、加注意力（模拟兴趣）**；模型结构不只决定效果，还决定了**它能怎么上线**：结构越重、越依赖实时特征，越只能走“离线算 Embedding + 线上轻模型”。

> 来源：模型演化脉络（MLP → Embedding+MLP → Wide&Deep → DeepFM → NeuralCF → DIN/DIEN）、记忆与泛化的定义、以及四种模型服务方式来自王喆《深度学习推荐系统实战》（极客时间，2020）第 13、16、18–21 讲；成本测算脚本与选型判据为本节补充。

## 先破除四个误区

| 误区 | 现实 |
|---|---|
| “模型越深，效果越好” | 加深同时抬高拟合能力与过拟合风险；线上还多一层延迟。深度是手段，不是目标 |
| “离线 AUC 涨了，线上一定涨” | 离线样本是固定的，线上要现取特征；**换一种上线方式，模型看到的输入就变了**，离线涨点线上不涨是常态（[63.3 特征与在线服务](63.3-特征与在线服务.md) 讲的线上线下一致性） |
| “特征交叉得靠人手工构造” | DeepFM / Deep&Cross 就是把“人工交叉”变成结构自动学，这是加宽那条线的核心贡献 |
| “端到端最优雅，应该一律端到端” | 表达力与延迟都有上限：PMML 撑不起复杂深模型；端到端把“离线复杂性”和“线上效率”绑死，改一点结构就要重新评估容量 |

## 深度学习带来的是两件事

| 能力 | 怎么来的 | 解决了什么 | 代价 |
|---|---|---|---|
| **强拟合** | 把矩阵分解里的**点积**换成多层神经网络（NeuralCF） | 点积只能表达线性交互，数据模式复杂时欠拟合；MLP 理论上可拟合任意函数 | 过拟合风险上升，需要正则/dropout/早停 |
| **结构灵活** | 用结构本身模拟用户行为：注意力（DIN）、兴趣演化序列（DIEN） | 让模型“看懂”用户当下关注什么、兴趣怎么漂移 | 结构复杂 → 上线方式受限、可解释性下降 |

> 🔑 记住这句：**深度学习对推荐的价值 = 拟合能力 + 行为建模能力**，后者才是推荐系统独有的部分。

## 谱系：三条主线，一张表

| 主线 | 代表模型 | 关键结构 | 它解决什么 | 边界 |
|---|---|---|---|---|
| **基础** | Embedding + MLP（Deep Crossing） | 原始稀疏特征先过 Embedding 层变稠密，再进 MLP | 稀疏特征没法直接喂给 MLP | 特征交叉仍靠 MLP 隐式学，效率低 |
| **加宽（记忆）** | Wide&Deep | Wide 部分**输入直接连输出**（单层 + 人工交叉特征），Deep 部分是 MLP | 同时要“记住直接规则”和“泛化到没见过的组合” | Wide 的交叉特征要人工设计 |
| **加宽（自动化）** | DeepFM / Deep&Cross | 把 Wide 换成 FM 层（两两交叉）/ Cross 网络，且与 Deep **共享 Embedding** | 免手工交叉，低阶+高阶交叉一起学 | 两两交叉仍是主要形式，高阶靠堆叠 |
| **加深** | NeuralCF | 点积层替换为多层 MLP | 提升协同过滤的拟合能力 | 参数多、需要更多样本 |
| **加注意力** | DIN | 对历史行为按**与候选的相关度**加权（激活单元） | 兴趣是有指向的：买电脑时只参考电子产品历史 | 需要行为序列，serving 成本上升 |
| **注意力 + 序列** | DIEN | 在 DIN 之上用序列模型模拟**兴趣演化** | 兴趣随时间漂移，静态加权不够 | 结构更重，训练与上线都更贵 |
| **跨领域** | 与 RL / GNN 结合（美团 RL、Pinterest GNN） | 把决策或图结构引入 | 长期收益、社交/图关系 | 工程复杂度高，收益依赖场景 |

演化关系一句话：**MLP 是地基，Embedding+MLP 是标准形态；往上分叉出“加宽”和“加深”，再叠加“注意力/序列”。** 理解这张图的价值不在背模型，而在遇到新问题时知道该往哪条线上改。

## 三条主线的口径

| 概念 | 一句话 | 例子 |
|---|---|---|
| **记忆能力** | 直接学历史数据里特征/物品的**共现规则**，记住“看了 A 就买 B” | Wide 部分学到的强规则，稀疏但准 |
| **泛化能力** | 对**没出现过的特征组合**也能给出合理预估 | “35 岁男性是否喜欢电影 A”——历史里没有这个组合，Deep 部分靠相似组合推断 |
| **注意力** | 同一条历史行为，对**不同候选**的权重不同 | 买笔记本时参考电子产品历史，不参考买衣服的历史 |

只有记忆 → 长尾与新品全都推不动；只有泛化 → 热门规则记不住、效果虚高；没有注意力 → 把用户所有历史等权平均，兴趣信号被稀释。

## 上线方式：四种，和结构强绑定

| 方式 | 做法 | 优点 | 限制 | 适合的结构 |
|---|---|---|---|---|
| **① 预存推荐结果** | 离线算好每人 Top-K，写 Redis，线上直接取 | 线上零推断，延迟最低 | 用户/物品一变就要重算；存储与更新成本高 | 早期系统、冷启动、榜单类场景 |
| **② 预存 Embedding** | 离线训练 Embedding（Item2vec、Graph Embedding），线上做相似度检索 | 存储比①小，线上极快 | **只能用相似度计算**，无法引入实时特征 | 召回、相似推荐 |
| **③ 预训练 Embedding + 轻量线上模型** | 复杂深模型离线产出 Embedding，线上跑 LR/浅层 NN 做最终预估 | 隔离“离线复杂性”与“线上效率”，业界主流 | 模型被切成两段，非端到端 | 有实时特征、又要复杂模型的排序层 |
| **④ 端到端服务** | PMML（Spark/JPMML/MLeap）或 TensorFlow Serving 直接加载模型推断 | 训练部署同为端到端，最“干净” | PMML 表达力有限；深模型依赖专用框架；容量与延迟要自己扛 | 模型不太复杂、团队有推理平台 |

> 🔑 **Embedding 就是“离线复杂性”与“线上效率”之间的接口**。这解释了一个常见现象：同一套模型，换个上线方式效果就变了——因为接口的位置变了，线上能看到的信息也变了。

## 可运行：三种方式的存储与单请求计算量

拍脑袋讨论“端到端更优雅”没有意义，把量算出来。假设：100 万用户、10 万物品、64 维 Embedding（float32）、每人预存 Top100、排序模型 200→128→64→1。

```python
#!/usr/bin/env python3
"""serving_cost.py —— 三种模型上线方式的存储与单请求计算量。

参数是假设（按自己业务改）：用户 100 万、物品 10 万、Embedding 64 维（float32）、
每人预存 Top100 结果、排序模型输入 200 维 + 128/64 两层隐藏层。
"""
U, I, D = 1_000_000, 100_000, 64
K = 100                     # 每人预存的推荐结果条数
F32, I32 = 4, 4
FEAT, H1, H2 = 200, 128, 64


def mb(x):
    return x / 1024 / 1024


a = U * K * I32                              # A 预存推荐结果：每人 K 个物品 ID
b_user, b_item = U * D * F32, I * D * F32    # B 预存 Embedding：用户侧 + 物品侧
b_flops = I * D * 2                          # B 每次请求与全库内积
c_params = I * D + FEAT * H1 + H1 * H2 + H2  # C 模型参数常驻
c_flops = FEAT * H1 * 2 + H1 * H2 * 2 + H2 * 2

print(f"{'方式':<22}{'常驻存储':>12}{'单请求计算量':>16}")
print(f"{'A 预存推荐结果':<20}{mb(a):>10.0f} MB{'—':>14}")
print(f"{'B 预存 Embedding':<18}{mb(b_user + b_item):>10.0f} MB{b_flops / 1e6:>12.1f} MFLOP")
print(f"{'C 端到端推理':<22}{mb(c_params * F32):>10.1f} MB{c_flops / 1e3:>13.1f} KFLOP")
print()
print(f"B 的存储构成：用户侧 {mb(b_user):.0f} MB + 物品侧 {mb(b_item):.1f} MB")
print(f"B 每次请求与 {I:,} 个物品做 {D} 维内积：{b_flops / 1e6:.1f} MFLOP，"
      f"单核 10 GFLOPS 约 {b_flops / 1e10 * 1000:.2f} ms")
print(f"C 的模型参数 {c_params:,} 个（{mb(c_params * F32):.2f} MB），单请求只有 "
      f"{c_flops / 1e3:.1f} KFLOP：算力不是瓶颈，取特征和网络往返才是")
```

**本机实测输出**（Python 3.14.8）：

```text
方式                            常驻存储          单请求计算量
A 预存推荐结果                   381 MB             —
B 预存 Embedding           269 MB        12.8 MFLOP
C 端到端推理                     24.5 MB         67.7 KFLOP

B 的存储构成：用户侧 244 MB + 物品侧 24.4 MB
B 每次请求与 100,000 个物品做 64 维内积：12.8 MFLOP，单核 10 GFLOPS 约 1.28 ms
C 的模型参数 6,433,856 个（24.54 MB），单请求只有 67.7 KFLOP：算力不是瓶颈，取特征和网络往返才是
```

三条读法：

1. **三种方式的成本瓶颈完全不同**：A 花存储与重算，B 花存储 + 每次 1.28 ms 内积，C 几乎不花算力、花在**取特征与网络往返**（[63.3 特征与在线服务](63.3-特征与在线服务.md) 里 50 个特征的 20ms 预算）。
2. **别把“端到端算力”当瓶颈**：67.7 KFLOP 在任何 CPU 上都是微秒级。真正决定能不能端到端的是**特征能不能在延迟预算内凑齐**，以及推理框架的工程成熟度。
3. **B 的 244 MB 用户向量是可以省的**：把用户向量与物品向量都放进向量索引（[44.18 向量数据库](../44-数据库/44.18-向量数据库.md)），用 ANN 检索替代全库内积，把 1.28 ms 压到亚毫秒——代价是精度损失（召回率）。

## 选型判据

| 你的情况 | 选什么 | 理由 |
|---|---|---|
| 用户 < 10 万、物品少、日更即可 | ① 预存推荐结果 | 线上线下都简单，延迟最低 |
| 要做“相似物品/相似用户”、召回层 | ② 预存 Embedding | 只算相似度，够用且快 |
| 有实时特征、排序要复杂模型、延迟预算 20–50ms | ③ 预训练 Embedding + 轻量线上模型 | 隔离复杂性与效率，业界主流 |
| 模型不复杂、团队已有推理平台 | ④ 端到端（TF Serving / PMML） | 少一次割裂，迭代快 |
| 需要建模兴趣序列 | DIN/DIEN 类结构，但先确认 serving 扛得住 | 序列特征 + 注意力会显著抬高线上开销 |

一条补充判据：**先定延迟预算，再选结构**。反过来（先选 SOTA 模型再压延迟）通常会砍掉最有效的特征。

## 反模式

| 反模式 | 后果 |
|---|---|
| 追新模型，不看 serving 能力 | 模型离线涨 2%，线上因特征取不到而持平，白干一季 |
| 用离线 AUC 直接决定上线 | 离线样本分布与线上不同，位置偏差还会放大（[63.6 偏差与反馈回路](63.6-偏差与反馈回路.md)） |
| 所有场景一律端到端 | 简单场景付出不必要的运维复杂度；复杂模型又扛不住延迟 |
| 预存结果不设更新策略 | 新品与长尾永远推不出来，列表越来越旧 |
| 只做记忆（Wide）不做泛化 | 冷启动与稀疏组合全失效 |
| 只做注意力不看序列质量 | 行为序列缺失/稀疏时，注意力权重等于噪声 |
| 把 Embedding 维度拍大 | 存储与内积成本线性涨，收益很快饱和 |

## 自检

**Q1** Wide&Deep 的 Wide 部分“输入直接连输出”，这么简单的结构为什么不能去掉？

▸ 答案：它提供**记忆能力**：直接学历史里强共现的规则（看了 A 就买 B）。Deep 部分泛化好但对稀疏、强规则的组合不敏感；去掉 Wide，模型会对“高频确定规则”欠拟合。代价是 Wide 的交叉特征通常要人工设计——这正是 DeepFM 要解决的问题。

**Q2** DeepFM 相比 Wide&Deep 改了什么？为什么这个改动重要？

▸ 答案：把 Wide 部分换成 FM 层（自动做两两特征交叉），并与 Deep 部分共享 Embedding。重要的是它把“人工设计交叉特征”变成结构自动学——特征工程的人力从模型里挪走了，同时低阶与高阶交叉一起建模。

**Q3** NeuralCF 相对矩阵分解的改动只有一处，为什么效果能提升？

▸ 答案：把用户向量与物品向量的**点积**替换成多层神经网络。点积只能表达线性交互，数据模式复杂时欠拟合；MLP 能拟合非线性交互。代价是参数与样本需求上升，且可解释性下降。

**Q4** 为什么说“Embedding 是离线复杂性与线上效率的接口”？

▸ 答案：离线可以用任意复杂的结构（序列、注意力、图），只要最终产出 Embedding；线上只做相似度或轻量 MLP。接口位置决定了线上能用多少信息：如果接口在 Embedding，实时特征就进不来；如果推到端到端，实时特征能进，但延迟与运维复杂度全上来。

**Q5** 一个团队离线 AUC 提升 3%，线上 AB 没差异。最可能的原因是什么？

▸ 答案：三个方向排查——① 线上线下特征不一致（离线批算 vs 在线实时算，分布漂移）；② 上线方式变了导致信息损失（例如为了延迟把实时特征砍了）；③ 离线评估方式有偏（按时间随机切分 vs 真实曝光分布，位置偏差未校正）。先查特征，再查 serving，最后查评估。

**Q6** 用户 5 万、物品 2 千的垂直电商，要不要上端到端深模型？

▸ 答案：一般不必。按本节算例，预存推荐结果只有 381MB 量级（用户更少则更小），更新成本可控；数据量也撑不起复杂深模型。更划算的是把特征与规则做扎实，等用户与物品规模上来了再考虑模型升级。

**Q7** 为什么“先选模型再压延迟”是反模式？

▸ 答案：延迟预算决定了特征的丰富度与模型的复杂度。先选 SOTA 模型，压缩延迟时最先被砍的就是特征（最贵也最有效），最后得到一个结构先进、输入贫瘠的模型，效果不如简单模型 + 丰富特征。正确顺序是：定延迟 → 定特征预算 → 选结构。

**Q8** DIN 的注意力权重，在什么情况下会变成噪声？

▸ 答案：行为序列太短（1–2 条历史，加权没有意义）、行为序列与候选完全无关（新类目）、或行为数据本身是脏的（误点、爬虫）。这些场景下注意力学到的权重接近随机，收益不如老老实实用统计特征。
