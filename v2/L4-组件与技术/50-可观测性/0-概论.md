## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **日志** | 一条带时间戳的字段事件 | 收银小票，一笔一张 |
| **链路（Trace）** | 一次请求跨所有服务走出的调用树 | 快递物流详情 |
| **Span** | 调用树上一个节点，一跳 | 物流里的一个中转站 |
| **trace_id** | 串起同次请求所有记录的编号 | 快递单号 |
| **指标** | 写入前就聚合好的数值序列 | 体重秤：只记数字，不记你吃了啥 |
| **基数** | 指标里标签组合的条数，就是账单 | 通讯录人数，加个维度就翻倍 |
| **SLO / 错误预算** | 给可靠性定目标，换成失败额度 | 流量套餐：剩多少决定还能不能刷 |

> 只记一句：**指标答「多少」，链路答「哪一跳」，日志答「为什么」**。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「可观测性 = 大屏 + 日志平台」 | 指标无个体、链路丢细节、日志无预聚合；买齐系统只是买齐原料（[50.1](50.1-三支柱与成本模型.md)） |
| 「日志越多越好，总能翻到」 | 统计要扫原文，日志算 QPS 比指标贵几百倍（[50.2](50.2-日志.md)） |
| 「链路一采样就废了」 | 丢的是覆盖了哪些请求，不是被采中那条的细节（[50.3](50.3-链路.md)） |

## 读完自检（入门级 3 题）

**Q1** 用户说「下单偶尔很慢」，先看哪个？

▸ 答案：先看**指标**定有没有事、多严重、从几点起；再用**链路**找哪一跳；最后用**日志**看为什么。先翻日志要拉几百 MB 原文，最贵。

**Q2** 同一次请求，指标、链路、日志各留下什么？

▸ 答案：指标多一个计数样本，**没有「这一次」**；链路留下 span 树，能下钻到每一跳；日志是几条带 `trace_id` 的文本，靠它与统一资源属性缝合。

**Q3** 老板问「还能不能继续发版」，用什么回答？

▸ 答案：看 SLO 的**错误预算**还剩多少。还有，继续发版；烧完，冻结变更修可靠性。
