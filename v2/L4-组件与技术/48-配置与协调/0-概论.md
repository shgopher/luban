## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **配置中心** | 改一处参数，全实例分批生效、能回退 | 贴错的通知撕掉，换回上一版 |
| **服务发现** | 一个服务名，此刻哪些实例活着、地址 | 内部换人，总机号不变 |
| **分布式锁** | 同时只让一个客户端进临界区 | 会议室只有一把钥匙 |
| **租约** | 锁有保质期，不续就作废 | 合同到期不续，房东可换人 |
| **fencing token** | 每次拿锁发递增号，存储拒收旧号 | 银行叫过 37 号，不再办 36 号 |
| **任期** | 每次选主任期加一，旧指令不认 | 换届文件带届次，上一届不作数 |
| **Watch** | 变了才通知，不用一直问 | 快递到了发消息，不用每分钟问 |
| **爆炸半径** | 坏配置能影响多少机器、多久 | 试爆先扔空地，别直接扔仓库 |

- 四个用法共用一套底座，难点不在「存」，在**变更怎么传播**；
- **版本号**管退回上一版，**fencing** 管旧持有者还能不能写。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「配置中心就是存配置的」 | 存最不值钱；没有灰度与版本，坏配置就是全量生效、逐个实例改回 |
| 「拿到锁就安全」 | 只管住加锁那一刻；GC 停顿、分区、切主会造双持有者，落点在租约 + fencing |
| 「选主只在选举时有风险」 | 最难是旧主恢复后仍以为自己是主，任期、租约、fencing 缺一就有两个主 |

## 读完自检（入门级 3 题）

**Q1** 配置中心能存配置了，为什么还要版本号？

▸ 答案：配置一定会改错，改错后要快的是**退回去**：有版本号一键切回上一版，没有只能逐个实例找原值。

**Q2** 为什么「加锁成功」不等于「一直独占」？

▸ 答案：持锁进程可能被 GC 停顿或分区卡住，租约到期它不知道；切主后新主也会发出同一把锁。所以要租约让锁自动失效，再加 fencing token 让存储端拒收旧持有者的写——保护点在存储端。

**Q3** 四个产品都能 KV + watch + 租约，选型比什么？

▸ 答案：比一致性语义、数据模型、多数据中心与生态，落到**故障模型与运维能力是否匹配**。
