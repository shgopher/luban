                            74.2 定向与人群

                            一句话

                            定向不是「给用户打标签」，而是在可识别的 ID 上做集合运算，再用匹配率把人群折算成可投放量；隐私合规不是外挂，它决定「哪些集合根本不能建、建了能存多久」。

                            先破除三个误区

                            误区 现实
                            标签越多越准 标签有覆盖率与时效：长尾标签覆盖不足 1%、模型标签几周就漂移；叠加 10 个条件，交集往往为空
                            人群包越大越好 大包精度低、频控压力大；定向真正的杠杆在「排除」和「分层」，不在无限扩量
                            上传 ID 包就能投 还要过媒体侧匹配率（15%–70% 不等）和合规（单独同意、去标识化、委托处理协议）

                            标签体系：三类标签，三种寿命

                            类型 例子 更新频率 覆盖率量级 稳定性 主要风险
                            事实标签 注册地、机型、系统版本、已安装 App 实时 / 日更 80%–99% 高 字段本身可能是敏感信息
                            统计标签 近 30 天购买次数、客单价、活跃天数 日更 10%–40% 中 窗口口径不一致，跨部门打架
                            模型标签 母婴概率、流失概率、价格敏感度 周更 5%–30% 低（会漂移） 训练数据偏差、效果衰减

                            🔑 定向效果衰减的根因通常不是「标签不够多」，而是模型标签半年没重训：人群概率分布漂移后，旧标签圈出来的仍是「半年前像目标用户的人」。

                            人群包：四种来源，四种精度

                            类型 怎么来 典型规模 精度 主要风险
                            规则圈选 标签 + 行为条件组合（近 7 天点击过母婴内容） 万级到百万级 中 条件叠加过深，交集为空
                            上传 ID 包 广告主上传手机号 / OAID / IDFA 的哈希值 万级到千万级 高（是已知客户） 无同意凭证、明文上传、过期名单
                            lookalike 以种子人群为样本，找特征相似的人扩量 种子 5–100 倍 随倍数下降 扩太狠≈通投
                            排除包 已购买、已退款、黑名单、竞品客户 万级 极高 漏掉「已退款」导致重复营销与投诉

                            集合运算：一次圈选的真实账

                            可投放人群的公式只有一行：

                            可投放 = (标签包 ∪ 上传包) − 排除包        // 集合
可触达 = 可投放 × 媒体匹配率               // 折算

                            本机仿真（Go，100 万设备，tools/examples/74-ad-models/raw-74.2.txt）里，各包规模与运算结果： 示例说明见 tools/examples/74-ad-models/。

                            步骤 集合 人数 占 universe
                            ① 兴趣标签（母婴） 标签包 120,044 12.0%
                            ② 广告主上传 ID 上传包 80,061 8.0%
                            ③ 两者交集 标签 ∩ 上传 9,622 0.96%
                            ④ 两者并集 标签 ∪ 上传 190,483 19.0%
                            ⑤ 排除已购买 上传包 × 25% 20,099 2.0%
                            ⑥ 可投放人群 ④ − ⑤ 170,384 17.0%

                            读这张表要抓两点：

                            • 交集只有 9,622：标签包和上传包高度不重合——上传的是「已知客户」，标签圈的是「兴趣人群」，两者天然不是一类人。想靠「标签 ∩ 上传」做精准投放，量级会小到跑不动。
                            • 排除包吃掉 2 个百分点：排除包是 ROI 最高的人群包——它不带来新客，但能避免「已购用户再被投一遍」的预算浪费和骚扰投诉。

                            lookalike：扩量倍数的代价

                            lookalike 的原理是「种子 → 特征 → 相似度排序 → 取 Top N」。扩量倍数越高，精度越低，有效真目标人数先升后降：

                            扩量倍数 覆盖人数 精度（仿真假设） 有效真目标 解读
                            1 倍（仅种子） 9,622 0.45 4,329 太窄，跑不出量
                            3 倍 28,866 0.28 8,082 精度尚可，量仍小
                            10 倍 96,220 0.16 15,395 有效真目标峰值附近
                            30 倍 170,384 0.09 15,334 覆盖到顶，精度掉一半
                            100 倍 170,384 0.05 8,519 已被可投放人群封顶，等于通投

                            🔑 扩量不是越大越好：从 10 倍到 30 倍，覆盖涨 77%，但精度从 0.16 掉到 0.09，有效真目标基本没变；再到 100 倍，有效真目标反而腰斩。扩量倍数的最优区间在「有效真目标人数」的峰值附近，而不是覆盖人数最大处。

                            匹配率：人群规模 ≠ 可投规模

                            人群包要在媒体侧「落地」，必须能匹配到媒体可识别的 ID。匹配不上，人数就是纸面数字：

                            ID 类型 匹配率量级 原因 170,384 人对应的可投规模
                            手机号哈希 40%–60% 媒体侧手机号覆盖不全、换号 93,711（55%）
                            OAID / Android 60%–80% Android 设备标识相对稳定 119,268（70%）
                            IDFA / iOS（ATT 后） 10%–20% 用户拒绝跟踪后拿不到 IDFA 25,557（15%）
                            设备号 + IP + UA 兜底 20%–40% 精度低但覆盖广 59,634（35%）

                            （各平台匹配率与 ID 口径以官方文档为准。）

                            🔑 同一个 17 万人的包，在 Android 上能投 11.9 万，在 iOS 上只能投 2.6 万——跨端投放的预算必须按「可投规模」分，而不是按「人群规模」分，否则 iOS 侧永远花不完预算。

                            隐私与合规：三条硬线

                            定向与人群是广告系统里离个人信息最近的一环，合规要求可以直接翻译成产品约束（依据见 3.2 个人信息保护与 GDPR）：

                            要求 对定向的具体约束 落地动作
                            合法性基础 个性化广告与画像需要「同意」或「合同必需」，不能默认开启 同意管理平台；拒绝后降级为上下文定向（按页面内容投，不用历史行为）
                            最小必要 与广告无关的字段不收集、不入人群 字段清单评审；敏感个人信息（医疗、金融账户、行踪）禁止做广告标签
                            可追溯 / 可撤回 用户能查、能关、能删 人群包记录来源与有效期；删除请求联动人群包下线
                            去标识化 上传 ID 必须哈希加盐，禁止明文手机号 SHA-256 + 每广告主独立盐；禁止回传可逆映射
                            委托处理 把人群包交给媒体投放属于委托处理 签数据处理协议（DPA），限定用途与留存期

                            🔑 合规不是「加密存储」四个字：真正会被审计问到的是三件事——这个字段的合法性基础是什么、同意记录在哪、用户撤回后多久生效。答不上来，加密也没用。

                            隐私增强技术常在两条路上选：去标识化 + 聚合（哈希、k-匿名、加噪）成本低但精度损失；隐私计算（联邦学习、多方安全计算）精度保留好但工程复杂。判断标准是：定向只需要「群体统计」时优先聚合；必须「个体级匹配」时才上隐私计算。

                            人群包生命周期：从创建到下线的五个状态

                            状态 触发 系统动作 过期策略
                            创建 运营圈选 / 上传 生成包 ID、记录来源与同意凭证 有效期默认 30 天
                            生效 审核通过 推送到投放引擎，参与集合运算 —
                            衰减 超过 15 天 命中率下降告警，提示重算 —
                            过期 到达有效期 自动退出投放，禁止新计划引用 强制
                            下线 用户撤回 / 审计要求 从投放与数仓同步删除，留删除审计日志 立即

                            名单类人群（黑名单、已购、已退款）还要与风控名单联动——见 68.1 风控系统架构：营销侧的「已退款」名单如果和风控侧的「黑名单」各存一份，两边更新不同步，就会出现「刚被风控拉黑的人又收到营销短信」。

                            代码：集合运算、lookalike 与匹配率

                            package main

import "fmt"

// 确定性伪随机：固定种子，保证每次运行输出一致
func lcg(seed uint64) func() float64 {
	x := seed
	return func() float64 {
		x = x*6364136223846793005 + 1442695040888963407
		return float64(x>>11) / float64(1<<53)
	}
}

func count(b []bool) int {
	n := 0
	for _, v := range b {
		if v {
			n++
		}
	}
	return n
}

func main() {
	const universe = 1_000_000
	r := lcg(20261122)
	tag := make([]bool, universe)    // 兴趣标签：母婴
	upload := make([]bool, universe) // 广告主上传的 ID 包
	for i := 0; i < universe; i++ {
		if r() < 0.12 {
			tag[i] = true
		}
		if r() < 0.08 {
			upload[i] = true
		}
	}
	exclude := make([]bool, universe) // 排除包：30 天内已购买
	for i := 0; i < universe; i++ {
		if upload[i] && r() < 0.25 {
			exclude[i] = true
		}
	}

	tagN, uploadN := count(tag), count(upload)
	interN := 0
	for i := 0; i < universe; i++ {
		if tag[i] && upload[i] {
			interN++
		}
	}
	union := make([]bool, universe)
	exN := 0
	for i := 0; i < universe; i++ {
		union[i] = tag[i] || upload[i]
		if union[i] && exclude[i] {
			exN++
		}
	}
	unionN := count(union)

	fmt.Println("=== 74.2 人群集合运算（本机仿真，universe = 100 万设备）===")
	fmt.Printf("兴趣标签包 %7d\n", tagN)
	fmt.Printf("上传 ID 包 %7d\n", uploadN)
	fmt.Printf("交集（标签 ∩ 上传） %7d\n", interN)
	fmt.Printf("并集（标签 ∪ 上传） %7d\n", unionN)
	fmt.Printf("排除包（上传包中已购买） %7d\n", exN)
	fmt.Printf("可投放人群（并集 − 排除） %7d（占 universe %.1f%%）\n",
		unionN-exN, float64(unionN-exN)/universe*100)

	fmt.Println("\n=== lookalike 扩量：扩得越狠，精度越低（精度为仿真假设值）===")
	type step struct {
		mult      int
		precision float64
	}
	for _, s := range []step{{1, 0.45}, {3, 0.28}, {10, 0.16}, {30, 0.09}, {100, 0.05}} {
		reach := interN * s.mult
		if reach > unionN-exN {
			reach = unionN - exN // 扩量不能超过可投放人群
		}
		fmt.Printf("%3d 倍扩量 → 覆盖 %8d 人，精度 %.2f（可触达真目标 %8d 人）\n",
			s.mult, reach, s.precision, int(float64(reach)*s.precision))
	}

	fmt.Println("\n=== 匹配率：人群包能不能在媒体侧落地（以官方文档为准）===")
	for _, m := range []struct {
		id   string
		rate float64
	}{
		{"手机号哈希", 0.55},
		{"OAID / Android", 0.70},
		{"IDFA / iOS（ATT 后）", 0.15},
		{"设备号 + IP 兜底", 0.35},
	} {
		fmt.Printf("%-22s 匹配率 %.0f%% → 最终可投 %7d 人\n",
			m.id, m.rate*100, int(float64(unionN-exN)*m.rate))
	}
}

                            反模式

                            反模式 后果
                            原始手机号明文上传做定向 违反个人信息保护要求，且一次泄露就是重大事故
                            人群包永不过期 已购、已退款用户被反复投放，ROI 虚高、投诉上升
                            只看人群规模不看匹配率 号称 100 万，iOS 侧实际只能投 2.5 万，预算花不完
                            排除包漏掉「已退款 / 投诉中」 营销骚扰升级为监管投诉
                            lookalike 直接扩到 100 倍 精度跌破 5%，成本等同通投，还多付了扩量费
                            定向条件叠加 10 个 交集为空，计划跑不出量，团队误判为「媒体没量」
                            不记录人群包来源与同意凭证 审计时无法举证合法性基础，整包下线
                            营销名单与风控名单各存一份 刚拉黑的人又收到营销触达，两边都挨骂

                            自检

                            Q1 为什么「标签越多越准」是错的？

                            ▸ 答案：标签不是独立的正向证据。条件叠加会让交集按乘法收缩，10 个覆盖率 30% 的标签交集可能只剩 0.003%；同时模型标签会漂移、事实标签可能过期。定向的准确率取决于「标签与目标的相关性 + 时效」，不是数量。

                            Q2 号称 100 万人群，实际只投出 15 万，最可能的原因是什么？

                            ▸ 答案：先查两步：① 排除包是否吃掉大量人群（已购、已退款）；② 媒体侧匹配率是否低（iOS ATT 后 IDFA 匹配率只有 10%–20%，以官方文档为准）。可投规模 =（并集 − 排除）× 匹配率，任何一项缩水都会让纸面人数落不了地。

                            Q3 lookalike 从 10 倍扩到 100 倍，为什么有效真目标反而下降？

                            ▸ 答案：扩量按相似度从高到低取人，倍数越高，后加入的人越不像种子。10 倍时精度 0.16、覆盖 9.6 万，有效真目标约 1.54 万；100 倍时覆盖被封顶在 17 万，精度掉到 0.05，有效真目标只有 0.85 万。扩量的正确判据是「有效真目标人数」的峰值，不是覆盖人数。

                            Q4 为什么说排除包是 ROI 最高的人群包？

                            ▸ 答案：排除包不带来新客，但它拦掉的是「已经买过 / 已退款 / 已投诉」的人——对这些人的曝光几乎不产生增量，还会消耗频控额度和预算。排除包的成本极低、收益是「省下来的无效曝光」，所以投入产出比最高。

                            Q5 用户拒绝个性化广告后，定向还能怎么做？

                            ▸ 答案：退化为上下文定向：按当前页面/内容/时段匹配广告，不使用用户历史行为与画像；同时停止把该用户加入个性化人群包。这样既不违反同意要求，也能保留一部分投放能力——代价是 eCPM 通常低于个性化定向。

                            Q6 把 ID 哈希后上传，就算合规了吗？

                            ▸ 答案：不算。哈希只是去标识化的一步，还要有合法性基础（同意或合同必需）、最小必要（只传必要字段）、加盐防撞库、委托处理协议、留存期与删除机制。审计看的是「同意记录 + 字段清单 + 删除链路」，不是「有没有哈希」。
