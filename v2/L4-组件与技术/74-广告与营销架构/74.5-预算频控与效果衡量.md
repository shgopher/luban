# 74.5 预算频控与效果衡量

## 一句话

> 预算决定**能花多少**，频控决定**花给谁几次**，效果衡量决定**这笔钱该不该继续花**；三者共用一条闭环——按边际 ROI 分配预算 → 执行频控 → 用增量实验验证 → 按结果重新分配。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 预算花完就说明效果好 | 花完只证明「买到了量」，不证明有用；无效曝光、重复触达也能把预算花光 |
| 频控越松量越大越好 | 频次越高，边际 CTR 越低；放宽频控买到的多是「已经看过的人」 |
| ROAS 高就该加预算 | 归因 ROAS 不是增量 ROI；加预算后边际 ROI 递减，平均 ROAS 会往下走 |

## 预算分配：两层约束，四种方法

预算分配有两层：**平台/媒体层**（总预算怎么切给各渠道）与**账户层**（计划之间怎么分）。两层都受同一个约束——花超了是亏损，花不完是浪费。

| 方法 | 依据 | 优点 | 缺点 | 适合 |
|---|---|---|---|---|
| 按历史 ROI 比例 | 过去 30 天各渠道 ROI | 简单、可解释 | 奖励「已经饱和」的渠道 | 冷启动、预算小 |
| 按边际 ROI 均等 | 每多花 1 元带来的增量收益 | 理论上总收益最大 | 需要增量数据、计算复杂 | 成熟账户、预算大 |
| 按目标 CPA 反推 | 目标 CPA × 目标转化数 | 与考核口径一致 | 目标定错就全错 | 效果考核驱动 |
| 实验驱动 | holdout / geo 实验的增量 | 因果可信 | 周期长、有测试成本 | 大预算、新渠道 |

边际 ROI 的逻辑一句话：**当各渠道「最后一块钱」的回报相等时，总回报最大**。所以「A 渠道 ROAS 5、B 渠道 ROAS 2」不意味着钱都该给 A——如果 A 已经饱和（再加预算边际 ROI 掉到 1.5），而 B 的边际 ROI 还有 3，就该加 B。

> 🔑 预算分配看的是边际，不是平均：平均 ROAS 是历史成绩，边际 ROI 才是下一块钱的回报。用平均 ROAS 做分配，必然把预算推向已经饱和的渠道。

## 频控：上限、衰减与边际成本

频控的维度有四种，粒度越细越贵：

| 维度 | 口径 | 实现成本 | 典型用途 |
|---|---|---|---|
| 用户 | 同一用户 7 天内最多看 N 次 | 中（要有稳定 ID） | 品牌广告、防疲劳 |
| 设备 | 同一设备每天最多 N 次 | 低 | 未登录流量兜底 |
| 创意 | 同一素材对同一用户最多 N 次 | 低 | 防素材疲劳、轮播 |
| 跨媒体 | 跨多个 App/媒体合并计数 | 高（要 ID 打通） | 集团级预算管控 |

频控的经济学是**边际收益递减**：同一用户第 1 次曝光的 CTR 3.0%，第 2 次 1.5%，第 3 次 0.8%……本机仿真（Go，100 万用户、7 天、预算 2 万元、CPM 10 元，`.cache/domain-74/raw-74.5.txt`）：

| 频次上限 | 曝光 | 独立触达 | 点击 | 转化 | 花费 | CPA |
|---|---|---|---|---|---|---|
| 1 次 | 825,839 | 825,839 | 24,780 | 2,043 | 8,258 元 | 4.04 元 |
| 2 次 | 1,428,389 | 825,267 | 33,986 | 2,672 | 14,284 元 | 5.35 元 |
| 3 次 | 1,745,910 | 825,467 | 36,599 | 2,892 | 17,459 元 | 6.04 元 |
| 不限 | 1,887,454 | 825,672 | 36,998 | 2,943 | 18,875 元 | 6.41 元 |

注意「独立触达」四行几乎一样（82.5 万左右）：频控放宽只增加**曝光次数**，不增加**触达人数**——多出来的预算买的是同一批人的重复曝光。

把每一档的增量单独算出来，边际成本一目了然：

| 放宽区间 | 增量曝光 | 增量点击 | 增量转化 | 增量花费 | 边际 CPA |
|---|---|---|---|---|---|
| 1 次 → 2 次 | +602,550 | +9,206 | +629 | +6,026 元 | 9.58 元 |
| 2 次 → 3 次 | +317,521 | +2,613 | +220 | +3,175 元 | 14.43 元 |
| 3 次 → 不限 | +141,544 | +399 | +51 | +1,416 元 | 27.76 元 |

> 🔑 频控上限应该定在「边际 CPA ≤ 目标 CPA」的位置。本机仿真里目标 CPA 10 元 → 上限 2 次（9.58 元）；放宽到 3 次，边际 CPA 14.43 元，已经超过目标——**继续放宽是在亏钱买重复曝光**。

## 效果衡量：ROI、增量与边际 CPA

| 指标 | 公式 | 回答什么 | 陷阱 |
|---|---|---|---|
| ROI / ROAS | 归因收入 ÷ 花费 | 这笔钱在账面上赚不赚 | 归因把自然转化算进来，虚高 |
| 增量转化 | 实验组转化 − 对照组转化 | 广告真正多带来的转化 | 需要随机对照、样本量足够 |
| 增量 ROAS | 增量收入 ÷ 花费 | 每一块钱的真实回报 | 高方差，需要更长周期 |
| 边际 CPA | 增量花费 ÷ 增量转化 | 下一块钱买一个转化要多少 | 依赖分档实验或曲线拟合 |

效果衡量有三条路，成本与可信度依次上升：

| 方式 | 做法 | 适合 | 代价 |
|---|---|---|---|
| 归因报表 | 按 last-click / linear 等模型分钱 | 日常复盘、结算 | 不回答因果，易被模型带偏 |
| **holdout 实验** | 随机 5%–10% 用户不投广告，比较两组 | 线上效果、可重复 | 少赚一部分预算，需要样本量 |
| geo 实验 | 选若干城市停投或加投，比较区域差异 | 无法按用户随机的渠道（如户外、电视） | 城市间差异大，周期长 |
| PSA / 公益广告对照 | 对照组看公益广告而非无广告 | 品牌广告 | 执行成本高 |

holdout 的样本量要按 [63.5 推荐效果评估与 AB](../63-推荐系统/63.5-推荐效果评估与AB.md) 的方法先算：CTR 从 2% 提升 5%（相对）每组约需 30 万人，转化率类指标方差更大、需求更高。本机仿真的设计是 100 万用户、10% 对照（10 万）、90% 实验（90 万），能测出 0.2 个百分点左右的提升：

| 频次上限 | 增量提升 | 每 10 万人增量转化 | 95% 区间下限 | 结论 |
|---|---|---|---|---|
| 1 次 | 0.199pp | 199 | 152 | 显著为正 |
| 2 次 | 0.269pp | 269 | 222 | 显著为正 |
| 3 次 | 0.293pp | 293 | 246 | 显著为正 |
| 不限 | 0.299pp | 299 | 252 | 显著为正 |

> 🔑 归因和增量的分工：**归因回答「钱花在哪」，增量回答「钱有没有用」**。渠道结算用归因（可复算、可对账），预算分配用增量（因果、抗归因偏差）。两者混用，就会出现「ROAS 很好看、加预算却不涨」的经典事故。

## 预算平滑与频控会互相打架

| 场景 | 现象 | 处理 |
|---|---|---|
| 频控收紧 | 可投库存下降，预算花不完 | 提高出价抢量，或放宽定向，而不是取消频控 |
| 预算提前花完 | 频控没跑满、下午断量 | 分时降出价，把预算留到高转化时段 |
| 追加预算 | 先撞频控上限，触达不增 | 加预算前先看「触达人数是否已到顶」 |
| 跨媒体频控 | 单媒体都合规、合并超频 | 建统一频控服务，或按媒体预算上限间接约束 |

本机计算（2 万元预算、CPM 10 元、当天总供给 300 万次曝光）：

| 策略 | 6 小时花费 | 12 小时花费 | 花费完成时点 |
|---|---|---|---|
| 尽快 | 4,792 元 | 12,364 元 | 第 19 小时 |
| 按流量比例 | 3,195 元 | 8,243 元 | 第 24 小时 |

## 代码：频控、增量实验与预算平滑

```go
package main

import (
	"fmt"
	"math"
)

func lcg(seed uint64) func() float64 {
	x := seed
	return func() float64 {
		x = x*6364136223846793005 + 1442695040888963407
		return float64(x>>11) / float64(1<<53)
	}
}

func main() {
	const users = 1_000_000
	const days = 7
	const cpm = 10.0
	const budget = 20000.0
	const targetProb = 0.30
	const baseConv = 0.005 // 自然转化率（对照组基线）
	ctr := []float64{0.030, 0.015, 0.008, 0.004, 0.002, 0.001, 0.0005}
	const adCVR = 0.08

	type result struct {
		name                string
		imp, reach          int
		clicks, conv        int
		spend               float64
		ctrPct, cpa         float64
		incConv, incPer100k float64
	}
	fmt.Println("=== 74.5 频控 1/2/3/不限：7 天、100 万用户、预算 2 万元、CPM 10 元 ===")
	fmt.Printf("%-6s %10s %10s %8s %8s %10s %8s\n", "上限", "曝光", "独立触达", "点击", "转化", "花费", "CPA")
	var res []result
	for _, capK := range []int{1, 2, 3, 0} {
		r := lcg(7405)
		expo := make([]int, users)
		ctrl := make([]bool, users)
		for u := 0; u < users; u++ {
			ctrl[u] = u%10 == 0 // 10% 用户作为对照，不投广告
		}
		var imp, reach, clicks, conv int
		spend := 0.0
		for d := 0; d < days; d++ {
			for u := 0; u < users; u++ {
				if ctrl[u] || r() >= targetProb {
					continue
				}
				limit := capK
				if capK == 0 {
					limit = days
				}
				if expo[u] >= limit {
					continue
				}
				if spend+0.01 > budget+1e-9 {
					continue // 预算耗尽，停止投放
				}
				expo[u]++
				imp++
				if expo[u] == 1 {
					reach++
				}
				spend += cpm / 1000
				j := expo[u] - 1
				if j >= len(ctr) {
					j = len(ctr) - 1
				}
				if r() < ctr[j] {
					clicks++
					if r() < adCVR {
						conv++
					}
				}
			}
		}

		// 自然转化：对照组与实验组同分布，差值即广告带来的增量
		r2 := lcg(99)
		ctrlN, ctrlConv := 0, 0.0
		treatN, treatOrganic := 0, 0.0
		for u := 0; u < users; u++ {
			if ctrl[u] {
				ctrlN++
				if r2() < baseConv {
					ctrlConv++
				}
			} else {
				treatN++
				if r2() < baseConv {
					treatOrganic++
				}
			}
		}
		treatConv := treatOrganic + float64(conv)
		incConv := treatConv/float64(treatN) - ctrlConv/float64(ctrlN)
		name := fmt.Sprintf("%d", capK)
		if capK == 0 {
			name = "不限"
		}
		cpa := spend / float64(conv)
		res = append(res, result{name, imp, reach, clicks, conv, spend,
			float64(clicks) / float64(imp) * 100, cpa, incConv, incConv * 100000})
		fmt.Printf("%-6s %10d %10d %8d %8d %10.0f %8.2f\n", name, imp, reach, clicks, conv, spend, cpa)
	}

	fmt.Println("\n=== 增量实验：10% 对照，测出广告带来的真实转化提升 ===")
	fmt.Printf("%-6s %10s %10s %10s %14s\n", "上限", "提升(pp)", "每 10 万人增量", "95% 区间下限", "结论")
	for i, rr := range res {
		capK := []int{1, 2, 3, 0}[i]
		_ = capK
		// 两组比例差的标准误：p1=实验组，p2=对照组
		p1 := (rr.incConv + 0.005)
		p2 := 0.005
		se := math.Sqrt(p1*(1-p1)/900000 + p2*(1-p2)/100000)
		lo := (rr.incConv - 1.96*se) * 100000
		verdict := "显著为正"
		if lo <= 0 {
			verdict = "不显著"
		}
		fmt.Printf("%-6s %9.3f %12.0f %14.0f %10s\n", rr.name, rr.incConv*100, rr.incPer100k, lo, verdict)
	}

	fmt.Println("\n=== 预算平滑：2 万元预算、CPM 10 元（当天总供给 300 万次曝光）===")
	weights := []float64{0.2, 0.2, 0.6, 1.0, 1.4, 1.6, 1.5, 1.4, 1.3, 1.2, 1.2, 1.3, 1.4, 1.3, 1.2, 1.2, 1.3, 1.5, 1.8, 2.0, 2.2, 2.0, 1.5, 1.0}
	sum := 0.0
	for _, w := range weights {
		sum += w
	}
	for _, mode := range []string{"尽快", "按流量比例"} {
		remaining, cum := budget, make([]float64, len(weights))
		exhaust := 0
		for h, w := range weights {
			supplyCost := w / sum * 3_000_000 / 1000 * cpm
			allow := remaining
			if mode == "按流量比例" {
				allow = budget * (w / sum) // 按小时流量占比分配预算
			}
			spend := math.Min(supplyCost, math.Min(allow, remaining))
			remaining -= spend
			cum[h] = budget - remaining
			if remaining <= 0.01 && exhaust == 0 {
				exhaust = h + 1
			}
		}
		fmt.Printf("%s：第 %2d 小时花完；6h 花 %5.0f 元，12h 花 %5.0f 元，24h 花 %5.0f 元\n",
			mode, exhaust, cum[5], cum[11], cum[23])
	}
}
```

## 反模式

| 反模式 | 后果 |
|---|---|
| 按归因 ROAS 直接砍渠道 | 砍掉上游触点，总转化下降，ROAS 反而更难看 |
| 频控只看人均次数、不算边际 CPA | 越放宽越贵，预算买重复曝光 |
| 预算花不完就盲目提价 | CPA 飙升，花完但亏 |
| 加预算前不做增量验证 | 把自然转化当增量，预算持续错配 |
| 跨媒体频控不打通 | 同一用户在各媒体各看 3 次，总频次爆表 |
| holdout 比例太小（如 1%） | 样本不足，测不出增量，实验白做 |
| 用短期 ROI 决定长期预算 | 品牌预算被砍光，拉新断档 |
| 预算、频控、出价三个参数同时大改 | 无法归因，不知道是哪个变量起了作用 |

## 自检

**Q1** 频控从 2 次放宽到 3 次，CPA 从 5.35 元涨到 6.04 元，为什么？

▸ 答案：边际收益递减。第 3 次曝光面对的是同一批用户，边际 CTR 只有 0.8%（第 1 次 3.0%），点击和转化的增量远小于花费增量：本机计算里 2→3 次的边际 CPA 是 14.43 元，远高于前两档的平均值，整体 CPA 被拉高。

**Q2** 预算花完了，但增量实验显示不显著，可能是什么原因？

▸ 答案：常见三种：① 花的是「本来就会转化」的人（定向过窄、频控过松，归因虚高）；② 曝光集中在低效库存（填充率靠低价库存堆出来）；③ 实验样本不足或对照被污染（同一用户跨组、埋点丢数据）。先查归因口径与分流，再查库存质量。

**Q3** 为什么预算分配该用边际 ROI 而不是平均 ROI？

▸ 答案：平均 ROI 是历史成绩，不告诉你「下一块钱」的回报。一个渠道平均 ROAS 5 但已饱和，边际 ROI 可能只有 1.5；另一个平均 ROAS 2 但边际 ROI 3。按平均分配会把钱推给饱和渠道，总收益下降；按边际 ROI 均等分配才使总收益最大。

**Q4** holdout 实验最小要多大？怎么算？

▸ 答案：先定要测的最小提升（如转化率提升 0.2pp）与基线（0.5%），再按两组比例差的样本量公式估算；[63.5](../63-推荐系统/63.5-推荐效果评估与AB.md) 给出的参考是 CTR 从 2% 提升 5%（相对）每组约 30 万人。本机仿真的 10 万对照 / 90 万实验，可测出约 0.2pp 且 95% 区间下限为正。

**Q5** 频控和预算平滑会互相打架，怎么解？

▸ 答案：先定优先级：频控是「用户体验与合规」的硬约束，预算平滑是「花钱节奏」的软约束。做法是把频控当库存上限，预算平滑在剩余库存内调整出价；预算花不完时优先放宽定向或提价，而不是取消频控——取消频控换来的量，边际 CPA 最高。
