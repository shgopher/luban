# 74.3 竞价与计费

## 一句话

> 竞价的本质是**把所有计费方式的出价折算成同一个 eCPM 再排序**，计费的本质是**只为可验证、可归因的事件收钱**；判据是结算价能复算、账单能和事件明细逐笔对上。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 出价高就赢 | 比的是 eCPM（出价 × 预估点击率 × 预估转化率），CPM 出 50 元可能输给 CPC 出 2 元 |
| 二价拍卖平台一定亏 | 二价降低广告主的出价策略复杂度，长期收入未必低；头部媒体常用一价 + 底价，二价见于部分 RTB 与联盟场景（以官方文档为准） |
| oCPX 就是把风险全转给平台 | 平台通过目标出价、赔付上限、成本保障期来控制风险，最终仍把约束折算回 eCPM |

## 四种计费方式：风险分配表

| 方式 | 计费事件 | 出价含义 | 风险在谁 | 适合 |
|---|---|---|---|---|
| **CPM** | 千次曝光 | 千次曝光付多少 | 广告主（曝光没转化也要付） | 品牌曝光、开屏、大促 |
| **CPC** | 一次点击 | 每次点击付多少 | 媒体（点击少则收入少） | 效果广告、搜索、信息流 |
| **CPA** | 一次转化 | 每次转化付多少 | 媒体（不转化收不到钱） | 应用激活、表单、成交 |
| **oCPX** | 转化（目标可调） | 目标转化成本 | 平台 + 媒体共担 | 放量又控成本的主力形态 |

> 🔑 计费方式决定的是「谁承担预估错误」：CPM 不预估，CPC 要预估点击率，CPA/oCPX 要同时预估点击率与转化率。**预估越深，单价越高，但预估偏差造成的亏损也越大**。

## eCPM：唯一可比的汇率

三种计费方式不能直接比出价，必须先折算成千次曝光的期望收入：

```
CPM:      eCPM = bid
CPC:      eCPM = bid × pCTR × 1000
CPA/oCPX: eCPM = bid × pCTR × pCVR × 1000
```

本机计算（Go，`tools/examples/74-ad-models/raw-74.3.txt`）给出四个候选的折算与排序： 示例说明见 [tools/examples/74-ad-models/](../../../tools/examples/74-ad-models/README.md)。

| 广告 | 计费 | 出价 | pCTR | pCVR | eCPM | 排名 |
|---|---|---|---|---|---|---|
| A 品牌 | CPM | 18.00 元/千次 | 0.018 | — | 18.00 | 4 |
| B 效果 | CPC | 1.20 元/次 | 0.025 | — | 30.00 | 2 |
| C 转化 | CPA | 28.00 元/次 | 0.030 | 0.035 | 29.40 | 3 |
| D oCPX | oCPX | 45.00 元/次 | 0.028 | 0.040 | 50.40 | 1 |

手工验算 D：`45 × 0.028 × 0.040 × 1000 = 50.40`；B：`1.20 × 0.025 × 1000 = 30.00`。A 的名义出价 18 元看似不低，但只对应 18 元 eCPM，垫底。

> 🔑 pCTR / pCVR 的偏差会直接改写排序：若 B 的真实 pCTR 只有 1.25%（预估 2.5% 高了一倍），它的真实 eCPM 是 15 元，会从第 2 掉到第 4——**按错误预估赢下的曝光，每一千次都在亏钱**。所以 [63.5 推荐效果评估与 AB](../63-推荐系统/63.5-推荐效果评估与AB.md) 里的校准与 A/B 方法，在广告里是「保命」而不是「优化」。

## 一价 vs 二价：赢家付多少

| 维度 | 一价（first price） | 二价（second price） |
|---|---|---|
| 赢家支付 | 自己的 eCPM（出价） | 第二名的 eCPM + 最小加价 |
| 出价策略 | 必须报真实价值，否则亏 | 理论上可略高于真实价值 |
| 平台收入 | 高，但可能被广告主压价 | 低而稳定，鼓励诚实报价 |
| 透明度 | 需要看到市场成交价 | 扣费不透明，广告主难优化 |
| 实践 | 头部媒体的主流（常配底价） | 部分 RTB / 联盟场景（以官方文档为准） |

本机计算里，D 的 eCPM 50.40 排第一，B 的 30.00 排第二：

- 一价：D 按自己的出价付 **45.00 元/次转化**。
- 二价：D 按第二名的 eCPM 30.00 + 0.01 付费，折算回转化单价 = `(30.01 ÷ 1000) ÷ (0.028 × 0.040) = 26.79 元/次转化`。

> 🔑 二价的扣费由「第二名的 eCPM」反推，**不是第二名的出价**：因为第二名可能是 CPC/CPA 出价，必须先把它的 eCPM 算出来。换算回自己的计费单价时，要除以自己的 pCTR × pCVR——这也是一价/二价结算最容易写错的一行代码。

## 预算平滑：把预算约束翻译成出价乘数

| 策略 | 行为 | 风险 | 适合 |
|---|---|---|---|
| **尽快（ASAP）** | 有多少量花多少，直到预算耗尽 | 上午花光、下午高转化时段没量 | 清库存、大促、抢新品期 |
| **按流量比例** | 按小时流量占比分配预算 | 均匀但可能错过高转化时段 | 常规效果投放 |
| **分时出价** | 高峰降价、低谷提价 | 依赖流量与转化预测 | 成熟账户、精细化运营 |

本机计算（日预算 10,000 元、CPM 10 元、当天总供给 200 万次曝光）：

| 策略 | 6 小时花费 | 12 小时花费 | 24 小时花费 | 预算耗尽时点 |
|---|---|---|---|---|
| 尽快 | 3,195 元 | 8,243 元 | 10,000 元 | 第 15 小时 |
| 按流量比例 | 1,597 元 | 4,121 元 | 10,000 元 | 第 24 小时 |

> 🔑 预算平滑的本质是**把「预算约束」翻译成「出价乘数」**：剩余预算 ÷ 剩余时间低于计划消耗速度时，降出价而不是直接停投。直接停投会让计划「断量」，重新起量又要重新学习，成本更高。

## 计费口径与无效流量

| 计费事件 | 口径选择 | 过滤规则 | 漏掉的后果 |
|---|---|---|---|
| 曝光 | 展示 vs 可见曝光（≥50% 像素可见 ≥1 秒，MRC 标准，以官方文档为准） | 可见性校验、异常 IP 过滤 | 背景曝光也计费，广告主投诉 |
| 点击 | 点击上报（落地页跳转 / 点击回调） | 同设备同广告去重、频率上限、CTIT 校验 | 刷量团队赚走预算 |
| 转化 | 归因窗口内的转化事件 | 按订单号/支付单号去重、退款回冲 | 一笔转化计两次费 |
| 扣量 | 结算前的质量扣减 | 按作弊识别结果扣回 | 渠道结算争议 |

本机计算（6,000 次点击、0.60 元/次）：无效点击 5% / 10% / 20% 时，计费点击变成 5,700 / 5,400 / 4,800，收入从 3,600 元降到 3,420 / 3,240 / 2,880 元。**20% 的无效点击意味着广告主 20% 的预算被刷走**——不做过滤，续费率会先崩。

计费与结算必须解耦：计费只负责「产生了什么计费事件」，结算负责「扣量、退款、账期、开票」。混在一起实时扣款，一旦要扣量或退款，就只能人工改账，账就再也对不平了（对账方法见 [67.3 对账与差异处理](../67-交易与账务/67.3-对账与差异处理.md)）。

## 代码：竞价折算、一价/二价、预算平滑与无效点击

```go
package main

import (
	"fmt"
	"sort"
)

type ad struct {
	name string
	bid  float64 // 出价：CPM 为元/千次曝光，CPC/CPA 为元/次
	pctr float64
	pcvr float64
	mode string
}

// eCPM：把三种计费方式的出价折算成同一个可比较的千次曝光价格
func (a ad) eCPM() float64 {
	switch a.mode {
	case "CPM":
		return a.bid
	case "CPC":
		return a.bid * a.pctr * 1000
	default: // CPA / oCPX
		return a.bid * a.pctr * a.pcvr * 1000
	}
}

func main() {
	ads := []ad{
		{"A 品牌 CPM", 18, 0.018, 0, "CPM"},
		{"B 效果 CPC", 1.20, 0.025, 0, "CPC"},
		{"C 转化 CPA", 28, 0.030, 0.035, "CPA"},
		{"D oCPX", 45, 0.028, 0.040, "oCPX"},
	}

	fmt.Println("=== 74.3 竞价：四种计费方式折算成 eCPM ===")
	fmt.Printf("%-14s %-5s %8s %7s %7s %10s\n", "广告", "计费", "出价", "pCTR", "pCVR", "eCPM")
	for _, a := range ads {
		fmt.Printf("%-14s %-5s %8.2f %7.3f %7.3f %10.2f\n", a.name, a.mode, a.bid, a.pctr, a.pcvr, a.eCPM())
	}

	sort.Slice(ads, func(i, j int) bool { return ads[i].eCPM() > ads[j].eCPM() })
	fmt.Println("\n=== 按 eCPM 排序（价高者得这次曝光）===")
	for i, a := range ads {
		fmt.Printf("第 %d 名 %-14s eCPM %6.2f 元\n", i+1, a.name, a.eCPM())
	}

	fmt.Println("\n=== 一价 vs 二价：赢家实际付多少 ===")
	win := ads[0]
	for _, second := range []bool{false, true} {
		charge := win.eCPM()
		if second && len(ads) > 1 {
			charge = ads[1].eCPM() + 0.01 // 二价：第二名的 eCPM 加最小加价
		}
		switch win.mode {
		case "CPM":
			fmt.Printf("二价=%v → 赢家 %s 付 %.2f 元/千次曝光（一价应 %.2f）\n",
				second, win.name, charge, win.eCPM())
		case "CPC":
			fmt.Printf("二价=%v → 赢家 %s 付 %.2f 元/次点击（一价应 %.2f）\n",
				second, win.name, charge/1000/win.pctr, win.bid)
		default:
			fmt.Printf("二价=%v → 赢家 %s 付 %.2f 元/次转化（一价应 %.2f）\n",
				second, win.name, charge/1000/win.pctr/win.pcvr, win.bid)
		}
	}

	fmt.Println("\n=== 预算平滑：日预算 10000 元、CPM 10 元（小时流量权重见代码）===")
	const budget, cpm = 10000.0, 10.0
	weights := []float64{0.2, 0.2, 0.6, 1.0, 1.4, 1.6, 1.5, 1.4, 1.3, 1.2, 1.2, 1.3, 1.4, 1.3, 1.2, 1.2, 1.3, 1.5, 1.8, 2.0, 2.2, 2.0, 1.5, 1.0}
	sum := 0.0
	for _, w := range weights {
		sum += w
	}
	for _, mode := range []string{"尽快", "按流量比例"} {
		remaining := budget
		cum := make([]float64, len(weights))
		exhaust := len(weights)
		for h, w := range weights {
			supplyCost := w / sum * 2_000_000 / 1000 * cpm // 当天总供给 200 万次曝光
			allow := remaining
			if mode == "按流量比例" {
				allow = budget * (w / sum) // 按小时流量占比分配预算
			}
			spend := supplyCost
			if spend > allow {
				spend = allow
			}
			if spend > remaining {
				spend = remaining
			}
			remaining -= spend
			cum[h] = budget - remaining
			if remaining <= 0.01 && exhaust == len(weights) {
				exhaust = h + 1
			}
		}
		fmt.Printf("%s：第 %2d 小时预算耗尽；6h 花 %5.0f 元，12h 花 %5.0f 元，24h 花 %5.0f 元\n",
			mode, exhaust, cum[5], cum[11], cum[23])
	}

	fmt.Println("\n=== 无效点击过滤对 CPC 收入的影响（6000 次点击、0.60 元/次）===")
	const clicks, cpc = 6000, 0.60
	for _, inv := range []float64{0.05, 0.10, 0.20} {
		valid := int(float64(clicks) * (1 - inv))
		fmt.Printf("无效点击 %.0f%% → 计费点击 %4d，收入 %6.0f 元（未过滤 %6.0f 元）\n",
			inv*100, valid, float64(valid)*cpc, float64(clicks)*cpc)
	}
}
```

## 反模式

| 反模式 | 后果 |
|---|---|
| 用 CPC 出价却不估 pCTR，直接和 CPM 比价 | 排序错位，高价低质广告赢走曝光 |
| 把 oCPX 当「保证 CPA」 | 平台超成本就停投，计划永远起不了量 |
| 一价拍卖不设底价、不报真实价值 | 被压价到成本线以下，越投越亏 |
| 预算按天平均分，不看流量与转化曲线 | 高峰没预算、低谷乱花钱 |
| 点击不过滤直接计费 | 刷量团队赚走预算，广告主 ROI 归零 |
| 曝光计费用「展示」冒充「可见」 | 广告主投诉、续费率下降、平台口碑受损 |
| 二价扣费按「第二名的出价」算 | 跨计费方式时结算金额全错，账单对不平 |
| 计费与结算耦合，实时扣款 | 扣量、退款、冲正无路可走，只能人工改账 |

## 自检

**Q1** CPM 出 50 元为什么可能输给 CPC 出 2 元？

▸ 答案：排序看的是 eCPM。CPC 出 2 元、pCTR 3% 时 eCPM = `2 × 0.03 × 1000 = 60` 元，高于 CPM 的 50 元；反之若 pCTR 只有 1%，eCPM 只有 20 元，就输。出价面值不能直接比较，必须折算。

**Q2** 二价拍卖里，赢家实际按什么价扣费？跨计费方式时怎么算？

▸ 答案：按第二名的 eCPM 加最小加价扣费，再按赢家自己的 pCTR/pCVR 换算回计费单价。本机计算里 D 的 eCPM 50.40 赢，第二名 B 的 eCPM 30.00，则扣费 eCPM 30.01，折算成转化单价 = `(30.01÷1000)÷(0.028×0.040) = 26.79 元`。写成「按第二名的出价扣费」在跨计费方式时必错。

**Q3** 为什么预算平滑要用「出价乘数」而不是「到点停投」？

▸ 答案：到点停投会让计划突然断量，重新起量要重新经历冷启动与学习期，成本更高；出价乘数是在不中断投放的前提下降低竞争强度，平滑地把预算摊到全天。判据是「剩余预算 ÷ 剩余时间」与计划消耗速度的比值，低于阈值就降乘数。

**Q4** 无效点击 20% 时 CPC 收入降多少？这笔钱谁承担？

▸ 答案：本机计算里 6,000 次点击、0.60 元/次，未过滤收入 3,600 元；20% 无效后计费点击 4,800，收入 2,880 元，降 20%。不做过滤时由广告主承担（白付 720 元）；做了过滤由媒体承担（收入减少），所以媒体有动力把过滤标准说清楚、并给出扣量明细。

**Q5** oCPX 平台怎么控制「超成本」风险？

▸ 答案：三层：① 目标出价与成本保障期（如首几天超成本赔付，以官方文档为准）；② 出价乘数动态调整，超成本就降出价、缩量；③ 归因与反作弊兜底，把无效转化从计费里剔除。平台不是无条件兜底，而是用「赔付上限 + 停投阈值」把风险控制在可接受范围。
