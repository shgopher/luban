# 68.5 设备指纹

## 一句话

> 设备指纹的目标不是“识别设备”，而是**在设备会被改机、重装、模拟的前提下，仍然能把“同一伙人”关联起来**；判据是**稳定性**（同一设备跨会话一致）与**区分度**（不同设备不碰撞）之间的平衡。

> 💡 本节主场是**风控场景**（支付、营销、团伙识别）；登录场景的设备信任与三层指纹在 [49.6 风险登录与设备指纹](../../L4-组件与技术/49-身份与访问管理/49.6-风险登录与设备指纹.md)，不重复。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 设备指纹 = IMEI / MAC | 这些标识可被改机工具篡改，且隐私合规上多数不可采集 |
| 指纹应该永久稳定 | 指纹会随系统升级、浏览器更新漂移；越“稳定”的信号往往越容易被伪造 |
| 指纹能证明“这是谁” | 指纹只能证明“像同一台设备”，不能证明身份 |

## 四层信号：越往下越稳，也越贵

| 层 | 例子 | 稳定性 | 成本 |
|---|---|---|---|
| **硬件** | 机型、屏幕分辨率、CPU 核数 | 中（可改机伪造） | 低 |
| **系统** | OS 版本、字体列表、时区、语言 | 中（升级会漂移） | 低 |
| **网络** | IP、ASN、Wi-Fi 名称、基站 | 低（会变） | 低 |
| **行为** | 点击节奏、滑动轨迹、输入习惯 | 高（难伪造） | 高（要采集与建模） |

判据（我的判断）：**风控用“系统 + 行为”做主体，硬件做辅助，网络只做关联**。只靠硬件，改机工具一改就失效；只靠网络，同一个 Wi-Fi 下所有人都会碰撞。

各信号的工程参数（经验值，用来选组合）：

| 信号 | 采集耗时 | 会话内稳定性 | 碰撞率 | 说明 |
|---|---|---|---|---|
| 机型 + 系统版本 | < 1 ms | 高（升级才变） | **高** | 同型号设备大量共享 |
| Canvas / WebGL | 5–20 ms | 中 | 低 | 渲染差异有区分度 |
| 字体列表 | 2–10 ms | 中 | 中 | 系统更新会漂移 |
| 传感器列表 | 1–5 ms | 高 | 低 | 模拟器常缺失 |
| 行为序列 | 100 ms+（需累积） | 高 | 极低 | 难伪造，但要建模 |

组合原则：**2–3 个中等稳定信号 + 1 个行为信号**，比“堆 10 个硬件字段”更稳。

## 稳定性与区分度：一对矛盾

| | 太稳定 | 太不稳定 |
|---|---|---|
| 表现 | 大量设备碰撞成同一指纹 | 同一设备每次都是新指纹 |
| 后果 | 误伤（把正常用户当团伙） | 漏判（攻击者换个指纹就绕过） |

浏览器侧常用信号：Canvas/WebGL 渲染特征、字体列表、时区、语言、UA。App 侧常用：机型、系统版本、传感器列表、安装列表（合规前提下）。

> ⚠️ 浏览器指纹的“稳定性”是双刃剑：同一型号、同一系统版本的设备，指纹可能高度相似——**相似不等于同一台**。

## 团伙识别：先算相似度，再看关系

```go
// 设备指纹相似度：两设备属性集合的 Jaccard 相似度，高于阈值视为疑似同设备/群控。
func jaccard(a, b map[string]bool) float64 {
	inter, union := 0, len(a)
	for k := range b {
		if a[k] {
			inter++
		} else {
			union++
		}
	}
	return float64(inter) / float64(union)
}
```

真实输出（本机 `go1.27.1 darwin/arm64`）：

```text
d1 vs d2 相似度=0.83
d1 vs d3 相似度=0.40
判据：>0.9 疑似同设备；0.6–0.9 需结合 IP/行为；<0.6 视为不同设备
```

读法：0.83 不能直接判“同一设备”，要结合 IP、支付账号、行为序列；0.40 基本可以排除。**相似度是线索，不是结论**。

团伙识别的常见做法是把“设备—账号—IP—银行卡”建成一张图，用连通分量或社区发现找簇；簇越大、越密集，越可能是群控。

## 对抗：改机、模拟器、群控

| 手法 | 特征 | 检测思路 |
|---|---|---|
| **模拟器** | 传感器缺失、CPU 指令异常、无真实电池 | 采集传感器与硬件一致性 |
| **改机** | 机型/序列号频繁变化，但行为不变 | 行为指纹与硬件指纹不一致 |
| **群控** | 多设备操作节奏高度一致 | 行为序列相似度聚类 |
| **多开** | 同一设备多账号、切换频繁 | 设备—账号图的高频切换 |
| **代理/VPN** | IP 与设备地理不一致 | IP 归属地与基站/时区交叉验证 |

> 🔑 对抗的本质是**成本抬高**，不是“彻底识别”。当伪造成本高于收益，攻击者就会换目标（[38.11 安全应急响应](../../L3-质量属性/38-安全/38.11-安全应急响应.md) 里那句“让攻击不划算”同样适用）。

## 反模式

| 反模式 | 后果 |
|---|---|
| 只用 IMEI/MAC 做指纹 | 改机工具一改就失效 |
| 指纹永久绑定账号 | 换机/重装即误伤，客诉不断 |
| 相似度高就直接拒绝 | 同型号设备大量碰撞，误杀一片 |
| 采集安装列表不做合规 | 隐私合规风险，可能直接下架 |
| 指纹只存不更新 | 系统升级后指纹漂移，识别率骤降 |
| 把指纹当身份凭证 | 指纹可伪造，不能替代认证 |
| 不做团伙维度分析 | 单设备看都正常，合起来是群控 |

## 自检

**Q1** 为什么设备指纹不能当身份凭证？

▸ 答案：因为指纹证明的是“像同一台设备”，不是“这是谁”。它可以被改机工具伪造、被同型号设备碰撞，也不具备法律意义上的身份唯一性。身份要靠认证（密码/证书/生物特征），指纹只做风险信号。

**Q2** “稳定性”与“区分度”为什么会互相矛盾？

▸ 答案：越稳定的信号（机型、系统版本）越容易被大量设备共享，碰撞率高；越独特的信号（行为、传感器）越容易随环境变化而漂移。好的指纹是两者的折中：用多个中等稳定信号组合，提高区分度，同时用行为信号兜住漂移。

**Q3** Jaccard 相似度 0.83 为什么不能直接判定同一设备？

▸ 答案：因为同型号、同系统版本的设备天然相似；0.83 只说明“属性高度重合”，还可能是两台不同设备。要结合 IP、账号、行为序列、时间线综合判断；相似度是线索，不是结论。

**Q4** 对抗改机的核心思路是什么？

▸ 答案：抬高伪造成本，而不是追求“彻底识别”。具体做法是交叉验证：硬件指纹与行为指纹是否一致、IP 地理与设备时区是否一致、传感器数据是否合理。攻击者要同时伪造多层信号，成本就上去了。

**Q5** 设备指纹在风控里通常放在哪一层？

▸ 答案：放在“特征层”，作为规则与模型的输入之一，而不是直接决策。它常与名单、频次、IP、账号画像组合使用；单独用指纹做拒绝，误杀率会很高。
