# 68.6 误杀与漏杀的权衡

## 一句话

> 误杀与漏杀不是“哪个更不能忍”的立场题，而是**成本题**：误杀成本 = 客诉 + 流失 + 人工复核，漏杀成本 = 资损 × 扩散；阈值按**成本比**选，不是按准确率选。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 准确率越高越好 | 准确率会把“误杀”和“漏杀”等权，而它们的代价差一个量级 |
| 误杀一定比漏杀严重（或反之） | 看业务：支付漏杀是资损，登录误杀是用户流失，权重完全不同 |
| 阈值定一次管终身 | 攻击强度、客群、大促都会变，阈值要能按场景调 |

## 混淆矩阵与成本

| | 实际是坏人 | 实际是好人 |
|---|---|---|
| **判为坏人** | TP（拦住） | **FP（误杀）** |
| **判为好人** | **FN（漏杀）** | TN（放行） |

```
总成本 = FP × 误杀单价 + FN × 漏杀单价
```

```go
// 阈值 0.5 与 0.8 两档：TP/FP/FN/TN；误杀单价 20，漏杀单价 300。
for _, c := range cases {
	cost := c.m.fp*fpCost + c.m.fn*fnCost
	fmt.Printf("阈值=%.1f TP=%d FP=%d FN=%d 成本=%d\n", c.threshold, c.m.tp, c.m.fp, c.m.fn, cost)
}
```

真实输出（本机 `go1.27.1 darwin/arm64`）：

```text
阈值=0.5 TP=80 FP=40 FN=20 成本=6800
阈值=0.8 TP=55 FP=10 FN=45 成本=13700
结论：阈值高→误杀少但漏杀多；按成本比选，而不是按准确率选
```

阈值 0.8 的“准确率”更高（TN 多、FP 少），但成本反而翻倍——因为漏杀单价是误杀的 15 倍。**准确率是给模型看的，成本是给业务看的。**

## 单价怎么估

| 成本项 | 估算方法 | 例子 |
|---|---|---|
| 误杀单价 | 客诉成本 + 流失概率 × LTV + 人工复核成本 | 一次误杀 ≈ 20 元 |
| 漏杀单价 | 单笔资损 × 扩散系数 | 一次漏杀 ≈ 300 元 |
| 复核单价 | 人工审核一条的成本 | 5–15 元/条 |

> ⚠️ 单价是**经验值**，不是财务精确值；它的用途是给阈值选择提供方向，而不是算出一个绝对正确的数。单价估错，结论就会偏——所以要定期用真实客诉与资损数据校准。

## 把“误杀”变成“多一步”

最有效的降误杀手段不是调阈值，而是**加处置档位**：

| 处置 | 误杀代价 | 漏杀风险 |
|---|---|---|
| 直接拒绝 | 最高（用户被挡） | 最低 |
| 降额 | 中 | 中 |
| 二次验证（短信/人脸） | 低（多一步） | 中 |
| 人工复核 | 低（延迟） | 低 |
| 放行 + 事后补查 | 最低 | 最高 |

判据：**能用“验证”解决的，不要用“拒绝”**。验证把“误杀”变成“多一步操作”，用户流失率会低一个量级；代价是转化率与体验略降。

## 动态阈值与申诉闭环

| 机制 | 做法 |
|---|---|
| 大促/攻击期 | 阈值临时收紧，事后恢复（有明确起止时间） |
| A/B | 两套阈值同时跑，对比资损与客诉 |
| 申诉 | 用户申诉 → 人工复核 → 误判样本回流 |
| 复盘 | 每周看误杀率、漏杀率、申诉率三条曲线 |

## 阈值该定在哪：一次成本最小化

0.5 与 0.8 两档的对比只回答了“高阈值成本更高”，没回答“最低点在哪、还要不要继续调”。最低点是可解的：把总成本写成阈值的函数，对阈值求导，**边际少误杀一人省下的钱 = 边际多漏杀一人多花的钱**，交点就是最优阈值。

设好用户分数分布为 `F_G`、坏用户为 `F_B`，阈值 `t` 之上判坏：

```
C(t) = N_G · (1 − F_G(t)) · c_fp + N_B · F_B(t) · c_fn
```

对 `t` 求导并令其为 0：

```
c_fp · N_G · f_G(t) = c_fn · N_B · f_B(t)
⇒ f_B(t) / f_G(t) = (N_G · c_fp) / (N_B · c_fn)
```

换成后验概率写法更直观：判坏的边际收益大于边际成本时判坏，即

```
P(坏 | 分数 t) / P(好 | 分数 t) > c_fp / c_fn
```

这条式子解释三件事：**0.5 不是默认值**（它只在“误杀与漏杀同价、好坏各半”时成立）；**阈值由成本比和后验决定**，准确率不出现在式子里；**先验变了阈值也要变**——坏用户占比从 2% 涨到 5%，同一套单价下最优阈值会自动下移，因为同样的分数在后验上更可疑了。

为什么曲线是单峰的：阈值上调，FP 按分布尾部指数下降，FN 按分布主体线性上升。两者一快一慢，交点之前“多拦”省钱、交点之后“多放”省钱，中间必有一个最低点。这也解释了为什么“把阈值调到 0.9 更安全”是错觉——0.9 的 FN 是 0.633 的 3 倍，成本从 291,020 涨到 532,580。

仿真：好用户 10 万（分数 μ=0.35、σ=0.18）、坏用户 2,000（μ=0.72、σ=0.16），误杀单价 20、漏杀单价 300（沿用 1:15 的量级），按 0.001 步长扫阈值：

| 阈值 | 误杀 FP | 漏杀 FN | 通过率 | 总成本 |
|---|---|---|---|---|
| 0.30 | 61,128 | 12 | 38.12% | 1,226,160 |
| 0.40 | 39,258 | 39 | 59.59% | 796,860 |
| 0.50 | 20,248 | 153 | 78.34% | 450,860 |
| 0.60 | 8,114 | 450 | 90.53% | 297,280 |
| **0.633** | **5,701** | **590** | **93.03%** | **291,020** |
| 0.70 | 2,534 | 931 | 96.47% | 329,980 |
| 0.80 | 594 | 1,427 | 98.86% | 439,980 |

```go
package main

// 68.6 阈值该定在哪：把总成本写成阈值的函数，扫一遍找最低点，
// 再用解析判据 f_bad/f_good = (N_good·C_fp)/(N_bad·C_fn) 复核，
// 最后看成本比变化时阈值与通过率怎么动。
// 分数分布为假设值（本机仿真），成本单价按 20:300 的量级设置。

import (
	"fmt"
	"math"
	"math/rand"
	"sort"
)

const (
	goodN    = 100_000 // 好用户
	badN     = 2_000   // 坏用户（先验 2%）
	muG, sdG = 0.35, 0.18
	muB, sdB = 0.72, 0.16
	cfp      = 20.0 // 误杀单价
	cfn      = 300.0 // 漏杀单价（基准 15 倍）
)

// draw 生成一批分数并排序，后续用二分统计 FP/FN
func draw(rng *rand.Rand, n int, mu, sd float64) []float64 {
	s := make([]float64, n)
	for i := range s {
		s[i] = rng.NormFloat64()*sd + mu
	}
	sort.Float64s(s)
	return s
}

// fpAt 分数 ≥ t 的好用户数（误杀）
func fpAt(sorted []float64, t float64) int {
	return len(sorted) - sort.SearchFloat64s(sorted, t)
}

// fnAt 分数 < t 的坏用户数（漏杀）
func fnAt(sorted []float64, t float64) int {
	return sort.SearchFloat64s(sorted, t)
}

// evaluate 给定阈值与单价，返回 (FP, FN, 通过率, 总成本)
func evaluate(good, bad []float64, t, fpCost, fnCost float64) (int, int, float64, float64) {
	fp := fpAt(good, t)
	fn := fnAt(bad, t)
	passed := (goodN - fp) + fn // 放行 = 好人放行 + 坏人放行
	passRate := float64(passed) / float64(goodN+badN)
	cost := float64(fp)*fpCost + float64(fn)*fnCost
	return fp, fn, passRate, cost
}

// bestThreshold 以 0.001 为步长扫 [0.01, 0.99]，返回成本最低的阈值
func bestThreshold(good, bad []float64, fpCost, fnCost float64) (float64, float64, int, int, float64) {
	bt, bc := 0.0, math.MaxFloat64
	var bfp, bfn int
	var bpass float64
	for t := 0.01; t <= 0.99; t += 0.001 {
		fp, fn, pass, cost := evaluate(good, bad, t, fpCost, fnCost)
		if cost < bc {
			bt, bc, bfp, bfn, bpass = t, cost, fp, fn, pass
		}
	}
	return bt, bc, bfp, bfn, bpass
}

// bestAccuracy 返回准确率最高的阈值，用来对照"按准确率选阈值"的代价
func bestAccuracy(good, bad []float64) (float64, float64) {
	bt, bacc := 0.0, 0.0
	for t := 0.01; t <= 0.99; t += 0.001 {
		fp := fpAt(good, t)
		fn := fnAt(bad, t)
		tp := badN - fn
		tn := goodN - fp
		acc := float64(tp+tn) / float64(goodN+badN)
		if acc > bacc {
			bt, bacc = t, acc
		}
	}
	return bt, bacc
}

// theoreticalRoot 用解析判据反解阈值：f_bad/f_good = RHS（二分）
func theoreticalRoot(fpCost, fnCost float64) float64 {
	rhs := float64(goodN) * fpCost / (float64(badN) * fnCost)
	ratio := func(t float64) float64 {
		fg := math.Exp(-(t-muG)*(t-muG)/(2*sdG*sdG)) / (sdG * math.Sqrt(2*math.Pi))
		fb := math.Exp(-(t-muB)*(t-muB)/(2*sdB*sdB)) / (sdB * math.Sqrt(2*math.Pi))
		return fb / fg
	}
	lo, hi := 0.0, 1.0
	for i := 0; i < 100; i++ {
		mid := (lo + hi) / 2
		if ratio(mid) < rhs {
			lo = mid
		} else {
			hi = mid
		}
	}
	return (lo + hi) / 2
}

func main() {
	rng := rand.New(rand.NewSource(42))
	good := draw(rng, goodN, muG, sdG)
	bad := draw(rng, badN, muB, sdB)
	total := float64(goodN + badN)

	// ① 固定单价 20:300，扫阈值
	fmt.Printf("好用户=%d 坏用户=%d（先验 %.1f%%），误杀单价=%.0f，漏杀单价=%.0f\n\n",
		goodN, badN, 100*float64(badN)/total, cfp, cfn)
	fmt.Printf("%-8s %-8s %-8s %-9s %-10s\n", "阈值", "误杀FP", "漏杀FN", "通过率", "总成本")
	fmt.Println("-------------------------------------------------------")
	for _, t := range []float64{0.30, 0.40, 0.50, 0.60, 0.70, 0.80, 0.90} {
		fp, fn, pass, cost := evaluate(good, bad, t, cfp, cfn)
		fmt.Printf("%-8.2f %-8d %-8d %-9s %-10.0f\n", t, fp, fn, fmt.Sprintf("%.2f%%", pass*100), cost)
	}

	bt, bc, bfp, bfn, bpass := bestThreshold(good, bad, cfp, cfn)
	fmt.Printf("\n最低成本阈值=%.3f：误杀=%d 漏杀=%d 通过率=%.2f%% 总成本=%.0f\n",
		bt, bfp, bfn, bpass*100, bc)
	_, _, _, c50 := evaluate(good, bad, 0.50, cfp, cfn)
	fmt.Printf("对照：阈值 0.50 的成本=%.0f，多花 %.1f%%\n", c50, 100*(c50/bc-1))

	accT, acc := bestAccuracy(good, bad)
	_, _, _, costAcc := evaluate(good, bad, accT, cfp, cfn)
	fmt.Printf("准确率最高阈值=%.3f（准确率 %.2f%%），成本=%.0f，比最低成本高 %.1f%%\n",
		accT, acc*100, costAcc, 100*(costAcc/bc-1))

	root := theoreticalRoot(cfp, cfn)
	fmt.Printf("解析判据反解阈值=%.3f（f_bad/f_good = %.2f），与扫描结果相差 %.3f\n",
		root, float64(goodN)*cfp/(float64(badN)*cfn), math.Abs(root-bt))

	// ② 敏感度：漏杀单价变化时，最优阈值与通过率怎么动
	fmt.Printf("\n%-10s %-10s %-10s %-10s %-8s %-8s %-10s\n",
		"误杀单价", "漏杀单价", "倍数", "最优阈值", "通过率", "误杀", "总成本")
	fmt.Println("-----------------------------------------------------------------------------")
	for _, mult := range []float64{5, 10, 15, 30, 60} {
		fc := cfp * mult
		t, cost, fp, fn, pass := bestThreshold(good, bad, cfp, fc)
		fmt.Printf("%-10.0f %-10.0f %-10.0f %-10.3f %-9s %-8d %-10.0f\n",
			cfp, fc, mult, t, fmt.Sprintf("%.2f%%", pass*100), fp, cost)
		_ = fn
	}

	// ③ 单价估错 2 倍时，阈值偏多少
	tHalf, _, _, _, _ := bestThreshold(good, bad, cfp, cfn/2)
	tDouble, _, _, _, _ := bestThreshold(good, bad, cfp, cfn*2)
	fmt.Printf("\n单价估错的影响：漏杀单价 150 → 阈值 %.3f；300 → %.3f；600 → %.3f（单价翻倍阈值移动约 %.2f）\n",
		tHalf, bt, tDouble, math.Abs(tDouble-bt))
}
```

读法：

- **最低点在 0.633，成本 291,020**；阈值 0.50 的成本 450,860，多花 54.9%。从 0.30 收紧到 0.633 每一步都在省钱，过了 0.633 才开始变贵。
- **准确率最高的阈值是 0.876（准确率 98.18%）**，它的成本 511,980，比最低点高 75.9%。准确率被 TN 主导（好用户占 98%），它奖励“少打扰好人”，而漏杀 1,427 人的代价它看不见——准确率是模型指标，成本是业务指标，二者在类别不平衡时必然分道扬镳。
- **解析解与扫描解一致**：`f_B/f_G = (100000 × 20) / (2000 × 300) = 3.33`，反解阈值 0.633，与扫描差 0.000。这条式子可以直接写进配置生成脚本，不必每次都扫一遍。

敏感度：误杀单价固定 20，漏杀单价从 5 倍拉到 60 倍：

| 漏杀:误杀 | 最优阈值 | 通过率 | 误杀 | 漏杀 | 总成本 |
|---|---|---|---|---|---|
| 5 倍 | 0.714 | 96.93% | 2,133 | 1,003 | 142,960 |
| 10 倍 | 0.663 | 94.78% | 4,046 | 719 | 224,720 |
| 15 倍 | 0.633 | 93.03% | 5,701 | 590 | 291,020 |
| 30 倍 | 0.567 | 87.23% | 11,351 | 323 | 420,820 |
| 60 倍 | 0.527 | 82.33% | 16,228 | 203 | 568,160 |

这张表回答“阈值该定在哪”的真正姿势：**不是找一个数，而是先定成本比**。成本比 15 倍时阈值 0.633、通过率 93%；成本比翻到 30 倍，阈值降到 0.567、通过率掉到 87.2%——多拦下 267 个坏用户，代价是多误杀 5,650 个好人。单价估错 2 倍（漏杀 150 对 600），阈值从 0.673 移到 0.567，移动约 0.07：这就是“单价只要估到能分档，阈值就不会跑偏”的量化含义。

同一套模型，换个场景就是换一组数（分布不变、只换成本比，用来对照）：

| 场景 | 漏杀:误杀 | 最优阈值 | 通过率 | 处置建议 |
|---|---|---|---|---|
| 登录 | 5 倍 | 0.714 | 96.93% | 拒绝 + 二次验证兜底 |
| 营销 | 15 倍 | 0.633 | 93.03% | 降额/加验证，不直接拒 |
| 支付 | 60 倍 | 0.527 | 82.33% | 拦下 + 人工复核队列 |

注意这张表的读法：**阈值随成本比从 0.714 降到 0.527，跨了 0.19**；如果三个场景共用一个 0.633，登录会多拦、支付会漏拦。真实场景的先验与分布各不相同，正确做法是按场景各算一遍，而不是把这里的阈值抄过去。

**曲线最低点附近的噪声要单独看。** 上表的成本在 0.60 与 0.633 之间只差 2%（297,280 对 291,020），而 2,000 条坏样本在 0.633 处漏杀率约 29.5%，95% 置信区间约 ±2 个百分点——换算成漏杀数是 590 ± 40 条、成本抖动 ±12,000。也就是说，**0.60 与 0.633 的差别可能小于采样噪声**，真正能站住脚的结论是“最低点在 0.63 附近”，不是“0.633 比 0.60 好 2%”。要让最低点稳定到小数点后两位，坏样本至少要上万条；拿不到，就把阈值按 0.02–0.05 分档发布，别用 0.001 的精度自欺。

**AUC 与 KS 不能替代这条成本曲线。** AUC 衡量的是“排序质量”，它与阈值无关——同一个模型的所有阈值共享一条 ROC 曲线，AUC 高的模型在某个阈值下成本仍可能很高；KS 给的是“区分度最大的那个点”，而成本最低点由成本比决定，两者只在特殊参数下重合。用 AUC 或“准确率”选阈值，等于用模型的平均表现替代业务的局部代价，类别不平衡时偏差最大：本机仿真里准确率最优的 0.876 比成本最优的 0.633 贵 75.9%，而两者的 AUC 完全相同。

成本比从哪来：`c_fp` 用申诉工单成本 + 客诉补偿 + 流失概率 × LTV 估，`c_fn` 用单笔资损 × 扩散系数估；两个数都要能被业务方质疑、能被复盘数据修正。校准频率按季度即可——上面的敏感度说明单价差 2 倍只让阈值移 0.07，不足以推翻结论，但方向错了（把 15 倍估成 1.5 倍）会让阈值移 0.1 以上，那就不是调参能救的了。

还有一条容易漏的边界：模型按“每个请求独立”算成本，但同一用户被反复误杀时边际成本递增——第一次是客诉，第三次可能是卸载，这时要按用户聚合算成本，而不是按请求累加。

模型边界有三条：**分数分布漂移**（大促、新客群、攻击换代）后阈值会失效，要么重估分布、要么分群设阈值；**分数不可比**（两个模型、两个版本的分数直接混用）时，先做分数校准再谈成本最优；**成本比极端**（漏杀:误杀 > 100:1）时最优阈值会贴着 1，此时误杀率上升，应该改用处置档位（先降额/验证，把误杀成本降下来）而不是继续抬阈值。

> 🔑 阈值是成本的函数，不是准确率的函数。定阈值之前，先把 `c_fp` 与 `c_fn` 写成两行可辩论的数字；写不出这两行，任何阈值都是拍脑袋，准确率再高也只是把成本藏起来了。

## 反模式

| 反模式 | 后果 |
|---|---|
| 只看准确率调阈值 | 成本被隐藏，业务为“指标好看”买单 |
| 所有场景用同一阈值 | 登录/支付/营销的代价结构完全不同 |
| 只有“拒绝/放行”两档 | 误杀没有缓冲，客诉激增 |
| 阈值调整无记录 | 出事无法回溯，也无法恢复 |
| 没有申诉通道 | 误杀用户流失且无反馈 |
| 单价拍脑袋且从不校准 | 阈值方向可能是反的 |
| 大促期永久收紧 | 攻击过去后误杀仍在，用户悄悄流失 |

## 自检

**Q1** 为什么“准确率更高”的阈值可能成本更高？

▸ 答案：因为准确率把 FP 与 FN 等权，而它们的代价不同。示例里阈值 0.8 的 FP 从 40 降到 10（少误杀 30），但 FN 从 20 涨到 45（多漏杀 25），按 20:300 的单价，总成本从 6800 涨到 13700。准确率看不出这个差别，成本能。

**Q2** 误杀单价和漏杀单价怎么估？

▸ 答案：误杀 = 客诉成本 + 流失概率 × 用户 LTV + 人工复核成本；漏杀 = 单笔资损 × 扩散系数（一次漏杀可能被复制）。两者都是经验值，要用真实客诉与资损数据定期校准；单价估错，阈值方向就会错。

**Q3** 降低误杀最有效的手段是什么？

▸ 答案：加处置档位，而不是一味调高阈值。把“拒绝”换成“二次验证/降额/人工复核”，误杀就从“用户被挡”变成“多一步操作”，流失率低一个量级；代价是转化率略降与复核成本上升。

**Q4** 为什么阈值要能按场景与时间调整？

▸ 答案：因为代价结构随场景变化：登录误杀是流失，支付漏杀是资损；也随时间变化：大促期攻击强度上升、客群变化。固定阈值要么在大促期漏杀，要么在平时误杀；可调 + 有记录 + 能恢复，才是工程做法。

**Q5** 申诉闭环为什么是风控系统的一部分？

▸ 答案：因为申诉同时提供三样东西：误杀用户的出口（降低流失）、误判样本（校准规则与模型）、以及“误杀率”的真实度量（只看系统日志看不到用户感受）。没有申诉，风控就失去了自我纠错的反馈环。
