# 68.6 误杀与漏杀的权衡

## 一句话

> 误杀与漏杀不是“哪个更不能忍”的立场题，而是**成本题**：误杀成本 = 客诉 + 流失 + 人工复核，漏杀成本 = 资损 × 扩散；阈值按**成本比**选，不是按准确率选。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 准确率越高越好 | 准确率会把“误杀”和“漏杀”等权，而它们的代价差一个量级 |
| 误杀一定比漏杀严重（或反之） | 看业务：支付漏杀是资损，登录误杀是用户流失，权重完全不同 |
| 阈值定一次管终身 | 攻击强度、客群、大促都会变，阈值要能按场景调 |

## 混淆矩阵与成本

| | 实际是坏人 | 实际是好人 |
|---|---|---|
| **判为坏人** | TP（拦住） | **FP（误杀）** |
| **判为好人** | **FN（漏杀）** | TN（放行） |

```
总成本 = FP × 误杀单价 + FN × 漏杀单价
```

```go
// 阈值 0.5 与 0.8 两档：TP/FP/FN/TN；误杀单价 20，漏杀单价 300。
for _, c := range cases {
	cost := c.m.fp*fpCost + c.m.fn*fnCost
	fmt.Printf("阈值=%.1f TP=%d FP=%d FN=%d 成本=%d\n", c.threshold, c.m.tp, c.m.fp, c.m.fn, cost)
}
```

真实输出（本机 `go1.27.1 darwin/arm64`）：

```text
阈值=0.5 TP=80 FP=40 FN=20 成本=6800
阈值=0.8 TP=55 FP=10 FN=45 成本=13700
结论：阈值高→误杀少但漏杀多；按成本比选，而不是按准确率选
```

阈值 0.8 的“准确率”更高（TN 多、FP 少），但成本反而翻倍——因为漏杀单价是误杀的 15 倍。**准确率是给模型看的，成本是给业务看的。**

## 单价怎么估

| 成本项 | 估算方法 | 例子 |
|---|---|---|
| 误杀单价 | 客诉成本 + 流失概率 × LTV + 人工复核成本 | 一次误杀 ≈ 20 元 |
| 漏杀单价 | 单笔资损 × 扩散系数 | 一次漏杀 ≈ 300 元 |
| 复核单价 | 人工审核一条的成本 | 5–15 元/条 |

> ⚠️ 单价是**经验值**，不是财务精确值；它的用途是给阈值选择提供方向，而不是算出一个绝对正确的数。单价估错，结论就会偏——所以要定期用真实客诉与资损数据校准。

## 把“误杀”变成“多一步”

最有效的降误杀手段不是调阈值，而是**加处置档位**：

| 处置 | 误杀代价 | 漏杀风险 |
|---|---|---|
| 直接拒绝 | 最高（用户被挡） | 最低 |
| 降额 | 中 | 中 |
| 二次验证（短信/人脸） | 低（多一步） | 中 |
| 人工复核 | 低（延迟） | 低 |
| 放行 + 事后补查 | 最低 | 最高 |

判据：**能用“验证”解决的，不要用“拒绝”**。验证把“误杀”变成“多一步操作”，用户流失率会低一个量级；代价是转化率与体验略降。

## 动态阈值与申诉闭环

| 机制 | 做法 |
|---|---|
| 大促/攻击期 | 阈值临时收紧，事后恢复（有明确起止时间） |
| A/B | 两套阈值同时跑，对比资损与客诉 |
| 申诉 | 用户申诉 → 人工复核 → 误判样本回流 |
| 复盘 | 每周看误杀率、漏杀率、申诉率三条曲线 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 只看准确率调阈值 | 成本被隐藏，业务为“指标好看”买单 |
| 所有场景用同一阈值 | 登录/支付/营销的代价结构完全不同 |
| 只有“拒绝/放行”两档 | 误杀没有缓冲，客诉激增 |
| 阈值调整无记录 | 出事无法回溯，也无法恢复 |
| 没有申诉通道 | 误杀用户流失且无反馈 |
| 单价拍脑袋且从不校准 | 阈值方向可能是反的 |
| 大促期永久收紧 | 攻击过去后误杀仍在，用户悄悄流失 |

## 自检

**Q1** 为什么“准确率更高”的阈值可能成本更高？

▸ 答案：因为准确率把 FP 与 FN 等权，而它们的代价不同。示例里阈值 0.8 的 FP 从 40 降到 10（少误杀 30），但 FN 从 20 涨到 45（多漏杀 25），按 20:300 的单价，总成本从 6800 涨到 13700。准确率看不出这个差别，成本能。

**Q2** 误杀单价和漏杀单价怎么估？

▸ 答案：误杀 = 客诉成本 + 流失概率 × 用户 LTV + 人工复核成本；漏杀 = 单笔资损 × 扩散系数（一次漏杀可能被复制）。两者都是经验值，要用真实客诉与资损数据定期校准；单价估错，阈值方向就会错。

**Q3** 降低误杀最有效的手段是什么？

▸ 答案：加处置档位，而不是一味调高阈值。把“拒绝”换成“二次验证/降额/人工复核”，误杀就从“用户被挡”变成“多一步操作”，流失率低一个量级；代价是转化率略降与复核成本上升。

**Q4** 为什么阈值要能按场景与时间调整？

▸ 答案：因为代价结构随场景变化：登录误杀是流失，支付漏杀是资损；也随时间变化：大促期攻击强度上升、客群变化。固定阈值要么在大促期漏杀，要么在平时误杀；可调 + 有记录 + 能恢复，才是工程做法。

**Q5** 申诉闭环为什么是风控系统的一部分？

▸ 答案：因为申诉同时提供三样东西：误杀用户的出口（降低流失）、误判样本（校准规则与模型）、以及“误杀率”的真实度量（只看系统日志看不到用户感受）。没有申诉，风控就失去了自我纠错的反馈环。
