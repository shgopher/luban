## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **事件时间** | 事情真正发生的时刻 | 快递单上的发货时间 |
| **处理时间** | 机器看到它的时刻 | 你拆开快递的时刻 |
| **水位线** | 「不会再有更早数据」的进度线 | 地铁末班车，到点就开，不再等人 |
| **窗口** | 把数据流切成一段段统计 | 长纸带剪成一截截 |
| **状态** | 到现在的结论，必须存住 | 记账本上的累计余额 |
| **Checkpoint** | 状态与位点的同一时刻快照 | 游戏存档，死了从存档点重来 |
| **Exactly-once** | 不重不漏，三方同时生效 | 转账：扣钱与到账一起成功 |
| **实时数仓** | 分层持续更新，能被迟到数据改对 | 一直修订的活账本 |

> **四环一根链条：窗口定「切哪段」，水位线定「切完没」，状态定「算到哪」，checkpoint 定「崩了怎么办」**——缺一环，结果就不可信。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「流处理就是把批处理调快」 | 批处理有界可等齐；流处理无界永远等不齐，**必须显式定义「何时算完」** |
| 「接了 Kafka 就算会流处理」 | Kafka 只是传输层。没有窗口、状态、水位线与容错，消费者只是**逐条转发** |
| 「Exactly-once 就是消息只来一次」 | 消息照样可能重发；保证的是状态、位点、输出提交**在同一检查点边界原子生效**，端到端还要 sink |

## 读完自检（入门级 3 题）

**Q1** 机器时间最省事，为什么还要引入水位线？

▸ 答案：处理时间随网络延迟和重放顺序变，同一份数据重跑两次，窗口切得不一样；事件时间定「属于哪段」，水位线定「何时敢宣布完整」，分开才好复现，代价是要等。

**Q2** 从 checkpoint 恢复后，为什么还可能重复输出？

▸ 答案：崩溃前已发出的结果撤不回来；checkpoint 只把状态和位点拉回同一时刻，输出端要靠事务或幂等写跟上，三者对齐才叫端到端。

**Q3** 实时大屏的数比离线报表少，先查哪两处？

▸ 答案：先查窗口是否被水位线提前关掉，迟到数据没进来数就少；再查口径与分层：去重键、维表版本、写入幂等是否和离线一致。
