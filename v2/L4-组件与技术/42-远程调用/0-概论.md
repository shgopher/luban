## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **RPC** | 调另一台机器的函数，写法像本地 | 给隔壁楼同事递话，写成"当面说" |
| **Stub** | 两端各一份替身，负责打包/拆包 | 谈判桌两边各一个翻译 |
| **序列化** | 参数从内存对象变成字节串 | 桌子拆成板材装箱 |
| **字段编号** | 二进制里字段的身份，名字给人看 | 门牌号不变，业主改名照送 |
| **IDL** | 一份定义，两端照它生成 Stub | 双方签同一份合同 |
| **gRPC** | HTTP/2 + Protobuf + 四种流模式 | 多车道高速，同时跑几趟车 |
| **流控** | 窗口限制未确认字节，内存有上界 | 传送带限位开关 |
| **deadline** | 剩余时间预算，随调用链传 | 外卖倒计时 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "RPC 就是把 HTTP 包一层" | 协议只是一段；真正的活在 Stub：序列化、组帧、还原 |
| "字段名就是契约，改名等于改协议" | 编码认编号，名字只给人看：改名安全，改号破坏 |
| "设了超时，请求就结束了" | 超时只是上游不再等，下游可能还在跑；不传 deadline 就有人白干 |

## 读完自检（入门级 3 题）

**Q1** 两端都能拿到参数对象，为什么不能直接把内存里的结构体发过去？

▸ 答案：内存对象带着本机布局和指针，对端读不懂；TCP 是字节流、没有边界。所以要**序列化**成字节、**按帧**切开，收到再**反序列化**。

**Q2** 字段 `name` 改名成 `user_name`，老客户端还能解析吗？编号从 2 改成 3 呢？

▸ 答案：改名通常安全，编码认编号、名字只给人看；改编号一定破坏，老客户端会按旧号解释新字节，字段错位。IDL 就是把编号钉成契约。

**Q3** 调用方 3 秒超时已返回失败，下游日志显示第 5 秒才处理完，问题在哪？

▸ 答案：**deadline 没随调用链传**。上游放弃了，下游还在替没人要的结果干活，再加重试就放大数倍。修法是每跳递减着传，写操作幂等。
