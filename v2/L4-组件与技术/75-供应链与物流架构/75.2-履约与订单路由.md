# 75.2 履约与订单路由 (拆单 / 寻源 / 时效承诺 / 库存分配)

## 一句话

> 履约路由要回答的不是“离客户最近的仓在哪”，而是**在成本、时效、库存三个约束下给出一句能兑现的承诺**：从哪发、拆几包、几天到；拆单、寻源、承诺、分配互为约束，改一个会反噬另外三个。

## 先破三个误区

| 误区 | 现实 |
|---|---|
| 拆单一定更贵 | 本机仿真 200 单：拆单率 23% 的 B 运费/单 50.4 元，只比整单发的 A 贵 0.7 元，却把未履约从 16 单降到 0——A 的便宜是拿 8% 订单不发货换的 |
| 时效承诺 = 距离 ÷ 速度 | 承诺由**截单时间 + 拣货时长 + 承运商时效 + 配送日历**四段拼出来，距离只影响第三段 |
| 有库存就能卖 | 现存量要扣已分配、预占、安全库存；只看现存量时 30 件预占被重复承诺，实测超卖 10 单 |

## 履约四件事一张表

| 动作 | 输入 | 输出 | 关键判据 |
|---|---|---|---|
| 拆单 | 订单行、各仓库存、包装限制 | 子单 / 包裹 | 拆单费 12 元 vs 超时罚 30 元/天 |
| 寻源 | 子单、仓到客户距离、承运商时效 | 发货仓 | 单仓能发全优先，发不全才拆 |
| 承诺 | 截单时间、拣货时长、承运商时效、配送日历 | 承诺送达时间 | 承诺 ≥ 预测 ETA + 缓冲 |
| 分配 | 库存位置、渠道优先级 | 预占 / 扣减 | 看 ATP，不看现存量 |

## 路由：三种目标函数，三种结果

本机仿真 200 单、3 仓、3 SKU，承诺 2 天达；运费 = 首重 8 + 续重 2 元/kg + 0.006 元/km·件 + 操作 3 元/件，每多一个包裹加 12 元拆单费，超 1 天罚 30 元。

| 策略 | 运费/单 | 单均总成本 | 包裹数 | 拆单数 | 超 2 天单数 | 违约金 | 未履约单 |
|---|---|---|---|---|---|---|---|
| A 单仓优先（能整单发才发） | 49.7 元 | 62.2 元 | 184 | 0 | 75 | 3,300 元 | **16** |
| B 时效优先（每行选最快仓） | 50.4 元 | 66.7 元 | 246 | 46 | 77 | 3,270 元 | 0 |
| C 成本优先（含拆单费与罚金） | **49.0 元** | 66.0 元 | 232 | 32 | 81 | 3,390 元 | 0 |

读数：

- **A 最便宜，代价是 16 单不履约**。这 16 单没有任何仓能整单发全，A 选择挂起等补货；62.2 元的成本没算这 8% 订单的客户流失。
- **B 拆得最多、包裹多 34%，运费却只贵 0.7 元**：从远仓整单发的干线运费比分两包近仓发更贵，拆单费被距离差价抵消。
- **C 的总成本不是最低**：它按“单笔最优”决策，但库存被前面订单消耗后，局部最优≠全局最优（序贯分配的顺序依赖）。所以要用“全局库存快照 + 统一分配器”。

> 🔑 拆单判据是**拆单代价 < 不拆的代价**：前者 = 12 元操作 + 多一个首重 + 多一次分拣；后者 = 超时罚金 + 缺货挂起 + 客诉。两者都是钱，别凭感觉“能整单就整单”。

## 库存分配：ATP 才算“可卖”

`ATP = 库存位置 − 预占（未支付/活动锁定）− 安全库存`，其中 `库存位置 = 现存量 + 在途 − 已分配`

| 校验口径 | 放行单数 | 实际可发 | 超卖 |
|---|---|---|---|
| 只看现存量（100 件，每单 3 件） | 33 单 | 23 单 | **10 单 / 30 件** |
| 看 ATP（100 − 预占 30 = 70 件；本仿真已分配/安全库存=0） | 23 单 | 23 单 | 0 |

> 🔑 本节是**口径型超卖**：承诺与扣减用的不是同一个数（现存量 vs ATP）。**并发型超卖**（查询与扣减非原子）见 [67.6 秒杀与抢购](../67-交易与账务/67.6-秒杀与抢购.md)；先统一到 ATP，再用条件更新/唯一约束保证并发下不为负（见 [25.4 幂等设计与去重](../../L1-分布式原理/25-并发、冲突与幂等/25.4-幂等设计与去重.md)）。先统一到 ATP，再用条件更新/唯一约束保证并发下不为负（见 [25.4 幂等设计与去重](../../L1-分布式原理/25-并发、冲突与幂等/25.4-幂等设计与去重.md)）。

## 仿真：三种路由策略与 ATP 口径

程序枚举 8 种仓组合做成本最优，三策略跑同一批 200 单；完整输出在 `tools/examples/75-scm-models/raw-75.2.txt`。 示例说明见 [tools/examples/75-scm-models/](../../../tools/examples/75-scm-models/README.md)。

```go
package main

import (
	"fmt"
	"math/rand"
)

var cities = []string{"上海", "杭州", "广州", "深圳", "北京", "成都"}

// 每行：上海仓、广州仓、天津仓到该城市的距离（km）
var dist = [][]int{
	{20, 1450, 1100},
	{180, 1250, 1250},
	{1450, 20, 2150},
	{1500, 140, 2200},
	{1200, 2150, 130},
	{2000, 1600, 1800},
}
var skus = []string{"A", "B", "C"}

// 各仓各 SKU 现存量：每个仓都有一个 SKU 偏少，制造“整单发不全”
var initial = [][]int{
	{60, 900, 900}, // 华东：A 少
	{900, 60, 900}, // 华南：B 少
	{900, 900, 60}, // 华北：C 少
}
var stock [][]int

type line struct {
	sku string
	qty int
}

type order struct {
	id     int
	city   int
	lines  []line
	pkgNo  int
	days   int
	freight float64 // 包裹成本（含距离运费与操作费）
	missed bool
}

// 时效分档：≤50km 次日、≤500km 2 天、≤1500km 3 天、更远 4 天
func daysOf(km int) int {
	switch {
	case km <= 50:
		return 1
	case km <= 500:
		return 2
	case km <= 1500:
		return 3
	}
	return 4
}

// 单个包裹：首重 8 + 续重 2 元/kg（每件 0.5kg）+ 距离 0.006 元/km·件 + 操作 3 元/件
func parcelCost(km, qty int) float64 {
	return 8 + 2*float64(qty)*0.5 + 0.006*float64(km)*float64(qty) + 3*float64(qty)
}

func idx(s string) int {
	for i, v := range skus {
		if v == s {
			return i
		}
	}
	return -1
}

func genOrders(n int, seed int64) []order {
	r := rand.New(rand.NewSource(seed))
	os := make([]order, n)
	for i := range os {
		os[i].id = i + 1
		os[i].city = r.Intn(len(cities))
		nl := 1 + r.Intn(3)
		used := map[int]bool{}
		for len(os[i].lines) < nl {
			k := r.Intn(3)
			if used[k] {
				continue
			}
			used[k] = true
			os[i].lines = append(os[i].lines, line{skus[k], 1 + r.Intn(4)})
		}
	}
	return os
}

// 策略 A：单仓优先——只找“能整单发全”的仓，按送达最快选；找不到就挂起（不拆单）
func routeSingle(o *order) {
	best, bestDays := -1, 99
	for w := 0; w < 3; w++ {
		ok := true
		for _, l := range o.lines {
			if stock[w][idx(l.sku)] < l.qty {
				ok = false
				break
			}
		}
		if ok && daysOf(dist[o.city][w]) < bestDays {
			best, bestDays = w, daysOf(dist[o.city][w])
		}
	}
	if best < 0 {
		o.missed, o.days = true, 99
		return
	}
	o.pkgNo, o.days = 1, bestDays
	for _, l := range o.lines {
		stock[best][idx(l.sku)] -= l.qty
		o.freight += parcelCost(dist[o.city][best], l.qty)
	}
}

// 策略 B：时效优先——每行独立选“送达最快且有货”的仓，允许拆单
func routeFast(o *order) {
	chosen := map[int]bool{}
	for _, l := range o.lines {
		wi, wd := -1, 99
		for w := 0; w < 3; w++ {
			if stock[w][idx(l.sku)] < l.qty {
				continue
			}
			if d := daysOf(dist[o.city][w]); d < wd {
				wi, wd = w, d
			}
		}
		if wi < 0 {
			o.missed, o.days = true, 99
			return
		}
		chosen[wi] = true
		stock[wi][idx(l.sku)] -= l.qty
		o.freight += parcelCost(dist[o.city][wi], l.qty)
		if wd > o.days {
			o.days = wd
		}
	}
	o.pkgNo = len(chosen)
	if o.pkgNo > 1 {
		o.freight += 12 * float64(o.pkgNo-1) // 拆单附加操作费
	}
}

// 策略 C：成本优先——包裹成本 + 每多 1 个包裹加 12 元拆单费 + 每超 1 天罚 30 元
func routeCost(o *order) {
	bestTotal := 1e18
	bestDays, bestPkg := 99, 0
	var bestAssign []int
	for mask := 1; mask < 8; mask++ {
		assign := make([]int, len(o.lines))
		cost := 0.0
		days, ok := 0, true
		for i, l := range o.lines {
			wi, wd := -1, 99
			for w := 0; w < 3; w++ {
				if mask&(1<<w) == 0 || stock[w][idx(l.sku)] < l.qty {
					continue
				}
				if d := daysOf(dist[o.city][w]); d < wd {
					wi, wd = w, d
				}
			}
			if wi < 0 {
				ok = false
				break
			}
			assign[i] = wi
			cost += parcelCost(dist[o.city][wi], l.qty)
			if wd > days {
				days = wd
			}
		}
		if !ok {
			continue
		}
		used := map[int]bool{}
		for _, w := range assign {
			used[w] = true
		}
		pkgs := len(used)
		if pkgs > 1 {
			cost += 12 * float64(pkgs-1)
		}
		if days > 2 {
			cost += 30 * float64(days-2)
		}
		if cost < bestTotal {
			bestTotal, bestDays, bestPkg, bestAssign = cost, days, pkgs, assign
		}
	}
	if bestPkg == 0 {
		o.missed, o.days = true, 99
		return
	}
	o.pkgNo, o.days = bestPkg, bestDays
	for i, l := range o.lines {
		o.freight += parcelCost(dist[o.city][bestAssign[i]], l.qty)
		stock[bestAssign[i]][idx(l.sku)] -= l.qty
	}
	if bestPkg > 1 {
		o.freight += 12 * float64(bestPkg-1)
	}
}

type agg struct {
	name   string
	freight float64
	pkgs   int
	splits int
	late   int
	pen    float64
	missed int
}

func run(name string, fn func(*order)) agg {
	stock = [][]int{{60, 900, 900}, {900, 60, 900}, {900, 900, 60}}
	os := genOrders(200, 11)
	a := agg{name: name}
	ok := 0
	for i := range os {
		fn(&os[i])
		if os[i].missed {
			a.missed++
			continue
		}
		ok++
		a.freight += os[i].freight
		a.pkgs += os[i].pkgNo
		if os[i].pkgNo > 1 {
			a.splits++
		}
		if os[i].days > 2 {
			a.late++
			a.pen += 30 * float64(os[i].days-2)
		}
	}
	a.freight /= float64(ok)
	return a
}

func main() {
	fmt.Println("200 单、3 仓、3 SKU；承诺 2 天达；运费 = 首重 8 + 续重 2/kg + 0.006 元/km·件 + 操作 3/件")
	fmt.Printf("%-12s %-12s %-13s %-7s %-7s %-12s %-10s %s\n",
		"策略", "运费/单", "单均总成本", "包裹数", "拆单数", "超 2 天单数", "违约金", "未履约单")
	rows := []struct {
		name string
		fn   func(*order)
	}{{"A 单仓优先", routeSingle}, {"B 时效优先", routeFast}, {"C 成本优先", routeCost}}
	for _, r := range rows {
		a := run(r.name, r.fn)
		total := (a.freight*float64(200-a.missed) + a.pen) / 200
		fmt.Printf("%-12s %7.1f 元   %7.1f 元    %5d   %5d      %5d        %4.0f 元    %d\n",
			a.name, a.freight, total, a.pkgs, a.splits, a.late, a.pen, a.missed)
	}

	fmt.Println("\n库存分配口径（SKU Z：现存量 100，已被未支付订单预占 30，在途 0，每单要 3 件）：")
	onHand, reserved := 100, 30
	for _, mode := range []string{"只看现存量", "看 ATP（库存位置-预占；已分配/安全库存=0）"} {
		avail := onHand
		if mode == "看 ATP（现存量-预占+在途）" {
			avail = onHand - reserved
		}
		passed := avail / 3
		shippable := (onHand - reserved) / 3
		fmt.Printf("  %-26s 放行 %2d 单，实际可发 %2d 单，超卖 %2d 单（%d 件）\n",
			mode, passed, shippable, passed-shippable, (passed-shippable)*3)
	}
}
```

## 时效承诺：拆成四段

| 段 | 谁决定 | 典型值 | 风险 |
|---|---|---|---|
| 截单时间 | 仓库作业排班 | 16:00 / 18:00 | 截单后下单多等一天 |
| 拣货打包 | WMS 波次与人力 | 2–6 小时 | 大促爆仓时翻倍 |
| 承运商干线 + 末端 | 承运商时效表 | 同城次日、跨省 2–3 天 | 恶劣天气、分拨积压 |
| 配送日历 | 客户地址与节假日 | 周末是否派送 | 承诺 3 天撞上国庆变 7 天 |

承诺写法：**承诺时间 = 截单后发货时间 + 承运商时效分位数（P90，不是均值）+ 日历缓冲**。用均值承诺一半订单迟到；用 P90 迟到率约 10%，再用赔付兜底。承运商时效分档与轨迹字段以官方文档为准。

## 反模式

| 反模式 | 后果 |
|---|---|
| 让每个仓各自决定发不发 | 全局库存被局部决策吃掉，A 仓缺货、B 仓积压同时发生 |
| 拆单只按距离，不算拆单费 | 一单拆 3 包，运费翻倍，客户收到 3 个到货时间 |
| 用“现存量”做可售判断 | 预占被重复承诺，超卖后只能赔钱或砍单 |
| 承诺时效用均值 | 一半订单迟到，客诉集中在“明明说 3 天” |
| 拆单后各子单独立承诺、不合并展示 | 客户看到 3 个包裹 3 个时间，体验比晚到更差 |
| 库存分配不做冻结/解冻 | 未支付订单长期占用库存，可售量越来越少 |

## 自检

**Q1** 为什么 B 策略拆单更多、包裹更多，运费却只比 A 贵 0.7 元？

▸ 答案：运费由距离与首重共同决定。A 为整单发全常从远仓发货，干线按 0.006 元/km·件计费；B 把每行拆到最近仓，虽多付 12 元拆单费与首重，但距离差价抵消了它。拆单是否更贵，看“远仓干线”与“拆单操作费”谁更大。

**Q2** A 策略单均总成本 62.2 元最低，为什么还说它可能更亏？

▸ 答案：62.2 元只统计了已履约的 184 单，16 单（8%）挂起未发货未计入。这 16 单要么延迟、要么退款，都会产生客诉与流失；按取消损失计入后 A 的真实成本会超过 B。评估路由必须把“未履约”折成钱。

**Q3** 现存量 100、预占 30，为什么“看现存量放行 33 单”会超卖 10 单？

▸ 答案：33 单 × 3 件 = 99 件，看似没超 100；但其中 30 件已被未支付订单预占，实际可发 70 件 = 23 单，多放行的 10 单就是 30 件超卖。校验口径必须与扣减口径一致，否则“库存够”是幻觉。

**Q4** 承诺时效为什么要用 P90 而不是均值？两者差在哪一行？

▸ 答案：P90 承诺的迟到率约 10%，均值承诺的迟到率是 50%。差异不在“平均快慢”，而在**迟到概率**；代价是承诺变长、转化率下降。

**Q5** 一个订单 3 个 SKU，华东仓有 2 个、华南仓有 1 个；华东到客户 1 天、华南 3 天。拆不拆？还需要哪些数才能决定？

▸ 答案：先算不拆：华东发 2 件、华南发 1 件 → 整单 3 天到；或整单等华东补货 → 约 5 天。再算拆的代价：多一个包裹（首重 + 12 元）与两个到货时间。承诺 2 天只能拆并让华南件走空运；承诺 4 天则整单等货更省。缺的数：华东补货时间、拆单费、时效罚金、客户对多包裹的接受度。
