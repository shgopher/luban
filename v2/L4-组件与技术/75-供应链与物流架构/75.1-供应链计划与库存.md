# 75.1 供应链计划与库存 (需求预测 / 补货策略 / 安全库存 / 牛鞭效应)

## 一句话

> 计划层不预测“明天卖几件”，它用三个数决定备多少货：**预测误差的尾部、补货策略的触发频率、需求波动往上游的放大倍数**——安全库存买的是这三条曲线叠加后的尾部，不是一个拍脑袋的百分比。

## 先破三个误区

| 误区 | 现实 |
|---|---|
| 预测越准，库存越少 | 库存由**误差尾部 × 补货周期**决定，不由均值精度决定；本节预测 MAPE 从 16.7% 降到 11.8%，安全库存一分没少 |
| 安全库存拍个百分比 | 它是 `z × σ × √LT` 的乘积：σ=17.8 件、LT=14 天、z=1.65 → 安全库存 110 件、再订货点 1,629 件，三个输入都算得出来 |
| 牛鞭效应是上游不理性 | 本机仿真：每级只按“库存位置低于目标就补足”行动，4 级后末端需求的波动被放大 **10.18 倍**；共享末端需求后降到 4.96 倍——放大来自规则，不来自人品 |

## 需求预测：先判有没有周期，再选方法

| 方法 | 参数 | 实测 MAPE | 实测偏差 | 适用判据 |
|---|---|---|---|---|
| 4 周移动平均 | 窗口 4 天 | 16.7% | -0.4% | 平稳、无周期；会把周末效应一起抹平 |
| 一次指数平滑 | α=0.3 | 14.8% | -2.3% | 有趋势、无强周期；对新数据反应更快 |
| 季节朴素（上周同日） | 滞后 7 天 | **11.8%** | -7.3% | 周周期明显（零售/餐饮/生鲜） |

本节需求：日均 100 件、周末 ×1.3、噪声 σ=12，365 天，358 个评分点（前 7 天预热）。

> 🔑 先看自相关有没有 7 天峰值，再决定要不要季节项。移动平均在强周期数据上必输：它把周末的高峰低谷平均掉，比“照抄上周同日”差 4.9 个百分点。偏差也要单独修：季节朴素偏差 -7.3% 是系统性低估，补货参数必须用偏差修正后的均值，否则再订货点天生偏低。

## 安全库存：一个公式，三个输入

需求波动主导时 `SS = z × σ_d × √LT`；提前期也波动时用 `SS = z × √(LT·σ_d² + d²·σ_LT²)`。

| 输入 | 含义 | 取值来源 | 本节取值 |
|---|---|---|---|
| z | 服务水平系数 | 目标周期服务水平 90%/95%/99% → 1.28/1.65/2.33 | 1.65（95%） |
| σ_d | 日需求标准差 | 历史去趋势、去周期后 | 17.8 件 |
| LT | 补货提前期 | 供应商交期 + 运输 + 入库上架 | 14 天（√14≈3.74） |
| SS | 安全库存 | z×σ×√LT | 110 件 |
| s | 再订货点 | 日均×LT + SS | 108.5×14+110=1,629 件 |

> 🔑 安全库存随 √LT 增长，不随 LT 线性增长：LT 从 14 天缩到 7 天，√LT 从 3.74 降到 2.65，安全库存降 29%，缺货暴露窗口同时减半。**缩短提前期比加大安全库存便宜**——前者降库存，后者只是把库存挪个位置。对接供应商的 EDI/ASN 字段与提前期口径，以对方官方文档为准。

## 补货策略：定量还是定期，差距在“暴露窗口”

| 策略 | 触发 | 参数 | 实测满足率 | 实测平均库存 | 实测缺货天数 | 适用 |
|---|---|---|---|---|---|---|
| (s,Q) 定量 | 每日查库存位置 ≤ s | s=1629，Q=700 | **97.8%** | 460 件 | 8 天 | 波动大、SKU 少、系统能事件驱动 |
| (R,S) 定期 7 天 | 每 7 天补到 S | S=2414 | 95.9% | 589 件 | 15 天 | 供应商按周接单、人工评审 |
| (R,S) 定期 14 天 | 每 14 天补到 S | S=3194 | 93.9% | 963 件 | 22 天 | 长周期、低价值、人工成本敏感 |

同一份需求、同一 z=1.65：评审周期越长，两次评审之间的暴露窗口越大，只能靠更多库存换回满足率——14 天评审要多备 503 件（963 vs 460），满足率还低 3.9 个百分点。

> 🔑 补货策略的坑不在公式，在**库存位置**（在手 + 在途 − 已分配）算错：只用现存量判断会重复下单；把已分配需求漏掉会超卖。库存位置是一个数，不是一张表。

## 仿真：三种预测、三种补货、四级链

程序用固定种子生成需求序列，依次跑预测评分、补货对照与四级链牛鞭；完整输出存 `.cache/domain-75/raw-75.1.txt`。

```go
// main.go —— go1.27.1 darwin/arm64，go run main.go
package main

import (
	"fmt"
	"math"
	"math/rand"
)

// 需求：日均 100，周末 ×1.3，噪声 σ=12
func demand(n int, seed int64) []float64 {
	r := rand.New(rand.NewSource(seed))
	d := make([]float64, n)
	for i := range d {
		w := 1.0
		if i%7 >= 5 {
			w = 1.3
		}
		d[i] = 100*w + r.NormFloat64()*12
	}
	return d
}

// kind：ma=4 周移动平均，ses=指数平滑 α=0.3，sn=季节朴素（上周同日）
func forecast(d []float64, kind string) []float64 {
	f := make([]float64, len(d))
	for i := range d {
		switch {
		case kind == "ma" && i >= 4:
			f[i] = (d[i-1] + d[i-2] + d[i-3] + d[i-4]) / 4
		case kind == "ses" && i > 0:
			f[i] = 0.3*d[i-1] + 0.7*f[i-1]
		case kind == "sn" && i >= 7:
			f[i] = d[i-7]
		default:
			f[i] = d[0]
		}
	}
	return f
}

func score(d, f []float64) (m, b float64) {
	for i := 7; i < len(d); i++ { // 前 7 天预热，不评分
		m += math.Abs(d[i]-f[i]) / d[i]
		b += d[i] - f[i]
	}
	n := float64(len(d) - 7)
	return 100 * m / n, 100 * b / n
}

// kind=sQ：库存位置 ≤ s 时订 Q；kind=rs：每 R 天补到 S。lost sales 口径
func sim(kind string, s, Q, S float64, R int, d []float64, lt int) (fill, inv float64, stock, orders int) {
	onHand := 700.0
	onOrder := make([]float64, lt+1)
	last := 0
	for t := range d {
		onHand += onOrder[t%len(onOrder)]
		onOrder[t%len(onOrder)] = 0
		ship := math.Min(onHand, d[t])
		onHand -= ship
		if ship < d[t] {
			stock++
		}
		fill += ship
		ip := onHand + sum(onOrder) // 库存位置 = 在手 + 在途（本节 lost-sales，已分配=0）
		var place float64
		if kind == "sQ" && ip <= s {
			place = Q
		}
		if kind == "rs" && t-last >= R {
			last = t
			place = S - ip
		}
		if place > 0 {
			onOrder[(t+lt)%len(onOrder)] += place
			orders++
		}
		inv += onHand
	}
	return 100 * fill / sum(d), inv / float64(len(d)), stock, orders
}

func sum(a []float64) float64 {
	s := 0.0
	for _, v := range a {
		s += v
	}
	return s
}

// 4 级链：每级 order-up-to + 12 期移动平均，提前期 2；shared 时各级都看末端需求
func chain(shared bool) []float64 {
	const tiers, n, lt, win = 4, 600, 2, 12
	r := rand.New(rand.NewSource(7))
	end := make([]float64, n)
	for i := range end {
		end[i] = math.Max(0, 100+r.NormFloat64()*12)
	}
	dem := append([]float64(nil), end...)
	out := make([]float64, tiers)
	for k := 0; k < tiers; k++ {
		orders := make([]float64, n)
		ip := 100.0 * (lt + 1)
		for t := 0; t < n; t++ {
			ip -= dem[t]
			base := dem[:t+1]
			if shared && k > 0 {
				base = end[:t+1]
			}
			hat := 100.0
			if t >= win {
				hat = sum(base[t+1-win:t+1]) / win
			}
			q := math.Max(0, hat*float64(lt+1)+1.65*12*math.Sqrt(lt+1)-ip)
			orders[t] = q
			ip += q
		}
		out[k] = variance(orders[50:]) / variance(end[50:])
		dem = orders
	}
	return out
}

func variance(a []float64) float64 {
	m, s := 0.0, 0.0
	for _, v := range a {
		m += v
	}
	m /= float64(len(a))
	for _, v := range a {
		s += (v - m) * (v - m)
	}
	return s / float64(len(a))
}

func main() {
	d := demand(365, 42)
	meanD, sdD := sum(d[:200])/200, 0.0
	for _, v := range d[:200] {
		sdD += (v - meanD) * (v - meanD)
	}
	sdD = math.Sqrt(sdD / 200)
	fmt.Printf("需求序列：365 天，前 200 天均值 %.1f 件/天，标准差 %.1f 件/天\n\n", meanD, sdD)

	fmt.Println("预测方法（提前 1 天，358 个评分点）：")
	for _, k := range []string{"ma", "ses", "sn"} {
		m, b := score(d, forecast(d, k))
		fmt.Printf("  %-4s MAPE %5.1f%%   偏差 %+5.1f%%\n", k, m, b)
	}

	lt, z := 14, 1.65
	s := meanD*float64(lt) + z*sdD*math.Sqrt(float64(lt))
	S7 := meanD*float64(7+lt) + z*sdD*math.Sqrt(float64(7+lt))
	S14 := meanD*float64(14+lt) + z*sdD*math.Sqrt(float64(14+lt))
	fmt.Printf("\n补货策略（提前期 %d 天，z=1.65；s=%.0f S(7)=%.0f S(14)=%.0f）：\n", lt, s, S7, S14)
	fmt.Printf("%-20s %-8s %-10s %-9s %s\n", "策略", "满足率", "平均库存", "缺货天数", "订货次数")
	for _, c := range []struct {
		name, kind string
		s, Q, S    float64
		R          int
	}{
		{"(s,Q) 每日检查", "sQ", s, 700, 0, 0},
		{"(R,S) 每 7 天", "rs", 0, 0, S7, 7},
		{"(R,S) 每 14 天", "rs", 0, 0, S14, 14},
	} {
		fill, inv, stock, orders := sim(c.kind, c.s, c.Q, c.S, c.R, d, lt)
		fmt.Printf("%-20s %5.1f%%  %6.0f 件  %5d 天   %d 次\n", c.name, fill, inv, stock, orders)
	}

	fmt.Println("\n牛鞭效应（4 级链，MA(12)，提前期 2）：")
	own, sh := chain(false), chain(true)
	prev := 1.0
	for k := 0; k < 4; k++ {
		inc := own[k] / prev
		fmt.Printf("  第 %d 级：本级 %.2fx  相对末端 %.2fx  共享信息后 %.2fx\n", k+1, inc, own[k], sh[k])
		prev = own[k]
	}
}
```

读数：

- **预测**：季节朴素 11.8% 最好，但偏差 -7.3%；选方法看“周期是否存在”，选参数看“偏差是否被修正”。
- **补货**：评审周期从 7 天拉到 14 天，库存多 63%、满足率低 2 个百分点；(s,Q) 用每天检查换来了最低库存与最高满足率。
- **牛鞭**：每级环比放大 1.62 → 1.75 → 1.86 → 1.94 倍，四级累计 **10.18 倍**；只做信息共享（各级都看末端需求）就降到 **4.96 倍**，放大降约 2.05 倍。

## 牛鞭效应：四个成因，四个对策

| 成因 | 机制 | 仿真里的表现 | 对策 |
|---|---|---|---|
| 需求信号处理 | 每级拿“自己收到的订单”做预测，而不是终端需求 | 第 2 级对着第 1 级的订单做移动平均 | 共享终端需求（CPFR / VMI） |
| 批量订货 | 凑单、凑车、凑折扣 | 订单流出现成串的 0 与大单 | 降低最小起订量、提高订货频率 |
| 价格波动 | 促销导致提前采购 | 需求序列出现人为脉冲 | 天天平价、限制促销深度 |
| 短缺博弈 | 缺货时多下单占额度 | 缺货后订单报复性放大 | 按历史销量分配、限量供应 |

> 🔑 对策性价比排序：**信息共享 > 缩短提前期 > 减小批量 > 平抑价格**。信息共享不动库存就把放大降 2.05 倍（约 51%）；后三条都要改流程或让利，落地成本高一个量级。

## 反模式

| 反模式 | 后果 |
|---|---|
| 用“月度销量均值”直接当安全库存 | 均值不含波动，缺货集中在旺季，A 类商品先断 |
| 预测用移动平均而不看周期 | 周末高峰被平均掉，MAPE 比季节朴素差 4.9 个百分点 |
| 补货判断只看现存量 | 在途订单重复下，库存爆仓；漏掉已分配则超卖 |
| 为了“降低缺货”无限加大 z | z 从 1.65 到 2.33，安全库存 +41%，满足率几乎不动 |
| 只考核满足率，不考核缺货时长 | 缺货集中在一周也能被月均掩盖（(R,S) 22 天缺货仍“93.9%”） |
| 把牛鞭效应归因于供应商不理性 | 真正病因在预测、批量、促销与短缺博弈，换供应商解决不了 |
| 用同一个服务水平系数覆盖所有 SKU | A 类缺货代价高、C 类滞销代价高，一刀切必然一头爆仓一头断货 |

## 自检

**Q1** 同一份需求，为什么 (s,Q) 比 (R,S) 平均库存低 129 件还能把满足率做到高 1.9 个百分点？

▸ 答案：(s,Q) 每天都看库存位置，一低于再订货点就补，暴露窗口只有提前期本身；(R,S) 要等到评审日才补，暴露窗口 = 提前期 + 评审周期。用更多库存（或更高 S）才能补上评审周期这段“看不见的缺口”，所以定期评审天然更费库存。

**Q2** 安全库存从 14 天提前期缩到 7 天，为什么只降 29% 而不是降一半？

▸ 答案：公式里是 √LT：SS ∝ √14 ≈ 3.74 → √7 ≈ 2.65，比值 0.71，只降 29%。需求波动在更长的窗口里互相抵消，所以安全库存对提前期是次线性关系；但缺货暴露时长是按 LT 线性缩短的，这正是“缩提前期”一箭双雕的原因。

**Q3** 季节朴素 MAPE 11.8%、偏差 -7.3%，这两个数一起说明什么？补货参数该怎么改？

▸ 答案：MAPE 说明“单日误差小”，偏差说明“方向性低估”。补货用的均值必须乘 1.073 修正，否则再订货点每天少备 7% 的量，长期累积就是周期性缺货；同时安全库存仍按误差尾部算，不能拿修正均值替代。

**Q4** 4 级链累计放大 10.18 倍，是不是说明仿真夸大？怎么用它判断真实风险？

▸ 答案：放大倍数由参数决定（预测窗口、提前期、安全系数），不是常数；10.18 倍是“每级都用 12 期移动平均、提前期 2、z=1.65”这组参数下的结果。真实价值在相对比较：同一组参数下共享末端需求降到 4.96 倍，说明信息共享能吃掉约 51% 的放大，这是可以拿去做方案论证的量级。

**Q5** 一个 SKU 日均 100 件、日标准差 20 件、提前期 10 天、目标 95% 服务水平，再订货点是多少？若供应商把交期压到 5 天呢？

▸ 答案：s = 100×10 + 1.65×20×√10 ≈ 1,000 + 104 = 1,104 件；交期 5 天时 s = 500 + 1.65×20×√5 ≈ 500 + 74 = 574 件，再订货点降 48%，同时安全库存从 104 降到 74。注意库存位置要扣在途与已分配，不能拿现存量直接和 s 比。
