                        75.5 逆向与异常 (退货 / 换货 / 异常件 / 赔付)

                        一句话

                        逆向不是“退货流程”，而是一个成本中心：每退一单要花多少处理费、能回收多少货值、几天回到可售库存——三个数决定该不该接这单退货；本节实测按原因分级处置比“全部回中心仓”少损失 28%，靠的不是更快的物流，而是把 65% 的退货留在离客户最近的节点处理。

                        先破三个误区

                        误区 现实
                        退货是“小概率事件”，不值得建系统 退货率 8% 意味着每 12.5 单就有 1 单逆向；本节 10,000 单产生 800 单退货，逆向净损失 4.4–6.1 万元
                        退货越快越好 快不等于省：全部空运回中心仓，处理时长 5 天、净损失 61,200 元；分级处置 3 天、净损失 44,282 元
                        仅退款是“吃亏” 低货值商品退货处理费 17 元、回收约 40.5%，货值低于 42 元时仅退款反而更省

                        五种逆向：触发条件不同，成本结构不同

                        类型 触发 货回不回来 成本大头 适用判据
                        仅退款 低货值、生鲜、明显质量问题 不回 货值（白送） 退货处理费 > 可回收货值
                        退货退款 7 天无理由、尺码不符 回 逆向运费 + 质检 货值较高、可二次销售
                        换货 质量瑕疵、发错货 回 + 再发 逆向运费 + 正向运费 换货成本 < 退款损失
                        维修 保修期内功能故障 回 维修工时 + 备件 维修成本 < 换新成本
                        拒收 到货即拒、地址异常 回 双向运费 拒收率高的区域要查地址质量

                        🔑 逆向决策的分界线是**“处理成本 vs 可回收货值”**，不是“客户满意度”或“公司规定”。按本节参数（处理成本 17 元、回收率 40.5%），货值 42 元是盈亏平衡点：低于它仅退款更省，高于它退货更省。

                        处置分级：质检结果决定去向

                        分级 判据 去向 回收率（相对货值）
                        A 品 包装完好、功能正常 区域退货仓直检直发，二次销售 95%（按 60 元再售）
                        B 品 轻微瑕疵、可降级 降级渠道/员工内购 50%
                        C 品 功能故障 返厂维修或供应商承担 50%
                        报废 破损、污染、效期过 就地报废 + 承运商理赔 30%（赔付）
                        供应商直退 质量问题、批次问题 退回供应商，供应商承担 50%

                        🔑 决定净损失的是分级规则，不是物流速度。把“无理由/尺码”这类占 65% 的退货留在离客户最近的区域退货仓直检直发，逆向成本从 17 元降到 8 元，回收率从 40.5% 升到 51.7%。

                        逆向成本构成：钱花在哪

                        项 单件成本 说明
                        逆向运费 8–12 元 区域退货仓 8 元，回中心仓 12 元
                        质检 3 元 逐件开箱、功能测试
                        上架/重新包装 2 元 可二次销售才发生
                        货值损失 货值 ×(1−回收率) 最大头，靠分级与再售渠道压
                        赔付 按规则 丢件按保价、破损按货值比例、超时按单

                        实测（本机仿真，10,000 单、退货率 8%、货值 100 元/件，800 单退货）：

                        策略 逆向成本 回收价值 货值回收率 净损失 平均处理天数
                        A 全部回中心仓质检 13,600 元 32,400 元 40.5% 61,200 元 5.0 天
                        B 按原因分级处置 5,637 元 41,355 元 51.7% 44,282 元 3.0 天

                        B 比 A 少损失 16,918 元（28%），处理时长缩短 2 天。关键在“无理由/尺码”两类（占 65%）不回中心仓。

                        异常件：先定责，再谈赔付

                        异常 识别方式 定责依据 赔付口径示例
                        丢件 轨迹超时未更新 + 查询无果 承运商责任/仓库漏发 按保价金额；未保价按运费倍数或平台规则
                        破损 签收验货、照片 包装责任/承运商暴力分拣 按货值 80% 或维修价
                        超时 ETA 超承诺 承运商时效 5 元/单（延迟 1–3 天）
                        拒收 签收失败 地址/客户原因/商品原因 双向运费由责任方承担
                        地址异常 派送失败 客户填写错误 改址费或退回

                        实测 50 单异常（丢 10 / 破损 20 / 超时 20）赔付合计 4,700 元：丢件 3,000 元、破损 1,600 元、超时 100 元；同期正向运费按 8 元/单计为 80,000 元，赔付占运费 5.9%。

                        🔑 赔付规则必须版本化 + 可解释：每一笔赔付都能回答“按哪条规则、依据哪张凭证、谁审的”。以平台规则与承运商官方赔付条款为准；规则变更要有生效日期，否则历史工单无法复核。

                        仿真：两种逆向策略与赔付成本

                        程序按原因分布生成 800 单退货并对比“全部回中心仓”与“按原因分级处置”；完整输出在 tools/examples/75-scm-models/raw-75.5.txt。 示例说明见 tools/examples/75-scm-models/。

                        package main

import (
	"fmt"
	"math/rand"
)

const (
	orderN   = 10000 // 订单数
	returnR  = 0.08  // 退货率
	goodsVal = 100.0 // 单件货值/售价（元）
)

// 退货原因分布（合计 100%）
type reason struct {
	name   string
	share  float64
	cost   float64 // 逆向物流 + 质检 + 上架成本（元/件）
	recov  float64 // 回收价值（元/件）：再售、供应商承担、承运商赔付
	days   float64 // 处理时长（天）
	resale float64 // 可再次销售的比例
}

var reasons = []reason{
	{"无理由 / 不喜欢", 0.45, 8, 57, 2, 0.95}, // 区域退货仓直检直发
	{"尺码 / 参数不符", 0.20, 8, 57, 2, 0.95}, // 同上
	{"质量问题", 0.20, 4, 50, 7, 0.00},      // 退回供应商，供应商承担
	{"运输破损", 0.10, 2, 30, 1, 0.00},      // 就地报废，承运商赔付
	{"其他", 0.05, 17, 40, 5, 0.40},       // 回中心仓质检
}

func main() {
	returns := int(orderN * returnR)

	// 策略 A：全部退回中心仓，统一质检、上架、再处置
	costA := 17.0 * float64(returns) // 12 运费 + 3 质检 + 2 上架
	recovA := 0.0                    // 55% 按 60 元再售、25% 降级按 30 元
	recovA = 0.55*60*float64(returns) + 0.25*30*float64(returns)
	lossA := goodsVal*float64(returns) - recovA + costA

	// 策略 B：按原因分级处置，只有“其他”回中心仓
	r := rand.New(rand.NewSource(2026))
	costB, recovB, daysB := 0.0, 0.0, 0.0
	// 先做一次随机分配，得出各原因的件数（分布稳定，随机只影响 ±1 件）
	counts := make([]int, len(reasons))
	for i := 0; i < returns; i++ {
		x := r.Float64()
		sum := 0.0
		for k := range reasons {
			sum += reasons[k].share
			if x <= sum {
				counts[k]++
				break
			}
		}
	}
	for k, rs := range reasons {
		n := float64(counts[k])
		costB += rs.cost * n
		recovB += rs.recov * n
		daysB += rs.days * n
	}
	lossB := goodsVal*float64(returns) - recovB + costB

	fmt.Printf("订单 %d 单、退货率 %.0f%% → %d 单退货；货值 %.0f 元/件\n\n", orderN, returnR*100, returns, goodsVal)
	fmt.Printf("退货原因：")
	for k := range reasons {
		fmt.Printf("%s %.1f%%(%d 件)  ", reasons[k].name, reasons[k].share*100, counts[k])
	}
	fmt.Println()

	fmt.Printf("\n%-26s %-11s %-11s %-12s %-13s %s\n",
		"策略", "逆向成本", "回收价值", "货值回收率", "净损失", "平均处理天数")
	fmt.Printf("%-26s %8.0f 元  %8.0f 元   %5.1f%%     %10.0f 元   %4.1f 天\n",
		"A 全部回中心仓质检", costA, recovA, 100*recovA/(goodsVal*float64(returns)), lossA, 5.0)
	fmt.Printf("%-26s %8.0f 元  %8.0f 元   %5.1f%%     %10.0f 元   %4.1f 天\n",
		"B 按原因分级处置", costB, recovB, 100*recovB/(goodsVal*float64(returns)), lossB, daysB/float64(returns))
	fmt.Printf("\nB 比 A 少损失 %.0f 元（%.0f%%），处理时长缩短 %.1f 天；关键在“无理由/尺码”直检直发，不回中心仓\n",
		lossA-lossB, 100*(lossA-lossB)/lossA, 5.0-daysB/float64(returns))

	// 异常件赔付：50 单异常（丢 10 / 破损 20 / 超时 20）
	type claim struct {
		name  string
		n     int
		each  float64
		basis string
	}
	claims := []claim{
		{"丢件", 10, 300, "按保价 300 元赔"},
		{"破损", 20, goodsVal * 0.8, "按货值 80% 赔"},
		{"超时", 20, 5, "5 元/单（延迟 1~3 天）"},
	}
	fmt.Println("\n异常件赔付（50 单异常：丢 10 / 破损 20 / 超时 20）：")
	fmt.Printf("%-8s %-6s %-10s %-12s %s\n", "类型", "件数", "单件赔付", "赔付合计", "依据")
	total := 0.0
	for _, c := range claims {
		total += float64(c.n) * c.each
		fmt.Printf("%-8s %-6d %7.1f 元  %8.1f 元   %s\n", c.name, c.n, c.each, float64(c.n)*c.each, c.basis)
	}
	fmt.Printf("合计 50 单赔付 %.0f 元；同期正向运费按 8 元/单计为 %.0f 元，赔付占运费 %.1f%%\n",
		total, 8*float64(orderN), 100*total/(8*float64(orderN)))
}

                        读数：

                        • 分级处置把逆向成本从 13,600 元压到 5,637 元（-59%），回收价值从 32,400 元升到 41,355 元（+28%）。
                        • 净损失 = 货值损失 + 处理成本 − 回收价值：A 为 80,000 − 32,400 + 13,600 = 61,200 元；B 为 80,000 − 41,355 + 5,637 = 44,282 元。
                        • 处理天数由 5 天降到 3 天，主要来自“不回中心仓”省掉的干线在途。

                        换货 vs 退款：一张算账单

                        设货值 100 元、A 策略净损失 76.5 元/单（61,200 ÷ 800），换货成本 = 逆向运费 8 + 质检 3 = 11 元/单，再发正向运费 8 元 = 19 元/单：

                        处理方式 直接成本 货值损失 净损失 结论
                        退款不换货 0 100 − 40.5 = 59.5 59.5 元 客户流失
                        换货 19 元 原货可再售，损失 ≤ 货值 50% 约 19 + 50 = 69 元 保留订单与客户
                        仅退款（货值 <42 元） 0 货值 货值 低货值最优

                        🔑 换货与退款的比较要看全生命周期：退款损失的是“这一单的钱”，换货损失的是“这一次的物流费 + 可能的二次折价”，但保住了客户与复购。低货值场景反过来——仅退款比任何逆向物流都便宜。

                        反模式

                        反模式 后果
                        所有退货都回中心仓 逆向成本高 59%，处理时长多 2 天（本节实测 13,600 vs 5,637 元）
                        质检标准靠人拍脑袋 同一件货今天判 A 明天判 C，再售与报废口径混乱
                        赔付规则写在 Word 里 工单审核口径不一，无法解释，无法复核
                        只统计退货率，不统计逆向成本 退货率 8% 看似正常，净损失 44,282 元没人负责
                        异常件不做根因归类 丢件、破损、超时混在一个池子里，改进无从下手
                        低货值商品也走退货流程 处理成本 17 元 > 回收 40.5%×货值，越退越亏
                        退货退款与换货共用一个库存池 可再售的 A 品被当成报废，回收率虚低

                        自检

                        Q1 为什么“全部回中心仓”净损失 61,200 元而“分级处置”只有 44,282 元？差额主要来自哪一项？

                        ▸ 答案：差额 16,918 元来自两项：逆向成本少 7,963 元（13,600 → 5,637，因为 65% 的退货留在区域退货仓）与回收价值多 8,955 元（32,400 → 41,355，因为直检直发提高了可再售比例）。处理天数缩短是附带收益，不是净损失差额的主体。

                        Q2 货值 42 元的分界线怎么来的？

                        ▸ 答案：退货净损失 = 处理成本 + 货值 − 回收价值；仅退款净损失 = 货值。两者相等时：处理成本 = 回收价值 = 回收率 × 货值 → 17 = 0.405 × 货值 → 货值 ≈ 42 元。低于 42 元，仅退款的“白送货值”比重更大；高于 42 元，退货回收更划算。回收率与处理成本一变，这条线就要重算。

                        Q3 赔付 4,700 元只占运费 5.9%，是不是说明异常处理“很便宜”？

                        ▸ 答案：不是。5.9% 是“已识别异常”的赔付；异常的真实成本还包括客服工时、重发/补发、客户流失与平台处罚。丢件 10 单赔 3,000 元，单件 300 元，已接近 3 单的货值；要按“每类异常的全成本”评估，而不是只看赔款。

                        Q4 为什么逆向流程要按“原因”分流而不是按“金额”分流？

                        ▸ 答案：原因是处置方式的决定变量：无理由/尺码 → 直检直发；质量问题 → 供应商承担；破损 → 报废理赔。金额只决定“值不值得退”，不决定“退回哪里、谁来承担”。按金额分流会把可直发的 A 品送进中心仓，回收率直接掉一半。

                        Q5 一个退货率 8%、客单价 100 元、逆向净损失率 55% 的品类，如何把逆向成本降 20%？

                        ▸ 答案：三条路径，按性价比排序：① 把“无理由/尺码”搬到区域退货仓直检直发（本节 -59% 逆向成本、+11pp 回收率）；② 低货值订单改仅退款（省掉 8–17 元物流与质检）；③ 把破损/丢件按根因归类，压承运商与包装。前两条不动物流网络，改规则即可；第三条需要供应链协同。量化目标是“净损失/成交额”从 0.55% 降到 0.44%（按 8% × 55% 折算）。
