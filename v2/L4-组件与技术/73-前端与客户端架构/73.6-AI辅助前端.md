# 73.6 AI 辅助前端：从 AI Slop 到可验收

## 一句话

> 模型默认输出「统计上最常见的 SaaS 页」——靛蓝紫、Inter、居中 Hero、三等分卡片；前端 Skill 的第一作用是**禁止**这些统计惯性，第二才是审美。生产上「好看」和「合格」是两条验收线：前者靠视觉方向，后者靠无障碍、键盘、触控与降级。

## 先破除五个误区

| 误区 | 现实 |
|---|---|
| 提示词说「高级感」就行 | 模型不知道什么是「高级」，只知道什么是「常见」；不给禁令，它向均值收敛 |
| 生成即上线 | 截图好看不等于能验收：焦点、键盘、aria、reduced-motion、触控热区都要单独过 |
| 一个 Skill 管所有页面 | 视觉冲击、生产可用、稳定量产、动效质感是四种能力，常常要组合 |
| 截图好看 = 好用 | 动效、Toast、校验、危险操作确认都在截图之外，必须真实交互 |
| 设计系统可以全交给 AI | AI 能给候选，不能替团队定品牌、组件边界与长期一致性 |

## AI Slop 的五件套

一份对照实验（10 个任务 × 8 个变体 = 80 个产物）里，不加任何 Skill 的对照组高度收敛：

| 维度 | 默认输出 |
|---|---|
| 主色 | 靛蓝 / 紫 / 蓝紫渐变 |
| 字体 | Inter 或 Noto Sans SC |
| Hero | 居中大标题 + 副标题 + 两个 CTA |
| 特性区 | 三等分卡片网格 |
| 图标 | emoji 或 lucide 默认款 |

这不是某个模型的缺陷，是统计：训练语料里这种页面最多，采样自然往最大似然处走。**换模型、换提示词，骨架不变**。

所以有效手段不是「教它什么是好设计」，而是**列禁令**：禁用惯用字体、禁用紫渐变、禁用居中构图、禁用「革命性/颠覆性/智能」这类套话。禁令打掉统计惯性，模型才被迫往别处找路。

## 六个 Skill：六种工序，不是六选一

| Skill | 定位 | 核心机制 | 长板 | 短板 |
|---|---|---|---|---|
| **frontend-design**（Anthropic） | 视觉冒险家 | 先选一个极端审美方向，再回答「什么让人记住」 | 记忆点最强，开放命题下断层领先 | 跨页风格容易跳跃，不擅长统一体系 |
| **web-design-guidelines**（Vercel） | 验收审计 | 拉取 Web Interface Guidelines，逐条对照，输出 `file:line` | a11y、键盘、焦点、移动端触控最全 | 不负责「惊艳」，管的是合格 |
| **ui-ux-pro-max** | 数据库驱动 | 161 套配色 + 57 组字体，先检索风格再落地 | 下限最稳、可复现，适合团队规模化 | 上限不如自由发挥 |
| **taste-skill** | 反模板纪律 | 1200 行 pre-flight 清单，连营销用词都禁 | 反模板最严；开放命题会主动提高冒险度 | 约束强，可能不适合强品牌规范 |
| **impeccable** | 确定性 polish | OKLCH 色彩种子、brand/product 分流、`detect.mjs` 45 条规则 | 可重复、能真实修违规，适合上线前门禁 | 是后置工序，不负责从零生成 |
| **emil-design-eng** | 动效工匠 | 统一缓动、入场、stagger、按压反馈、hover 防误触 | 交互质感最好，移动端手感强 | 静态截图几乎看不出价值 |

> 数据与实验来自 [《AI 时代的软件工程》第 40 章](https://se.rpcx.io/40.html)；安装方式与规则以各仓库 README 为准，版本会漂。

## 实验里最值得带走的四条

那场 10×8 的对比实验，比「哪个 Skill 最好」更有价值的是四条结论：

1. **Skill 的第一作用是禁止，不是教学。** 效果最好的两个（frontend-design、taste-skill）核心都是负面清单；禁令比正面示范更能打破统计惯性。
2. **「好看」和「合格」是两条赛道。** frontend-design 赢截图；web-design-guidelines 赢验收（skip-link、aria-sort、`tabular-nums`、`text-wrap: balance`、`reduced-motion`、焦点陷阱、Esc 关闭、焦点返还）。生产里应当**先设计、后审计**。
3. **数据库检索 ≈ 稳定的中上水平。** ui-ux-pro-max 把「选风格」从概率采样变成检索，上限不惊艳但下限最稳，适合多项目/多人协作。
4. **动效的价值在截图之外。** emil-design-eng 的静态布局和对照组差距不大，但交互后差异明显；评估必须真实点一遍，不能只看缩略图。

## 选型：按交付目标查

| 你的目标 | 首选 | 叠加 |
|---|---|---|
| 营销页、作品集，要视觉冲击 | frontend-design 或 taste-skill | web-design-guidelines 做验收 |
| 产品 UI、后台、无障碍验收 | web-design-guidelines | impeccable 做上线前 polish |
| 多项目、多人协作，要稳定下限 | ui-ux-pro-max | 团队设计 token + review |
| 组件库、App，要交互质感 | emil-design-eng | impeccable 的 detect 门禁 |
| 已有页面，只想抛光 | impeccable | 先跑 detect，再按规则修 |
| 开放命题（404、活动页） | taste-skill 或 frontend-design | 人工定品牌边界，防跨页跳跃 |

一个务实的流水线：

```text
定品牌 token（字体/色板/间距/圆角）
  → 生成（frontend-design / taste / ui-ux-pro-max）
  → 验收审计（web-design-guidelines：a11y/键盘/触控/降级）
  → 抛光（impeccable detect + polish）
  → 动效（emil-design-eng，交互密集页）
  → 人审：截图 + 真实交互 + 设计系统一致性
```

## 接进仓库：把「品味」变成约束

AI 前端要稳定，不能每次靠提示词。把约束写进仓库，让 Agent 每次都读到：

```text
禁用：
- Inter / Roboto / 默认 Noto 作为品牌字体（除非设计系统明确指定）
- 紫蓝渐变、居中 Hero、三等分特性卡片作为默认版式
- emoji 当功能图标
- 「革命性 / 颠覆性 / 智能」这类营销套话
- transition: all、无 reduced-motion 兜底的动画

必须：
- 品牌字体与色板来自 design tokens
- 键盘可走通、focus-visible 可见、Esc 能关弹层
- 触控目标 ≥ 44px，表单有 inputmode / autocomplete
- loading / empty / error 三态都有
- 深色模式与 200% 缩放不破版
```

配套三件事：

1. **设计 token 进代码**：字体、色板、间距、圆角、动效曲线，不要让 Agent 每次自由发挥。
2. **验收清单进 PR 模板**：a11y、键盘、触控、降级、三态；截图只是附件，不是证据。
3. **评估要交互**：向导校验、危险操作确认、Toast 时序、移动端手势，必须真实点一遍；只看截图会低估动效类 Skill，也会高估「好看但不可用」的页面。

## 反模式

| 反模式 | 后果 |
|---|---|
| 只写「做得好看一点」 | 模型回到统计均值，产出 AI Slop |
| 六个 Skill 同时开 | 规则互相打架，风格不统一 |
| 生成完直接上线 | 焦点、键盘、aria、reduced-motion 全漏 |
| 只看截图验收 | 动效、交互、错误态全没测 |
| 让 AI 决定品牌 | 每页都「有记忆点」，合起来不像一个产品 |
| 设计 token 不落代码 | 每次生成都漂移，review 无法收敛 |
| 把 a11y 留到最后 | 返工成本最高，很多问题要改结构 |

## 自检

**Q1** 为什么「告诉模型什么是好设计」不如「告诉它什么不许用」？

▸ 答案：模型的默认输出是训练语料的统计均值；正面描述「高级、简洁」没有可执行边界，它仍会回到最常见配方。负面清单（禁字体、禁紫渐变、禁居中、禁套话）直接切断高概率路径，迫使它去别处采样，效果更稳定。

**Q2** 「好看」和「合格」分别该由什么保证？

▸ 答案：好看由视觉方向类 Skill（frontend-design / taste-skill）和品牌 token 保证；合格由验收类工具与清单（web-design-guidelines、a11y/键盘/触控/reduced-motion 检查）保证。两者是不同赛道，生产项目应「先设计、后审计」，不能用一个替代另一个。

**Q3** 为什么动效类 Skill 不能只看截图评估？

▸ 答案：动效价值在时序与交互：缓动、入场、stagger、按压反馈、Toast 消失、可中断 toggle，静态截图都看不到。必须真实交互、录屏或浏览器实测；只看缩略图会严重低估它，也会误判「静态好看但交互糟糕」的方案。

**Q4** 团队要把 AI 前端接进仓库，最小要做哪三件事？

▸ 答案：① 设计 token 落代码（字体/色板/间距/圆角/动效曲线）；② 把禁用清单和验收清单写进 Agent 指令与 PR 模板；③ 评估必须包含真实交互与 a11y，不只截图。三件事缺一件，产出就会随提示词和模型版本漂移。

**Q5** 为什么「一个 Skill 包打天下」在前端不成立？

▸ 答案：前端至少有三类不同目标：视觉冲击（营销）、验收合格（产品/a11y）、交互质感（动效/移动端），它们的规则经常冲突。正确做法是按工序组合：生成 → 审计 → 抛光 → 动效，每步一个主 Skill，最后由人做一致性判断。
