## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **秒杀** | 同一秒把大量读写压到同一件商品上 | 全城人挤一家只开一扇门的店 |
| **超卖** | 卖出的比库存多，扣成负数 | 100 张票卖给了 130 个人 |
| **少卖** | 货还在，库存被锁死 | 座位占着没人来 |
| **限购** | 按商品和个人限制能买几件 | 每人限领一份的试吃摊 |
| **防刷** | 把脚本的“合法请求”挡在业务外 | 实名验票，专挡黄牛 |
| **削峰** | 把瞬时高峰摊平，让下游匀速处理 | 水库蓄洪，慢慢放水 |
| **分层过滤** | 每层只放行下一层接得住的量 | 一道道安检，逐层筛人 |
| **QPS** | 每秒请求数，流量的尺子 | 每分钟进闸机的人数 |

> 记住**“四个约束 + 漏斗”**：超卖、少卖、被刷、雪崩，各对应漏斗的一层或库存的一条规矩。

## 一张图：这章的骨架

```
    同一秒，所有人抢同一件商品：百万级 QPS 砸向一行库存
                          │
                          ▼
   ┌──────────── 外  层 ────────────┐
   │  DNS / 安全  │  网关  │  Web   │  ← 每层只放行下一层接得住的量
   └───────┬───────────┬───────┬────┘
           ▼           ▼       ▼
        拦刷子       限购     排队削峰
       （防刷）    （过滤网） （匀速放行）
           │           │       │
           └───────────┴───┬───┘
                           ▼
               库存扣减：判断与扣减必须原子
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
     不超卖             不少卖             不雪崩
   条件更新/行锁       超时回补         隔离 + 兜底
```

- **上半张是“挡”**：流量由外到内变细，每层只做一件事；
- **下半张是“守”**：判断与扣减必须原子，松一环就超卖；
- **右边是“退”**：兜底保证雪崩时页面不白屏。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “秒杀难在流量大，多买机器就行” | 难在同一秒压到**同一个商品**上：百万级 QPS 原样进库必崩，堆资源也付不起 |
| “库存加把锁就安全了” | 超卖有两个根因：**判断与扣减非原子**、**并发请求无序**；锁只解决前者 |
| “预扣库存就万无一失” | 预扣把超卖换成少卖，锁住的库存必须超时回补，否则货在仓里、用户看到售罄 |

## 读完自检（入门级 3 题）

**Q1** 秒杀要在哪四个约束下做？

▸ 答案：**不超卖、不少卖、不被刷、不雪崩**：靠扣减原子、超时回补、校验前置、削峰兜底各守一条。

**Q2** 为什么“先查库存、再扣库存”一定会超卖？

▸ 答案：两者不是一个原子动作：两人同时读到“还剩 1 件”，各减 1 就成了 -1。修法：让判断加扣减原子，或让同一商品排队。

**Q3** 限购和削峰，分别在漏斗的哪一段起作用？

▸ 答案：限购在**库存之前**，把请求压到与库存匹配；削峰在**下游之前**，用队列改变时间分布。
