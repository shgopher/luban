## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **HDFS** | 大文件切块，分散存在多台机器上 | 一套书拆成 100 册，分放 100 个书架 |
| **YARN** | 决定哪个作业先拿机器的调度层 | 工地上的派工员 |
| **Hive / HBase** | 一个用 SQL 查 HDFS，一个按 key 随机读写单条 | 仓库柜台 vs 索书号 |
| **RDD 血统** | 记录数据是一步步怎么算出来的，丢了照单重算 | 菜谱：菜糊了照方子再炒一遍 |
| **shuffle** | 按 key 重发到别的机器，要落盘、走网络 | 全班按姓氏重排座位，人都得站起来走 |
| **stage** | 按宽依赖切开、中间不落盘的一段计算 | 流水线上不被截断的一段 |
| **关键路径** | 依赖链上必须串行、省不掉的最长链 | 水电→瓦工→木工，人再多也得按序等 |
| **数据倾斜** | 总量正常，某个 key 特别多，一个 task 拖住全场 | 10 人搬 100 箱，1 人分到 91 箱 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “大数据就是数据量大” | 大只是前提，变的是处理方式：装不下才切块存，算不完才并行分片 |
| “加机器就能更快” | 只在并行度没到关键路径宽度时成立，超过后 makespan 停在下限 |
| “慢一定是数据太多” | 常见是分布不均：99 个 task 几分钟完，1 个跑两小时 |

## 读完自检（入门级 3 题）

**Q1** “存、调度、算、SQL 与随机读写”分别由哪一层负责？

▸ 答案：HDFS 存、YARN 调、Spark/MapReduce 算、Hive/HBase 提供 SQL 与随机读写。四层可各自替换。

**Q2** 两段逻辑等价的代码，一段 shuffle 5GB、一段 0.2GB，差在哪？

▸ 答案：差在是否**在 map 端先局部聚合**。`groupByKey` 把每个 key 的所有 value 送过网络，`reduceByKey` 先局部求和，shuffle 只剩每 key 一个值。

**Q3** 100 个 task，99 个 3 分钟完、1 个跑 2 小时，第一步查什么？

▸ 答案：先查倾斜，别先加机器。看各 task 输入字节的 **max/avg 比**，比值离谱即某个 key/分区特别多；治理靠加盐、预聚合、拆热 key。
