## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **特征** | 喂给模型的输入数字，如「近 7 天下单次数」 | 下锅前切好的配菜 |
| **训练/推理一致性** | 两边算特征用同一份定义 | 后厨与前厅不能各写菜谱 |
| **离线回填** | 用历史数据补算过去各时间点的特征 | 补写前几年的旧账本 |
| **时间点正确性** | 算某时刻特征只用之前的数据 | 不能拿明天的报纸赌今天的球 |
| **shadow** | 新模型跟着真实流量跑，结果丢掉 | 新司机坐副驾，不碰方向盘 |
| **canary** | 只放一小部分真实流量给新模型 | 先让一桌客人试新菜 |
| **模型注册表** | 版本不可变，上线即切指针 | 换灯泡不换灯座 |
| **KV Cache** | 缓存已算过的中间结果 | 输入法记住你打过的词 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「特征平台就是把特征存进 Redis」 | 存只是在线服务那一格；价值在把定义、回填、时间点做成契约 |
| 「模型上线就是发个新版本」 | 上线是用真实流量换信息：shadow 不伤人、canary 验系统、A/B 验业务 |
| 「多卡一定更快」 | 数据并行复制状态、模型并行加通信、流水并行生气泡——都在换资源 |

## 读完自检（入门级 3 题）

**Q1** 训练指标很好，上线后明显变差，先查哪一处？

▸ 答案：先查训练与推理的特征是否同一份定义：离线一段 SQL、线上一段代码最常见；再查时间点。

**Q2** 回滚为什么要「切别名」，而不是「重新部署旧版本」？

▸ 答案：切别名只改指针，秒级完成；重新部署要重新打包、加载，故障时来不及。前提是版本不可变。

**Q3** shadow、canary、A/B 按什么顺序用？

▸ 答案：先 shadow 旁路跑、结果丢掉；再 canary 看延迟与错误；最后 A/B 比业务。
