## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **命中率** | 十次读里有几次不用回源 | 有鸡蛋就不用下楼买 |
| **旁路缓存** | 应用自己查、自己回填、自己删 | 便签谁买东西谁改，超市不管 |
| **TTL** | 每个 key 的到期时间 | 牛奶盒上的保质期，到日子就扔 |
| **淘汰策略** | 内存满了先扔谁 | 冰箱塞满，先扔最久没人动的 |
| **陈旧窗口** | 数据改了到读者看到新值的间隔 | 室友按改前的便签去买 |
| **布隆过滤器** | 只会说“一定不在”或“可能在” | 保安的黑名单：说不在就真不在，说在要核对 |
| **多级缓存** | 本地加分布式，按距离排 | 口袋 → 背包 → 家里仓库 |
| **分片** | 把 key 分散到多台机器 | 加店员能分流，爆款仍挤一个柜台 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “加缓存就是装个 Redis” | 缓存是三个决定：放哪层、谁维护、脏多久；没有失效通道，脏数据只会存更久 |
| “不一致就设过期时间兜底” | TTL 只是把脏值**保存到过期**；到期前它一直被当正确答案 |
| “热点 key 加机器就能扛” | 哈希能分均匀 key，却拆不开一个 key；它仍打向同一分片 |

## 读完自检（入门级 3 题）

**Q1** 加了缓存，接口一定变快吗？

▸ 答案：不一定。只有**命中**才快：本地纳秒级，分布式多一次 0.2–2ms 往返；未命中还回源。

**Q2** 写库之后删掉缓存，就一致了吗？

▸ 答案：不一定。窗口 = 写库 + 回填耗时；窗口内未命中的读可能读到旧值，删除后才回填，还会被 TTL 留着。

**Q3** 有人一直查不存在的 id，为什么能把库打挂？

▸ 答案：这是穿透：数据不存在，缓存永不命中，请求全落到库。布隆过滤器可前置挡掉，但说“可能在”时仍回源。
