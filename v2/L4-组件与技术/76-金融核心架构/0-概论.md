# 第 76 章 金融核心架构 · 概论

## 一句话

> 金融核心架构要同时守住四件事——**账记得对、钱结得清、差错追得回、故障切得动**；四件事分别落在账务模型、清结算、差错处理、风控与多活上，任何一件失守都会以资损、监管罚单或长时间停业的形式暴露。

## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **账户** | 钱的容器，一个账户只挂一个科目 | 一个钱包 |
| **科目** | 钱的分类，决定报表口径 | 账本的分类标签 |
| **凭证** | 一笔业务落成的借贷分录，只增不改 | 收据存根联 |
| **总账** | 按科目按日汇总的账，服务报表与监管 | 月度汇总表 |
| **轧差** | 把多笔收付互相抵消，只结净额 | 朋友之间互相欠的钱一次算清 |
| **结算** | 真正把资金从 A 挪到 B，不可逆 | 银行转账到账那一刻 |
| **冲正** | 生成反方向凭证纠正错账，原凭证保留 | 作废要用红字单，不能撕原单 |
| **留痕** | 谁在何时改了什么、依据是什么，可校验 | 手术记录：谁主刀、谁签字 |

> 记住：**账户装钱、科目管口径、凭证记事实**；其余概念都能挂到这三件事上。

## 读前须知：金融核心与普通业务系统的 5 个差异

| 差异 | 普通业务系统 | 金融核心 |
|---|---|---|
| 数据可改性 | 记录可更新、可删除 | 账务只允许追加，错账用冲正 |
| 正确性判据 | 功能测试通过 | 借贷平衡 + 总分核对 + 账实相符，缺一不算对 |
| 时间口径 | 用服务器时间即可 | 必须区分业务日期与入账日期，跨日要定归属 |
| 失败处理 | 报错、重试、人工修数据 | 未知态单列（不成功不失败），靠查询与对账收敛 |
| 变更代价 | 发版即可 | 改账务模型要历史数据迁移 + 监管报备，回滚极难 |

> 记住一句话：**普通系统怕「功能不对」，金融核心怕「账不对」**——前者靠测试发现，后者只能靠多层校验与对账发现。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「金融核心就是数据库加事务」 | 事务只保证一笔操作原子；账对不平、清算轧错、差错不闭环，事务再好也救不回来 |
| 「这套东西只有银行用」 | 任何「先记账、后结算、能退款、要对账」的系统都是它的简化版：支付、电商、券商、供应链金融 |
| 「合规是法务的事」 | 留痕字段、不可篡改、留存期是架构设计约束，事后补不回来 |
| 「多活就是多建一个机房」 | 没有数据同步、流量切换与切换后校验，两个机房只是两套单点 |

## 读完自检（入门级 3 题）

**Q1** 为什么账务系统不允许「直接改余额」？

▸ 答案：余额是凭证的派生值。直接改余额等于没有事实依据地改数字，一旦对账或审计追问「这笔变动从哪来」，系统答不出来；而且改完无法复算，总分核对与试算平衡都会失去意义。正确做法是生成凭证，让余额由分录重算。

**Q2** 交易、清算、结算三段里，哪一段不可逆？为什么？

▸ 答案：结算不可逆——资金已经离开付款方账户进入收款方，只能靠反向交易（冲正）纠正，不能「撤销」。清算只是算账，可以重跑、重算；交易可以撤单，但一旦进入清算就应按清算结果走完。

**Q3** 风控拦截率从 1% 提高到 3%，是不是更安全？

▸ 答案：不一定。拦截率上升意味着误杀上升：被误杀的正常客户会客诉、流失，甚至走监管投诉渠道。判断标准是「漏放造成的资损」与「误杀造成的客诉与流失成本」之和最小，而不是单看拦截率。
