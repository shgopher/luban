                        76.1 金融系统全景与账务

                        一句话

                        金融核心系统的骨架是「账户 + 科目 + 凭证」：账户装钱、科目管口径、凭证记事实；每笔业务都落成借贷相等的凭证，日终再用试算平衡证明「账没记错」——判据是借贷合计相等、每级科目等于其子科目之和、资产 = 负债 + 权益 + 损益。

                        先破除三个误区

                        误区 现实
                        账务就是一张余额表 余额是派生值，必须能被分录复算；直接改余额等于抹掉事实，事后查不出谁改的
                        总账就是流水表 总账按科目按日汇总，服务报表与监管；流水按笔记录，服务追溯。粒度差 3 个数量级以上
                        科目是配置项，怎么配无所谓 科目决定报表口径与监管报送口径；科目体系变更要版本化迁移，不能改历史凭证
                        复式记账是财务的事 借贷方向决定余额怎么算；代码里方向写反，账永远平不了

                        六层全景：一笔钱经过谁

                        层 典型系统 职责 判据
                        渠道层 手机银行、柜面、ATM、开放 API 受理请求、身份核验 渠道故障不阻断记账
                        产品层 存款、贷款、理财、支付 产品参数、计息计费 利率费率变更不改代码
                        交易层 交易网关、订单、支付单 幂等、路由、状态机 同一笔交易只记一次账
                        账务层 核心账务引擎 复式记账、账户余额、冻结 单笔记账 p99 < 50ms（经验值）
                        总账层 GL、日终批量、报表 科目汇总、试算平衡 日终批量在 2 小时窗口内跑完
                        清结算层 清算、结算、对账 轧差、资金划拨、差异处理 净额文件 T 日晚间产出
                        合规层 风控、反洗钱、监管报送 决策、留痕、报送 每笔业务可复述决策依据

                        🔑 分层判据不是「有几个系统」，而是每层都能被替换而不改上层契约：渠道换小程序、总账换新 GL，账务接口不变。

                        四类账户：钱的容器

                        账户类型 谁在用 典型例子 记账约束
                        客户账户 客户 活期主户、子户、保证金户 实名开户、必须挂唯一科目
                        内部账户 银行自己 支付过渡户、挂账户、损益户、清算户 可暂挂，但日终必须清零或逐笔说明
                        表外账户 或有事项 抵押物、开出保函、未贴现票据 不进资产负债表，单独出表
                        往来账户 同业/央行 存放同业、同业存放、存放央行 与对账单逐日核对

                        关键区分：账户是「钱的容器」，科目是「钱的分类」。同一笔钱从账户看是余额变动，从科目看是报表口径；混成一张表，退款、手续费、分账都表达不了（见 67.4 复式记账与账务模型）。

                        三层账：流水、明细账、总账

                        层 粒度 写入方式 用途 校验关系
                        流水 / 事件 单笔 只插不改 追溯、举证 流水之和 = 明细变动
                        明细账 单账户逐笔 追加 账户对账、客诉 明细变动 = 总账发生额
                        总账 单科目按日 日终批量汇总 报表、监管 总账 = Σ 明细

                        一句话：流水证明发生过，明细账证明记在谁头上，总账证明对外口径。

                        科目树与借贷方向（方向定义与 67.4 一致，本节只补报表位置）

                        科目大类 增加记 减少记 正常余额方向 报表位置
                        资产 借 贷 借 资产负债表左侧
                        负债 贷 借 贷 资产负债表右侧
                        所有者权益 贷 借 贷 资产负债表右侧
                        收入 贷 借 贷 利润表
                        费用 借 贷 借 利润表

                        🔑 有借必有贷，借贷必相等。这不是会计习惯，而是系统的自校验机制：每张凭证入账前自校验一次，日终再全局校验一次，两层都过才叫「账对了」。

                        日终轧账：7 步，缺一步都会在第二天暴露

                        步 动作 耗时量级 失败处置
                        1 交易截止（T 日 20:00） — 截单后新单落 T+1
                        2 赶平未决交易（超时查询、回调补记） 10–30 分钟 挂账，保留原始流水号
                        3 计息、计提、摊销 20–60 分钟 重跑幂等，不重复计提
                        4 凭证汇总、总账过账 10–20 分钟 过账失败整批回滚后重跑
                        5 试算平衡 1–2 分钟 不平则禁止出报表
                        6 总分核对（总账 vs 明细） 10–30 分钟 差额挂账，次日核销
                        7 出报表、监管口径映射、备份留痕 30–80 分钟 报表与总账同源；备份失败不得开市

                        本机可运行：复式记账 + 试算平衡校验

                        go run main.go（go1.27.1 darwin/arm64）。本机仿真：5 张平衡凭证过账 + 1 张不平衡凭证被拒 + 科目树汇总 + 试算平衡 + 恒等式。原始输出存 tools/examples/76-fin-models/raw-76.1.txt。 示例说明见 tools/examples/76-fin-models/。

                        package main

import "fmt"

// Account 是账务树上的一个科目节点。
// Kind 决定余额方向：资产/费用 借增贷减；负债/权益/收入 贷增借减。
type Account struct {
	Code, Name, Kind, Parent string
	Open, Dr, Cr             int64 // 期初余额、借方发生额、贷方发生额（元）
}

// Entry 是凭证里的一行分录，Dr 与 Cr 只有一个非零。
type Entry struct {
	Acct   string
	Dr, Cr int64
}

type Voucher struct {
	ID      string
	Entries []Entry
}

func debitNormal(kind string) bool { return kind == "资产" || kind == "费用" }

// balance 返回期末余额，正数表示该科目正常方向（资产在借、负债在贷）。
func (a *Account) balance() int64 {
	net := a.Dr - a.Cr
	if debitNormal(a.Kind) {
		return a.Open + net
	}
	return a.Open - net
}

func main() {
	accts := []*Account{
		{Code: "1000", Name: "资产", Kind: "资产"},
		{Code: "1001", Name: "库存现金", Kind: "资产", Parent: "1000", Open: 8000},
		{Code: "1002", Name: "存放中央银行款项", Kind: "资产", Parent: "1000", Open: 5000},
		{Code: "1101", Name: "客户贷款", Kind: "资产", Parent: "1000"},
		{Code: "2000", Name: "负债", Kind: "负债"},
		{Code: "2001", Name: "客户存款", Kind: "负债", Parent: "2000", Open: 3000},
		{Code: "2002", Name: "应付结算款", Kind: "负债", Parent: "2000"},
		{Code: "3000", Name: "所有者权益", Kind: "权益"},
		{Code: "3001", Name: "实收资本", Kind: "权益", Parent: "3000", Open: 10000},
		{Code: "3002", Name: "未分配利润", Kind: "权益", Parent: "3000"},
		{Code: "4000", Name: "收入", Kind: "收入"},
		{Code: "4001", Name: "手续费收入", Kind: "收入", Parent: "4000"},
		{Code: "5000", Name: "费用", Kind: "费用"},
		{Code: "5001", Name: "利息支出", Kind: "费用", Parent: "5000"},
	}
	byCode := map[string]*Account{}
	for _, a := range accts {
		byCode[a.Code] = a
	}

	vouchers := []Voucher{
		{ID: "V001", Entries: []Entry{{"1001", 10000, 0}, {"2001", 0, 10000}}}, // 现金存入
		{ID: "V002", Entries: []Entry{{"1101", 50000, 0}, {"2001", 0, 50000}}}, // 发放贷款
		{ID: "V003", Entries: []Entry{{"2001", 300, 0}, {"4001", 0, 300}}},     // 收手续费
		{ID: "V004", Entries: []Entry{{"5001", 120, 0}, {"2002", 0, 120}}},     // 计提利息支出
		{ID: "V005", Entries: []Entry{{"1002", 2000, 0}, {"1001", 0, 2000}}},   // 现金交存央行
		{ID: "V006", Entries: []Entry{{"1001", 500, 0}, {"2001", 0, 400}}},     // 故意不平衡
	}

	fmt.Println("== 1. 凭证校验与过账（每张凭证先自校验，不平衡整张拒绝）==")
	okCnt, badCnt := 0, 0
	for _, v := range vouchers {
		var d, c int64
		for _, e := range v.Entries {
			d += e.Dr
			c += e.Cr
		}
		if d != c {
			badCnt++
			fmt.Printf("%s ✗ 借 %d ≠ 贷 %d（差额 %d）→ 整张凭证拒绝入账\n", v.ID, d, c, d-c)
			continue
		}
		okCnt++
		for _, e := range v.Entries {
			byCode[e.Acct].Dr += e.Dr
			byCode[e.Acct].Cr += e.Cr
		}
		fmt.Printf("%s ✓ 借 %d = 贷 %d\n", v.ID, d, c)
	}
	fmt.Printf("过账汇总：接受 %d 张，拒绝 %d 张\n\n", okCnt, badCnt)

	// 只取叶子科目做主表
	var leaves []*Account
	for _, a := range accts {
		if a.Parent != "" {
			leaves = append(leaves, a)
		}
	}

	fmt.Println("\n== 2. 期末余额表（正 = 该科目正常方向）==")
	fmt.Printf("%-6s %-14s %-4s %10s\n", "科目", "名称", "方向", "余额")
	for _, a := range leaves {
		dir := "借"
		if !debitNormal(a.Kind) {
			dir = "贷"
		}
		fmt.Printf("%-6s %-14s %-4s %10d\n", a.Code, a.Name, dir, a.balance())
	}

	// 科目树：父科目余额必须等于所有子科目之和
	children := map[string][]*Account{}
	for _, a := range accts {
		if a.Parent != "" {
			children[a.Parent] = append(children[a.Parent], a)
		}
	}
	var roll func(code string) int64
	roll = func(code string) int64 {
		if len(children[code]) == 0 {
			return byCode[code].balance()
		}
		var s int64
		for _, ch := range children[code] {
			s += roll(ch.Code)
		}
		return s
	}
	fmt.Println("\n== 3. 科目树汇总（父 = 子之和）==")
	for _, root := range []string{"1000", "2000", "3000", "4000", "5000"} {
		var childSum int64
		for _, ch := range children[root] {
			childSum += roll(ch.Code)
		}
		mark := "✓"
		if childSum != roll(root) {
			mark = "✗"
		}
		fmt.Printf("%s %-10s 汇总 %8d | 子科目之和 %8d %s\n", root, byCode[root].Name, roll(root), childSum, mark)
	}

	fmt.Println("\n== 4. 试算平衡（借方余额合计 = 贷方余额合计）==")
	var sumDr, sumCr int64
	for _, a := range leaves {
		b := a.balance()
		if debitNormal(a.Kind) {
			sumDr += b
		} else {
			sumCr += b
		}
	}
	fmt.Printf("借方余额合计 %8d\n贷方余额合计 %8d\n差异 %12d\n", sumDr, sumCr, sumDr-sumCr)

	assets := roll("1000")
	liab := roll("2000")
	equity := roll("3000")
	income := roll("4000")
	expense := roll("5000")
	fmt.Printf("\n== 5. 资产负债表恒等式 ==\n资产 %d = 负债 %d + 权益 %d + (收入 %d - 费用 %d) = %d → 差异 %d\n",
		assets, liab, equity, income, expense, liab+equity+income-expense,
		assets-(liab+equity+income-expense))
}

                        读输出只需盯三处结论：

                        输出 结论
                        V006 ✗ 借 500 ≠ 贷 400 → 整张凭证拒绝入账 凭证级自校验在入账前拦下，不会只记一半

                        ⚠️ 试算平衡的盲区：借贷同时多记/少记、或记错科目但方向对，它照样平。所以只是第一道闸，还须配总分核对与逐笔对账（见 76.3 对账与差错处理）。

                        反模式

                        反模式 后果
                        直接 UPDATE 余额，不生成凭证 余额与分录永久对不上，审计时无法举证
                        修改历史凭证「更正」错账 审计链断裂，监管检查必挂
                        用订单表当总账 退款、手续费、分账都表达不了，报表口径随时错
                        日终批量无断点续跑 跑到一半失败只能全量重跑，窗口不够
                        只跑试算平衡，不做总分核对 明细与总账的差额永远发现不了
                        内部账户长期挂账不清 挂账户变成垃圾桶，最终沉淀为资损

                        自检

                        Q1 试算平衡平了，账就一定没记错吗？

                        ▸ 答案：不一定。它只校验「借方合计 = 贷方合计」。把 100 元本该记 A 的钱记到 B，方向都对，试算平衡照样平，但 A、B 都错。它是必要非充分条件，还须配总分核对与逐笔对账。

                        Q2 为什么总账要日终批量汇总，而不是由流水实时算出？

                        ▸ 答案：总账服务报表与监管口径，要求「同一时点、同一口径、可复现」；实时汇总随交易变化，不能对外披露。批量还带来幂等重跑与备份窗口：实时余额在账户层，总账走批量。

                        Q3 内部账户为什么必须日终清零或逐笔说明？

                        ▸ 答案：内部户是「暂时放钱」的地方，长期挂账说明有未决事项被遗忘；客户视角看不到它，累积即隐性资损。判据：每笔挂账有原始流水号、责任人与核销时限。

                        Q4 科目树为什么要求「父 = 子之和」？

                        ▸ 答案：这是科目汇总的自校验。报表按科目层级汇总，父科目若不等于子科目之和，说明归属或汇总逻辑有错。日终校验这一条能拦住「报表对不上明细」的绝大多数问题，且定位到具体科目分支。

                        Q5 记账方向写反了，系统会表现成什么样？

                        ▸ 答案：余额符号反转；试算平衡可能仍平（另一侧也反了），但恒等式会崩、总分核对不对、监管报表异常。所以方向必须由科目大类在代码里推导，不能靠调用方传参。
