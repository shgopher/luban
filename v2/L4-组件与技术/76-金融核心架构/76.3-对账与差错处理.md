# 76.3 对账与差错处理

## 一句话

> 对账负责「把差异找出来」，差错处理负责「把差异变成有凭证、有责任人、有时限的账务动作」：**冲正改事实、补账补遗漏、挂账等核查**，三者不能混用；判据是差异在 **T+1 内完成账务动作、T+3 内完成核销**，且处理完之后账仍然是平的。

## 先破除三个误区

| 误区 | 现实 |
|---|---|
| 对完账就结束了 | 对账只产出差异清单；不处理差异等于没对，差异会滚成资损 |
| 冲正就是把原记录删掉或改掉 | 冲正是生成反方向凭证，原凭证永久保留，两笔事实都要能查到 |
| 补账和冲正是同义词 | 补账补「漏记的」，冲正纠「错记的」，方向相反，用错会把短款补成真资损 |
| 挂账就是拖着不管 | 挂账必须有原始流水、责任人、核销时限与核销凭证 |

四相符的框架（账账、账证、账表、账实）在 [67.3 对账与差异处理](../67-交易与账务/67.3-对账与差异处理.md) 讲透，本节只讲金融核心特有的部分：**差错落到账务上具体生成什么凭证，以及总分核对怎么做**。

## 四类对账：比的对象不同，差异的含义也不同

| 类别 | 比什么 | 频率 | 差异含义 | 处理入口 |
|---|---|---|---|---|
| 渠道对账（账实） | 平台账 vs 渠道账单 | 日终 | 长款/短款/金额/状态差 | 补账、冲正 |
| 总分核对（账账） | 总账科目余额 vs 明细账户合计 | 日终 | 汇总或归属错误 | 挂账、查分录 |
| 账证核对 | 余额变动 vs 凭证 | 实时 + 日终 | 无凭证改余额 | 强制补凭证并追责 |
| 账表核对 | 报表 vs 总账 | 日终 | 口径映射错误 | 修映射、重出报表 |

> 🔑 渠道对账最常见的坑不是「对不平」，而是**对得平但口径错了**：只比金额不比状态、只比成功笔不比退款笔。判据是差异类型至少覆盖「金额、状态、方向、时间」四维。

## 差错的账务动作（差异定义见 67.3）

> 差异的「现象 / 根因」两列见 [67.3 对账与差异处理](../67-交易与账务/67.3-对账与差异处理.md) 的五类差异表，本节不重复；这里只补金融核心特有的**账务动作与时限**。

| 差错类型 | 账务动作 | 账务动作时限 | 核销时限 |
|---|---|---|---|
| 长款 | 补账：借「存放央行/清算户」、贷「应付结算款」 | T+1 | T+3 |
| 短款 | 冲正：反方向凭证，冲掉平台已记的收款 | T+1 | T+3 |
| 金额不一致 | 差额冲正或补记，差额入损溢 | T+1 | T+3 |
| 状态不一致 | 以渠道为准补状态，并补退款凭证 | T+1 | T+3 |
| 时间差 | 下一窗口自动核销，不计差错 | 自动 | 自动 |

## 冲正的三条规则

| 规则 | 做法 | 为什么 |
|---|---|---|
| **原凭证不动** | 生成反方向凭证，关联原凭证号 | 审计要求保留完整事实链，改历史凭证等于销毁证据 |
| **区分当日与隔日** | 当日可红字冲销；隔日必须反向蓝字，两笔都留 | 当日冲销不影响日终轧账；隔日已出报表，只能用新交易纠正 |
| **带原因码与原凭证号** | 每张冲正凭证必填 cause_code、origin_voucher | 否则事后无法解释「为什么冲」，也无法统计差错类型分布 |

补账与冲正的判定只有一问：**这笔业务真实发生了吗？**

| 情况 | 判定 | 动作 |
|---|---|---|
| 真实发生、但平台漏记 | 漏记 | 补账（同方向补记） |
| 未真实发生、但平台已记 | 错记 | 冲正（反方向冲销） |
| 金额记错（多记/少记） | 错记 | 差额冲正或差额补记 |
| 查不清是否真实发生 | 未决 | 挂账到待处理损益，T+1 核查 |

## 挂账：给「查不清」留一个合规出口

挂账不是垃圾桶，它是一笔有明确科目的凭证：差额从原科目转到「待处理损益 / 待查款项」，并在挂账池里登记原始流水、差异类型、责任人、到期日。

| 挂账要素 | 要求 | 缺了会怎样 |
|---|---|---|
| 原始流水号 | 精确到渠道交易号与平台单号 | 无法回溯，只能当损溢核销 |
| 差异类型 | 五类之一 + 技术/业务标记 | 统计不出根因，无法驱动上游修复 |
| 责任人 | 具体到人，不是「财务部」 | 无人推进，超期挂账 |
| 核销时限 | 一般 T+1 至 T+7 | 挂账池只增不减，最终成为资损 |
| 核销凭证 | 核销时必须生成对冲凭证 | 账上永远挂着，报表失真 |

## 本机可运行：对账 diff + 自动生成差错凭证

`go run main.go`（go1.27.1 darwin/arm64）。本机仿真：5 笔内部账 vs 5 笔渠道账，识别四类差异、自动生成处理凭证并校验借贷平衡，再做一次故意差 1 分的总分核对与挂账。原始输出存 `.cache/domain-76/raw-76.3.txt`。

```go
package main

import "fmt"

type Rec struct {
	ID     string
	Amt    int64 // 分
	Status string
}

type Line struct {
	Vid, Note string
	DrAcct    string
	CrAcct    string
	Amt       int64
}

func yuan(v int64) string { return fmt.Sprintf("%.2f", float64(v)/100) }

func main() {
	// 内部账（账务系统）与渠道账单（以官方文档为准的字段）
	inner := []Rec{
		{"P01", 10000, "SUCCESS"},
		{"P02", 25000, "SUCCESS"},
		{"P03", 200000, "SUCCESS"},
		{"P04", 5000, "SUCCESS"},
		{"P05", 8800, "SUCCESS"},
	}
	channel := []Rec{
		{"P01", 10000, "SUCCESS"},
		{"P02", 25000, "REFUND"},
		{"P03", 180000, "SUCCESS"},
		{"P04", 5000, "SUCCESS"},
		{"P06", 30000, "SUCCESS"},
	}

	innerMap := map[string]Rec{}
	for _, r := range inner {
		innerMap[r.ID] = r
	}
	chMap := map[string]Rec{}
	for _, r := range channel {
		chMap[r.ID] = r
	}

	fmt.Println("== 1. 逐笔比对（内部账 vs 渠道账单）==")
	var lines []Line
	var longCnt, shortCnt, amtCnt, statusCnt int
	vid := 100
	newVid := func() string { vid++; return fmt.Sprintf("CZ%03d", vid) }
	addLine := func(note, dr, cr string, amt int64) {
		lines = append(lines, Line{newVid(), note, dr, cr, amt})
	}
	for _, in := range inner {
		ch, ok := chMap[in.ID]
		if !ok {
			shortCnt++
			fmt.Printf("%s 短款：内部 %s 元、渠道无此笔 → 查渠道状态，未受理则冲正\n", in.ID, yuan(in.Amt))
			addLine("短款冲正 "+in.ID, "2001", "1002", in.Amt) // 反方向：冲掉内部已记的收款
			continue
		}
		if in.Amt != ch.Amt {
			amtCnt++
			diff := in.Amt - ch.Amt
			side := "内部多记"
			if diff < 0 {
				side = "内部少记"
				diff = -diff
			}
			fmt.Printf("%s 金额不一致：内部 %s、渠道 %s（%s %s）→ 差额入损溢\n",
				in.ID, yuan(in.Amt), yuan(ch.Amt), side, yuan(diff))
			if in.Amt > ch.Amt {
				addLine("金额差冲正 "+in.ID, "2001", "1002", diff)
			} else {
				addLine("金额差补记 "+in.ID, "1002", "2001", diff)
			}
			continue
		}
		if in.Status != ch.Status {
			statusCnt++
			fmt.Printf("%s 状态不一致：内部 %s、渠道 %s → 以渠道为准补状态\n", in.ID, in.Status, ch.Status)
			addLine("退款补记 "+in.ID, "2001", "1002", in.Amt)
			continue
		}
		fmt.Printf("%s 一致：%s 元 %s\n", in.ID, yuan(in.Amt), in.Status)
	}
	for _, ch := range channel {
		if _, ok := innerMap[ch.ID]; !ok {
			longCnt++
			fmt.Printf("%s 长款：渠道 %s 元、内部无此笔 → 按渠道流水补单\n", ch.ID, yuan(ch.Amt))
			addLine("长款补单 "+ch.ID, "1002", "2002", ch.Amt)
		}
	}
	fmt.Printf("差异合计：长款 %d、短款 %d、金额 %d、状态 %d\n\n", longCnt, shortCnt, amtCnt, statusCnt)

	fmt.Println("== 2. 系统自动生成的差错处理凭证（每张都必须借贷相等）==")
	var drSum, crSum int64
	for _, l := range lines {
		drSum += l.Amt
		crSum += l.Amt
		fmt.Printf("%s %-16s 借 %s / 贷 %s  %s 元\n", l.Vid, l.Note, l.DrAcct, l.CrAcct, yuan(l.Amt))
	}
	fmt.Printf("凭证合计：借 %s = 贷 %s → 差异 %s\n\n", yuan(drSum), yuan(crSum), yuan(drSum-crSum))

	// 总分核对：总账科目余额应等于其下明细账户余额之和
	fmt.Println("== 3. 总分核对（总账 2001 客户存款 vs 明细账户合计）==")
	glBalance := int64(100000) // 总账余额
	detailSum := int64(99999)  // 明细账户逐户合计
	suspense := glBalance - detailSum
	fmt.Printf("总账余额 %s 元\n明细合计 %s 元\n差额     %s 元\n", yuan(glBalance), yuan(detailSum), yuan(suspense))
	if suspense != 0 {
		fmt.Printf("差额挂账：借 2001 %s / 贷 5002 待处理损益 %s（次日核销）\n",
			yuan(suspense), yuan(suspense))
	}
	fmt.Printf("挂账后校验：明细 %s + 挂账 %s = 总账 %s → %v\n\n",
		yuan(detailSum), yuan(suspense), yuan(glBalance), detailSum+suspense == glBalance)

	fmt.Println("== 4. 差错处理时限（经验值）==")
	for _, s := range []struct {
		t, what string
	}{
		{"T+1 03:00", "日终对账完成，差异写入挂账池（带原流水号与差异类型）"},
		{"T+1 06:00", "自动核查：查渠道单、查回调日志、查计费规则"},
		{"T+1 12:00", "自动核查不通过的转人工，双人复核"},
		{"T+1 18:00", "账务动作完成：补单/冲正/确认无差异"},
		{"T+3", "核销完成：差异清零或转入已批准挂账"},
		{"T+7", "复盘：同类差异是否重复出现，修上游根因"},
	} {
		fmt.Printf("%-9s %s\n", s.t, s.what)
	}
}
```

| 输出 | 结论 |
|---|---|
| `差异合计：长款 1、短款 1、金额 1、状态 1` | 一笔对一笔比，才能分出类型；只比总额这四笔会互相抵消 |

## 差错处理的生命周期

| 阶段 | 动作 | 时限（经验值） | 产出 |
|---|---|---|---|
| 发现 | 日终对账 / 准实时核对 / 客诉 | 实时–T+1 03:00 | 差异清单 |
| 分类 | 按五类差错打标，附原流水 | T+1 06:00 | 差异工单 |
| 自动核查 | 查渠道单、查回调日志、查计费规则 | T+1 06:00–12:00 | 处理建议 |
| 人工介入 | 自动核查不通过的转人工，双人复核 | T+1 12:00–18:00 | 处理决定 |
| 账务处理 | 补账 / 冲正 / 挂账 | T+1 18:00 | 凭证 |
| 闭环复盘 | 同类差异重复率、根因修复 | 周度 | 上游缺陷单 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 对账只比总额或只比笔数 | 方向相反的差异互相抵消，问题被抹平 |
| 差异只记录不处理 | 挂账池越滚越大，最后无人敢动 |
| 直接改原凭证「更正」 | 审计链断裂，监管检查必挂 |
| 冲正不带原因码与原凭证号 | 事后无法解释，差错分布统计不出来 |
| 长款当收入、短款当损失直接核销 | 掩盖上游缺陷，同类问题反复发生 |
| 1 分钱差额「四舍五入抹掉」 | 账实永远差一点，总分核对再也对不平 |
| 对账结果不驱动上游修复 | 每周补同样的单，团队疲于奔命 |

## 自检

**Q1** 渠道有、平台无的「长款」，为什么不能直接当收入核销？

▸ 答案：长款意味着渠道认为这笔钱到了、平台没记账，客户的钱可能还挂在渠道侧，一旦客户要求退款就要平台垫付。正确做法是按渠道流水补账（借清算户、贷应付结算款），让平台账与渠道一致后再决定资金归属；直接核销等于把负债当利润。

**Q2** 冲正和补账的判定依据是什么？

▸ 答案：只看一问——这笔业务真实发生了吗。真实发生但平台漏记 → 补账（同方向）；未真实发生但平台已记 → 冲正（反方向）；金额记错则做差额冲正或差额补记；查不清则挂账。方向搞反会把短款补成真实资金流出。

**Q3** 为什么隔日冲正必须用反向蓝字，不能用红字冲销？

▸ 答案：隔日已经出过报表并对外报送，红字冲销会让历史报表与当前账不符；用一笔新的反向交易纠正，既保留原凭证、又让「报表当时是真实的」这一事实成立。审计要看到的是完整时间线，而不是被改干净的账。

**Q4** 总分核对的差额为什么要挂账而不是直接调平？

▸ 答案：直接调平等于承认「总账与明细可以不一致」，且没有凭证、没有责任人。挂账把这 1 分钱落到「待处理损益」科目并登记工单，既让总分暂时一致（明细 + 挂账 = 总账），又保留了追查与核销的义务。

**Q5** 差异处理闭环的判据是「处理完了」还是别的？

▸ 答案：不是处理完了，而是**同类差异不再重复产生**。如果每周都在补同一类单，说明上游有系统性缺陷（回调不可靠、口径不统一、计费不一致），要修根因；补单只是止血，不修根因就是长期出血。
