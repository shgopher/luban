# 0.10 行为型 11 种：策略、观察者、模板方法、责任链、状态、命令、迭代器、中介者、备忘录、访问者、解释器

## 一句话

> 行为型 11 种管的是同一件事——**把「下一步走哪条分支」从调用点搬走**；Go 里 8 种能落到函数值、表、channel、`iter.Seq` 上，只有责任链、访问者、解释器值得保留结构，而**责任链漏写终止条件会静默空转、观察者漏监听 `context` 会泄漏 goroutine**，这两条比选哪种模式更要紧。

## 11 种一张表：意图、Go 实现、什么时候别用

| 模式 | 意图 | Go 惯用实现 | 什么时候别用 |
|---|---|---|---|
| 策略 | 换算法 | `type Rule func(int) int` + map 注册表 | 分支 ≤3 且半年不变：直接 if |
| 观察者 | 一变多通知 | 有界 `chan Event` + `select default` | 要求不丢不重：上消息队列 |
| 模板方法 | 固定骨架、留钩子 | 钩子函数字段（不是嵌入） | 骨架本身会变：钩子越加越多 |
| 责任链 | 逐级处理或否决 | `func(Handler) Handler` 中间件 | 节点只有 1 个、顺序写死 |
| 状态 | 状态驱动行为 | `[状态][事件]转移` 表 | 状态 >20 且每态有独立副作用 |
| 命令 | 操作变数据 | 闭包 + 队列 + 逆操作 | 只调用一次：直接调函数 |
| 迭代器 | 惰性遍历 | `iter.Seq[T]` + `range` over func | 数据本来就在切片里、只遍历一次 |
| 中介者 | N×M 变 N+M | hub（注册表 + 广播） | 参与者只有 2 个：直接调用 |
| 备忘录 | 快照与回滚 | 值拷贝 / 只读快照结构 | 单次快照 >10MB：落盘 |
| 访问者 | 不改类型加操作 | `type switch`，必要时访问者 | 类型集常加：加了必崩 |
| 解释器 | 解析并执行 | AST + `Eval` | 语法超 20 条：用解析器生成器 |

> 🔑 **8 比 3**：11 种里只有责任链、访问者、解释器需要真正的结构，其余 8 种在 Go 里都能退化成「一个函数值、一张表、一个 channel、一个迭代器」。写成 11 套接口 + 结构体，是把 Java 的类层级硬搬过来。

## 策略：调用点差不到 1 ns，构造成本差 3 倍

```go
type Rule func(cents int) int

var rules = map[string]Rule{
	"vip":    func(c int) int { return c * 90 / 100 },
	"coupon": func(c int) int { return c * 80 / 100 },
}

func price(kind string, cents int) int {
	if r, ok := rules[kind]; ok {
		return r(cents)
	}
	return cents
}
```

直觉认为「接口有虚表开销，函数值更快」。本机实测两边都在 2.7–2.9 ns，差在噪声内；真正拉开差距的是**策略对象的构造**——同一份逻辑，构造一次 2.7 ns，每次重建 8.2–9.4 ns。下面只比「怎么持有策略」，map 查找不计入（那是另一件事）。

```go
// bench_test.go：同一份计价逻辑，两种持有方式

//go:noinline

}

}

}
```

## 观察者：channel 只负责传输，背压和取消才是设计

```go
type Hub struct {
	mu      sync.Mutex
	subs    []chan Event
	dropped int
}

func (h *Hub) Publish(e Event) {
	h.mu.Lock()
	defer h.mu.Unlock()
	for _, ch := range h.subs {
		select {
		case ch <- e:
		default: // 必须显式选一种背压策略，default 就是「丢弃」
			h.dropped++
		}
	}
}
```

同一份 1000 条事件、消费者 1 ms/条的程序，三种背压策略的实测结果：

| 背压策略 | 发布耗时 | 收到 / 丢弃 | 适用 |
|---|---|---|---|
| 丢弃 + 计数（`select default`，buffer=8） | 26 µs | 8 / 992 | 指标、日志、可丢的埋点 |
| 阻塞（无缓冲 `ch <- e`） | 1.132 s | 1000 / 0 | 不允许丢、允许拖慢发布方 |
| 合并最新（`atomic.Store`） | 18.5 µs | 1 / 999 | 状态快照类，只要最终值 |

泄漏是观察者的第二个死穴。同样 100 个订阅者、同样「发布方已经退出」：

```text
② 监听 ctx.Done 的 100 个订阅者：goroutine 1 → 1
③ 不监听退出的 100 个订阅者：goroutine 1 → 101（泄漏 100 个）
```

**订阅者的 `select` 必须同时有数据分支和 `ctx.Done()` 分支**；只有数据分支时，发布方一停，这些 goroutine 永久挂在 channel 上，`sync.WaitGroup` 永不归零。channel 与 `context` 的语义细节见 [15.6 并发原语 (channel / context / sync)](../../L0-运行时底座/15-语言运行时/15.6-并发原语.md)。

进程内 hub 跨进程后的形态是消息总线，顺序、重投、分区都要重新设计，见 [31.2 事件驱动架构 (EDA)](../../L2-架构风格/31-事件驱动/31.2-事件驱动架构.md)。

## 模板方法：嵌入调不到「子类」的覆写

Java 的模板方法是父类调 `this.step()`，动态分派到子类。Go 没有虚方法，照搬会得到一个**静默错误**：

```go
type Base struct{}

func (b *Base) parse(row string) string { return "base:" + row }
func (b *Base) Run(rows []string) {
	for _, r := range rows {
		fmt.Println(b.parse(r)) // b 的静态类型是 *Base，永远到不了子类
	}
}

type CSV struct{ *Base }

func (c *CSV) parse(row string) string { return "csv:" + row } // 覆写无效

func main() {
	c := &CSV{Base: &Base{}}
	c.Run([]string{"1,2", "3,4"})
}
```

真实输出：

```text
base:1,2
base:3,4
```

`CSV.parse` 一次都没被调用，而且没人报错。Go 的模板方法要写成**钩子函数字段**，把可变步骤当参数传进去：

```go
type Importer struct {
	Parse func(row string) (Record, error) // 钩子：由调用方决定
	Save  func(Record) error
}

func (im Importer) Run(rows []string) (int, error) {
	n := 0
	for _, r := range rows {
		rec, err := im.Parse(r)
		if err != nil {
			return n, err
		}
		if err := im.Save(rec); err != nil {
			return n, err
		}
		n++
	}
	return n, nil
}
```

| 写法 | 覆写是否生效 | 可测性 | 编译期能发现写错吗 |
|---|---|---|---|
| 嵌入 + 「子类」方法 | ❌ 静默不生效 | 要构造真实子类 | 不能 |
| 钩子函数字段 | ✅ 注入即生效 | 每个钩子单独替换 | 能（字段必须有值） |
| 接口 + 实现 | ✅ | 需要 mock 整个接口 | 能 |

## 责任链：不写终止条件，链就是装饰

```go
type Handler func(context.Context, *Order) error
type Middleware func(Handler) Handler

func Chain(h Handler, ms ...Middleware) Handler {
	for i := len(ms) - 1; i >= 0; i-- {
		h = ms[i](h) // 从后往前包，执行顺序 = 书写顺序
	}
	return h
}
```

链的终止只有两种合法写法，其余都是 bug：

| 写法 | 语义 | 漏了会怎样 |
|---|---|---|
| 调 `next(ctx, o)` 并把 error 往上返回 | 继续往后走 | — |
| 返回非 nil error，不调 next | 在此否决 | — |
| 不调 next 且返回 nil | **未定义** | 调用方以为成功，业务静默丢单 |

实测两种路径（完整程序见下节）：正常链路 `trace=[→auth →trace ←trace ←auth]`，洋葱式进出；`guard(false)` 提前返回时 `trace=[→guard]`，后面两层一次都没进。

链上如果要放熔断、限流这类治理动作，逻辑与阈值的主场在 [35.6 熔断与降级](../../L3-质量属性/35-可用性/35.6-熔断与降级.md)，这里只需要保证它们**放在链的前段**且**失败时返回 error**。

## 状态：4 状态 × 3 事件 = 12 条边，表只要 24 行

```go
type edge struct {
	next State
	ok   bool
}

// trans[当前状态][事件]：表里没有的边就是非法转移
var trans = [4][3]edge{
	Created: {EvPay: {Paid, true}, EvClose: {Closed, true}},
	Paid:    {EvShip: {Shipped, true}, EvClose: {Closed, true}},
	Shipped: {EvClose: {Closed, true}},
}

func fire(s State, e Event) (State, error) {
	if ed := trans[s][e]; ed.ok {
		return ed.next, nil
	}
	return s, fmt.Errorf("illegal: %s -/-> %s", s, eventName[e])
}
```

| 写法 | 4 状态 3 事件的代码量 | 加一个状态的改动点 | 非法转移何时暴露 |
|---|---|---|---|
| 状态类（每态一个结构体 + 4 个方法） | 64 行（不含 `main`） | 新增 1 个类型 + 每态加 1 个方法 | 运行时返回 error |
| 状态机表 | 19 行（含 `fire`） | 表加 1 行、事件枚举加 1 个 | 同上，越界也会被 `ok=false` 挡住 |
| 散落的 `if o.State == Paid` | 随调用点线性增长 | 全仓 grep 一遍 | 漏一个分支就静默放过 |

状态超过 20 个、或者每个状态都要发消息 / 调外部服务时，表会退化成「表 + 大 switch」，这时候才值得回到类型 + 方法。

## 命令：撤销是逆操作，重放是重跑

```go
type Cmd struct {
	Name string
	Do   func() error
	Undo func() error
}
```

区别必须分清：**撤销要写逆操作**（`+100` 的逆是 `-100`），不是「把 Do 再跑一遍」。实测执行 3 条再撤销 2 条，`total` 从 120 回到 100，中间态与顺序完全可追溯（输出见下节 ④）。

命令队列的两个硬约束：队列要有上限（否则撤销栈随会话无限长），`Undo` 必须幂等（重试或重复调用不能二次扣减）。

## 迭代器：`iter.Seq` 买的是「调用方能 break」，不是速度

```go
func (s *Store) All() iter.Seq[*Order] {
	return func(yield func(*Order) bool) {
		for _, o := range s.orders {
			if !yield(o) { // 调用方 break，这里立即停止
				return
			}
		}
	}
}
```

`n=1000`，环境同上，同一个求和用两种写法（`bench_test.go` 的后半段）：

```go
func count(n int) func(yield func(int) bool) {
	return func(yield func(int) bool) {
		for i := 0; i < n; i++ {
			if !yield(i) {
				return
			}
		}
	}
}

//go:noinline
func sumSeq(n int) int {
	s := 0
	for v := range count(n) {
		s += v
	}
	return s
}

//go:noinline
func sumLoop(n int) int {
	s := 0
	for i := 0; i < n; i++ {
		s += i
	}
	return s
}

func BenchmarkSumSeq(b *testing.B) {
	for i := 0; i < b.N; i++ {
		sink = sumSeq(1000)
	}
}

func BenchmarkSumLoop(b *testing.B) {
	for i := 0; i < b.N; i++ {
		sink = sumLoop(1000)
	}
}
```

实测：

| 写法 | ns/op（3 次） | allocs/op |
|---|---|---|
| `for v := range count(1000)` | 355.9 / 396.8 / 459.4 | 0 |
| `for i := 0; i < 1000; i++` | 337.9 / 349.8 / 373.8 | 0 |

> 🔑 最差的一次 459 ns 对 338 ns，慢约 **20%**，量级相同——`iter.Seq` 不是性能优化。它买到的是**惰性 + 可组合 + 调用方能提前退出**：`filter(st.All(), keep)` 不用生成中间切片，`break` 之后生成器立刻 `return`（实测只处理了第 1 条就停）。

三条约束：`yield` 里不许阻塞、不许跨 goroutine（`yield` 必须在生成器所在的 goroutine 里调）、错误用 `iter.Seq2[T, error]` 而不是塞进 `T`。惰性遍历省下的中间内存，量级估算见 [34.4 优化手段 (缓存 / 异步 / 批处理 / 池化 / 索引 / 并发)](../../L3-质量属性/34-性能/34.4-优化手段.md)。

## 拼起来跑：一张表 + 一条链 + 一个迭代器 + 一个撤销栈

环境 `go1.27.1 darwin/arm64`（Apple M1），命令 `go run ./final10`：

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"iter"
)

// ---------- 状态：一张转移表 ----------
type State uint8

const (
	Created State = iota
	Paid
	Shipped
	Closed
)

var stateName = [...]string{"created", "paid", "shipped", "closed"}

func (s State) String() string { return stateName[s] }

type Event uint8

const (
	EvPay Event = iota
	EvShip
	EvClose
)

var eventName = [...]string{"pay", "ship", "close"}

type edge struct {
	next State
	ok   bool
}

var trans = [4][3]edge{
	Created: {EvPay: {Paid, true}, EvClose: {Closed, true}},
	Paid:    {EvShip: {Shipped, true}, EvClose: {Closed, true}},
	Shipped: {EvClose: {Closed, true}},
}

func fire(s State, e Event) (State, error) {
	if ed := trans[s][e]; ed.ok {
		return ed.next, nil
	}
	return s, fmt.Errorf("illegal: %s -/-> %s", s, eventName[e])
}

// ---------- 责任链 ----------
type Order struct {
	ID    string
	State State
	Total int
	Trace []string
}

type Handler func(context.Context, *Order) error
type Middleware func(Handler) Handler

func Chain(h Handler, ms ...Middleware) Handler {
	for i := len(ms) - 1; i >= 0; i-- {
		h = ms[i](h)
	}
	return h
}

func traced(name string) Middleware {
	return func(next Handler) Handler {
		return func(ctx context.Context, o *Order) error {
			o.Trace = append(o.Trace, "→"+name)
			err := next(ctx, o) // 不调 next 就等于链断在这里
			o.Trace = append(o.Trace, "←"+name)
			return err
		}
	}
}

func guard(ok bool) Middleware {
	return func(next Handler) Handler {
		return func(ctx context.Context, o *Order) error {
			o.Trace = append(o.Trace, "→guard")
			if !ok {
				return errors.New("拒绝：风控未通过")
			}
			return next(ctx, o)
		}
	}
}

func payHandler(_ context.Context, o *Order) error {
	ns, err := fire(o.State, EvPay)
	if err != nil {
		return err
	}
	o.State = ns
	if o.Total > 10000 {
		o.Total = o.Total * 8 / 10
	}
	return nil
}

// ---------- 迭代器 ----------
type Store struct{ orders []*Order }

func (s *Store) All() iter.Seq[*Order] {
	return func(yield func(*Order) bool) {
		for _, o := range s.orders {
			if !yield(o) {
				return
			}
		}
	}
}

func filter(seq iter.Seq[*Order], keep func(*Order) bool) iter.Seq[*Order] {
	return func(yield func(*Order) bool) {
		for o := range seq {
			if keep(o) && !yield(o) {
				return
			}
		}
	}
}

// ---------- 命令 ----------
type Cmd struct {
	Name string
	Do   func() error
	Undo func() error
}

func main() {
	// ① 状态机表
	o := &Order{ID: "A1", State: Created}
	for _, e := range []Event{EvPay, EvShip, EvClose} {
		ns, err := fire(o.State, e)
		fmt.Printf("① %-8s --%-5s--> %-8s err=%v\n", o.State, eventName[e], ns, err)
		o.State = ns
	}
	_, err := fire(Shipped, EvPay)
	fmt.Printf("   非法边：%v\n", err)

	// ② 责任链
	o2 := &Order{ID: "A2", State: Created, Total: 20000}
	h := Chain(payHandler, traced("auth"), traced("trace"))
	fmt.Printf("② 正常：err=%v trace=%v state=%s total=%d\n",
		h(context.Background(), o2), o2.Trace, o2.State, o2.Total)

	o3 := &Order{ID: "A3", State: Created, Total: 100}
	h2 := Chain(payHandler, guard(false), traced("auth"))
	fmt.Printf("   短路：err=%v trace=%v state=%s\n",
		h2(context.Background(), o3), o3.Trace, o3.State)

	// ③ 迭代器
	st := &Store{orders: []*Order{{ID: "A4", State: Paid}, {ID: "A5", State: Created}, {ID: "A6", State: Paid}}}
	paid := filter(st.All(), func(o *Order) bool { return o.State == Paid })
	var ids []string
	for o := range paid {
		ids = append(ids, o.ID)
	}
	fmt.Printf("③ 全量遍历已支付：%v\n", ids)
	for o := range paid {
		fmt.Printf("   提前退出：只处理了 %s 就 break\n", o.ID)
		break
	}

	// ④ 命令队列
	total := 0
	var done []Cmd
	push := func(name string, delta int) {
		c := Cmd{
			Name: name,
			Do:   func() error { total += delta; return nil },
			Undo: func() error { total -= delta; return nil },
		}
		_ = c.Do()
		done = append(done, c)
		fmt.Printf("   执行 %-12s total=%d\n", c.Name, total)
	}
	push("add-item:100", 100)
	push("add-item:50", 50)
	push("coupon:-30", -30)
	for i := len(done) - 1; i >= len(done)-2; i-- {
		_ = done[i].Undo()
		fmt.Printf("   撤销 %-12s total=%d\n", done[i].Name, total)
	}
	fmt.Printf("④ 命令队列：执行 %d 条，撤销 2 条后 total=%d\n", len(done), total)
}
```

真实输出：

```text
① created  --pay  --> paid     err=<nil>
① paid     --ship --> shipped  err=<nil>
① shipped  --close--> closed   err=<nil>
   非法边：illegal: shipped -/-> pay
② 正常：err=<nil> trace=[→auth →trace ←trace ←auth] state=paid total=16000
   短路：err=拒绝：风控未通过 trace=[→guard] state=created
③ 全量遍历已支付：[A4 A6]
   提前退出：只处理了 A4 就 break
   执行 add-item:100 total=100
   执行 add-item:50  total=150
   执行 coupon:-30   total=120
   撤销 coupon:-30   total=150
   撤销 add-item:50  total=100
④ 命令队列：执行 3 条，撤销 2 条后 total=100
```

四行输出对应四个结论：**非法边被表挡住**（不是 panic，是可返回的 error）；**链路进出对称**、短路时后面一层没进；**`break` 真的停掉了生成器**；**撤销是逆操作**，`total` 逐条回退。

## 中介者与备忘录：两个别写重的模式

中介者的价值就是一个除法：6 个服务两两直连是 `6×5/2 = 15` 条链路，接一个 hub 是 6 条。参与者到 10 个时是 45 对 10。但 hub 一旦开始「知道每个订阅者的业务语义」，它就成了上帝对象——hub 只做路由和背压，不做业务判断。

备忘录是快照，成本要按容量算：1 万订单 × 每单 200 B ≈ **2 MB**，10 万单 ≈ 20 MB。后者不能塞进请求内存，要落到对象存储，只留一个版本号在内存里。快照必须深拷贝或结构不可变，否则「快照」会跟着原对象一起变。

## 访问者：只在「类型封闭、操作常加」时成立

同一道题（4 种 AST 节点 × 2 个操作：打印 + 求值），两种写法实测：

| 写法 | 代码量 | 加一个 `Sub` 节点 | 加一个操作 |
|---|---|---|---|
| 访问者（双分派） | 55 行 | **8 条编译错误**（2 个实现 × 4 个调用点），必须补 `VisitSub` | 新增 1 个类型，0 改动 |
| `type switch` | 38 行 | 0 条编译错误，但 `Print` 返回 `""`、`Eval` 返回 0，**静默漏** | 新增 1 个函数 + 4 个 case |

所以判据是反的：**类型集稳定、操作经常加**（编译器里的 AST）才用访问者；类型经常加、操作稳定（业务事件、消息体）用 `type switch` + 一个遍历全部类型名的测试兜住。业务代码里 3 个类型加操作，写访问者是净亏——多 17 行，还多一层间接。

## 解释器：AST 是唯一正解

```go
type Node interface{ Eval(env map[string]int) int }

type Num struct{ V int }

func (n Num) Eval(map[string]int) int { return n.V }

type Add struct{ L, R Node }

func (a Add) Eval(env map[string]int) int { return a.L.Eval(env) + a.R.Eval(env) }

type Var struct{ Name string }

func (v Var) Eval(env map[string]int) int { return env[v.Name] }
```

节点用「接口 + 递归」最短，不要为了「符合解释器模式」给每个节点再加 `Accept`。真正的成本在词法和语法：表达式里出现优先级、括号、函数调用之后，手写递归下降很快会失控——**超过 20 条语法规则就换 `goyacc` / `participle` 之类的生成器**，让 AST 保持傻瓜结构。

## 反模式

| 反模式 | 后果 |
|---|---|
| 每条折扣规则建一个结构体 + 接口，再加一个工厂 | 4 条规则 29 行变 3 层，分派 2.5 ns 变 17.6 ns、每次调用多 1 次分配 |
| 观察者用无缓冲 channel 且订阅方不监听 `context` | 发布方一停，每个订阅者泄漏一个 goroutine（实测 100 个） |
| 责任链中间件不调 `next` 也不返回 error | 调用方以为成功，业务静默丢单，日志里什么都没有 |
| 责任链没有终端 handler | 链空转或死循环，压测才发现 QPS 掉到 0 |
| 状态判断散落成 `if o.State == X` | 加一个状态要全仓 grep，漏一处就放过非法转移 |
| 命令模式包一层只为「以后可能要重放」 | 多一个队列 + 一个上限 + 一份序列化，实际只调用一次 |
| 在 `iter.Seq` 的 `yield` 里做 IO 或加锁 | 惰性遍历变成「逐条网络请求」，还占着生成器 goroutine |
| 用访问者给 3 个业务类型加操作 | 多 17 行代码；加类型时 8 条编译错误 |
| 中介者持有业务逻辑、知道每个订阅者是谁 | hub 变上帝对象，改一个订阅者要动 hub |
| 备忘录对 10 万条订单做全量深拷贝 | 单次快照 20 MB 级，GC 压力和延迟尖刺 |

## 自检

**Q1** 面试官说「接口有虚表开销，所以策略要用函数值」。用本机数据回应他，并说出真正的取舍点。

▸ 答案：两边在调用点都是一次间接跳转——接口查 itab，函数值取 funcval 地址，实测 2.70 / 2.74 ns，差在噪声内，都是 0 分配。真正拉开差距的是**构造**：把策略写进请求处理里每次重建，闭包捕获 `rate` 立刻逃逸，16 B/1 alloc、8.18–9.43 ns，是复用版的 3 倍多。所以取舍点不是 ns，而是「要不要多方法、要不要被 mock 替换」；一个函数能表达完就用函数值，否则用接口。

**Q2** 观察者 `buffer=8`、消费者 1 ms/条、发布 1000 条，为什么只收到 8 条而不是「慢一点但全收到」？这个设计对哪类事件是事故？

▸ 答案：因为发布走的是 `select { case ch <- e: default: }`，通道满了就进 `default` 丢弃，收到条数的上限就是 buffer 容量（实测 8 条、丢 992 条、26 µs 发完）。对「可以丢」的指标和日志没问题；对支付成功、库存扣减这类**必须最终一致**的事件是事故——事件消失了，下游永远等不到。这类事件要换成阻塞或消息队列（[31.2 事件驱动架构 (EDA)](../../L2-架构风格/31-事件驱动/31.2-事件驱动架构.md)）。

**Q3** 用嵌入写模板方法，`Base.Run` 里调 `b.parse` 为什么永远调到 `Base.parse`？怎么改？

▸ 答案：Go 没有虚方法分派。`b` 的静态类型是 `*Base`，`b.parse` 在编译期就定死；`CSV` 的 `parse` 只是另一个方法，不构成覆写，所以输出是 `base:1,2` 而不是 `csv:1,2`，且没有任何报错。改法是把可变步骤做成**钩子函数字段**（`Importer{Parse: ..., Save: ...}`），或者定义接口由外部注入实现。这也是「组合优于继承」在 Go 里最硬的一条证据。

**Q4** 责任链里 `guard(false)` 返回 error 且不调 `next`，后面的 `traced("auth")` 为什么没执行？如果它返回 nil 又不调 next 会怎样？

▸ 答案：`next` 就是下一层 handler，不调用它等于链在这里终止，所以 `trace` 只有 `[→guard]`。如果返回 nil 又不调 next，上层拿到「成功」但业务动作一次没做——这是最坏的一种：编译通过、测试不覆盖、日志干净、数据丢了。所以 code review 的检查项应该写成「每个中间件必须要么调 next 并透传 error，要么返回非 nil error」，两句话，没有第三种。

**Q5** 4 状态 × 3 事件，状态机表比 4 个状态类少写多少行？什么情况下反而该用类？

▸ 答案：12 条边，表 + `fire` 一共 19 行；类版要 4 个类型、每个类型 4 个方法（`Pay`/`Ship`/`Close`/`Name`），实测 64 行，是表的 3.4 倍，而且加一个状态要新增类型 + 给每个已有类型补一个方法。反过来，状态超过 20 个、或者每个状态都有独立副作用（发消息、调外部服务、写审计）时，表会退化成巨大的 switch，这时候用类型 + 方法更好维护。

**Q6** `iter.Seq` 实测最差比手写循环慢 20%（459 vs 338 ns），那它买到了什么？什么情况下这个优势会消失？

▸ 答案：先承认它没有速度优势（差 0–20%，量级相同）。买到的是惰性 + 可组合 + 调用方能提前退出：`filter(st.All(), keep)` 不生成中间切片，`break` 之后生成器立刻 `return`（实测只处理了 1 条）。优势消失的条件有三个：`yield` 里分配（每次往切片 append 就又有了中间态）、`yield` 里阻塞或加锁（变成逐条 IO）、跨 goroutine 调 `yield`（语言层面禁止）。满足这三条时它就是纯开销。

**Q7** 访问者常被说成「加操作方便」。加一个节点类型时两种写法各是什么后果？

▸ 答案：访问者版会得到 **8 条编译错误**（`Printer`、`Evaluator` 两个实现 × 4 个递归调用点），必须补 `VisitSub` 才能编译——这是它的价值：编译期强制补全。`type switch` 版 0 条错误，但 `Print` 静默返回空串、`Eval` 静默返回 0，属于「跑得通但算错」。结论：类型封闭且操作常加 → 访问者；类型常加 → `type switch` + 一个遍历所有类型的测试兜住。
