# 0.16 浮点数的位表示与近似算法

## 一句话

> 那段带 `// what the fuck?` 的代码不是魔法：**IEEE 754 的位表示**说明"浮点数是离散的"，**`log2(1+m) ≈ m + σ` 的直线近似**把"求平方根倒数"变成"一次整数减法 + 一次右移"，**牛顿迭代**再把初值精化到 0.2%；而本机实测（Apple M1，go1.27.1）表明这段 1990 年代的加速技巧**今天已经不快了**——值得带走的是三段推导与"先测再抄"的判据，不是那个魔数。

**来源**：魔数代码、IEEE 754 拆解、3.14 与 0.015 两个算例、`I_y ≈ R - ½I_x` 的推导、牛顿迭代、魔数考据，来自陈皓《左耳听风》第 13 讲（2018）；误差统计与基准为本节新做的实测（代码在 [tools/examples/0.16-rsqrt](../../../tools/examples/0.16-rsqrt/README.md)）。

## 先破除四个误区

| 误区 | 现实 |
|---|---|
| "`0x5f3759df` 是误差最小的魔数" | 不是。按"误差最小"反推是 `0x5f37642f`；按"迭代 1–2 次后最精确"暴力搜索是 `0x5f375a86`。原值只是**恰好很好**，且至今没人证明它最优 |
| "这段代码今天还能提速" | 不能。本机实测位运算版 2.33–3.46 ns/op，硬件 `sqrtss` 版 1.68–2.63 ns/op——**位技巧反而略慢**（硬件开方已是一条指令） |
| "浮点误差是语言 bug" | 是位宽的必然。`3.14` 存成 float32 是 `3.1400001049041748047`，`0.015` 是 `0.014999999664723873138`——23 位尾数只够约 7 位十进制有效数字 |
| "多迭代几次就精确了" | 天花板由 float32 决定。一次迭代误差 1.75e-3，两次 4.71e-6，再迭代也只是逼近 float32 的 1.2e-7，**收益递减** |

## 一、IEEE 754 单精度：1 + 8 + 23

32 位分三段，公式是 `(-1)^S × (1 + M/2^23) × 2^(E-127)`：

| 段 | 位宽 | 含义 | 取值范围 |
|---|---|---|---|
| **S** 符号位 | 1 bit | 正数 0、负数 1 | {0, 1} |
| **E** 指数位 | 8 bit | 存的是"偏移后"的指数，真值 `e = E - 127` | E ∈ [1, 254]，e ∈ [-126, 127] |
| **M** 尾数位 | 23 bit | 把 `[2^n, 2^(n+1)]` 这段等分成 `2^23 = 8388608` 份，M 是"走了几份" | [0, 2^23) |

一句话读法：**浮点数 = 归一化小数 × 2 的幂**；尾数决定精度（有效数字约 7 位），指数决定范围（约 1e-38 到 1e38）。

### 两个算例：为什么不精确是必然

```go
// tools/examples/0.16-rsqrt/rsqrt_test.go
cases := []struct {
	dec    float64
	want   Parts  // S/E/M
	wantIn string // 位模式
}{
	{3.14, Parts{Sign: 0, Exponent: 128, Mantissa: 4781507}, "0x4048F5C3"},
	{0.015, Parts{Sign: 0, Exponent: 120, Mantissa: 7717519}, "0x3C75C28F"},
}
```

以 `3.14` 为例，手算一遍：

1. `2^1 < 3.14 < 2^2` → `n = 1` → `E = 128`；
2. 尾数比例 `(3.14 - 2) / (4 - 2) = 0.57`，乘 `2^23` 得 `4781506.56`，四舍五入 **M = 4781507**；
3. 回算 `(1 + 4781507/2^23) × 2 = 3.1400001049041748047`。

0.015 同理：`2^-7 < 0.015 < 2^-6` → `E = 120`；比例 `0.92` → **M = 7717519**；回算 `0.014999999664723873138`。

本机输出（真实粘贴）：

```text
3.14   E=128 M=4781507  回算=3.1400001049041748047 相对误差=3.341e-08
0.015  E=120 M=7717519  回算=0.014999999664723873138 相对误差=-2.235e-08
0.1+0.2 = 0.30000000000000004441, 0.3 = 0.2999999999999999889, 差 = 5.551e-17
```

> 🔑 `0.1 + 0.2 != 0.3` 的差是 **5.551e-17**，与机器无关。这不是"精度不够"，而是三个十进制字面量在二进制里都存不准，误差不会自动抵消。

**工程结论**：金额、库存、计数一律用整数（分/厘）或 `decimal`；浮点只用于"容许误差的物理量"（坐标、概率、度量）。参见 [72.3 多币种与汇率](../../L4-组件与技术/72-国际化与多地域/72.3-多币种与汇率.md)、[50.4 度量](../../L4-组件与技术/50-可观测性/50.4-度量.md)。

## 二、从位表示到线性近似：四步推导

目标：算 `y = 1/√x = x^(-1/2)`。

| 步 | 动作 | 结果 |
|---|---|---|
| ① 取对数 | 两边以 2 为底 | `log2(y) = -½·log2(x)` |
| ② 代入位表示 | `x = (1+m_x)·2^{e_x}`、`y = (1+m_y)·2^{e_y}`，且整型 `I = M + E·2^23` | `log2(1+m_y) + e_y = -½[log2(1+m_x) + e_x]` |
| ③ 直线近似 | `m ∈ [0,1)` 时 `log2(1+m)` 接近直线，记 `log2(1+m) ≈ m + σ` | 把非线性压成线性 |
| ④ 合并常数 | 移项后乘 `3/2·2^23`，把含 σ 的项收成常量 `R` | **`I_y ≈ R - ½·I_x`** |

第 ③ 步是整套推导的支点：它**故意接受误差**，换来"乘法/开方"变成"减法/移位"。`σ` 是这个近似的系统偏差，反解出来是：

```
R = (127 - σ) · (3/2) · 2^23 = 0x5f3759df  →  σ ≈ 0.0450465
```

代码与公式一一对应：

```go
i := math.Float32bits(x) // i = * (long *) &y   把 float 的 32 位当整数读
i = magic - (i >> 1)     // i = 0x5f3759df - (i >> 1)   即 I_y ≈ R - ½·I_x
y := math.Float32frombits(i)
```

到这里只完成了"初值"：直线近似的相对误差约 **3.4%**（`log2(1+m)` 在区间两端的偏差最大），对图形学勉强、对通用计算不够。精化交给牛顿。

## 三、牛顿迭代：初值换迭代次数

对固定的 `x`，要求 `y` 使 `1/y² - x = 0`，即 `f(y) = y^(-2) - x`、`f'(y) = -2y^(-3)`。代入牛顿通用式 `y_{n+1} = y_n - f(y_n)/f'(y_n)`：

```
y_{n+1} = y_n - (y_n^-2 - x) / (-2·y_n^-3)
        = y_n · (1.5 - 0.5·x·y_n²)
```

`threehalfs - (x2 * y * y)` 就是它。原文里第二次迭代被注释掉，原因是"Quake III 的图形计算不需要那么高精度"——这是**场景判据**，不是通用结论。

本机实测误差（`[10^-2, 10^3]` 上 20 万点，相对误差）：

| 魔数 | 一次迭代 最大 | 一次迭代 平均 | 两次迭代 最大 | 两次迭代 平均 |
|---|---|---|---|---|
| `0x5f3759df`（Quake 原值） | 1.752e-03 | 9.363e-04 | 4.706e-06 | 1.828e-06 |
| `0x5f37642f`（最小误差） | 1.776e-03 | 9.461e-04 | 4.842e-06 | 1.865e-06 |
| `0x5f375a86`（迭代后最优） | 1.751e-03 | 9.369e-04 | 4.718e-06 | 1.831e-06 |

读法有两条：

1. **三个魔数的差别在第四位有效数字上**——换魔数的收益（1.752e-3 → 1.751e-3）远小于多迭代一次（1e-3 → 5e-6，差三个数量级）；
2. 两次迭代的 4.7e-6 距 float32 的极限 1.2e-7 还差一个量级，说明"两次"已是这套近似的天花板。

## 四、魔数考据：一个没人认领的常数

| 候选值 | 来源与判据 |
|---|---|
| `0x5f3759df` | Quake III 源码原值；`σ ≈ 0.0450465` 反解得到，**无人能证明它最优** |
| `0x5f37642f` | Chris Lomont 按"误差最小"推出的最佳 R |
| `0x5f375a86` | Lomont 改口径：按"1–2 次牛顿迭代后最精确"暴力搜索得到，实际代入更准 |
| `0x5fe6ec85e7de30da` | 双精度对应魔数；后来发现 `0x5fe6eb50c7aa19f9` 更准，McEniry 给出折中的 `0x5fe6eb50c7b537aa` |

作者归属是一条"越查越回去"的链：最初被归给 John Carmack，他本人回邮件否认，猜是汇编程序员 Terje Mathisen；Mathisen 说自己在 1990 年代初只做过**类似实现**；已知最早的实现来自 Gary Tarolli（SGI Indigo），但他只承认改进了常数 R；经 Cleve Moler 求证后，Rys Sommefeldt 认为原始算法出自 Ardent Computer 的 Greg Walsh，同样没有确定性证据。

Lomont 的追问值得记住："如果可能我想询问原作者，此速算法是以数学推导还是以反复试错的方式求出来的？"——McEniry 后来用**带权二分法**得到的常数恰好是 `0x5f3759df`，暗示它是"在可容忍误差范围内二分"的产物。

## 五、本机实测：这段代码今天还快吗

1024 个不同输入轮转（避免编译器把同一常数折叠掉），go1.27.1 darwin/arm64，Apple M1：

| 实现 | ns/op（5 次区间） | 精度 |
|---|---|---|
| 位技巧 + 1 次牛顿迭代 | 2.33 – 3.46 | 最大相对误差 1.75e-3 |
| `1/math.Sqrt(float64(x))` | 1.68 – 2.63 | 正确舍入到 float64 |

**结论：没有可测收益，位技巧均值还略慢。** 原因很直接：1990 年代浮点远慢于整数，`sqrt` 是软件例程；今天是 `sqrtss` 一条指令、延迟十几个周期。所以：

| 场景 | 该不该用 |
|---|---|
| 现代 CPU/GPU 的通用计算 | **不该**。先测再说，大概率不如硬件指令 |
| 无 FPU 的 MCU、只有整数单元的协处理器 | 该用。这是它的原始主场 |
| 需要 SIMD 批量近似、且能容忍 1e-3 误差 | 可以，但要写明误差预算 |
| 金额、库存、跨端一致性、可复现的科学计算 | **不该**。精度不可控，换整数或 decimal |

> 🔑 这段代码的真正价值不是"快"，而是**它把三件事串起来了**：数据表示决定能做到什么、近似决定代价、迭代决定精度。任何"用近似换速度"的方案（布隆过滤器、HyperLogLog、采样、量化）都是同一笔账——先问误差预算，再问换来多少。

## 反模式

| 反模式 | 后果 |
|---|---|
| 把 `0x5f3759df` 当"最优魔数"背下来 | 记错结论：最小误差是 `0x5f37642f`，迭代后最优是 `0x5f375a86` |
| 看到"经典优化"就照抄 | 20 年前的性能前提可能已消失，本机实测显示它已不快 |
| 用 float/double 记账 | `0.1+0.2 != 0.3`，对账永远差几分钱；累计误差还能放大 |
| 用 `==` 比较浮点结果 | 相等判断永远失败；要用 `|a-b| <= ε·max(1,|a|,|b|)` |
| 以为"限制输入长度就能防精度问题" | 精度问题来自位宽，与输入长度无关 |
| 只做一次牛顿迭代就当通用解 | 原文一次迭代的前提是"图形学不需要高精度" |

## 自检

**Q1** 为什么 `3.14` 存成 float32 之后会变成 `3.1400001049041748047`？

▸ 答案：因为尾数只有 23 位，`[2,4]` 这段被等分成 `2^23` 份，`3.14` 落在第 `4781506.56` 份上，只能取整到 `4781507`。这点舍入在回算时变成约 `3.3e-8` 的相对误差——**不是实现问题，是位宽决定的**。

**Q2** 推导里最关键的一步是哪一步？换掉它会怎样？

▸ 答案：第 ③ 步 `log2(1+m) ≈ m + σ`。它把非线性压成直线，才使"求平方根倒数"能用一次整数减法和右移完成。换掉它就没有闭式的 `I_y ≈ R - ½I_x`，只能用查表或分段拟合——精度更高但常数更大、缓存更差。

**Q3** 既然魔数换一换误差只差 0.001e-3，为什么还有人研究它？

▸ 答案：因为魔数决定的是**初值**，初值决定达到目标精度需要几次迭代。在只能做一次迭代的场景（1990 年代的 Quake），把初值压到最优就是全部收益；在本机能随便迭代两次的时代，这项研究的价值已经降到"考古"。这也说明优化的收益要看**约束**，不看绝对值。

**Q4** 本机实测位技巧比硬件慢，是否说明原文讲错了？

▸ 答案：不是。原文成立的前提是"90 年代多数浮点操作速度远滞后于整数操作"，这个前提今天不成立。判据是：**任何优化都有它的硬件与负载前提**，跨时代引用要重测。这也是本节要把基准代码留在 `tools/examples/` 的原因——结论会过期，复现步骤不会。

**Q5** 为什么 `0.1+0.2 != 0.3`，但 `0.5+0.25 == 0.75`？

▸ 答案：因为 0.5、0.25、0.75 都是 `1/2^n` 的和，二进制能精确表示；0.1、0.2、0.3 的分母含因子 5，二进制是无限循环小数，只能截断。判据：**分母只含因子 2 的十进制小数才精确**。

**Q6** 要把一个"误差 1e-3 可接受"的近似函数上线，除了写代码还要交付什么？

▸ 答案：三样——① 误差预算（最大相对误差、在什么输入区间、用什么分布测）；② 复现方式（示例目录 + 命令 + 期望区间）；③ 失效边界（超出哪个量级会崩、换硬件是否重测）。缺任何一样，这个近似就是不可维护的。
