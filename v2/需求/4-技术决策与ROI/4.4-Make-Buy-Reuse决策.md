# 4.4 Make / Buy / Reuse 决策

## 一句话

> 自建、买、复用不是 “技术偏好”，而是**三年 TCO 的比较**：自建付人力与维护，买付订阅与绑定，复用付适配与协调——算清三笔账，再谈 “我们想不想自己做”。

## 三年 TCO 实测（示例口径）

按 “初始 + 月成本 × 36” 估算，单位万元：

| 能力 | 自建 | 买 | 复用（内部平台） |
|---|---|---|---|
| 通用（HR/报销） | **740** | **318** | 128 |
| 差异化（推荐） | **840** | **960** | 420 |

两个结论：① **通用能力买最省**（自建 2.3 倍于买）；② **差异化能力买到第三年反而更贵**（订阅随规模涨，且定制受限）——这正是 “核心域必须自建” 的量化版本。

```python
def tco(init, monthly, years=3): return init + monthly*12*years
print(tco(200,15), tco(30,8), tco(20,3))   # 740 / 318 / 128
```

## 三个方案的隐藏成本

| 方案 | 显性成本 | 隐性成本 |
|---|---|---|
| 自建 | 人力、服务器 | 招聘、离职风险、长期维护、合规 |
| 买 | 订阅费 | 绑定、涨价、定制受限、数据迁移 |
| 复用 | 适配开发 | 协调成本、平台优先级、被上游改挂 |

判据：**隐性成本往往在第二三年才显现**，TCO 至少要算 3 年，并把 “退出成本” 单列。

## 决策表

| 你的情况 | 选择 |
|---|---|
| 通用能力、有成熟 SaaS | 买 |
| 差异化核心、变更频繁 | 自建 |
| 公司内已有平台且能力匹配 | 复用 |
| 合规要求极高（数据不能出域） | 自建/私有化 |
| 一次性/低频需求 | 买或外包，别自建 |

## 三年 TCO 算例：自建 / 买 / 复用

> 🔑 **只算「初始投入 + 月成本 × 36」会漏掉三项钱**：人力涨薪、订阅随量涨价、退出迁移。把三项放进同一个可重算模型，「长期自建便宜」才会变成一个具体的月份，而不是一句口号。

**先把参数固定下来。** 场景选核心定价 / 风控能力：因为跟 GMV 走，订阅按交易额阶梯计价。单位万元，所有单价都是示例，换成自己账单里的数才能拿去决策。

| 成本项 | 自建 | 买 SaaS | 复用内部平台 |
|---|---|---|---|
| 一次性投入（接入 / 迁移 / 机房 / 合规整改） | 200 | 40 | 60 |
| 人力（3.6 万/人月，年涨 8%） | 8 人 = 28.8 万/月 | 1.5 人 = 5.4 万/月 | 2 人 = 7.2 万/月 |
| 云资源（首年，年涨 35%） | 80 万/年 | 含在订阅里 | 20 万/年 |
| 许可 / 平台分摊（年涨） | 15 万/年（0%） | 订阅 32 万/月（年涨 38% = 涨价 15% × 用量 20%） | 36 万/年（10%） |
| 定制 / 协调 | — | 20 万/年（15%） | 14.4 万/年（4 人月） |
| 退出成本（第 3 年末，单列不摊） | 0 | 100 | 40 |

**模型只有四条规则**：① 初始投入在启用月一次性计入；② 每项月度成本按「合同年」跳档（价格与用量都按年调，不是按月）；③ 退出成本单列、不摊进月度，否则它会从表里消失；④ 回本点 = 自建累计成本第一次低于「买」的月份，按月算，不算「大约第几年」。

```go
// 三年 TCO 计算器：自建 / 买 SaaS / 复用内部平台（单位：万元）
// 口径：初始投入在启用月一次性计入；月度成本按“合同年”跳档增长；退出成本单列、不摊入月度。
package main

import (
	"fmt"
	"math"
)

type comp struct {
	name    string
	monthly float64 // 首年每月成本（万元）
	grow    float64 // 每个合同年的增长率
}

type plan struct {
	name  string
	init  float64 // 一次性：接入 / 迁移 / 机房改造 / 合规整改
	exit  float64 // 第 3 年末退出成本（单列）
	comps []comp
}

func (p plan) monthCost(m int) float64 { // m 从 0 开始
	y := m / 12
	sum := 0.0
	for _, c := range p.comps {
		sum += c.monthly * math.Pow(1+c.grow, float64(y))
	}
	return sum
}

func (p plan) yearCost(y int) float64 { // 第 y 年（1..3）的 12 个月
	s := 0.0
	for m := (y - 1) * 12; m < y*12; m++ {
		s += p.monthCost(m)
	}
	if y == 1 {
		s += p.init
	}
	return s
}

func (p plan) total3() float64 { return p.yearCost(1) + p.yearCost(2) + p.yearCost(3) }

func (p plan) cum(m int) float64 { // 第 m 个月末的累计成本
	s := p.init
	for i := 0; i < m; i++ {
		s += p.monthCost(i)
	}
	return s
}

// 回本点：自建累计成本第一次低于“买”的月份；36 个月未追上返回 0
func payback(self, buy plan) int {
	for m := 1; m <= 36; m++ {
		if self.cum(m) < buy.cum(m) {
			return m
		}
	}
	return 0
}

func main() {
	// 场景：核心定价/风控能力，跟 GMV 走；以下单价均为示例，按自身账单替换。
	self := plan{"自建", 200, 0, []comp{
		{"研发+SRE 8 人", 28.8, 0.08}, // 8 人 × 3.6 万/人月
		{"云资源", 80.0 / 12, 0.35},   // 首年 80 万/年
		{"许可", 15.0 / 12, 0.0},
		{"合规审计", 15.0 / 12, 0.10},
	}}
	buy := plan{"买", 40, 100, []comp{
		{"对接运营 1.5 人", 5.4, 0.08},
		{"订阅费", 32, 0.38}, // (1+15% 涨价) × (1+20% 用量) - 1
		{"定制/集成", 20.0 / 12, 0.15},
	}}
	reuse := plan{"复用", 60, 40, []comp{
		{"适配+对接 2 人", 7.2, 0.08},
		{"平台分摊", 36.0 / 12, 0.10},
		{"云资源", 20.0 / 12, 0.35},
		{"协调成本", 14.4 / 12, 0.10}, // 每年 4 人月
	}}

	fmt.Println("== 1. 三年总成本（万元，不含退出成本） ==")
	fmt.Println("方案 | 初始 | 第1年 | 第2年 | 第3年 | 3年合计 | 退出成本")
	for _, p := range []plan{self, buy, reuse} {
		fmt.Printf("%s | %.1f | %.1f | %.1f | %.1f | %.1f | %.1f\n", p.name, p.init,
			p.yearCost(1)-p.init, p.yearCost(2), p.yearCost(3), p.total3(), p.exit)
	}
	fmt.Printf("含退出成本合计：自建 %.1f，买 %.1f，复用 %.1f\n",
		self.total3()+self.exit, buy.total3()+buy.exit, reuse.total3()+reuse.exit)

	fmt.Println("\n== 2. 回本点（自建 vs 买） ==")
	if m := payback(self, buy); m > 0 {
		fmt.Printf("第 %d 个月（%.1f 年）自建累计成本首次低于买；3 年末自建省 %.1f 万\n",
			m, float64(m)/12, buy.total3()-self.total3())
	} else {
		fmt.Printf("36 个月未回本，买便宜 %.1f 万\n", self.total3()-buy.total3())
	}
	fmt.Printf("复用相对买：3 年省 %.1f 万\n", buy.total3()-reuse.total3())

	fmt.Println("\n== 3. 敏感性：订阅年涨幅 × 用量年增长 → 自建回本月份 ==")
	fmt.Println("用量增长\\订阅年涨 | 8% | 15% | 22% | 30%")
	for _, vol := range []float64{0, 0.10, 0.20, 0.30} {
		fmt.Printf("用量 +%.0f%%", vol*100)
		for _, price := range []float64{0.08, 0.15, 0.22, 0.30} {
			b := plan{"买", 40, 0, []comp{
				buy.comps[0], {"订阅费", 32, (1+price)*(1+vol) - 1}, buy.comps[2]}}
			if m := payback(self, b); m > 0 {
				fmt.Printf(" | %d 月", m)
			} else {
				fmt.Printf(" | 不回本")
			}
		}
		fmt.Println()
	}

	fmt.Println("\n== 4. 敏感性：适配超支 × 协调成本 → 复用 3 年合计 ==")
	fmt.Println("适配超支 | 1× | 1.5× | 2×")
	for _, coord := range []float64{1.2, 2.4} {
		fmt.Printf("协调 %.1f 万/月", coord)
		for _, mult := range []float64{1, 1.5, 2} {
			r := plan{"复用", 60 * mult, 40, []comp{
				reuse.comps[0], reuse.comps[1], reuse.comps[2], {"协调成本", coord, 0.10}}}
			fmt.Printf(" | %.1f 万", r.total3())
		}
		fmt.Println()
	}

	fmt.Println("\n== 5. 首年月度成本结构 ==")
	for _, p := range []plan{self, buy, reuse} {
		total := p.monthCost(0)
		fmt.Printf("%s（%.2f 万/月）：", p.name, total)
		for _, c := range p.comps {
			fmt.Printf("%s %.1f%%  ", c.name, c.monthly/total*100)
		}
		fmt.Println()
	}
}
```

**先读三个数。** ① 3 年总成本（不含退出）：自建 **1750.4 万**、买 **1965.0 万**、复用 **590.8 万**；② 回本点：**第 26 个月（2.2 年）**自建累计成本首次低于买，3 年末省 **214.6 万**；把买第 3 年末的 100 万退出成本算进去，差距放大到 **314.6 万**——退出成本不是「备注」，是直接加在差额上的钱；③ 复用比买省 **1374.3 万**，是 TCO 世界里的最低价，但它未必该选——它真正的成本不在 TCO 表里。

**回本点对两个变量最敏感：订阅年涨幅与用量年增长。** 把敏感性网格摆成矩阵：

| 用量年增长 \ 订阅年涨幅 | 8% | 15% | 22% | 30% |
|---|---|---|---|---|
| +0% | 不回本 | 不回本 | 不回本 | 29 月 |
| +10% | 不回本 | 32 月 | 27 月 | 25 月 |
| +20% | 30 月 | 26 月 | 25 月 | 22 月 |
| +30% | 26 月 | 24 月 | 22 月 | 20 月 |

同一套自建参数，回本点从 **20 个月**摆到 **32 个月**，最差格直接翻转成「买更便宜」。所以「自建还是买」不是技术判断，而是两个业务事实的判断：**合同里订阅年涨幅上限是多少、业务用量一年涨多少**。两个数都拿不到时，按最差格（涨幅 22% × 用量 +0%）决策——即不自建。

**成本结构决定降本该往哪使劲。** 自建首年月成本里 **75.9% 是人力**（3 年人力合计 1121.9 万，占 3 年总成本 64.1%），云只占 17.6%——自建降本只能减人或提效，砍云费是砍错了地方。买正相反：**81.9% 是订阅**（3 年订阅 1645.2 万，占 83.7%），而订阅涨幅通常写在合同里、砍不动——买方的杠杆只有「谈涨幅上限」和「保留退出能力」两条。复用是人力 55.1% + 平台分摊 23.0%，两项都是内部账，可谈。

**复用最便宜，但它省的是「账面钱」。** 适配超支 2 倍只多 60 万，协调成本从 1.2 万/月翻到 2.4 万/月只多 47.6 万——两项加起来都吃不掉它对买的 1374.3 万优势。复用真正的成本是**路线图控制权**：需求被排在平台半年后、一次升级破坏你的用法，这项损失在 TCO 表里没有行。所以复用成立的前提不是「便宜」，而是平台给得出**书面承诺**（接口兼容期、需求排期、SLA）；给不出，就按自建算。

**把上面的数变成决策表**（核心 / 非核心、变更频率、合规三个维度）：

| 能力属性 | 变更频率 | 合规 / 数据归属 | 三年内建议 | 判据（用本算例的数） |
|---|---|---|---|---|
| 非核心通用（HR、报销、监控） | 低 | 可出域 | 买 | 自建 64% 成本是人力，通用能力摊不薄；回本点大概率 > 36 个月 |
| 非核心但要集成 | 中 | 可出域 | 买 + 轻定制 | 定制费 < 自建 1 人年（43.2 万），买仍省 |
| 核心差异化（定价、风控） | 高（周级） | 不出域 | 自建 | 订阅年涨 ≥ 22% 且用量 ≥ +10% 时，回本 ≤ 27 个月 |
| 核心但变更极慢（年 2 次） | 低 | 可出域 | 买 / 复用 | 标准能力够用；自建等于为「变更频率」提前付费 |
| 核心 + 强合规（金融、医疗） | 任意 | 不出域 | 自建 / 私有化 | 数据归属与审计条款谈不下来；退出成本按 2× 计（本例 200 万） |
| 内部平台已有同能力 | 中 | 任意 | 复用 + 书面承诺 | 平台分摊 36 万/年 ≈ 1 人年，偏低，要换真实成本重算 |

**三条可操作判据**：① 回本点落在合同期外（> 36 个月）就不自建——还没回本，第一份合同就该续了；② 订阅涨幅上限没写进合同，就按 22% 这一列算，别按销售口头承诺的 8% 算；③ 退出成本 > 3 个月订阅费（本例 100 万 > 96 万）时，签合同前先做一次数据导出演练。

**替换参数再重跑。** 3.6 万/人月含社保与办公摊销，云单价按账单，订阅按合同阶梯；把假设换成自己的，结论可能翻转——模型的价值是给出「翻转条件」，不是替你拍板。假设、回本点与翻转条件要一起写进决策记录（见 [4.6 决策框架与决策记录](4.6-决策框架与决策记录.md)）；单位成本与容量口径对齐 [39.1 成本模型与单位经济](../../L3-质量属性/39-成本/39.1-成本模型与单位经济.md)；供应商涨价、退出条款与替代方案评估见 [4.8 外包与供应商评估](4.8-外包与供应商评估.md)。

## 反模式

| 反模式 | 后果 |
|---|---|
| 只算 “第一年成本” | 第二年订阅涨价/维护成本暴露 |
| 把 “自建” 当技术能力证明 | 核心域反而投入不足 |
| 买完不做退出方案 | 被绑定，迁移成本高到不敢换 |
| 复用不考虑平台优先级 | 你的需求永远排在平台后面 |
| 忽略合规与数据归属 | 后期整改成本远超省下的钱 |
| 不记录决策依据 | 换人后无法解释 “为什么自己做” |

## 三条铁律

> 🔑 **核心域自建、通用域买**；用 TCO 而不是偏好决策。

> 🔑 **必须算 3 年 + 退出成本**。

> 🔑 **决策要留依据与复核点**（见 [4.6 决策框架与决策记录](4.6-决策框架与决策记录.md)）。

## 自检

**Q1** 为什么 “通用能力” 自建的 TCO 会高这么多？

▸ 答案：因为自建要承担**全生命周期成本**：开发、招聘、值班、升级、合规审计；而通用能力（HR、报销）已有成熟产品，边际成本低。本例 740 vs 318，差在 “持续人力” 而不是 “初始投入”。

**Q2** 为什么 “差异化能力” 买到第三年反而更贵？

▸ 答案：因为 SaaS 的订阅通常随**用量/席位**增长，且定制要额外付费；而差异化能力往往需要深度定制与快速迭代，买来的系统跟不上节奏，最终 “买 + 定制 + 补丁” 的总成本超过自建。

**Q3** “复用” 为什么不是免费的？

▸ 答案：因为要付**适配与协调成本**：接入平台要改代码、对齐规范；平台有自己的优先级，你的需求可能排队；平台升级还可能破坏你的用法。复用的前提是 “能力匹配 + 平台有承诺”。

**Q4** TCO 里为什么要单列 “退出成本”？

▸ 答案：因为绑定成本往往在**迁移时才爆发**：数据导出格式、接口兼容、重新培训。把退出成本写进决策，能避免 “因为迁移太贵，所以只能继续续费” 的被动局面。

**Q5** 什么情况下 “买” 反而不划算？

▸ 答案：当需求**高度定制、变更极快、或数据不能出域**时：SaaS 的标准化能力跟不上，定制费与合规成本会超过自建。此时 “买” 只是把成本推迟，而不是消除。

**Q6** “复用内部平台” 和 “买 SaaS” 的本质区别？

▸ 答案：复用是**组织内协作**（可以提需求、可以影响路线图），买是**市场交易**（只能接受产品路线）。复用的风险是 “平台优先级”，买的风险是 “厂商绑定与涨价”。

**Q7** 怎么让这个决策可复核？

▸ 答案：记录四样：**假设**（人力单价、订阅涨幅、用量增长）、**TCO 模型**（可重算的脚本）、**触发复核的条件**（如 “订阅年涨幅 > 15% 或用量翻倍”）、**退出方案**。没有假设与触发条件，决策就变成 “一次性的政治结论”。
