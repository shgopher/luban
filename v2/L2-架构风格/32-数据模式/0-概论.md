## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **写模型** | 只管数据合不合规则、能不能落库 | 柜台记账本：只核余额对不对 |
| **读模型** | 按“你会怎么问”提前摆好的数据 | 便利店货架：按动线摆 |
| **CQRS** | 两套模型分开设计，中间接同步链路 | 餐厅前厅与后厨分开 |
| **物化视图** | 查询结果提前算好，存成表 | 提前熬好的高汤，点单就舀 |
| **事件溯源** | 不存“现在多少”，只存“发生过什么” | 银行流水：余额是加出来的 |
| **投影** | 把事件流折叠成一张能查的表 | 流水抄成月度汇总表 |
| **重建** | 从最早的事件重算投影 | 抄错了，拿原始流水再抄 |
| **共享数据库** | 多个服务直接读写同一张表 | 几家人共用一个冰箱 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “CQRS 就是读写分离” | 读写分离只把同一份数据抄到从库分流量；CQRS 是两套模型加同步链路 |
| “物化视图刷得越勤越好” | 读变快、写变贵；要定的是刷新方式与陈旧窗口，不是“尽量实时” |
| “有了事件溯源就不需要数据库” | 它换来历史与可重放，代价是回放成本、版本管理、查询复杂 |

## 读完自检（入门级 3 题）

**Q1** 为什么写模型和读模型常常不能是同一张表？

▸ 答案：写侧要规则、事务与聚合一致性，读侧要查询形状与速度；硬合成一套两端都让步，拆开就多一条同步链路与延迟窗口（[32.3](32.3-读写模型分离.md)）。

**Q2** 在 CQRS 里读到的数据比写侧旧，是故障还是设计？

▸ 答案：是设计。同步靠事件或 CDC，读写之间必然有延迟窗口；要做的是量出它、按业务定容忍度（[32.1](32.1-CQRS.md)、[32.2](32.2-物化视图.md)）。

**Q3** 投影写错了，为什么还能补救？前提是哪两条？

▸ 答案：事件流是事实来源，投影只是折叠结果，重放即可重建（[32.5](32.5-投影与重建.md)）。前提是投影幂等、位点可记。
