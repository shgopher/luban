## 5 分钟入门：先记住这 6 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **分层** | 把代码按抽象级别分摞：上层用下层，下层不认识上层 | 写字楼：一楼接待，三楼记账，前台不用会记账 |
| **接口（抽象）** | 只说"要什么"，不说"怎么做" | 插座孔：不管插进来的是台灯还是电饭锅 |
| **依赖倒置** | 内层规定插头长什么样，外层照着做 | 先定插座标准再买电器，不是买了电器再改墙 |
| **整洁 / 洋葱** | 一圈套一圈，依赖只朝圆心；洋葱多一层领域服务 | 靶子与洋葱：一个看靶心，一个剥到心 |
| **六边形**（端口与适配器） | 核心只开孔，每个孔接一个可换的插头 | 手机壳的开孔：换壳不换手机 |
| **包（模块）** | 编译期就拦得住越界 | 小区门禁：刷卡才进，翻墙报错 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "分层就是把目录分成 controller / service / dao" | 那是按技术角色分文件夹。分层切的是**变化原因**；三层砍掉领域层，规则会沉进 Service |
| "依赖倒置就是抽个 interface" | 接口**定义在内层**、实现在外层才算倒置；留在实现旁边，方向没变 |
| "整洁、洋葱、六边形选错就完了" | 三者同构，规则都是依赖朝内；成败在规则有没有落到包与 CI 上 |

## 读完自检（入门级 3 题）

**Q1** 一个需求改完，改动散落在 `util`、`dao`、`service` 三个包，违反了哪条原则？

▸ 答案：**CCP 共同闭包**。同原因变化的代码没放在一起，说明是按技术角色分包了。

**Q2** "应用层 import 了 DAO" 与 "DAO 实现应用层定义的接口"，哪句是倒置成功？

▸ 答案：第二句。前者高层直接依赖细节；后者依赖由外向内，判据是换数据库时应用层一行不改。

**Q3** 领域层里出现 `gorm`、`http`，问题在哪、该挪去哪？

▸ 答案：该层只允许业务术语；细节应由基础设施层实现领域层定义的接口。
