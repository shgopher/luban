## 一句话

## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **命令** | “请你做”，可拒绝，失败要有结果 | 派工单，不接要回话 |
| **事件** | “已经发生”，广播、不可撤回 | 小区贴停水通知 |
| **消息** | 传输载体，本身不带语义 | 信封 |
| **生产者 / 消费者** | 发的一方 / 订阅的一方 | 贴公告的物业 / 看公告的住户 |
| **事件流** | 按序只追加，不改写 | 银行流水，只往后加行 |
| **幂等** | 做多次等于做一次 | 电梯按钮按 5 次也只来一趟 |
| **死信队列** | 处理不了的消息单独关起来 | 快递“异常件”货架 |
| **兼容演进** | 新读旧、旧读新都成立 | 表格只加一栏备注 |

记住：**事件是广播，命令是点对点**。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “事件驱动就是解耦，越解耦越好” | 解开的只是“生产者知道消费者”这一层；**可见性与一致性都要额外建** |
| “消息队列保证不丢不重” | 它只能给 at-most-once 或 at-least-once；**“恰好一次”是业务用幂等换来的** |
| “回头改个事件字段没关系” | 事件收不回，消费者可能几周后才重放；删改会让旧读者读错，只能**换新事件类型** |

## 读完自检（入门级 3 题）

**Q1** “库存已扣减”写成命令和事件，失败处理差在哪？

▸ 答案：命令可被拒绝，失败要回结果，调用方据此重试；事件不可撤回，收到的人只能补偿。把事件当命令重试就会重复执行。

**Q2** 已经发了订单事件，要加“发票”下游，改哪些服务？代价是什么？

▸ 答案：只加发票的订阅，订单服务不改。代价是没人知道谁在听，出问题只能靠事件追踪和死信去查。

**Q3** 系统承诺“至少一次”，为什么对账还会多一笔？

▸ 答案：重投是正常的——处理成功、ack 丢失就会再收到一遍。没有幂等就执行两次。
