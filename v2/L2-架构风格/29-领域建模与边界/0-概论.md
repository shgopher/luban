## 5 分钟入门：先记住这 8 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **领域** | 软件服务的那门生意 | 饭馆卖的是“吃饭” |
| **子域** | 生意按值不值钱切开的块 | 招牌菜、洗碗、买调料 |
| **限界上下文** | 模型自洽的边界，界内一词一义 | 后厨“一份”≠前台“一份” |
| **上下文映射** | 两个模型冲突时谁让步 | 两家对接，谁按谁格式填单 |
| **聚合** | 一个事务里必须同时成立的规则 | 订单和明细，一起成立 |
| **领域事件** | 已发生、别人要知道的事实 | 收银小票：钱付过了 |
| **通用语言** | 写进代码、列名、接口的词 | 全店叫“翻台”，不叫“桌位复用” |
| **事件风暴** | 按时间轴把已发生的事贴满墙 | 打烊后复盘整天，贴便签 |

        │
        ▼ 边界靠事件风暴问出来（时间轴 + 口径冲突） ← 29.6

- 两段不能混：上面**问题空间**（业务怎么分工），下面**解空间**（模型画多大）。
- **聚合**画事务，**上下文**画模型，**服务**最后谈；顺序反了就是一个聚合一个服务。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “一个子域就是一个上下文” | 只在最简单时成立：一个子域常拆多个上下文，多个子域也可共用一个 |
| “上下文就是微服务” | 上下文是模型边界，服务是部署边界；可先落成模块化单体的模块 |
| “聚合就是个实体对象” | 聚合圈的是必须同时成立的规则，也是并发边界；越大并发越少 |

## 读完自检（入门级 3 题）

**Q1** 8 个微服务 = 8 个限界上下文？

▸ 答案：不是。服务数管部署，上下文数管模型；多个上下文可合成一个服务、用包边界区分，服务里塞多个上下文就是分布式单体。

**Q2** 下单同时写两张表，说明边界画错了？

▸ 答案：是的。强一致事务证明两者共享一个不变量，这正是聚合的定义；拆开再上分布式事务，是拿更大复杂度模拟本地事务。

**Q3** 术语表怎么算真通用语言？

▸ 答案：看词有没有落到代码标识符、列名、API 字段、测试名、文档标题五处；只停在表里的，开口照样各说各的。
