## 5 分钟入门：先记住这 6 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **康威定律** | 架构必然长成组织沟通结构的影子 | 分几个部门，系统就分几个模块 |
| **协商边界** | 接口即合同，得由能直接对话的人谈 | 合同得当面谈，隔三层传话签不下来 |
| **逆康威定律** | 主动改组织，让想要的架构自然长出来 | 先分好柜子格子，再安排谁用哪格 |
| **所有权** | 代码库、发布权、值班、SLO 归谁 | 钥匙和房产证在谁手上 |
| **认知负荷** | 团队能同时扛住多少东西 | 一人看几口锅，锅多必糊 |
| **分布式单体** | 服务拆开了，改动还得几个团队一起上 | 几户分房住，却共用一把总闸 |

## 一张图：这章的骨架

```
问题：命令下了，架构怎么还不动？
        │
        ▼
  架构 = 组织沟通结构的影子（必然，非倾向）
        ├── 接口即合同，合同靠协商
        ├── 转述一次，细节丢一次
        └── 局部理性：只管自己边界内
        │
        ▼
  组织不动，架构白拆；组织一合，架构必合
        │
        ▼
  答案：逆康威定律（顺序不能反）
       ① 目标架构 → ② 团队边界 → ③ 依赖方向
       ④ 所有权 → ⑤ 平台能力
        │
        ▼
 74.2 四种团队类型（按负荷构成选）
 74.3 三个接触面：所有权 / 契约 / 值班
 74.4 认知负荷：规模的上限是负荷，不是人数
```

- 上半段答"为什么"，下半段答"怎么办"，转折是"组织不动，架构白拆"。
- 顺序反了必失败：只做 ② 不做 ④，团队只换个名字。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "康威定律是管理学鸡汤，信不信由你" | 它是约束：沟通形状不变，架构必被拉回原形 |
| "改个名、换条汇报线，架构就跟着变" | 所有权不转移就没有决策权 |
| "拆不动是服务拆得不够细" | 边界只能沿原分工线切，拆完是分布式单体 |

## 读完自检（入门级 3 题）

**Q1** 康威定律为什么用"必然"而不是"倾向于"？

▸ 答案：关键词是"受限于"不是"倾向于"：模块边界就是协商边界，谈不出来的接口会退化成各写一份或共享数据库。想改架构，先改能协商的边界。

**Q2** 逆康威定律最容易死在哪一步？怎么判定？

▸ 答案：死在**所有权**。代码库、发布权、on-call 还在原团队，遇事仍要请示。判定：能不能不经审批自己发布到生产？

**Q3** 团队管的服务远超自己熟得过来的量，上线就慌，违反康威定律了吗？

▸ 答案：不是，是**认知负荷**超了。解法是收敛服务数量、通用能力收编成平台，不是拆团队。
