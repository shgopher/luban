## 5 分钟入门：先记住这 6 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **门禁** | 质量由机器守，不靠自觉 | 地铁闸机：不刷卡过不去 |
| **无指责复盘** | 追机制，不追人 | 查事故原因，不查谁背锅 |
| **透明** | 决策与数据默认公开 | 玻璃厨房：看得见才放心 |
| **知识地图** | 先有结构，再挂知识点 | 先有书架，再放书 |
| **ARTS** | 每周一次的输出节奏 | 每周存一笔，年底有复利 |
| **上手阻塞时长** | 新人到第一个 PR 被卡多久 | 新店员多久能独立收银 |

```
问题：人一走，知识和能力就清零？
        │
        ▼

        │  没有这三样，沉淀与成长都靠自觉

        ▼

        │  留存率：听讲 5% ↔ 教别人 90%
        ▼
78.4 上手：看得懂 → 跑得起来 → 改得动
        │  退出标准：3–10 天上线第一个改动
        ▼
```

- 上半段是**制度**（78.1–78.2）：让信息与标准不依赖某个人。
- 下半段是**人**（78.3–78.4）：让成长有节奏、上手有路径。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “文化是氛围，不可度量” | 文化是默认行为，能用门禁绕过率、行动项完成率、复发率三个数验收 |
| “沉淀就是多写文档” | 没有唯一真相源与 owner 的文档是负资产 |
| “学习靠自觉，组织帮不上忙” | 组织能给三样：源头、节奏、反馈；三样都便宜 |

## 读完自检（入门级 3 题）

**Q1** 团队没有门禁，靠 code review 保证质量。三个月后质量会怎样？

▸ 答案：会随工期压力漂移。review 是人的判断，标准随人、随时段变化；门禁是机器判断，稳定且可审计。更重要的是 review 只能覆盖看得见的改动，而门禁能覆盖全部合并。

**Q2** 同一份接口说明，写在 wiki 和写在代码里，一年后哪份更可信？

▸ 答案：代码（或从代码生成的文档）。wiki 没有 review、没有版本关联，代码一改它就过期；代码与生成文档跟代码一起版本化、一起回滚，腐烂速度低一个量级。

**Q3** 新人第一周，导师最该做的三件事是什么？

▸ 答案：给方向（每天 15 分钟说清今天看什么）、挑毛病（每个 PR 只挑 1–2 个最重要的）、挡需求（前两周不让业务直接派活）。**不要直接给答案**——提问让他自己走一遍，才是真的上手。
