# 80.5 能力阶段：从高级新手到专家

## 一句话

> 工作年限不等于技术能力：新手会**自然**变成高级新手，但高级新手**不会自然**变成胜任者——因为他的熟练只是对规则的熟练，而规则只在特定场景有效。超过半数的人终身停在高级新手，且**不知道自己停在那里**。

**来源**：德雷福斯模型的五阶段划分、高级新手陷阱与三条成长建议来自李智慧《后端技术面试 38 讲》第 34 讲（极客时间，2020）；阶段判据表、评审模板与自检题为本节补充。

## 先破除四个误区

| 误区 | 现实 |
|---|---|
| “干了十年，能力自然比干五年强” | 能力与年限不相关。技术能力在入职三五年后普遍停滞，简历上最明显的信号是：**最近几年的职责、技术、项目类型和头几年几乎一样** |
| “熟练 = 精通” | 熟练是“在旧场景里做得快”，精通是“在新场景里能找对方法”。行业一变革，前者立刻抓瞎，后者反而受益 |
| “专家靠天赋” | 专家约占 1%，但路径是公开的：对结果负责 + 难度递增 + 盯住场景。三条都不需要天赋，只需要选择 |
| “多做几年就会成长” | 高级新手不会自动升级，这一点是这个模型最悲观也最有用的结论。没有“新问题 + 责任”这两个输入，做十年也不会变 |

## 五个阶段：判据是“遇到新问题时的反应”

| 阶段 | 能做什么 | 遇到新问题 | 典型表现 |
|---|---|---|---|
| **新手** | 在指导下完成工作，学规则与套路（工具、框架、流程、业务术语） | 必须有人带 | 大约两三年掌握套路后离开这一阶段 |
| **高级新手** | 无需指导，熟练套用规则 | **束手无策，或硬套旧办法** | 把规则当真理且引以为豪；不明白规则为什么这样定 |
| **胜任者** | 主动寻找新方案解决问题 | 能解决，但只“见招拆招” | 有主动性，缺反思与全局视角 |
| **精通者** | 主动反思、主动学习，能自我改进 | 没有新问题也能自我突破 | 明白所有规则只在特定场景有效，重视对场景的理解 |
| **专家** | 融会贯通形成直觉，用最直接简单的方法解决 | 直觉判断 | 约占 1%；他人学习其解法并沉淀为行业规则 |

> 🔑 分水岭在“高级新手 → 胜任者”：这一步靠的不是时间，是**主动性**——遇到新问题时去找新方案，而不是把旧办法套在新问题上。

## 高级新手陷阱：为什么多数人会停住

三个特征，中一个就要警惕：

1. **把规则当真理**。熟练使用某个框架、某种架构，并因此自信；但说不出“为什么是它而不是另一个”。
2. **不知道自己停在那里**。高级新手觉得自己混得不错——做事熟练、经验丰富。**这种“不错”恰恰是陷阱**：它没有痛感，所以没有改变的动力。
3. **岁月静好时无感**。流程稳定、需求重复时，高级新手和精通者产出差不多；一旦技术变革或工作出现新情况，差距在一周内显现。

这也解释了一个常见的招聘现象：**“空有十年经验”的候选人反而劣势**——面试官会怀疑他已经没有成长空间，而年限更短、能力相当的人被认为还有空间。

## 怎么判断一个人在哪一阶段

用**行为证据**判断，不用年限、不用自我评价。三组问题，逐层加深：

| 问什么 | 高级新手的回答 | 胜任者及以上的回答 |
|---|---|---|
| “为什么用这个框架/方案？” | 大家都用 / 一直这么用 / 性能好 | 说出当时的约束、备选方案与被排除的原因 |
| “如果场景换成 X 会怎样？” | 还是这套做法，或答不上来 | 能指出方案的适用边界，并给出新的取舍 |
| “上次做完之后，你改了什么？” | 没有，接着做下一个 | 复盘出规则或清单，下次做法确实变了 |

简历与面试之外，还有三个低成本信号：

- **职责与技术在最近 3 年是否变过**（没变=高风险）；
- **有没有“从 0 到 1”或“救火”类经历**（只有“维护既有系统”通常停在高级新手）；
- **能否讲清一次失败**（讲不清或全是别人的问题，说明从未对结果真正负责）。

一个可直接粘进评审记录的模板：

```yaml
# 晋升/招聘评审记录：用行为证据定位阶段，而不是用年限
candidate: 张三
years: 9
evidence:
  independent_same_kind: 4     # 能独立完成同类需求（高级新手门槛）
  new_scene_solution: 1        # 在新场景下主动找到方案（胜任者证据）
  reflect_and_rule: 0          # 复盘后沉淀出规则并改了做法（精通者证据）
stage_estimate: 高级新手
decision: 不给“更高职级”，给“新场景 + 对结果负责”的机会，半年后复评
```

> ⚠️ 阶段与职级不是一回事：职级是组织给的标签，阶段是认知状态。一个人可以是 P7 却仍是高级新手——头衔靠年限和机会，阶段靠有没有真正处理过“规则失效”的场景。

## 三条成长杠杆

### ① 承担责任：对结果负责，才会看透本质

真正的领悟都是“痛的领悟”。只按别人的规则做事，永远不会知道事物的真相；只有对结果负责、在压力下，才会去追问技术的关键点、缺陷与边界。

对应到团队动作：给**端到端的所有权**（从设计到线上），而不是“完成分配的任务”。这也是 [78.2 平台团队与中台](../78-技术组织设计/78.2-平台团队与中台.md) 里“平台是产品、有内部用户”的同一逻辑——有用户、有结果，才有责任。

### ② 挑战递增：摘跳起来够得着的苹果

一万小时定律的误读是“重复一万小时就能成专家”。有效的是**每次比上次难一点点**：伸手就够到的苹果没有成长，注定失败的苹果也没有成长，**跳起来够得着的才有**。

对应到管理动作：分活时按“当前能力 + 10%~20%”的难度分配，而不是按“谁熟谁做”。后者效率最高，但把团队锁死在高级新手。

### ③ 关注问题场景：别拿锤子找钉子

熟练的技术如果不匹配问题，就是负资产。专家不是“掌握最多技术的人”，而是**最善于根据场景找到解法的人**——有时最简单的办法就够了。

对应到架构决策：先写清约束与场景，再选技术（[58.5 技术选型流程](../../L5-工程效能/58-架构治理/58.5-技术选型流程.md) 的七个阶段就是这条的工程化）。

## 反模式

| 反模式 | 后果 |
|---|---|
| 用年限定职级 | 组织里堆满高级新手，关键项目无人能接 |
| 把“熟练”当“精通”来奖励 | 奖励的是套用规则的速度，团队越发不敢尝试新方案 |
| 只分配熟悉的活 | 效率短期最高，团队长期停在高级新手 |
| 只给任务不给结果 | 没有责任压力，犯错成本由别人承担，学不到本质 |
| 用“他做了十年”说服评审 | 十年重复等于一年经验重复十次 |
| 把晋升当成长手段 | 头衔涨了、场景没变，认知没动，反而更难推动 |
| 面试只考知识点 | 知识点可以背，场景判断背不了；问“为什么”和“换场景怎么办”才有区分度 |

## 自检

**Q1** 一个人工作 8 年，同一个系统维护了 6 年，线上问题都能快速修掉。他在哪个阶段？

▸ 答案：大概率是高级新手。判据不是“能不能修”，而是“遇到没见过的问题会怎样”。如果 6 年里问题类型没变、修法没变，说明是对规则的熟练。要确认，问一句：“如果让你重做这个系统，你会改什么、为什么？”答不出取舍，就是停在了高级新手。

**Q2** 为什么“高级新手不知道自己停在高级新手”这件事，比“能力不够”更危险？

▸ 答案：因为能力不足会带来痛感，痛感会驱动改变；而“熟练”带来的是舒适和自信，没有任何触发改变的信号。等到技术变革或组织调整，才发现自己的经验是场景绑定的——那时补课的成本最高。

**Q3** 团队里效率最高的做法是“谁熟谁做”，为什么本节的建议相反？

▸ 答案：“谁熟谁做”优化的是单次交付效率，代价是把成长机会锁死：熟练者永远在做同一类事，新人永远得不到挑战。正确做法是按“当前能力 + 10%~20%”分配，慢一点，但每做一次团队能力上限就抬一点。短期效率与长期能力，必须显式取舍。

**Q4** 为什么“对结果负责”是升级的必要条件，而不是“多学几门技术”？

▸ 答案：学技术是输入，输入再多也不会自动变成判断力。只有对结果负责，才会在压力下追问：这个方案的关键点是什么、哪里可能崩、代价是什么。这些追问才是从“套规则”到“懂原理”的通道。学一门新技术只是换了一套规则。

**Q5** 面试里怎么用 3 个问题区分高级新手和胜任者？

▸ 答案：① “这个方案为什么是它，当时排除了什么？”（有没有权衡）；② “如果 QPS 涨 10 倍 / 数据量涨 100 倍，哪里先崩？”（有没有边界感）；③ “上次线上事故你改了什么？”（有没有闭环）。三个问题都答不出取舍，基本可以判定停在高级新手。

**Q6** 一个 P7 一定是精通者吗？为什么？

▸ 答案：不一定。职级是组织按年限、机会、稀缺度给的标签，阶段是认知状态。有人靠年限和“救火”能力升到 P7，但从没处理过“规则失效”的场景，仍是高级新手。反过来的错配也存在：精通者因为团队没有职级名额而被低估。

**Q7** “摘跳起来够得着的苹果”具体怎么落地到任务分配？

▸ 答案：给任务时标注两件事——**熟悉度**（做过几类相似任务）和**不确定性**（有几个未知变量）。熟悉度高、不确定性低 → 交给新人练手；熟悉度低、不确定性中 → 交给要升级的人（有挑战但不至于失控）；不确定性极高 → 由精通者带做，同时把过程拆成可复用的规则。全都自己扛或全给新手，两个极端都不产生成长。

**Q8** 如果一个人已经在高级新手待了十年，还有救吗？

▸ 答案：有，但需要“换场景”而不是“加年限”。三条同时给：① 一个他没做过、且要对结果负责的端到端任务；② 允许失败的缓冲（第一次大概率做不好）；③ 强制的复盘输出（把踩的坑变成规则）。缺任何一条，都会回到旧路径——因为没有新场景，就没有新规则可学。
