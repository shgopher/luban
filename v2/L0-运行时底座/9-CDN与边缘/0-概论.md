## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **CDN** | 把内容放到离用户更近处 | 总仓 + 全城门店的便利店 |
| **PoP（边缘节点）** | 直接服务当地用户的机房 | 小区门口的自提柜 |
| **回源** | 边缘没有或过期，就回源站取 | 门店缺货，让总仓补货 |
| **缓存键** | 判断内容归谁的标识 | 快递单上的地址，写错就送到邻居家 |
| **TTL（失效）** | 内容到期作废的时间 | 牛奶盒上的保质期 |
| **预热 / 刷新** | 发布前先送新内容 / 让旧内容立刻作废 | 开学前先发教材 / 撕掉旧通知 |
| **动态加速** | 不能存的内容改走更快那条路 | 不能囤货，就换条不堵的高速 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “CDN 就是一堆缓存服务器” | 三层：**调度**决定去哪个节点、**边缘**决定怎么出去、**控制面**决定多久生效 |
| “节点越多，用户越快” | 节点数量不提高命中率，反而稀释它；体验看调度与回源链路 |
| “回源风暴是流量太大” | 几乎总是配置问题：预热、刷新、TTL 顺序，或键拆得太碎 |

## 读完自检（入门级 3 题）

**Q1** 同一份静态资源，为什么“再加一个边缘节点”可能让整体命中率下降？

▸ 答案：命中率是**缓存键 × 容量 × 请求分布**相乘的结果，不是节点数量；请求摊薄后，单节点重复变少。

**Q2** 图片 URL 后面被拼上了时间戳或随机参数，会发生什么？

▸ 答案：**每个 URL 都成了新键**，边缘永远命中不了，请求全部回源；参数不影响内容，却把一份拆成无数份。

**Q3** 发布新版本时，预热、刷新、TTL 的顺序应该是什么？

▸ 答案：**先预热**把新内容送上边缘，**再刷新**作废旧内容，**TTL** 兜底。反过来先刷新，请求同时回源。
