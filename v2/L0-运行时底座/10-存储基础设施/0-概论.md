# 第 10 章 存储基础设施 · 概论

## 一句话

> 同一份数据，为什么有时放块设备、有时放对象存储？**三种存储是三种访问语义**，选型就是决定放弃哪一部分能力。

## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **块存储** | 裸设备，文件系统自己格式化 | 毛坯房：隔断自己砌 |
| **文件存储** | 多机能同时挂的目录树 | 共享盘：按门牌找文件 |
| **对象存储** | 桶 + 扁平 key，整份覆盖 | 快递柜：整箱存取，不能拆开改 |
| **快照** | 某时刻的数据视图，与源共命运 | 给房间拍照：房塌了照片没用 |
| **副本** | 几份一样的拷贝，读哪份都行 | 钥匙配三把，丢一把还有门 |
| **纠删码** | 校验块算回数据，省空间、重建慢 | 拼图缺一块，用其余块反推 |
| **元数据** | 记录「东西在哪」的账本 | 图书馆目录卡：卡丢找不到书 |

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| 「对象存储是网盘，也能挂成磁盘」 | 没有原地修改、没有目录；共享目录只能靠文件存储 |
| 「做了快照就不用备份」 | 快照与源共享底层，误删源、删账号、区域故障时一起消失 |
| 「副本数越多越安全」 | 三副本挤在同一机架，故障域还是一个：可靠性不涨，成本翻倍 |

## 读完自检（入门级 3 题）

**Q1** 合同 PDF 写完只读、偶尔整份替换，选哪种？为什么不能选另两种？

▸ 答案：选**对象存储**，一次写多次读 + 整对象替换正合它的语义。块要自己管文件系统；文件存储靠目录树，规模上去元数据先撑不住。

**Q2** 云盘 IOPS 没打满，写入却超时，最可能卡在哪？

▸ 答案：卡在**吞吐**或**延迟**。小块看 IOPS，大块看 MB/s，两个上限要一起看。

**Q3** 有人说「把三副本全换成纠删码」，你追问哪两个数？

▸ 答案：追问**存储成本**与**重建代价**。纠删码省空间，但重建要读 k 块、吃 CPU，恢复窗口更长；要快速恢复时副本仍对。
