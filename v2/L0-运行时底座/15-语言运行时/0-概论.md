## 5 分钟入门：先记住这 6 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **P（逻辑处理器）** | 夹在线程与 goroutine 间的工位，持有队列与内存缓存 | 每个灶配一个备菜台，切好的菜摆台上，换手不回仓库 |
| **goroutine** | 运行时调度的小任务，初始栈 2KB，不够就复制到别处 | 便签写满了换一张更大的重抄，不是撕掉重写 |
| **逃逸分析** | 编译期判断变量能否留栈，活过函数的才上堆 | 只在店里用的碗放消毒柜，要递出去的才装盒 |
| **STW** | 所有 goroutine 短暂停下的瞬间 | 全场红灯两秒，让清洁工清过道 |
| **profile** | pprof 五类数据源之一：CPU、堆、阻塞 | 体温计量体温，别拿它量血压 |
| **happens-before** | 两个操作的先后有保证，竞态判定靠它 | 有签收记录的快递才算送到 |

## 一张图：这章的骨架

```
        你写下 go f() 的那一刻
                │
                ▼
    ┌────────────────────────────┐
    │ 编译期：逃逸分析（15.3）    │  上栈还是上堆，这里就定了
    └──────────────┬─────────────┘
                   ▼
    ┌────────────────────────────┐
    │ 运行期：造一个 goroutine     │  2KB 栈，不够就复制（15.2）
    └──────────────┬─────────────┘
                   ▼
      P 的本地队列 ──► M 绑 P 执行 ──► 队列空了偷别人的（15.1）
                   │
                   ▼
      分配对象（15.3）──► 堆变大 ──► 三色标记 + 写屏障（15.4）
                   │
                   ▼
      慢 / 内存高 / 卡住 ──► pprof 五选一（15.5）──► 火焰图（15.9）
                   │
                   ▼
      怀疑顺序不对 ──► race detector（15.7）──► 回到原语（15.6 / 15.8）
```

- 上半段是运行时替你做的事，下半段是出事取证的路；
- 分配越快、存活越多，GC 越忙：这两站是因果，不是并列。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “goroutine 就是更轻的线程” | 线程由内核调度、栈固定；goroutine 由运行时调度、栈可增长。**轻是结果，不是定义** |
| “GC 停顿是卡顿主因” | 只有两次极短 STW；吃掉 CPU 与延迟的是分配速率与 mark assist |
| “加了锁就线程安全” | 锁被复制、没成对、等待点不可取消，有锁照样出错 |

## 读完自检（入门级 3 题）

**Q1** 同一函数里的变量，凭什么有的在栈上、有的在堆上？

▸ 答案：由**编译期逃逸分析**决定：活过函数或被外部引用的才上堆。降 GC 压力不靠调参，靠让变量别逃逸。

**Q2** 服务 P99 抖动，同事让你调大 GOGC，先问什么？

▸ 答案：先问抖动是否由 GC 引起、存活堆多大。存活堆大时调大 GOGC 只是把 GC 推后、把堆顶高，可能撞 limit 被杀。

**Q3** `go test -race` 全绿，能说明没有数据竞争吗？

▸ 答案：不能。它是**动态** happens-before 分析，只覆盖跑到的交错：报“有”可信，报“没有”不可信。
