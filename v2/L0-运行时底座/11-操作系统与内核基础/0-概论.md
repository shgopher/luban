## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **进程** | 独占地址空间与句柄表 | 独立门牌、独立电表的房子 |
| **线程** | 同一地址空间里被轮流调度 | 同屋共用餐桌的几个工人 |
| **虚拟内存** | 每个进程都以为自己独占全部地址 | 房卡写 801，住哪间由前台定 |
| **缺页** | 用到的页不在内存，现场去取 | 书在仓库，等管理员跑一趟 |
| **page cache** | 读过的文件页被留在内存 | 常用调料摆在灶台边 |
| **中断** | 硬件主动打断 CPU 说"我好了" | 外卖到了打电话，不是死守门口 |
| **epoll** | 就绪连接列成名单，你只读名单 | 前台只递"客人已到"的房间号 |

> 记住 **"资源与调度分开、缓存与拷贝最贵"**。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "CPU 使用率不高，说明没问题" | load 含 D 状态；`wa`/`si` 高、D 堆积时 CPU 空闲，请求照样超时 |
| "`free` 变小就是内存不足" | page cache 也占内存但可回收，看水位与页面能不能丢 |
| "用上 epoll 或零拷贝，吞吐就上去了" | epoll 不省拷贝与协议解析，零拷贝不减少磁盘与网卡耗时 |

## 读完自检（入门级 3 题）

**Q1** 工作线程从 50 加到 5000，吞吐先升后降，为什么？

▸ 答案：**切换频率吃掉了收益**。切换只要 1–3μs，但换任务会挤掉 cache 与 TLB 的工作集，代价到数十 μs；线程越多越留不住，于是 CPU 很忙、吞吐不涨。

**Q2** `free` 只剩几百 MB 但服务正常，要不要处理？

▸ 答案：先分清那是**可回收的 page cache 还是要靠 swap 的匿名页**。`low` 以下 `kswapd` 异步收，`min` 以下分配者同步收，收不动才 OOM——看水位，不看 `free` 数值。

**Q3** "CPU 不高但请求变慢"，先看哪两个数？

▸ 答案：先拆时间块看 **`wa` 与 `si`**，再看 load 里 **R 与 D 的构成**——D 长期堆积指向存储，`si` 偏就看 `/proc/softirqs`。
