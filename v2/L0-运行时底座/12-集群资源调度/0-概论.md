# 第 12 章 集群资源调度 · 概论

## 一句话

> 调度器只做两件事：把资源抽象成可分配向量，为每个任务找位置；三代架构与公平/抢占算法，都是在**利用率、公平、延迟、碎片**之间做取舍。

## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **资源向量** | 机器能给的 CPU、内存、端口、GPU 写成一组数 | 行李箱三张标签：限重、限体积、限件数 |
| **碎片** | 总量够，零散剩余却拼不成整块 | 箱子满了，还剩条放不进鞋的缝 |
| **单体调度** | 全部任务进一个队列，串行拍板 | 只开一个窗口，全队排一条 |
| **两层调度 / offer** | 上层把资源"报价"给下层，下层自己挑任务 | 阿姨先把菜盛你盘里，一犹豫就凉 |
| **共享状态调度** | 多个调度器读同一份状态，提交时校验 | 几个人改同一份文档，保存时撞了 |
| **主导份额** | 按占全局容量的比例比公平，不比绝对用量 | 合租按占房间面积算，不按谁东西多 |
| **抢占** | 高优任务来了，杀掉低优任务腾位置 | 救护车鸣笛，前车靠边，路得重走 |

- 上半段管"怎么决策"：一个大脑、两层报价、还是并发快照，本质是**吞吐、延迟、一致性**的取舍；
- 下半段管"分给谁"：先有公平规则，才谈得上抢占。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| "调度就是找台空闲的机器" | 先按约束过滤，再打分；**约束每加一条，可调度位置就少一批** |
| "公平就是把资源平均分" | 平均分忽略任务形状；按主导份额比，"1 核 8G"和"8 核 1G"才可比 |
| "抢占能提高利用率" | 抢占是拿低优的命换高优的 SLO；缺三件套，只是排队变反复重试 |

## 读完自检（入门级 3 题）

**Q1** 集群 CPU 还剩 30%，为什么一个要 8 核的任务还是排不上？

▸ 答案：**总量够不等于放得下**。剩余 30% 散在多个节点，拼不出连续 8 核；也可能先被亲和、污点、拓扑过滤，先看卡在哪类。

**Q2** Mesos 的 offer 和 Omega 的共享状态，一句话差别在哪？

▸ 答案：**offer 是悲观地先递给你、会过期**：不冲突，犹豫就浪费；**共享状态是各自读快照、提交时校验**：不浪费，但会冲突重试。

**Q3** A 用 1 核 8G、B 用 8 核 1G，谁更占资源？

▸ 答案：**绝对值不可比**，要折成主导份额：取占 CPU 比例与占内存比例里大的那个再比，相同就同样排队；只按 CPU 比会误判 A 很闲。
