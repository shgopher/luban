## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **容器** | 被限定了“看得见什么”“能用多少”的普通进程 | 带独立门牌和电表的隔间 |
| **镜像** | 一组只读层加一份配置 | 一摞透明胶片，叠起来才是完整画面 |
| **写时复制** | 真要改文件时才拷进可写层 | 只在复印件上做笔记，原书不动 |
| **namespace** | 决定进程看得见哪些进程、网卡、挂载点 | 单向玻璃：看得见工位，看不见隔壁 |
| **cgroups** | 决定进程最多能用多少 CPU 和内存 | 电表加空气开关，超了就跳闸 |
| **容器运行时** | 真正动手建隔离、起进程的那一环（containerd / runc） | 施工队：图纸再漂亮也得有人砌墙 |
| **数据卷** | 与容器生命周期解耦的存储 | 行李箱：房子退租了箱子还能带走 |

> 记住“**共用宿主内核 + 只隔一半不算容器**”：启动快、镜像胖、数据会丢，都由这两句推出。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “容器就是轻量虚拟机” | 共用宿主内核，镜像里只有 rootfs；`uname -r` 看到的是宿主版本 |
| “扫描通过 = 镜像安全” | 扫描只管四环的第三环；来源不可信、没签名，照样进生产 |
| “数据写容器里就行” | 根文件系统是临时的，删容器即丢；要挂卷，或写 stdout |

## 读完自检（入门级 3 题）

**Q1** 同一个镜像在两台机器上跑，`uname -r` 输出不一样，为什么？

▸ 答案：容器没有自己的内核，镜像里只有 rootfs；内核版本与漏洞都是**宿主的责任**——这正是“便宜、启动快”的代价。

**Q2** 一个进程死循环吃满 CPU，为什么没拖死整台机器？只做 namespace 不做 cgroups 呢？

▸ 答案：cgroups 给了额度，超了就节流。只隔离不限流，它照样吃满整机；只限流不隔离，进程互相看得见。

**Q3** 日志写进容器 `/var/log/app`，重启后没了，改哪一步？

▸ 答案：日志落在可写层（临时根目录），容器一重建就丢。挂成数据卷，或写 stdout 交给采集。
