# 8.15 网关与路由：一跳一跳怎么走到对端

## 一句话

> 出不出网关，只看目标 IP 与本机是否同网段；出了网关，**MAC 逐段换、IP 只在 NAT 网关处改写**，而路由器靠路由表决定下一跳——静态路由写死、动态路由自愈、BGP 用 AS 路径给坏消息止损。

## 出不出网关，只看一件事

判据只有一条：**目标 IP 与本机是否同网段**（用子网掩码或 CIDR 算）。同网段，ARP 取目标 MAC 直接发；跨网段，把包交给默认网关。**网关地址必与源 IP 同网段**，否则连网关的 MAC 都 ARP 不到。

| 比较项 | 同网段 | 跨网段 |
|---|---|---|
| ARP 问谁 | 目标主机 | 默认网关 |
| 帧的目的 MAC | 目标主机 | 网关 |
| IP 头的目的地址 | 目标主机 | **仍是目标主机** |

算例：本机 `192.168.1.101/24` 访问 `192.168.1.50`，同网段；访问 `192.168.4.101`，跨网段，包交给 `192.168.1.1`。`/24` 里网关往往不是 `.1` 就是 `.2`。

> ⚠️ 只配 IP 不配 Gateway，跨网段必然不通；网关配成别的网段地址，等于配了一个“不存在”的下一跳。

## 过一个网关，什么变了、什么没变

网关往往是路由器，是三层转发设备：**把 MAC 头与 IP 头都摘下来，按路由算法选另一只手，再加 IP 头与 MAC 头扔出去**。一台五口路由器相当于五只手，每只手的 IP 都与所连局域网同网段。MAC 头依次是目标 MAC、源 MAC、协议类型；IP 头含版本、TOS、TTL、**8 位协议字段**（6 是 TCP、17 是 UDP）与源/目的 IP。

| 网关类型 | IP 头 | MAC 头 | 典型场景 | 代价 |
|---|---|---|---|---|
| **转发网关** | 源/目的 IP 全程不变 | 每过一段换一次 | 欧洲十国游：一个签证走多国 | 两端地址不能冲突 |
| **NAT 网关** | 源或目的 IP 被改写 | 每过一段换一次 | 玄奘西行：两侧都用私网段，地址撞车 | 有状态映射；公网地址太贵 |

> 🔑 “MAC 地址只要过网关，就必定会改变，因为已经换了局域网。”

以源 `192.168.1.101` → 目标 `192.168.4.101` 为例：主机把帧发给网关 A（目的 MAC 是 A）；A 按路由从 `192.168.56.1` 出，ARP 取下一跳 `192.168.56.2` 的 MAC；路由器 B 再从 `192.168.4.1` 出，ARP 目标主机的 MAC。**三段的 IP 头一个字没动，MAC 头每段都换。**

NAT 网关不同：两侧局域网各定网段，大唐与印度都是 `192.168.1.101`；于是给目标一个国际身份 `192.168.56.2`，网关 B 记住它对应 `192.168.1.101`，源侧也换成 `192.168.56.1`，收包后再按映射改回国内地址。理由很直白：“公网地址实在是太贵了”。

> 🔑 “在 IP 头里面，不会保存任何网关的 IP 地址。”所谓的下一跳，是**把这个 IP 地址转换为 MAC 放入 MAC 头**。

## 路由表长什么样

每条路由至少三个要素：**目的网段 + 出口设备 + 下一跳**。缺出口设备，不知道从哪只手扔出去；缺下一跳，不知道该 ARP 谁。静态路由就是逐条写死这些规则（`ip route add 10.176.48.0/20 via 10.173.32.1 dev eth0`），选路时**逐条匹配、命中即转发**。

一台 Linux 网关的 `main` 表（Docker 29.9.2 + iproute2 6.1.0，容器网段 `172.17.0.0/16`）：

```bash
ip route list table main
# default via 172.17.0.1 dev eth0
# 172.17.0.0/16 dev eth0 proto kernel scope link src 172.17.0.2
```

- `default` 是兜底：所有明细都不匹配才走它；没有它，跨网段直接被丢。
- `proto kernel` 是配 IP 时内核自动生成的直连路由，没有下一跳。

要按“源 IP / 入口设备 / TOS”分流，就得先选表再查表，即策略路由。`ip rule` 的四个档位：

| 优先级 | 表 | 作用 |
|---|---|---|
| 0 | `local` | 本机地址与广播，最高优先，内核自带 |
| 32765 | 自定义（如 `200 chao`） | 自己加的规则默认落在这一档，先于主表 |
| 32766 | `main` | 主表：直连、静态、默认路由 |
| 32767 | `default` | 兜底表，通常为空 |

> ⚠️ 数值越小越先匹配。规则顺序写错，包会先命中 `main` 的默认路由，明细规则永远轮不到。

## 策略路由：按源 IP、入口、TOS 选表

默认路由是**按目的 IP 查一张表**；要按源 IP、入口设备、TOS 分流，就建多张表加规则。房东拉两根宽带的场景：默认走慢线，付费的 `192.168.1.101` 走快线。

1. 建表：在 `/etc/iproute2/rt_tables` 加一行 `200 chao`。
2. 加规则：`ip rule add from 192.168.1.101 table chao`。
3. 写路由：`ip route add default via <快线网关> dev eth1 table chao`。
4. 刷缓存：`ip route flush cache`，否则已缓存的旧路由继续生效。

```bash
# 环境：Linux 网关（iproute2 6.1.0）；前两条在 Docker 容器内实跑
ip route list table main   # 主表：default 与直连路由
ip rule ls                 # 加 from 192.168.1.101 table 200 之后：数值越小越先匹配
traceroute -n 8.8.8.8      # 逐跳看实际出口；-n 不解析域名
# 0:	from all lookup local
# 32765:	from 192.168.1.101 lookup 200
# 32766:	from all lookup main
# 32767:	from all lookup default
```

> 🔑 “默认的路由走慢的，谁让你不付钱。”不差钱的源命中 `chao` 表走快线，其余源继续命中 `main` 的默认路由。

同一张表里，一条路由也能带多个下一跳，按权重分流：`ip route add default table chao nexthop via 192.168.1.1 dev eth1 weight 1 nexthop via 192.168.2.1 dev eth2 weight 2`。

> ⚠️ 改完规则或路由不 `ip route flush cache`，已缓存的流仍按旧路走，表现为“配置明明对了，速度没变”。

## 两族动态路由：距离矢量 vs 链路状态

网络简单可控时，静态路由逐条配就够；拓扑一变就要手工改，规模大时运维不可承受，这才需要动态路由。

| 算法 | 交换什么 | 多久一次 | 收敛 | 规模 | 代表协议 |
|---|---|---|---|---|---|
| **Bellman-Ford**（距离矢量） | 到所有路由器的距离，整张表 | 每几秒向邻居周期通告 | 慢：坏消息逐轮 +1 | 小：RIP 只适用 < 15 跳 | RIP；BGP（路径矢量，升级版） |
| **Dijkstra**（链路状态） | 链路状态包：谁和谁相连、代价多少 | hello 周期探活，拓扑变化才广播 | 快：只播变化，邻居会广播某台挂掉 | 大：OSPF 用于数据中心内部 | OSPF |

- **距离矢量**：每台路由器存一张表，每行是“到目标从哪条线出去 + 距离”；邻居说“我到目标 M”，自己算出“我到目标 = x + M”。
- **链路状态**：先向邻居 say hello 发现邻居，再发 echo 要求立即返回，**往返时间除以二**得到距离；链路状态包广播到全网，每台路由器在本地建完整图并跑 Dijkstra。

> ⚠️ 距离矢量每次要发送整个全局路由表；链路状态只广播变化了的拓扑，带宽与 CPU 都省。

## 坏消息为什么传得慢，BGP 怎么修

四台路由器排成 A—B—C—D，D 是目标。正常时 C 到 D 为 1，B 为 2，A 为 3。D 挂掉后，C 先置为不可达，但 B 还在相信“经 C 到 D 是 2”：

| 轮次 | C 认为到 D | B 认为到 D | A 认为到 D |
|---|---|---|---|
| 正常 | 1 | 2 | 3 |
| D 刚断 | ∞ | 2 | 3 |
| 第 2 轮 | 3 | 4 | 3 |

第 1 轮 C 听 B 的 2 得 3，第 2 轮 B 听 C 的 3 得 4，此后两者交替 +1；谁都没见过“D 没了”，只能等距离超过阈值（RIP 是 15 跳）才判定真挂——这就是“好消息传得快，坏消息传得慢”。两个缺陷：坏消息收敛慢、每次发全表。

BGP 用**路径矢量**修第一刀：除了下一跳，还带上这条路由经过的 **AS 路径**；收到含自己 AS 号的路由直接丢弃，坏消息不会绕回来把自己“喂”成可达。

- **eBGP**：AS 之间的边界路由器互相广播路由；**iBGP** 再把外部路由导入内部，让内部路由器找到最佳边界路由器。
- **压缩规模**：把 AS 当整体看，自治系统数目非常有限，路由表才可控。

AS 分三类：Stub 对外只有一个连接、不替别人传包；Multihomed 多个连接、大多拒绝替别人传包；Transit 多连接且愿意替别人传包。

> 🔑 “这就好比，虽然从我家里到目的地最近，但是不能谁都能从我家走啊！”

> 💡 本节只讲 BGP 的选择逻辑（AS 路径），报文格式与承载层不展开。

## 对架构的三条含义

1. **ECMP 换横向带宽**：OSPF 属 IGP，能发现多条等价最短路径做负载均衡，即等价路由。数据中心用它把流量摊到多条链路上，与 LVS 配合即可做高吞吐接入。
2. **策略路由换多出口**：一条默认线保底，贵的线只给特定源、特定入口或特定 TOS；`ip rule` 决定选哪张表，表内再决定下一跳。
3. **AS 边界 = 可控域边界**：AS 内部怎么走用 OSPF 求最短；跨 AS 要看政策，谁愿意替你转、谁只当 Stub，都由 BGP 表达。

## 反模式

| 反模式 | 后果 |
|---|---|
| 只配 IP 不配网关 | 同网段能通、跨网段全断，现象像“时好时坏” |
| 网关配成别的网段地址 | 网关 MAC 永远 ARP 不到，包发不出去 |
| 以为过网关 IP 一定变 | 把转发网关当 NAT，排障找错层 |
| 以为 IP 头里存着网关地址 | 理解不了“下一跳只是换个 MAC” |
| 拓扑一变就手工改静态路由 | 规模上去后运维不可承受，必出错 |
| 用 RIP 撑大网 | 15 跳上限，坏消息收敛慢到超时 |
| 策略路由改完不刷缓存 | 旧缓存继续走老路，配置看着对但不生效 |
| 让所有邻居免费过境 | 谁都能从你家走，带宽被吃干 |

## 自检

**Q1** 本机 `192.168.1.101/24` 要访问 `192.168.4.101`，ARP 问的是谁？IP 头里的目的地址写谁？

▸ 答案：ARP 问默认网关（如 `192.168.1.1`），因为跨网段必须把帧先交给网关；IP 头里的目的地址**仍是 `192.168.4.101`**。网关地址只用于取 MAC，不会写进 IP 头。

**Q2** 一个包过了三个转发网关，哪些字段变了？换成 NAT 网关呢？

▸ 答案：转发网关下，源/目的 IP 全程不变，每一段的源 MAC、目的 MAC 都换——因为换了一个局域网。NAT 网关下，除 MAC 逐段换，源或目的 IP 还会按映射改写；代价是网关要有状态、记住映射。

**Q3** 路由表三要素是什么？为什么“出接口”和“下一跳”都要写？

▸ 答案：目的网段、出口设备、下一跳网关。出接口决定从哪个网口发，下一跳决定该 ARP 谁的 MAC；只写其一，内核无法组出下一跳的帧。下一跳还必须与本机某口直连，否则会报 `Nexthop has invalid gateway`。

**Q4** 策略路由配好了，`ip rule` 里也能看到规则，为什么流量还是走老线？

▸ 答案：路由缓存没刷。已经查过的目的地址仍按旧缓存转发，必须 `ip route flush cache` 让新规则重新参与选路；另外要确认规则优先级在主表之前，否则先命中 `main` 的默认路由。

**Q5** “好消息传得快，坏消息传得慢”具体怎么发生？BGP 靠什么止损？

▸ 答案：邻居失效后，其他路由器仍相信经邻居可达，距离被逐轮 +1，直到超过阈值才判定不可达，期间可能形成转发环路。BGP 在路由里携带 AS 路径，收到含自己 AS 号的路由直接丢弃，既防环也终止“计数到无穷”。

**Q6** OSPF 的等价路由在架构上用来干什么？

▸ 答案：做 ECMP 横向扩容。OSPF 发现多条等代价最短路径后，路由器把流量分摊到多条链路，用并行链路换吞吐；与 LVS 配合即可做高吞吐接入。
