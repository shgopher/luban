# 8.16 DHCP 与 PXE：地址租约与网络启动

## 一句话

> IP 不是机器的属性，而是租来的使用权：手工配错不会报错，只会「包发不出去」；DHCP 用四包广播把地址租出去、租期过半续租；PXE 让同一套 DHCP 顺便当引路人，把还没有操作系统的机器送进装机流程。

## 配错 IP 的现象，比错误本身更难查

数据中心里的服务器，IP 配好基本不变，相当于**买房自己装修**；DHCP 是**租房**——「DHCP 的方式就相当于租房。」不用装修、用完退租，代价是地址随时可能被房东（服务器）收回去。

坏消息是配错不报错，三种常见错法：

| 配错方式 | 现象 | 原因 |
|---|---|---|
| 随手编一个和谁都不搭边的地址（例 `16.158.23.6` 放进 `192.168.1.0/24`） | 什么都没发生：没报错、没告警，`ping` 静默超时 | 「不会出现任何现象，就是包发不出去呗。」目标被判定为跨网段，包要交给网关；网关不在这个网段里，连 ARP 都问不到 |
| 网关配成异网段（源 `192.168.1.6/24`，网关写 `10.0.0.1`） | 配置直接不生效：Linux 不会让配置成功 | 网关是「下一跳的邻居」，得能在本网段用 ARP 换成 MAC；异网段网关二层不可达，属于无效配置 |
| 同网段却不同掩码（`192.168.1.6/25` 对端 `192.168.1.200/24`） | 一方直投、一方走网关，于是单向通或时通时不通 | 💡 按掩码定义推导：`/25` 的一方认为 `.200` 不在自己网段，交给网关；网关与对端都认为同网段，回包直接 ARP 给 `.6`，回程绕过了网关 |

## 跨网段：为什么必须过网关

Linux 发包前只做一道判断：**目标和我的某块网卡同网段吗？** 同网段，ARP 问目标的 MAC；不同网段，ARP 问网关的 MAC。

> 🔑 「Linux 默认的逻辑是，如果这是一个跨网段的调用，它便不会直接将包发送到网络上，而是企图将包发送到网关。」

| 目标 | ARP 问谁 | 帧里的目标 MAC | 没有网关时 |
|---|---|---|---|
| 同网段（`10.0.0.2`，从 `10.0.0.1/24` 发出） | 目标 `10.0.0.2` | 目标的 MAC | 不影响，照发 |
| 跨网段（`16.158.23.6`） | 网关 | 网关的 MAC | 包发不出去，且不报错 |

所以「网关必须与某块网卡同网段」不是惯例而是前提：网关地址是拿来 ARP 的，ARP 只在同一广播域内工作。跨网段真正发生的事是——**IP 头里的源/目的地址全程不变，帧里的 MAC 每跳换一次**，这是分层与封装的结果（[8.0](8.0-分层与封装.md)）；逐跳怎么选路属于 [8.15 网关与路由](8.15-网关与路由协议.md)，ARP 报文长什么样属于 [8.14 二层](8.14-二层-ARP-交换机与VLAN.md)。

```bash
# 两套等价命令：net-tools 与 iproute2。正式环境还要把 CIDR、掩码、广播地址、网关写进配置文件
sudo ifconfig eth1 10.0.0.1/24 && sudo ifconfig eth1 up      # ifconfig 配完接口常常还是 DOWN
sudo ip addr add 10.0.0.1/24 dev eth1 && sudo ip link set up eth1   # 漏了 dev、写成 ip link up 都会报错
```

## DHCP：四包把地址租出去

DHCP 像**房产中介**：要商谈、签约、续租，而且不能「抢单」。全过程四次广播：

| 包 | 源 / 目的 | 携带什么 | 为什么这么发 |
|---|---|---|---|
| **Discover** | `0.0.0.0` → `255.255.255.255`（UDP 封 BOOTP） | 自己的 MAC，声明「我还没有 IP」 | 没地址、也不知道服务器在哪，只能广播喊话 |
| **Offer** | 仍广播 | 可用 IP、子网掩码、网关、租用期，并**保留**该地址 | 新人还没有 IP，单播送不到；先占住，免得被第二个客户端要走 |
| **Request** | 广播 | MAC、接受的那份租约、提供租约的服务器地址，并请其他服务器撤销各自的 Offer | 广播是让所有服务器都听见「我选了谁」，没被选中的必须撤回保留 |
| **ACK** | 广播 | 合法的租用信息与其他配置 | 到这一刻客户端才真正拿到地址；广播让同链路的服务器同步这次租约 |

## 租期与续租：50% 这条线

> 🔑 「客户机会在租期过去 50% 的时候，直接向为其提供 IP 地址的 DHCP Server 发送 DHCP request 消息包。」

提前到一半，是为了留出**重试预算**：原服务器不响应时，客户端还有半个租期去找别的服务器，而不是在地址失效的瞬间掉线。这次 request 单播直达原服务器，不再广播；续租成功后按新租期与更新后的 TCP/IP 参数刷新配置。租约最终达成时仍要广播：

> 「最终租约达成的时候，还是需要广播一下，让大家都知道。」

⚠️ 别等租期到点才续。地址一过期，正在跑的连接全部作废；续租窗口是 50%–100%，过了 100% 只能从 Discover 重来。

## PXE：把 DHCP 当引路人

机房几百台空机器，一台台插 U 盘会累死；可装机程序自己也需要一台「已装好的机器」当服务器，客户端这边**连操作系统都没有**，谁来跑 PXE 客户端？只能往更早的地方找。正常引导链是：

```text
BIOS → 硬盘 MBR 启动扇区 → GRUB → 内核 + initramfs（当根文件系统）→ 内核接管
```

装机只能插在 BIOS 之后、硬盘之前，因为没装系统时**连启动扇区都没有**。所以 **PXE 客户端只能放在 BIOS 里**：固件是系统之前唯一会执行的代码，开机时把这段网络客户端调入内存，它才有机会去网络上找系统。这五段接力在 [11.14 内核启动链](../11-操作系统与内核基础/11.14-内核启动链-从固件到1号进程.md) 里有完整拆解，PXE 只是把「找引导器」从硬盘换成了网络。

1. **DHCP 拿三样**：IP 地址、PXE 服务器地址（`next-server`）、启动文件名（`filename`，例 `pxelinux.0`）。
2. **TFTP 下载** `pxelinux.0`：TFTP 比 DHCP 还简陋，UDP 承载、无连接。
3. **执行它**，并向 TFTP 请求配置 `pxelinux.cfg`。
4. **配置告知**内核与 initramfs 在哪里，再去请求这些文件。
5. **启动 Linux 内核**，之后就是正常的 initramfs → 真根 → 1 号进程。

为什么是 TFTP 而不是 HTTP？客户端此刻只有塞在固件里的极小协议栈，为下载几个文件维护 TCP 状态机不值得（[8.1](8.1-TCP-IP与三次握手.md) 讲 UDP 取舍时用的就是这个例子）。TFTP 服务通常与 DHCP 同机，即样例里的 `192.168.1.180`。

💡 「网络管理员不仅能自动分配 IP 地址，还能帮你自动安装操作系统！」——同一台 DHCP 服务器既发地址，又指路。

## 一份可直接改的 DHCP 配置

改 `/etc/dhcp/dhcpd.conf`。前置：本机 `eth1` 静态配成 `192.168.1.2/24`（DHCP 服务器自己不能靠 DHCP 拿地址），装 `isc-dhcp-server` 4.4.x；同网段的 `192.168.1.180` 跑 TFTP 与 PXE 文件。

```conf
default-lease-time 21600;      # 默认租期 6 小时：客户端到 50%（3 小时）就该续租
max-lease-time 43200;          # 最长租期 12 小时：要更久也不能越过这条线
option time-offset -18000;     # 时区偏移，-18000 秒 = UTC-5
authoritative;                 # 本网段唯一 DHCP 服务器，敢直接 NAK 掉错误请求
allow booting;                 # 允许这台服务器参与 PXE 引导
allow bootp;

subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.240 192.168.1.250;   # 只发这 11 个地址，其余留给静态设备
  option routers 192.168.1.1;          # 网关必须与 192.168.1.0/24 同网段
  option subnet-mask 255.255.255.0;
  filename "pxelinux.0";               # PXE 第一步要下载的文件名
  next-server 192.168.1.180;           # 告诉客户端：去这个地址找 TFTP
}
```

验证（预期行为；本节未实机跑，缺第二个网段与一台可广播的 DHCP 服务器）：

```bash
sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf   # 只查语法：无输出即通过，报错会指到行号
sudo systemctl restart isc-dhcp-server
sudo dhclient -v eth1                    # 客户端上先清掉旧地址
# 预期依次出现四行：DHCPDISCOVER → DHCPOFFER → DHCPREQUEST → DHCPACK
ip addr show eth1 | grep inet            # 预期 inet 192.168.1.24x/24，落在 range 内
```

⚠️ 回滚：用备份的 `dhcpd.conf` 覆盖回去再重启服务；`range` 写错一行就可能把全网地址发乱。

## 对架构的三条含义

| 含义 | 具体影响 |
|---|---|
| **地址是租约，不是资产** | 云主机重建就换 IP，写死 IP 的配置都是定时炸弹；用 DNS 或注册中心做间接层 |
| **装机流水线 = DHCP + TFTP + 配置管理** | 三者缺一不可：DHCP 发地址并指路、TFTP 供文件、配置管理保证装完是同一个状态 |
| **IP 规划错误在最长链路上暴露** | 配错不报错，等业务对不上才被发现；规划与地址台账必须前置 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 随手编一个「看着像内网」的地址 | 不报错也不通，从应用日志一路查到网卡才发现 |
| 网关填成异网段地址 | Linux 拒绝配置，或配上了也不生效 |
| 两端掩码不一致却当成同网段 | 单向通、时通时不通，只能靠抓包看出不对称 |
| 等租期到点才续租 | 地址失效瞬间连接全断，引发重连风暴 |
| 把 DHCP 服务器自己设成 DHCP 客户端 | 它没有稳定地址，租约表与网关都可能指错 |
| PXE 只配 `next-server` 不配 `filename` | 客户端拿到 IP 却不知道下什么文件，卡在引导阶段 |
| 以为 PXE 能适配任何网卡 | 固件里的客户端只认自带驱动，新网卡可能没有 |
| `range` 覆盖了静态设备地址 | 地址冲突：两台机器同一个 IP，随机掉线 |

## 自检

**Q1** 一台机器配成 `16.158.23.6/24`、没配网关，`ping 192.168.1.6` 会怎样？为什么「什么都没发生」也是信息？

▸ 答案：包发不出去。两者不同网段，Linux 要把包交给网关，但没配网关，于是本地就失败，连 ARP 都不会发。没有报错是设计使然：ICMP 差错需要有一个能出去的包，「出不去」发生在本地，没有任何设备会回错误。所以静默本身就是「断在配置层」的强信号。

**Q2** 为什么网关地址必须与某块网卡同网段？配成异网段，Linux 为什么不让配置成功？

▸ 答案：网关的作用是提供**下一跳的 MAC**。拿 MAC 只能发 ARP，而 ARP 是广播，出不了本广播域。异网段网关在二层上不可达，ARP 永远问不到，配了也是死配置，所以内核在设默认路由时就拒绝。这条规则把三层路由牢牢建在二层可达之上。

**Q3** Offer 和 ACK 为什么还要广播？不是已经知道客户端 MAC 了吗？

▸ 答案：知道 MAC 不够，单播得先有 IP。Offer 阶段客户端还没接受任何地址，ACK 之前它的配置里仍是 `0.0.0.0`，发给它的单播包没有可用路由。所以选择与确认两步都靠广播；只有续租时客户端已有地址，才能单播直达原服务器。

**Q4** 租期 21600 秒，客户端在第几秒发起续租？为什么不是 100%？

▸ 答案：租期过半即第 10800 秒（50%）时，直接向原服务器单播 request。提前是为了留重试预算：原服务器不应答时，还有半个租期去找别的服务器、重走 Discover，而不是等到地址失效才开始救火。

**Q5** 一台没装系统的机器，PXE 客户端为什么只能放在 BIOS 里？DHCP 在这里多给了什么？

▸ 答案：任何「装系统」的程序都得先被某段代码加载，而这段代码必须在硬盘之外——没系统时连 MBR 启动扇区都没有，唯一能执行的就是固件。DHCP 除了 IP、掩码、网关、租期，还多给 `next-server`（去哪台机器取文件）与 `filename`（取哪个文件，如 `pxelinux.0`），这就是「既发地址又指路」的落地方式。
