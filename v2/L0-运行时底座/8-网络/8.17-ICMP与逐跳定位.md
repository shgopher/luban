# 8.17 ICMP 与逐跳定位：ping、traceroute 与 MTU

## 一句话

> ICMP 是 IP 层的“侦察兵”：它不运数据，只报情况——ping 用**查询报文**（类型 8/0）问“能不能到、来回多久”，traceroute 用**差错报文**（类型 11 与 3/4）故意制造错误，反推出路径与 MTU。

## 两类报文：主动打探 vs 出事回报

| 类别 | 谁发起 | 典型类型 | 解决的问题 | 行军类比 |
|---|---|---|---|---|
| **查询报文** | 主帅主动派人 | 8（请求）、0（应答） | 目标可达吗？往返多久？ | “前方战事如何，快去打探” |
| **差错报文** | 出事的设备 | 3、4、11、5 | 为什么没送到？ | “报告主公，张将军全军覆没” |

类型码速查：

| 类型 | 名称 | 代码 | 代码含义 |
|---|---|---|---|
| 8 | 主动请求（ECHO REQUEST） | — | ping 发出的探测 |
| 0 | 请求应答（ECHO REPLY） | — | 目标回显 |
| 3 | 终点不可达 | 0/1/2/3/4 | 网络 / 主机 / 协议 / 端口 不可达；需要分片但设了不分片位 |
| 4 | 源站抑制 | — | 让源站放慢发送速度 |
| 11 | 时间超时 | — | TTL 耗尽还没到 |
| 5 | 路由重定向 | — | 下次发给另一个路由器 |

> 🔑 类型 3 的五个代码，正好对应“粮草没送到”的五种原因：找不到地方 / 没这个人 / 口号没对上 / 事儿没对上 / 山路窄却不许换小车。**端口不可达（3/3）和需要分片（3/4）是排障里最常用的两个。**

差错报文不只报信，还带“证物”回来：外层仍是 IP 头，ICMP **前 8 字节**不变，后面跟上**出错那个 IP 包的 IP 头与正文前 8 个字节**——源主机据此知道是哪条连接、哪个端口出的问题。

## ping 走一遍：从构建到算出 RTT

1. 构建 ICMP 请求：类型 8、序号（每发一个自动加 1）、**数据区里塞进发送时刻**。
2. 交给 IP 层：填源 IP、目的 IP，构成 IP 包。
3. 查 ARP 表拿目标 MAC；没有就先发 ARP，再组帧发出。
4. 对端比对目标 MAC → 逐层上交 IP → ICMP，回一个**类型 0、序号照抄**的应答。
5. 源端收到后，用当前时刻减去数据区里的发送时刻，就是 RTT；规定时间内没收到，判“不可达”。

| 现象 | 说明什么 | 下一步 |
|---|---|---|
| 有应答、RTT 稳定偏高 | 距离远或路由绕行 | `traceroute` 看绕到哪一跳 |
| 有应答、RTT 抖动大 | 拥塞或链路质量差 | 看丢包率与重传（[8.2](8.2-拥塞控制-Nagle与延迟.md)） |
| 请求发出、无应答 | 目标禁 ICMP / 中间设备丢 / 真不通 | 换 TCP 探测，别下结论 |
| 应答来自非目标 IP | 中间设备代答或重定向 | 看类型 5 与拓扑 |

> ⚠️ ping 不通不代表网络不通。很多中间设备与云主机默认禁 ICMP，此时用 `telnet`/`nc` 借 TCP 端口验证连通性。

## traceroute：故意犯错，靠差错报文反推

traceroute 是“大骗子”，它发的是**故意会出错**的包，两种玩法：

| 玩法 | 怎么制造错误 | 收到什么 | 得到什么 |
|---|---|---|---|
| **TTL 递增** | 依次把 TTL 设为 1、2、3… | 每被路由器丢弃一次，回类型 11 | 逐跳的路由器 IP 与路径 |
| **MTU 探测** | 置“不分片”位，首包按出口 MTU 大小，逐步减小 | 撞到窄链路回类型 3 代码 4 | 整条路径上最小的 MTU |

“到没到目的地”怎么判？traceroute 故意选一个 **大于 30000 的不可能 UDP 端口**，目的机回**端口不可达（3/3）**——收到它，说明这一跳就是终点。

```bash
# Linux / macOS：-n 不解析域名，更快；-I 用 ICMP，-T 用 TCP（禁 ICMP 时更可靠）
traceroute -n 8.8.8.8
sudo traceroute -T -p 443 -n example.com

# 逐跳配合抓包：看请求到了哪一跳、应答从哪回来
sudo tcpdump -i any -nn 'icmp' -c 20

# MTU 探测：1472 + 28（IP 20 + ICMP 8）= 1500，不分片
ping -M do -s 1472 -c 2 192.0.2.10      # Linux
ping -D -s 1472 -c 2 192.0.2.10         # macOS
```

环境说明：`-M do` 是 Linux 的 `ping`（iputils），macOS 用 `-D`；云主机与容器里可能没有 raw socket 权限，需 `--cap-add=NET_RAW` 或 `sudo`。

## 逐跳定位的标准动作

1. **画拓扑**：源 → 网关 → 出口 → 骨干 → 目标机房 → 目标机，标出每段的设备 IP。
2. **从近到远逐个 ping**：第一个不通的跳，就是故障段。
3. **在关键点抓包**：`tcpdump -i eth0 icmp`，看请求是否到达、应答从哪回。
4. **禁 ping 就换协议**：`nc -zv host port`、`curl -v --connect-timeout 3`。
5. **拿到结论再改配置**：MTU 问题就调 MTU，别去重启服务。

> 💡 ICMP 与 TCP/UDP 的完整内核路径、`nf_conntrack` 打满这类丢包，见 [11.11 网络包内核路径与丢包定位](../11-操作系统与内核基础/11.11-网络包内核路径与丢包定位.md)。

## 对架构的三条含义

| 含义 | 具体影响 |
|---|---|
| **探测能力要留口子** | 安全组全禁 ICMP，等于放弃了最便宜的可达性诊断；至少对内网放行 |
| **MTU 是跨层契约** | 隧道（VXLAN/GRE）会吃掉 24–50 字节，不改 MTU 就是“小包通、大包不通”（见 [8.19](8.19-Overlay与隧道-GRE-VXLAN-VPN.md)） |
| **路径不是对称的** | traceroute 看到的是去程；回程可能走另一条路，故障定位要以双向抓包为准 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 把“ping 不通”当成“服务挂了” | 误重启、误扩容，真因只是 ICMP 被禁 |
| 只 ping 最终目标，不逐跳 | 知道不通，但不知道该找谁 |
| 用 traceroute 结果断定“回程也这样” | 路径不对称，结论可能完全相反 |
| 忽略 `* * *` 的含义 | 中间设备不回 ICMP 是常态，不代表断 |
| MTU 问题只在大包上报错，却去查应用 | 上传/传文件必现、小请求正常，被误判为业务 bug |
| 生产环境长期开着全量 ICMP | 暴露拓扑，且可被用于放大探测 |
| 用 ICMP 验证 K8s Service | ClusterIP 是虚拟地址，ICMP 通常不处理（见 [7.8](../7-容器编排/7.8-网络模型.md)） |
| 抓包不指定接口 | 抓到的是别的网卡的包，结论全错 |

## 自检

**Q1** 目标主机完全禁 ICMP，你怎么证明“网络是通的”？

▸ 答案：换协议探测。用 `nc -zv host 443` 或 `curl -v --connect-timeout 3 https://host` 验证 TCP 建连；再看 `traceroute -T -p 443` 是否到达最后一跳。TCP 能建连就说明路由、NAT、安全组都是通的，ping 不通只是 ICMP 被过滤。

**Q2** traceroute 收到的最后一跳是“端口不可达”，这意味着什么？

▸ 答案：说明包已经到达目的主机。traceroute 故意用大于 30000 的不可能 UDP 端口，目的机找不到监听者，回 ICMP 类型 3 代码 3；收到它就证明整条路径通了，之前的每一跳都是类型 11（TTL 耗尽）。

**Q3** 为什么差错报文要带回“出错 IP 包的 IP 头 + 正文前 8 字节”？

▸ 答案：为了让源主机能定位到**具体哪条连接**。IP 头给出源/目的地址，正文前 8 字节覆盖 TCP/UDP 的源端口、目的端口与序号——有了这四元组与序号，内核才知道该通知哪个 socket、哪次重传。

**Q4** 小请求正常、上传大文件必失败，用 ICMP 怎么确认是 MTU 问题？

▸ 答案：发一个“不分片 + 满 1500 字节”的 ping（`-M do -s 1472`，1472 + 20 + 8 = 1500）。如果它失败、而 `-s 1400` 成功，就说明路径 MTU 小于 1500；再二分找到临界值。容器/隧道场景常见临界值是 1450 或 1400。

**Q5** 为什么“逐跳 ping”比“直接 traceroute”更适合定位故障？

▸ 答案：traceroute 依赖中间设备回 ICMP，很多设备不回（显示 `* * *`），路径就断了；逐跳 ping 是主动对每个已知设备发探测，只要拓扑清楚，就能定位到“第一处不回应的设备”，不依赖设备是否愿意回 TTL 超时报文。
