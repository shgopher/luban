# 8.18 数据中心网络：从三层到叶脊

## 一句话

> 数据中心网络是**逐段买可用性**：边界多台多运营商，服务器双网卡 bond，TOR 与汇聚层层冗余；每加一条冗余链路就多一个二层环，于是用 POD 网段加三层路由把环交给路由去选，最后因东西流量占多数改成扁平的叶脊。

## 一张图看全：从国境口岸到机架

> 「数据中心是一个大杂烩，几乎要用到前面学过的所有知识。」

| 段 | 设备 | 解决什么 | 单点在哪 |
|---|---|---|---|
| 运营商出口 | 边界路由器（Border Router），多台、多运营商 | 把数据中心这个 AS 接入互联网，跑 BGP | 只接一家运营商，一家抖动就全站不可用 |
| 安全与分发 | 入侵检测、DDoS 防护、负载均衡器 | 整个数据中心的屏障，兼做流量分发 | 串在链路上，自身故障即断网 |
| 核心层 | 核心交换机，多组、与汇聚全互连 | 互联多个可用区 | 只剩一组核心，可用区之间就断了 |
| 汇聚层 | 汇聚交换机，成对部署 | 把多个机架汇成一个 POD，二层域的边界 | 传统方案里备机不转发，一半端口闲着 |
| 接入层 | TOR（Top Of Rack，机架顶端交换机） | 机架内服务器接入 | 单台 TOR 挂掉，整个机架失联 |
| 服务器 | 双网卡、双网线、bond（LACP） | 网卡与网线级冗余，兼做带宽叠加 | 单网卡单网线，坏一块卡就失联 |

这里的三层是**网络层次**的三层：「这里的三层不是指 IP 层，而是指接入层、汇聚层、核心层三层。」接入层专指 TOR，与应用侧说的“接入层”不是一回事——后者是流量进入系统的第一跳代理。边界路由器要多台、多运营商，因为出口是“一处不通、全站不通”的位置：数据中心本身往往是 BGP 里的一个**自治系统（AS）**，内外互通靠 BGP，接多家运营商就是「多线 BGP」，任何一家线路出问题，路由还能从别家绕出去。

> 💡 核心之上还挂两类东西：安全设备（入侵检测、DDoS 防护）与负载均衡器；存储侧传统上单独建 SAN/NAS 存储网络，云上多用 x86 上的软件定义存储，与计算同机架融合，省掉一张独立网络。

## 逐段买可用性

> 一句话：冗余不是“买一台备机”，而是**每一段各自买一份**；整体可用性由最弱的那一段决定。

| 段 | 冗余手段 | 失效后果 | 代价 |
|---|---|---|---|
| 服务器 | 2 块网卡、2 根网线接 TOR，做 bond | 单网卡时坏卡即失联，业务直接中断 | 网卡、交换机端口、布线翻倍 |
| TOR | 双上行到两台汇聚；或堆叠成一台逻辑交换机 | 单 TOR 时整机架服务器同时失联 | 双连必成环，要么 STP 阻塞一半，要么上堆叠 |
| 汇聚 | 两台成对，同时连两台 TOR 与多组核心 | 单汇聚时它下面所有机架一起掉 | 一主一备时一半带宽闲置；双活要堆叠 |
| 核心 | 多组核心，与所有汇聚全互连 | 单组核心时可用区之间全断 | 端口数与光纤数量随组数平方增长 |

🔑 这几段里，服务器和 TOR 的冗余最便宜（两根线、一台备机），核心的冗余最贵（全互连的端口是平方级）；预算永远先花在离服务器最近、失效面最大的那一段。

## 环路：二层的老问题

双上行一旦落地，环就出现了：两台 TOR 各连两台汇聚，四条链路围成一个圈。二层没有 TTL，广播帧会沿环永远转下去，同一源 MAC 从两个口交替到达，转发表被反复推翻——这正是 [8.14 二层](8.14-二层-ARP-交换机与VLAN.md) 里“学一会儿就好了不成立”的场景。所以「两接入两汇聚、层层双连」的传统方案**必然一主一备**：STP 把图剪成一棵树，只有一条链路转发，另一条被阻塞。冗余买到了，带宽只用到一半。

| 对比项 | STP 去环 | 交换机堆叠 |
|---|---|---|
| 去环方式 | 算出一棵树，阻塞多余端口 | 多台合成一台逻辑交换机，靠私有协议统一转发 |
| 链路利用 | 阻塞口不转发，汇聚层一半在工作 | 双活，带宽叠加 |
| 冗余形态 | 一主一备 | 双活互备 |
| 横向扩展 | 加设备只多几个阻塞口，带宽不涨 | 组内可扩，最多可堆 4 台 |
| 代价 | 一半端口闲置，拓扑变化要重算生成树 | 私有协议，绑定同一家厂商 |

> ⚠️ 堆叠只解决“组内”的环：几台堆在一起是一台逻辑交换机，组与组之间全互连照样成环，而且 STP 之下多组核心无法扩大横向带宽。

## POD 与三层下沉：用网段隔离广播域

> 一句话：把一个大二层切成多个 POD，让广播止步于 POD 边界，环就从“必须消掉”变成“交给路由去选”。

汇聚层把大量计算节点连成一个二层域，这个区域叫 **POD**，也叫**可用区**；可用区之间用核心交换机互联。要让它不炸，只做四步：

1. **每个 POD 一个独立网段**：广播域与网段一一对应，ARP 广播不跨区。
2. **汇聚与核心之间走三层**：不再用 Trunk 把二层拉通，核心只做 IP 转发。
3. **二层域止步于 POD**：一个 POD 内的广播风暴，打不到隔壁可用区。
4. **核心与汇聚跑 OSPF**：多条等价路径交给 **ECMP**，同时做多路径负载均衡与高可用。

三层也有环，但三层不怕环：每个包都带 TTL，逐跳减 1，绕路有上限；有多条等价路径时，路由协议选最优，ECMP 把流量分摊到多条上。**同样两条线，二层只能留一条，三层可以两条都用**——这就是“三层下沉”买到的东西。

> 🔑 判据：能不能用网段隔开，比用什么协议去环更重要。网段隔开了，环路问题降级成选路问题；隔不开，就只能在 STP 和厂商私有协议之间二选一。

## 大二层与 TRILL：把路由能力搬进二层

云计算与大数据要求**大规模集群同处一个二层网络**：虚拟机要能不带网关地迁移，集群节点要像在同一台交换机下一样互通。于是二层互连从汇聚上移到核心，整个数据中心变成一个大的二层域，这就是**大二层**。它把前面所有招数都逼到墙角：堆叠只能保证组内无环；多组核心全互连，组间仍是环；STP 之下多组核心无法扩大横向带宽。TRILL 的思路一句话说清：

> 「二层环有问题，三层环没有问题，那就把三层的路由能力模拟在二层实现。」

跑 TRILL 的交换机叫 **RBridge**（Routing Bridge）：它**按 MAC 而不是 IP 路由**，RBridge 之间跑链路状态协议学拓扑、算最短路、做等价路由。

| 二层的老毛病 | TRILL 的对应手段 |
|---|---|
| 环路只能靠 STP 剪树，多路径变闲置 | RBridge 间跑链路状态协议，自己算最短路 |
| 只有一条最优路径在转发 | 做等价路由，多条路径同时用 |
| 转发靠 MAC 表加广播泛洪 | 按 MAC 路由，像三层一样逐跳转发 |
| 广播没有边界 | 用分发树限定范围；不同树对应不同 VLAN，做负载均衡与高可用 |

封装是理解 TRILL 的关键：原帧外面加一个 **TRILL 头**，再加一个**外层 MAC 头**。TRILL 头里的 **Ingress RBridge / Egress RBridge** 相当于源 IP 与目的 IP，**端到端不变**；外层 MAC 则逐跳改写，跟 IP 包过网关换 MAC 一模一样；TRILL 头带跳数，**每跳减 1**，作用与 IP 的 TTL 相同——防止包在环里永远转。

## 南北 vs 东西：为什么要叶脊

| 维度 | 南北流量 | 东西流量 |
|---|---|---|
| 方向 | 上北下南：外部请求进来、响应出去 | 左右横穿：节点之间互相拷数据、互相调用 |
| 两端是谁 | 用户 ↔ 数据中心 | 服务器 ↔ 服务器，同可用区或跨可用区 |
| 传统路径 | 边界 → 核心 → 汇聚 → TOR → 服务器 | 也要先上到汇聚甚至核心，再折下来 |
| 先打满的是 | 出口带宽与边界设备 | 汇聚与核心的横向带宽 |
| 对拓扑的要求 | 垂直分层就够 | 扁平，任意两点路径尽量等长 |

「上北下南，所以称为南北流量。」早期数据中心以对外服务为主，三层垂直结构正好匹配：流量从边界进来，一层层往下走到服务器。等到集群内部互拷成为大头，问题就反了——两个同机架的服务器通信，也要绕到汇聚甚至核心再下来，横向链路先被打满。

叶脊（Spine/Leaf）就是为这件事改的：

- **leaf 直连服务器**，L2/L3 的分界在 leaf，**leaf 之上全是三层**。
- **spine 相当于核心**，但它不为服务器提供接入，只为 leaf 提供弹性的三层路由网络。
- **叶脊之间用 ECMP** 做动态多路径，而不是 STP 剪树。
- 南北流量**不必直接从 spine 出去**：可以走与 leaf 并行的交换机再接边界路由器。

| 判据 | 叶脊的答案 | 为什么关键 |
|---|---|---|
| 谁接服务器 | 只有 leaf 接，spine 一个业务口都不接 | spine 纯转发，坏一台换一台，不影响接入 |
| 二层边界在哪 | 止步于 leaf，往上全三层 | 广播域最小，二层环无从产生 |
| 谁做路由与多路径 | spine 只跑三层，叶脊间 ECMP | 加一台 spine 就多一组等价路径，带宽线性扩 |

> 「传统的三层网络架构是垂直的结构，而叶脊网络架构是扁平的结构，更易于水平扩展。」

## 对架构的三条含义

1. **网络收敛比决定集群规模**。服务器端口的总带宽与上联带宽的比值就是收敛比，它决定了“多少台机器同时满负荷对拷才会堵”。判据是：收敛比越接近 1，东西流量越不堵，交换机和光纤的账单越贵；算集群规模时，要按“同时互拷的机器数 × 单机带宽”去对，而不是按端口总数。
2. **二层域大小等于故障域大小**。广播风暴、ARP 风暴、MAC 表翻转的影响范围，就是一个二层域的边界；POD 划得越小，一处出事牵连越少。大二层是“不得不做”时的选择，不是默认选择。
3. **叶脊是可水平扩展的拓扑**。端口不够加 leaf，带宽不够加 spine，两者都只是往同一层加一台设备，不用改另一层的连线；这就是“扁平、更易水平扩展”的实际含义。

## 反模式

| 反模式 | 后果 |
|---|---|
| 服务器单网卡单网线 | 坏一块网卡就失联，bond 和双上行都无从谈起 |
| 只在服务器配 bond，交换机侧没配 LACP | 协商不上，聚合起不来或只有一个口在转发 |
| TOR 只部署一台 | 整机架服务器同时失联，冗余只做到了服务器段 |
| 指望 STP 同时给带宽和冗余 | 阻塞口不转发，汇聚层长期只有一半带宽，扩容无效 |
| 多组核心全互连却仍留在二层 | 环打不完，STP 把多组核心压成一主一备 |
| 用堆叠去解跨组、跨可用区的环 | 堆叠只管组内，组间照样成环 |
| 一个大二层贯穿所有可用区 | 广播域等于全站，一处风暴全站抖 |
| 把“数据中心三层”当成 IP 层 | 概念错位，把 TOR 和应用侧接入层混为一谈 |
| 只接一家运营商 | 这家线路抖动，全站对外不可用 |
| 东西流量已占多数，还留在三层垂直架构 | 横向流量绕核心再下汇聚，先撞横向带宽 |

## 查 bond 与链路：四条命令看什么

```bash
# 环境：一台双网卡做 LACP bond 的 Linux 服务器（CentOS/Ubuntu 均可，需 root）
# ① LACP 成功时模式为 802.3ad，两个 Slave Interface 都该是 MII Status: up
cat /proc/net/bonding/bond0
# ② 所有网卡的 UP/DOWN：bond0 必须存在，两个 slave 都该是 UP
ip -br link
# ③ 两端速率、双工是否一致，Link detected 是否为 yes
ethtool eth0 && ethtool bond0
# ④ 默认路由应指向 TOR 上的网关地址
ip route
```

看三件事：bond0 里两个 `Slave Interface` 是否都 `MII Status: up`（一个 down 就是网线、光模块或交换机端口的问题，此时冗余还在、带宽腰斩）；`ethtool` 两端速率是否一致（一端千兆一端万兆，轻则降速、重则链路起不来）；`ip route` 的默认路由是否指向 TOR 网关。容器里实测（单网卡环境）：`ip -br link` 只有 `eth0@if188 UP`，`ip route` 只有 `default via 172.17.0.1 dev eth0`——**没有 bond0**，正好是“bond 没建起来”的样子，可以拿它当反例对照。

## 自检

**Q1** 「两接入两汇聚、层层双连」上线后，汇聚层实测带宽只有标称的一半，为什么？

▸ 答案：双连围成了二层环，STP 必须阻塞其中一条链路才不广播风暴，于是两台汇聚实际是**一主一备**：备机端口 up 但不转发。冗余买到了，带宽只拿到一半。要两条都用，得换堆叠做双活，或者把汇聚与核心之间改成三层加 ECMP。

**Q2** 不同可用区用不同网段、汇聚与核心走三层之后，环路去哪了？三层就没有环吗？

▸ 答案：环还在，但被降级成了选路问题。二层环没有终点，广播帧会一直转；三层环里每个包带 TTL，逐跳减 1，绕路有上限，路由协议还会选最短路。所以做法不是“消灭物理环”，而是**把广播域切断、让三层去处理环**——物理上仍可多路径，ECMP 还能把多条都用上。

**Q3** TRILL 的 Ingress/Egress RBridge 和 IP 的源/目的地址像在哪？外层 MAC 为什么每跳都变？

▸ 答案：Ingress/Egress 标识的是“从哪台 RBridge 进、从哪台出”，在整个 TRILL 域内端到端不变，作用等同源 IP 与目的 IP；外层 MAC 只是“这一跳到下一跳”的局部寻址，每过一台 RBridge 就重写一次，跟 IP 包过网关换 MAC 完全同理。TRILL 头里的跳数每跳减 1，兜住环路的底。

**Q4** 东西流量占多数后，为什么堆叠和 STP 都不够，必须换叶脊？

▸ 答案：两者的上限都卡在“二层域只有一个”这个前提上：STP 让多组核心一主一备，堆叠只管组内无环，组间全互连仍成环，横向带宽扩不上去。叶脊把二层边界压到 leaf，leaf 之上全三层，任意 leaf 到任意 leaf 走 ECMP；加 spine 就是加一组等价路径，带宽能随设备数线性扩，而不用再剪树。

**Q5** 一台服务器 `bond0` 里两个 slave，一个 up 一个 down，业务没报障，要不要处理？

▸ 答案：要，但优先级不是“救火”而是“恢复容量”。冗余正在生效（流量全走 up 的那条），所以业务无感；但带宽已经腰斩，且另一条链路再坏就真断。按 `ethtool` 的 `Link detected`、两端速率、交换机端口状态、光模块顺序查，别等第二条也坏。

**Q6** 为什么数据中心要接多家运营商，而不是买“最大那家”的带宽？

▸ 答案：出口是单点中的单点，一家运营商的路由抖动、互联带宽被打满、甚至光缆被挖断，都会让全站对外不可用。接多家、让数据中心作为 BGP 的一个 AS 对外宣告，路由可以在多家之间切换，这就是“多线 BGP”买的东西——买的是**出口的故障域隔离**，不是带宽数字。
