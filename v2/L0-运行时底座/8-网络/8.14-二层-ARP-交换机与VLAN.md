# 8.14 二层：ARP、交换机与 VLAN

## 一句话

> 同一网段内，IP 包靠 **ARP 吼出目标 MAC → 组帧 → 交换机按转发表转发** 这一段送到；Hub 时代 MAC 层解决的是“谁先发”，交换机把广播换成一张**会过期的转发表**，STP 把成环的图剪成树，VLAN 用 **12 位 TAG** 在一条线上切出多个局域网。

## 一层：一根线、一个 Hub，能走多远

两台电脑直连，是最小的网络：一根两头水晶头的网线，问题落在物理层。普通网线不通，要做**交叉线**，即 **1－3、2－6** 交叉接法——水晶头第 **1、2** 与第 **3、6** 脚分别承担收、发信号，把一端的 1 号与 3 号、2 号与 6 号互换，就变成一端发、另一端收。

线对了还不算通。直连还要配 **IP、子网掩码、默认网关**，三项同网段，例如 **192.168.0.1/24** 与 **192.168.0.2/24**；三层不在一个网络，照样不通。此时才构成最小局域网 LAN，而包依然是完整的，带着 MAC 层。

第三台机器加入，就该上 Hub。Hub 有多个口，**完全在物理层工作，没有大脑**，它的行为只有一条：

> 「会将自己收到的每一个字节，都复制到其他端口上去。」

于是同一条线上所有人一起说话、一起听，冲突概率随机器数上升；同时每一个字节都被复制给不相干的机器，纯属浪费。这就是“多路访问”问题。

| 设备 | 工作层 | 转发行为 | 后果 |
|---|---|---|---|
| 网线直连 | 物理层 | 一端发、一端收，点对点 | 只能两台，多一台就接不上 |
| **Hub** | 一层，不摘头 | 每个字节复制到其他所有口 | 人人听得见，冲突与浪费随规模放大 |
| **交换机** | 二层，摘 MAC 头 | 按转发表转发，不知目标就泛洪 | 几十台、上百台可承载 |
| 路由器 | 三层，再摘 IP 头 | 按路由表换下一跳（见 [8.15 网关与路由](8.15-网关与路由协议.md)） | 跨网段，MAC 头逐跳重写 |

## MAC 层解决的不是地址，是“谁先发”

把 Hub 的问题拆开是三个：**包发给谁、谁先发谁后发、出错怎么办**。后两个才是 MAC 层的主场——MAC 的全称是 **Medium Access Control**，即媒体访问控制，管的是往媒体上发数据时谁先发、谁后发，学名叫**多路访问**。

> 「MAC 层是用来解决多路访问的堵车问题的」

| 方案 | 做法 | 生活里的对应 | 以太网用不用 |
|---|---|---|---|
| 信道划分 | 把一条线切成多条车道，各走各的 | 马路分车道 | 不用 |
| 轮流协议 | 排号，单号走、双号走 | 单双号限行 | 不用 |
| **随机接入** | 先出门，堵了退回来重发 | 错峰出门，撞了再退 | **用** |

💡 “包发给谁”是另一个问题，由**以太网帧里的地址**回答，不由多路访问回答。两件事常被混成一件。

以太网二层格式只有四个字段，顺序固定：**目标 MAC、源 MAC、类型、CRC**。类型说明载荷是什么（多为 IP 数据包）；CRC 是循环冗余检测，用 **XOR 异或校验**。各字段的常见字节数见 [8.0 分层与封装](8.0-分层与封装.md)（MAC 头 14 字节）。收包时网卡依次比对：**目标 MAC → IP → 端口**（例 80，nginx 监听 80）；回包时源与目标 MAC 互换。

MAC 地址本身长 **48 比特（6 字节）**，十六进制表示，分前后两半：前 **24 位**是组织唯一标志符（OUI，IEEE 分配给厂家），后 **24 位**由厂家自行分配。它设计上要求全球唯一，但虚拟化与改 MAC 的工具太常见，工程上只能保证「**至少一个局域网内唯一**」。这也解释了它为什么还有用：机器启动时在拿到 IP 之前，可以先靠 MAC 通信。

## ARP：知道 IP，怎么拿到 MAC

组帧的最后一步必须填一个目标 MAC，**不能空着**。所以“我知道 IP 了为什么还要 MAC”的标准答案是：MAC 拿不到，帧就组不出来，包发不出去。

ARP 干的就是这件事：已知 IP，求 MAC。

| 步 | 谁做 | 做什么 |
|---|---|---|
| ① | 发起方 | 广播一个 ARP 请求：“谁的 IP 是 x？” |
| ② | 同网段所有机器 | 都收到了，只有 IP 匹配的那台回应自己的 MAC |
| ③ | 发起方 | 把结果写进**本地 ARP 缓存**，随后组帧发出 |
| ④ | 一段时间后 | 缓存**过期**，下次再吼一遍 |

> 「ARP 是通过吼的方式来寻找目标 MAC 地址的，吼完之后记住一段时间，这个叫作缓存」

缓存为什么要过期：机器会上下线，IP 会变，口也会变。写死的映射迟早指向一台不存在的机器，包发出去就是黑洞。

> ⚠️ 这个“吼”只在**同一个广播域**内有效。广播域边界之外，ARP 听不到、也答不了——跨网段时你吼的是**网关**的 MAC，不是最终目标的 MAC。

## 交换机：一张会过期的转发表

交换机是二层设备：摘下 MAC 头，看目标 MAC，再按策略转发。它的全部聪明都来自“学习”，过程只有三步：

1. **泛洪起步**：不知道目标在哪个口，就转发给除来源口外的所有网口。
2. **记住来源**：同时把“这个源 MAC 从哪个口进来”写进表里。
3. **精确转发**：下次目标 MAC 在表里，就直接从对应口出去，不广播了。

> 「交换机是有 MAC 地址学习能力的，学完了它就知道谁在哪儿了，不用广播了。」

学到的结果叫**转发表**，每条带**过期时间**——理由和 ARP 缓存一样：机器会搬家、口会变，旧记录必须能自己烂掉。

| 现象 | 表里发生了什么 |
|---|---|
| 第一次给某台机器发包，全网都收到了 | 表中无此目标 → 泛洪 |
| 同目标第二次发包，只有它收到 | 源 MAC 已被学习，命中转发表 |
| 一台机器换到另一个口，短暂乱发 | 旧记录还在，等它过期或被打包刷新 |
| 交换机重启后立刻变“笨” | 表在内存里，清空了，重新泛洪学习 |

## 成环：广播风暴与 STP

两台交换机把两个局域网**同时连两条线**，看着像提高了可用性，实际造了一个环。广播帧（含 ARP）会沿环来回转发，永远停不下来——这就是**广播风暴**。同时学习表被反复覆盖：

> 交换机 B 先在右口收到 A 转来的、源自局域网一的广播，就误判“机器 1 搬到右边了”，清掉原记录；下一个包又从左边来，再刷一次。

> 「别想了，压根儿学不会的。」

STP（生成树协议）的思路：让交换机互相“比武”，把**图**剪成**树**。

| 步 | 做什么 | 依据 |
|---|---|---|
| ① | 每台交换机初始都自认掌门 | 各自认为自己是根桥 |
| ② | 比 Bridge ID，最小者当选根桥 | Bridge ID 里含**管理员优先级**字段 |
| ③ | 各交换机认根、算到根的路径开销 | **BPDU**（网桥协议数据单元）只有根桥能发，已隶属某根桥的交换机只能转发掌门指示 |
| ④ | 多余的链路被阻塞，只留一棵树 | 比较用的 Priority Vector 是 `[Root Bridge ID, Root Path Cost, Bridge ID, Port ID]`，值小者优 |

四种合并情形，一句话概括：**掌门遇掌门，输的那位带人归顺；同门相遇，说明发现了环，或把绕路的小弟提成直连、或让更近的小弟当上司；掌门遇别派小弟，小弟拿本帮掌门去比，赢了就对方掌门拜入；不同门的小弟相遇，各自搬出掌门比，输的一方改拜。**

> ⚠️ STP 的代价是**冗余链路平时不转发**。你为可用性买了两条线，其中一条常年闲着，故障切换要等收敛——可用性不是免费的。

## VLAN：在一条线上切出多个局域网

广播域过大的两个后果：广播风暴，以及**同一广播域内可以抓包**（HR 在会议室谈升职加薪，旁人听得见）。人少时物理隔离最省事，人多口不够、人少口浪费，于是有了 VLAN。

做法：在**二层头前加一个 TAG**，里面是 **VLAN ID**，只有 **12 位**。交换机取下二层头时能识别这个 ID：

> 「这样只有相同 VLAN 的包，才会互相转发，不同 VLAN 的包，是看不到的。」

| 项 | 内容 |
|---|---|
| 位置 | 二层头**前**加 TAG |
| 宽度 | **12 位** |
| 上限 | 「因为 12 位可以划分 4096 个 VLAN。」 |
| 隔离判据 | 只有相同 VLAN 的包才互相转发 |
| 端口配置 | 端口可逐口设置所属 VLAN，并可随时改 |
| 示例编号 | 程序员 10、人事 20、财务 30 |

机器一多，一个交换机不够，多台互连时每台都配一遍 VLAN 会崩。解法是把交换机之间的互连口设为 **Trunk 口**：

| 端口角色 | 收发什么帧 | 用在哪 |
|---|---|---|
| 终端接入口 | 只逐口设置所属 VLAN，收帧打 TAG、发帧剥 TAG | 接终端机器 |
| **Trunk 口** | 可转发属于**任何 VLAN** 的帧 | 交换机与交换机互连 |

⚠️ 4096 是硬天花板。公有云用户数早已超过 4096，一个 VLAN ID 已经标不出一个租户，这是后来 Overlay 出现的直接原因之一——见 [8.19 Overlay 与隧道](8.19-Overlay与隧道-GRE-VXLAN-VPN.md)。

## 对架构的三条含义

1. **广播域 = 故障域**。ARP 吼、DHCP、广播风暴、抓包嗅探，全部以一个广播域为边界。划 VLAN 不是整理癖，是在缩小爆炸半径。
2. **同子网才二层直通**。同网段：ARP 拿目标 MAC，交换机转发，一跳到底。不同网段：ARP 拿的是**网关** MAC，包交给三层，MAC 头逐跳重写（见 [8.15 网关与路由](8.15-网关与路由协议.md)）。这解释了“网关配错但能 ping 通同网段”的经典现象。
3. **标识空间是硬约束**。12 位 = 4096 个 VLAN，是协议给的，不是运维能调的。租户数超过它就是架构问题，不是配置问题。

## 反模式

| 反模式 | 后果 |
|---|---|
| 两台交换机之间拉两条线，以为提高了可用性 | 直接造环，广播风暴 + 学习表被反复覆盖，整网瘫痪 |
| 开了 STP 就认为两条线都在干活 | 冗余链路平时阻塞，带宽与吞吐并未翻倍 |
| 以为交换机学一会儿就能收敛 | 成环时永远学不会，转发表被两个方向来回覆盖 |
| 把 ARP 缓存当永久映射 | IP 会变、口会变，缓存过期后旧条目指向黑洞 |
| 用 Hub 扩端口，共享一个冲突域 | 每个字节复制给所有口，规模一上去就拖垮 |
| 一个扁平二层网络承载全公司 | 广播域过大：广播风暴 + 同域可嗅探泄密 |
| 只改 VLAN 编号，不改端口所属 | 人走了权限还在，隔离形同虚设 |
| 把 4096 当“够用的上限” | 公有云租户数已超过，必须换 Overlay 标识空间 |

## 自检

**Q1** 两台机器同网段，`ping` 一个 IP，从“知道 IP”到“帧上线”中间缺哪一步？缺了会怎样？

▸ 答案：缺 **ARP**。IP 包必须装进以太网帧才能上线，帧头的目标 MAC 不能为空，所以要先广播问“这个 IP 是谁”，拿到 MAC 才能组帧。缺了这一步，包在协议栈里就组不出来，现象是“配了 IP 也不通”，而不是“丢包”。

**Q2** 交换机第一次转发某个目标 MAC 时泛洪，第二次就精确转发——中间到底发生了什么？

▸ 答案：泛洪的同时它把**源 MAC 与入端口**写进了转发表。第二次目标 MAC 已在表里，直接命中出端口，不再广播。所以“聪明”来自对**源**地址的学习，而不是对目标地址的查询。

**Q3** 两台交换机双链路互连，为什么“学一会儿就好了”不成立？

▸ 答案：广播帧沿环无限循环，同一源 MAC 的帧会从**两个不同的口**交替到达，学习表被反复覆盖、互相推翻——刚记下“在左口”，下一个包又从右口来。结论是：学不会。解法是用 STP 把图剪成树，阻塞多余链路。

**Q4** STP 比较两个 Priority Vector 时，第一项相同、第二项不同，谁赢？这个顺序为什么重要？

▸ 答案：第二项是 **Root Path Cost**，值小者赢（即离根更近的更优）。顺序是 `[Root Bridge ID, Root Path Cost, Bridge ID, Port ID]`，逐项比、先比根 ID。顺序重要是因为它决定了“先认掌门、再比远近、最后比自身”，保证全网对同一拓扑算出**同一棵树**，否则各自算各自的就会打架。

**Q5** 一个 VLAN ID 12 位、能划 4096 个，为什么公有云不能靠它区分租户？

▸ 答案：4096 是**协议固定**的上限，租户数早已超过它，且它还是**全局**编号空间，多个云/多个域之间会冲突。所以要把标识空间搬到三层之上的封装里（VXLAN 等），用更大的 ID 空间识别租户——见 [8.19 Overlay 与隧道](8.19-Overlay与隧道-GRE-VXLAN-VPN.md)。

## 观测命令

```bash
# ===== 在一台 Linux 主机上（不是交换机上）=====
ip neigh show                # ARP 缓存：IP ↔ MAC ↔ 网卡 ↔ 状态，STALE 表示该复核了
arp -an                      # 老命令，macOS 也能跑；看 Flags 里的 I/E

# Linux bridge 的 fdb 就是交换机的转发表：permanent 不老化，动态条目会过期
sudo bridge fdb show br br0  # 需要 br0 存在且 sudo；看 mac 与 dev(哪个口)

# 看接口的二层细节：有没有 VLAN 标签、vlan_filtering 是否打开
ip -d link show              # 出现 vlan protocol 802.1Q id 10，说明在收发带 TAG 的帧
```

⚠️ 这三条看的是**主机视角**，真正的交换机转发表要用厂商命令（`show mac address-table` 一类，各厂商语法不同）看；两者结构等价：**MAC → 端口 + 老化时间**。
