## 5 分钟入门：先记住这 7 个词

| 词 | 一句话解释 | 生活类比 |
|---|---|---|
| **环境** | 同一套服务在不同用途的副本：开发、预发、生产 | 练车场、模拟考、正式考试 |
| **隔离** | 低风险环境碰不到生产：网络、数据、密钥、权限、配额 | 五道门禁，缺一道就串门 |
| **基础设施即代码** | 机器和网络也写成文件，跟代码一起评审 | 装修先出图纸 |
| **state** | “代码里的资源”对应云上哪个真资源的账本 | 库存台账：哪件货在哪个货架 |
| **plan** | 执行前的差异清单：改什么、建什么、删什么 | 动工前的拆改清单，先签字 |
| **漂移** | 声明一套、实际跑另一套 | 恒温器被拧过，到点又拨回去 |
| **配置中心** | 运行期参数集中存放、可审计 | 小区广播站 |

> 记住 **隔离 → 代码 → 一致** 三步。

## 一张图：这章的骨架

```
问题：测试全绿，上线就炸
        │
        ▼
① 14.1 先分开环境 ── 网络 ├ 数据 ├ 密钥 ├ 权限 └ 配额
        │
        ▼
② 14.2 再写成代码 ── 代码 + state（远端加锁）└ plan（人工评审）
        │
        ▼
③ 14.3 最后让声明等于现实 ── 配置唯一来源 └ 漂移即告警
        │
        ▼
答案：变更先在低风险环境暴露，生产只收评审过的 diff
```

- 顺序不能换：先划边界，才谈得上按环境切 state。
- 三个检查口：五件事是否独立、plan 有无评审、plan/diff 是否长期为空。
- 只有第③步是闭环：漂移不会自己消失，只会被下次发布覆盖。

## 3 个最常见误解

| 误区 | 现实 |
|---|---|
| “多环境就是多买几套机器” | 隔离是网络、数据、密钥、权限、配额；机器分开但数据库共用，测试事故照样打生产 |
| “会写 `.tf` 就算会 IaC” | 难在 state 管理、模块边界、漂移治理；state 放本地等于没有代码 |
| “配置有个地方存着就是配置管理” | 目标是声明等于实际；分叉后下次发布把手改悄悄抹掉 |

## 读完自检（入门级 3 题）

**Q1** 测试全过、上线报错，先查哪五样？

▸ 答案：网络、数据、密钥、权限、配额——逐个问“是否和生产共用”。

**Q2** 同事在控制台手改参数救了一次火，为什么几周后故障又回来了？

▸ 答案：期望状态没变，下次 apply 把现实拉回旧值，手改被静默抹掉。

**Q3** 用什么判据说明这套东西“被管住了”？

▸ 答案：plan/diff 长期为空、变更可追溯、回滚到分钟级；三条同时成立才算被管住。
