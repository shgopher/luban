# 13.3 网络隔离与最小暴露面

## 一句话

> 最小暴露面 = “**默认拒绝 + 白名单放行**”：能不通的就不通、能只走一跳的就别直连；判断标准不是 “有没有防火墙”，而是 “**从互联网出发，能到达哪些不该到达的东西**”。

## 实测：策略矩阵下的可达性

一个 6 节点拓扑（internet → waf → web → app → db，另有 admin 直连 internet 与 db）：

| 策略 | 从 internet 可达 | 说明 |
|---|---|---|
| 全通（默认允许） | **admin、app、db、web、waf、internet** | 数据库与运维后台可被互联网直达 |
| 收敛（默认拒绝 + 白名单） | **waf、web、app、db** | admin 不可从互联网直达；db 只能经 app 间接访问 |

```python
# 可达性检查：默认拒绝，只走白名单边
def reachable(allow):
    seen, stack = {"internet"}, ["internet"]
    while stack:
        n = stack.pop()
        for a, b in edges:
            if a == n and (a, b) in allow and b not in seen:
                seen.add(b); stack.append(b)
    return seen
```

关键不是 “节点多不多”，而是**路径**：`internet → admin → db` 这条边存在，等于把所有隔离都绕过了。

## 隔离的四个层次

| 层 | 手段 | 作用 |
|---|---|---|
| 边界 | 安全组/NACL/WAF | 挡 “从外到内” |
| 东西向 | 服务网格 mTLS / NetworkPolicy | 挡 “内部横向移动” |
| 管理面 | 堡垒机 / 跳板机 | 运维不直连生产 |
| 数据面 | 私网访问、无公网 IP | 数据库不出网 |

## 代码：K8s NetworkPolicy（默认拒绝 + 白名单）

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: default-deny}
spec:
  podSelector: {}                     # 所有 Pod 默认拒绝
  policyTypes: [Ingress, Egress]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: app-from-web}
spec:
  podSelector: {matchLabels: {app: app}}
  policyTypes: [Ingress]
  ingress:
    - from: [{podSelector: {matchLabels: {app: web}}}]
      ports: [{protocol: TCP, port: 8080}]
```

## 暴露面清单与分级

> 结论：最小暴露面不是“配好安全组”就结束，而是把“**入口 × 端口 × 可达范围 × 认证/加密**”逐条登记成清单，再给每条一个等级和处置时限；没有清单，“默认拒绝”也守不住——因为没人说得清哪些口子是业务必需的。

先看一份从 CMDB 导出的 14 条暴露记录（示例资产，分布贴近常见生产环境）：

| 入口 | 端口 | 协议 | 可达范围 | 认证/加密 | 风险等级 |
|---|---|---|---|---|---|
| edge-lb | 443 | TCP | 互联网 | 有/有 | P2 |
| admin-console | 8443 | TCP | 互联网 | 有/有 | **P1** |
| ssh-prod | 22 | TCP | 互联网 | 有/无 | **P1** |
| kube-apiserver | 6443 | TCP | 互联网 | 有/有 | **P1** |
| dns-recursive | 53 | UDP | 互联网 | 无/无 | **P0** |
| legacy-ftp | 21 | TCP | 互联网 | 无/无 | **P0** |
| smtp-relay | 25 | TCP | 互联网 | 无/无 | **P0** |
| mysql-primary | 3306 | TCP | 仅内网 | 有/有 | P2 |
| redis-cache | 6379 | TCP | 仅内网 | 无/无 | **P1** |
| node-exporter | 9100 | TCP | 仅内网 | 无/无 | **P1** |
| prometheus | 9090 | TCP | 仅内网 | 有/无 | P2 |
| backup-agent | 22 | TCP | 仅堡垒机 | 有/有 | P2 |
| internal-api | 8080 | TCP | 仅内网 | 有/无 | P3 |
| job-worker | 9000 | TCP | 仅内网 | 有/无 | P3 |

等级不是拍脑袋定的，而是按“**可达范围 → 认证/加密 → 数据类型**”三条依次判、先命中先定级：

| 等级 | 判定条件（自上而下，先命中先定级） | 处置时限 | 本次清单中的典型条目 |
|---|---|---|---|
| **P0** | 互联网可达 **且** 无强制认证 | 24 小时内关闭或加认证 | dns-recursive、legacy-ftp、smtp-relay |
| **P1** | 互联网可达的管理面；或公网明文；或数据面/管理面未认证 | 本迭代内（≤7 天） | admin-console、ssh-prod、kube-apiserver、redis-cache、node-exporter |
| **P2** | 受控公网业务入口；数据面有认证；内网管理面 | 本季度内 | edge-lb、mysql-primary、prometheus、backup-agent |
| **P3** | 内网业务面（已认证） | 登记，季度复核 | internal-api、job-worker |

判据里的三个数字值得记住：**“互联网可达”是乘数不是加数**——一旦可达，认证缺失就把风险直接推到 P0；**管理面即使有认证，上公网也只能算 P1**，因为认证后有漏洞利用、口令喷洒两条路；**数据面的第一道防线不是加密而是认证**：内网未认证的 Redis（6379）比公网带 TLS 的 API 更容易变成拖库入口。

清单靠人维护必然腐化，所以把它写成可跑的检查器：输入“服务 → 端口 → 可达范围”的登记表，输出对外数量、等级分布和 P0/P1 处置动作。环境 `go1.27.1 / darwin/arm64 / Apple M1`，`go run main.go`：

```go
// 13.3 端口矩阵检查器：把“服务 → 端口 → 可达范围 → 认证/加密”的登记表，跑成一张分级暴露面清单。
// 输入：每行一条暴露记录，逗号分隔：服务,端口,协议,可达范围(internet|bastion|private),认证(true|false),加密(true|false),类型(public|business|management|data)
// 输出：逐条等级、按等级汇总、互联网可达数量、P0/P1 高危项与处置动作。
package main

import (
	"fmt"
	"strconv"
	"strings"
)

type item struct {
	service string
	port    int
	proto   string
	reach   string // internet / bastion / private
	auth    bool   // 是否强制认证
	tls     bool   // 是否传输加密
	kind    string // public / business / management / data
}

type finding struct {
	it     item
	level  int // 0=P0 ... 3=P3
	reason string
	action string
}

// inventory 模拟从 CMDB / 云控制台导出的暴露面登记表（14 条）
const inventory = `edge-lb,443,tcp,internet,true,true,public
admin-console,8443,tcp,internet,true,true,management
ssh-prod,22,tcp,internet,true,false,management
mysql-primary,3306,tcp,private,true,true,data
redis-cache,6379,tcp,private,false,false,data
kube-apiserver,6443,tcp,internet,true,true,management
node-exporter,9100,tcp,private,false,false,management
prometheus,9090,tcp,private,true,false,management
internal-api,8080,tcp,private,true,false,business
job-worker,9000,tcp,private,true,false,business
backup-agent,22,tcp,bastion,true,true,management
dns-recursive,53,udp,internet,false,false,public
legacy-ftp,21,tcp,internet,false,false,business
smtp-relay,25,tcp,internet,false,false,public`

func parse(s string) []item {
	var out []item
	for _, line := range strings.Split(strings.TrimSpace(s), "\n") {
		f := strings.Split(strings.TrimSpace(line), ",")
		if len(f) != 7 {
			panic("列数不对：" + line)
		}
		port, err := strconv.Atoi(f[1])
		if err != nil {
			panic("端口不是数字：" + line)
		}
		out = append(out, item{
			service: f[0], port: port, proto: f[2], reach: f[3],
			auth: f[4] == "true", tls: f[5] == "true", kind: f[6],
		})
	}
	return out
}

// grade：按“可达范围 → 认证/加密 → 数据类型”依次判，先命中先定级
func grade(it item) finding {
	f := finding{it: it}
	switch {
	case it.reach == "internet" && !it.auth:
		f.level, f.reason, f.action = 0, "互联网可达且未强制认证", "立即关闭公网入口或前置统一认证"
	case it.reach == "internet" && it.kind == "management":
		f.level, f.reason, f.action = 1, "管理面上公网（有认证）", "收敛到堡垒机或 IP 白名单"
	case it.reach == "internet" && !it.tls:
		f.level, f.reason, f.action = 1, "公网明文传输", "启用 TLS，否则下线"
	case it.reach == "internet":
		f.level, f.reason, f.action = 2, "受控公网业务入口", "保持 WAF / 限流 / 证书巡检"
	case !it.auth && it.kind == "data":
		f.level, f.reason, f.action = 1, "数据面未认证，内网可达即拖库", "加认证并限定来源到 app 网段"
	case !it.auth && it.kind == "management":
		f.level, f.reason, f.action = 1, "管理面未认证", "加认证或改为仅本机监听"
	case it.reach == "bastion" && !it.auth:
		f.level, f.reason, f.action = 1, "跳板可达且未认证", "补认证，跳板侧加双人审批"
	case it.kind == "data" && !it.tls:
		f.level, f.reason, f.action = 2, "数据面明文", "启用内网 TLS"
	case it.kind == "data":
		f.level, f.reason, f.action = 2, "数据面可达，需最小权限", "来源限定到 app 网段并审计"
	case it.kind == "management":
		f.level, f.reason, f.action = 2, "内网管理面", "限制到堡垒机网段"
	case it.reach == "bastion":
		f.level, f.reason, f.action = 2, "经堡垒机可达", "纳入清单，按季度复核"
	default:
		f.level, f.reason, f.action = 3, "内网业务面（已认证）", "保持现状，纳入清单"
	}
	return f
}

func main() {
	items := parse(inventory)
	findings := make([]finding, 0, len(items))
	internet, perLevel := 0, map[int]int{}
	for _, it := range items {
		if it.reach == "internet" {
			internet++
		}
		f := grade(it)
		perLevel[f.level]++
		findings = append(findings, f)
	}

	fmt.Printf("== 暴露面清单（%d 条）==\n", len(items))
	fmt.Printf("%-16s %-6s %-5s %-10s %-6s %-6s %-12s %-5s %s\n",
		"服务", "端口", "协议", "可达范围", "认证", "加密", "类型", "等级", "理由")
	for _, f := range findings {
		fmt.Printf("%-16s %-6d %-5s %-10s %-6s %-6s %-12s %-5s %s\n",
			f.it.service, f.it.port, f.it.proto, f.it.reach,
			yn(f.it.auth), yn(f.it.tls), f.it.kind, levelName(f.level), f.reason)
	}

	fmt.Printf("\n== 汇总 ==\n")
	fmt.Printf("  条目总数 %d；互联网可达 %d 条（%.0f%%）\n", len(items), internet, 100*float64(internet)/float64(len(items)))
	fmt.Printf("  P0 %d 条 / P1 %d 条 / P2 %d 条 / P3 %d 条\n",
		perLevel[0], perLevel[1], perLevel[2], perLevel[3])

	fmt.Printf("\n== P0（24 小时内处置）==\n")
	for _, f := range findings {
		if f.level == 0 {
			fmt.Printf("  %s %d/%s：%s → %s\n", f.it.service, f.it.port, f.it.proto, f.reason, f.action)
		}
	}
	fmt.Printf("\n== P1（本迭代内处置）==\n")
	for _, f := range findings {
		if f.level == 1 {
			fmt.Printf("  %s %d/%s：%s → %s\n", f.it.service, f.it.port, f.it.proto, f.reason, f.action)
		}
	}
}

func yn(b bool) string {
	if b {
		return "有"
	}
	return "无"
}

func levelName(n int) string {
	return [...]string{"P0", "P1", "P2", "P3"}[n]
}
```

三个数字直接可用来排期：**14 条登记里 7 条互联网可达（50%）**；**P0 3 条、P1 5 条，高危合计 8 条（57%）**；把 P0 的三条（开放递归 DNS、FTP、开放中继 SMTP）处理掉后，互联网可达降到 4 条（29%），且剩下的每条都有认证。注意“对外数量”本身不是 KPI：edge-lb 的 443 必须对外，关键不是 0 条对外，而是**每条对外都有登记、有认证、有到期复核**。

用清单的方式管暴露面，落地成五条检查单：

1. **每条公网入口都有登记三要素**：用途、负责人、复核日期；缺一项按“默认永久开放”处理，当月底强制复核。
2. **管理面零公网直达**：SSH、容器 API、监控、控制台端口，只能经堡垒机或 IP 白名单到达；用“从互联网 telnet/curl 能否握手”验证，而不是看安全组截图。
3. **数据面认证 + 来源限定**：3306/6379 一类端口必须开认证并把来源限到 app 网段；明文数据面端口数为 0。
4. **每季度做一次“外部视角”对齐**：云上公网 IP 清单 × 外部扫描结果 × 本清单三方对照，任何差异开变更单或下线单。
5. **新增暴露走变更单**：端口、可达范围、有效期一并申报；到期未续期自动回收，避免“临时开的口子”变成永久后门。

这套方法的边界要说清：清单只覆盖**登记过的**入口，对影子资产（私开的测试机、忘了注销的公网 IP）无效，必须配合资产测绘与外部扫描一起用；它也只能证明“端口开着、认证配了”，证明不了“认证实现没漏洞”——那属于应用安全与 [13.1 WAF](13.1-WAF.md) 的职责范围。暴露面收敛之后，主机与镜像上还留着的默认配置由 [13.5 系统基线加固](13.5-系统基线加固.md) 接手。

## 反模式

| 反模式 | 后果 |
|---|---|
| 默认允许、只加几条拒绝 | 漏一条就等于全通 |
| 安全组按 “网段” 全开 | 内网横向移动畅通 |
| 运维后台直接暴露公网 | 被扫到即被爆破（见 [38.6 常见攻击](../../L3-质量属性/38-安全/38.6-常见攻击.md)） |
| 数据库有公网 IP | 拖库风险，且难审计 |
| 只做边界不做东西向 | 一台被攻破后可横向到全部 |
| 不做可达性定期扫描 | 策略随时间腐化，没人知道实际暴露面 |

## 三条铁律

> 🔑 **默认拒绝**；白名单之外的流量一律不通。

> 🔑 **运维面不走公网**；堡垒机是底线。

> 🔑 **定期扫可达性**，而不是 “配完就不管”。

## 自检

**Q1** 为什么 “只加几条拒绝规则” 不可靠？

▸ 答案：因为默认允许意味着**任何新增的路径都自动通**：新加一个服务、改一条路由，就可能绕过拒绝规则。默认拒绝 + 白名单则相反：新增路径默认不通，必须显式放行，暴露面只会 “被批准地增加”。

**Q2** 实测里 “全通” 状态下最危险的是哪条边？

▸ 答案：`internet → admin` 与 `admin → db`：攻击者不需要攻破应用，直接打运维后台就能进数据库。收敛后这两条被去掉，db 只能经 app 访问——把 “运维面” 与 “数据面” 从公网隔开。

**Q3** 东西向隔离为什么越来越重要？

▸ 答案：因为边界防护假设 “内部可信”，但现实中**一台机器被攻破后可以横向移动**：容器/微服务之间默认互通，攻击者从弱服务跳到数据库。东西向策略（mTLS + NetworkPolicy）把 “内网” 也变成 “需要授权才能通”。

**Q4** 安全组与 NACL 有什么区别？

▸ 答案：安全组是**有状态**的（放行请求即自动放行响应），作用在实例/网卡级；NACL 是**无状态**的（要分别配入站/出站），作用在子网级。常见用法是 “NACL 做粗粒度子网隔离，安全组做实例级精细控制”。

**Q5** 如何验证 “暴露面真的收敛了”？

▸ 答案：从**外部视角**扫：公网端口扫描、DNS 解析记录、云上 “公网 IP 清单”、以及 “从互联网能否到达管理端口”。配置检查只能证明 “你以为的”，扫描才能证明 “实际的”。

**Q6** 隔离会不会影响可用性/排障？

▸ 答案：会：默认拒绝会让 “临时联调” 变麻烦，排障时可能被策略挡住。缓解办法是 **IaC 管理策略变更**（可审计、可回滚）、**按环境分级**（dev 宽松、prod 严格）、**保留观测通道**（日志/指标可出，业务流量不可随意进）。

**Q7** 最小暴露面和 “零信任” 是什么关系？

▸ 答案：最小暴露面是零信任的**一部分**：零信任还要求 “每次访问都认证授权、不因内网位置而默认信任”。先做最小暴露面（网络层收敛），再做身份层（mTLS/短期凭证）与策略层（按身份授权），是渐进路径（见 [38.8 零信任](../../L3-质量属性/38-安全/38.8-零信任.md)）。
