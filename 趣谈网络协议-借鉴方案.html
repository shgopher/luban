                3. 落地的 12 条（按价值 × 成本排序）

                3.1 【C】分层即封装：一个包的一生（新 8.0-分层与封装.md）

                为什么排第一：本库 8-网络 从 TCP 起讲，全书没有一处说清“分层是套娃、不是各自开会”。缺的不是知识点，是整章的视图语言——8.1 有四层分工表，但没有回答“二层设备里到底有没有 HTTP”。

                课程给了什么：

                • 反驳教科书比喻：「所有不能表示出层层封装含义的比喻，都是不恰当的」；正确图景是套娃——总经理被经理装进兜里，经理被组长装进兜里。
                • 一条铁律：「只要是在网络上跑的包，都是完整的。可以有下层没上层，绝对不可能有上层没下层」。
                • 判据：二层设备 = 只摘 MAC 头；三层设备 = 再摘 IP 头；四层 LB 再摘端口；七层 LB 再解应用层。
                • 程序视角：process_layer2 → process_layer3 → process_tcp/udp，没有 process_http，靠端口交给应用。

                落盘内容：协议三要素表 → 收/发两条链（含“目标 MAC 不能空着”）→ 各层头部典型长度表（14/20/20/8）→ 套娃误区表 → 铁律解释四个常见困惑 → 设备判据表 → 一次下单的链路地图 + 一条可跑抓包命令 → 8 条反模式 + 5 题自检。

                价值：后面 8.14/8.15/8.18/8.19 全部引用它；8.0 是本章的“坐标系”。

                3.2 【C】二层：ARP、交换机与 VLAN（新 8.14-二层-ARP-交换机与VLAN.md）

                库内现状：集线器、CSMA、广播风暴、STP、Trunk、802.1Q、ARP 缓存 全库零命中；VLAN 只有 2 处泛泛提及。

                课程给了什么：

                • 三点归纳：「MAC 层是用来解决多路访问的堵车问题的」；「ARP 是通过吼的方式来寻找目标 MAC 地址的，吼完之后记住一段时间」；「交换机是有 MAC 地址学习能力的」。
                • 环路的机制：两台交换机双链路互连 → 广播在两边来回转发 → 学习表被反复覆盖，「别想了，压根儿学不会的」。
                • STP：Bridge ID 含管理员优先级、BPDU 只有根桥能发、Priority Vector 四项值小者优、四种合并情形。
                • VLAN：二层头前加 TAG、12 位 → 4096 个、「只有相同 VLAN 的包，才会互相转发」、互连口设 Trunk。
                • 答疑补的：MAC 地址 48 比特，前 24 位 OUI 由 IEEE 分配、后 24 位厂家分配；「至少应该保持一个局域网内是唯一的」。

                落盘内容：一层/Hub 的代价 → MAC 层解决的是“谁先发”（三种多路访问）→ ARP 四步 + 缓存过期 → 交换机泛洪/学习/过期表 → 环路与 STP → VLAN/TAG/Trunk 与 4096 天花板 → 对架构的三条含义（广播域=故障域；同子网才二层直通；标识空间是硬约束）。

                3.3 【B+C】网关与路由：一跳一跳怎么走到对端（新 8.15-网关与路由协议.md）

                库内现状：8.8 讲 NAT、8.7 讲 VPC/子网，但 距离矢量、链路状态、自治系统 零命中，OSPF 只有 1 处、BGP 6 处都是零散提及。

                课程给了什么：

                • 判据只有一条：目标 IP 与本机是否同网段；网关地址必与源 IP 同网段，否则配不上。
                • 转发网关 vs NAT 网关的分界：「MAC 地址只要过网关，就必定会改变，因为已经换了局域网」；「在 IP 头里面，不会保存任何网关的 IP 地址」。
                • 策略路由：多张表 + ip rule（0/32765/32766/32767 四档）+ ip route flush cache + nexthop weight。
                • 两族算法：距离矢量（Bellman-Ford，「好消息传得快，坏消息传得慢」，RIP <15 跳）vs 链路状态（Dijkstra，只播变化）；OSPF 的等价路由（ECMP）与 LVS 配合；BGP 用 AS 路径给坏消息止损、eBGP/iBGP 分工。

                落盘内容：同/跨网段判定表 → “什么变了、什么没变”的逐段表 → 路由表三要素 + ip route/ip rule 实跑输出 → 策略路由（房东拉两根宽带的类比）→ 六列算法对照表 → 坏消息传得慢的算例 → 三条架构含义（ECMP 换横向带宽、策略路由做多出口、AS 边界=可控域边界）。

                3.4 【C】DHCP 与 PXE：地址租约与网络启动（新 8.16-DHCP与PXE.md）

                库内现状：DHCP 零命中，PXE 只在 11.14 出现 1 次（固件章节，没有租约与四包）；TFTP 零命中。

                课程给了什么：

                • 配错不报错：「不会出现任何现象，就是包发不出去呗」；「Linux 默认的逻辑是，如果这是一个跨网段的调用，它便不会直接将包发送到网络上，而是企图将包发送到网关」。
                • 四包：Discover（0.0.0.0 → 255.255.255.255，UDP 封 BOOTP）→ Offer（仍广播）→ Request（广播选中并要求其他服务器撤销）→ ACK（广播确认）。
                • 续租：租期过去 50% 直接向原服务器要；「最终租约达成的时候，还是需要广播一下，让大家都知道」。
                • PXE 五步 + 为什么客户端只能放在 BIOS 里（还没装系统、连启动扇区都没有）；样例 DHCP 配置里的 next-server/filename/21600/43200。

                落盘内容：三种配错对照（乱配网段 / 网关异网段 / 同网段不同掩码）→ 跨网段为什么必须过网关 → 四包表 → 租期与续租 → 引导链与 PXE 五步 → 一份可改的 dhcpd.conf + 验证命令 → 三条架构含义（地址是租约不是资产、装机流水线=DHCP+TFTP+配置管理）。

                3.5 【B】ICMP 与逐跳定位：ping、traceroute 与 MTU（新 8.17-ICMP与逐跳定位.md）

                库内现状：11.11:206 只把 ping/traceroute 当工具列了一行（“RTT 稳定但高 = 距离/绕行”），没有报文类型、没有代码位、没有 TTL 逐跳与 MTU 探测的原理。

                课程给了什么：

                • 类型码：8/0 查询；3/4/11/5 差错；类型 3 的代码 0–4（网络/主机/协议/端口不可达、需分片但设了不分片位）。
                • 差错报文带“证物”：「除了前面还是 IP，ICMP 的前 8 字节不变，后面则跟上出错的那个 IP 包的 IP 头和 IP 正文的前 8 个字节」。
                • traceroute 两用：TTL 递增收类型 11；置不分片位收 3/4 做 MTU 探测；用 >30000 的不可能端口触发 3/3 判定到达。
                • 边界：「ping 不通不代表网络不通」，禁 ICMP 时用 telnet 借其他协议。

                落盘内容：两类报文 + 类型码速查（含代码含义）→ ping 全过程 → 四种现象对照 → traceroute 两种玩法 → 逐跳定位五步 + 三条命令（含 macOS/Linux 的 -M do / -D 差异）→ 三条架构含义（探测留口子、MTU 是跨层契约、路径不对称）。

                3.6 【C】数据中心网络：从三层到叶脊（新 8.18-数据中心网络-从三层到叶脊.md）

                库内现状：Dragonfly、BCube、胖树、Spine/Leaf、TOR、TRILL 全库零命中；数据中心 只在成本与合规语境出现。这是全书最彻底的空白之一——读者不知道一个机房内部怎么连线。

                课程给了什么：

                • 「数据中心是一个大杂烩，几乎要用到前面学过的所有知识」；「这里的三层不是指 IP 层，而是指接入层、汇聚层、核心层三层」。
                • 逐段高可用：服务器双网卡双线 + LACP bond；TOR 走 STP 主备或堆叠双活（最多 4 台堆成一台）；汇聚层形成 POD/可用区；核心多组全互连 + OSPF/ECMP。
                • 大二层与 TRILL：「二层环有问题，三层环没有问题，那就把三层的路由能力模拟在二层实现」；RBridge 跑链路状态协议、加 TRILL 头 + 外层 MAC、广播用分发树。
                • 南北 vs 东西：「上北下南，所以称为南北流量」；东西流量占多数后改 Spine/Leaf：L2/L3 分界在 leaf、spine 提供弹性 L3、叶脊间 ECMP；「传统的三层网络架构是垂直的结构，而叶脊网络架构是扁平的结构，更易于水平扩展」。

                落盘内容：6 行全景表（段/设备/解决什么/单点在哪）→ 逐段买可用性表 → 环路 STP vs 堆叠 → POD 四步 → 大二层与 TRILL → 南北/东西与叶脊三条判据 → 三条架构含义（收敛比决定集群规模、二层域=故障域、叶脊是可水平扩展拓扑）；附 cat /proc/net/bonding/bond0 的容器真实输出作反例（容器只有 eth0，没有 bond）。

                3.7 【B+C】Overlay 与隧道：GRE、VXLAN、VPN（新 8.19-Overlay与隧道-GRE-VXLAN-VPN.md）

                库内现状：7.8:80 已经把 VXLAN 的落地讲得很细（三张表、UDP 模式三次拷贝、host-gw 的 10% vs 隧道 20–30%、BGP N²），但没有：VLAN 4096 为什么不能靠改协议解决、GRE 的三个不足、VNI 24 位的语义、VTEP 的组播 ARP 学习、IPsec 两阶段、MPLS VPN 的三件套。

                课程给了什么：

                • 扩容的边界：「当这个协议形成一定标准后，千千万万设备上跑的程序都要按这个规则来」——所以只能扩展，不能改字段。
                • GRE：IP-over-IP、key 32 位、NVGRE 网络 ID 24 位；三个不足（点对点导致隧道数指数增长、不支持组播、很多防火墙无法解析）。
                • VXLAN：二层外再套 VXLAN 头（VNI 24 位）→ UDP → IP → 外层 MAC；VTEP 是“虚拟机网络的管家”；ARP 靠 IGMP 加入组播组，「我不是加入了一个微信群么？可以在里面 @all 一下」，应答走单播，双方互学。
                • IPsec：三目标（私密性=对称加密、完整性=hash、真实性=预共享密钥/数字签名）；两阶段（DH 算 K 建 IKE SA → 用 K 下发 M 建 IPsec SA）；AH 只摘要、ESP 加密+摘要。
                • MPLS VPN：标签 20 位、LSR 的 FIB/LFIB、LDP 从下游分发、PE/CE/P 三角色、VRF + MP-BGP + 两层标签。

                落盘内容：VLAN 天花板 → 隧道三协议骨架（轮渡类比）→ GRE 三个坑 → VXLAN 封装逐行 + 组播学习五步 → VPN 三条路 + IPsec 三目标/两阶段 → MPLS 三件套 → 选型表（GRE/VXLAN/IPsec/MPLS × 封装/租户标识/组播/过防火墙/场景）+ 可跑的 ip link add ... type vxlan 命令。

                3.8 【C】SDN 与网络 QoS：控制面集中之后（新 8.20-SDN与网络QoS.md）

                库内现状：SDN 全库 1 处（与网络无关的上下文），OpenFlow、流表 零命中；QoS 23 处全是应用层“服务质量”的泛称，没有一台设备级的队列。

                课程给了什么：

                • SDN 三特点：控制与转发分离、开放接口（「上北下南嘛」）、逻辑集中控制；「控制平面就是统一的控制中心，就像小区物业的监控室」。
                • OpenFlow/OpenvSwitch：流表匹配-动作模型覆盖四层，in_port/dl_*/nw_*/tp_* 与 mod_*；access/trunk 端口语义；bond 三模式；内核 datapath 未命中 upcall。
                • QoS 第一原则：「其实我们能控制的只有出方向……进入的方向是无法控制的，只能通过 Policy 将包丢弃」；pfifo_fast/SFQ/TBF 三种无类别队列；HTB 树 + 「同一个 root class 下的子类可以相互借流量」；rate 之和等于网卡上限；OVS 的 ingress policing 与 egress shaping。

                落盘内容：四类症状 → SDN 三特点 → 流表四层匹配-动作表 → access/trunk 与 bond → 只能控出向的两行表 → 三种队列对照 → HTB 树 + 一段可抄的 tc 命令（root class 必须先建）→ 三条架构含义（集中控制=爆炸半径集中、QoS 是隔离最后一道、标识与策略一起设计）。

                3.9 【B】UDP：同一层里的另一个选择（8.1 增一节）

                原 8.1 只讲 TCP，UDP 仅出现在分层表里。增节内容：TCP/UDP 五维对照 → UDP 头标准四字段（8 字节）→ 「建立连接的真实含义是维护数据结构」 → 三大使用场景判据（内网/广播多播/时延优先）→ 五个“城会玩”（QUIC、直播、实时对战、IoT、GTP-U）→ ss -lunp 与 ICMP 端口不可达的验证 → 一条警告：用 UDP 却不自建可靠性，是把四件事全推给业务。

                3.10 【B】HTTPDNS：把解析权收回客户端（8.4 增一节）

                原 8.4 有 ECS/GeoDNS，但没有“LocalDNS 会指错路”的机制与工程方案。增节内容：五个问题表（缓存不刷新/转发/出口 NAT/更新慢/递归延迟）→ 自建 HTTP 集群 + SDK → curl 'http://ip/d?dn=host' → 缓存三层与同步（Cache-Aside）/异步（Refresh-Ahead）对照 → 分维度缓存与调度闭环 → *「慢也比访问不到好」*的兜底。

                3.11 【B】四代协议演进（42.6 增一节）

                原 42.6 有五协议对比与决策表，但缺“为什么会演化成这样”。增节内容：一张四代表（ONC RPC → SOAP → REST → Hessian2/Protobuf+gRPC），每代补的是上一代的哪个洞、新引入的代价；四个可算的细节（123 的 8 位 vs 3/6 字节、Protobuf Tag=(field<<3)|wire_type 得 26、变长整数 7 位/128、required 与字段号不可改）；一句判据：契约放在哪里，决定了加一个字段要通知多少人；末尾接 Envoy 四要素与 Service Mesh。

                3.12 【B】P2P：把用户变成节点（9.0 增一节）

                原第 9 章只有 CDN。增节内容：四种分发模式的成本结构表（集中式/CDN/P2P/混合）→ 三个技术要点表（分片+SHA-1 校验、.torrent 的元数据/数据分离、DHT 的 XOR 距离与 log2(N)）→ 「虽然下载的过程是非中心化的，但是加入这个 P2P 网络的时候，都需要借助 tracker 中心服务器」 → 一句结论：P2P 把分发成本从带宽账单换成了客户端资源 + 校验开销 + 合规风险。
